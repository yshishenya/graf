- Идемпотентный checkout теперь возвращает ранее сохранённый hosted URL до
  повторной проверки промокода; campaign reservations сериализуются счётчиком
  на строке кампании, а освобождение допускается только до provider mutation.
- Referral lookup использует user-scoped auth context; migrations `0054` и
  `0055` добавляют campaign-level reservation counter и owner-scoped RLS.
  Refund observations проверяют валюту,
  размер и cumulative partial-refund cap.
- Публикация canonical playback теперь вызывает storage `reserve → commit` и
  применяет effective plan cutoff: истёкший trial/paid row получает Free capacity.
- Reconciliation activity дополнительно делает provider GET для сохранённых
  `initial_checkout.provider_id` при потерянном webhook; поиск платежа по
  metadata/idempotency после POST-timeout без provider id остаётся gap.
- Refund webhook backstop теперь проходит bounded YooKassa cursor pagination
  (limit 100, до 20 страниц, повторный/некорректный cursor переводит событие
  в pending gap). Потерянные registry parts и ежедневный registry import по-
  прежнему требуют операционного доказательства.
- При demotion/deactivation назначенного billing Owner recurring authority
  теперь отзывается под row-lock с увеличением authority/application version;
  исторический owner id сохраняется для referral/refund attribution.
- `/api/v1/admin/metrics` публикует только агрегированные billing counters, а
  `/api/v1/health/ready` содержит отдельный `billing_mutations` diagnostic
  (`disabled`/`emergency_stop`/`ready`) и не делает общий readiness красным при
  остановленном биллинге.
- 28 targeted referral/RLS/promo/account tests и 20 normalization unit tests
  прошли; PostgreSQL finalize/RLS прогон не запускался из-за отсутствующих
  `TWOBRAIN_DATABASE_URL` и `GRAF_TEST_POSTGRES_ADMIN_URL`.
- Runtime launch blockers перечислены в `open-gaps.md`; они намеренно не
  закрыты фиктивным чекбоксом и требуют provider/production evidence.

## Ремедиация после повторного review

- Webhook ingress теперь читает chunked body потоково и прекращает чтение при
  `256 KiB`, поэтому отсутствие `Content-Length` не превращается в unbounded
  memory buffer.
- Включение billing требует непустые YooKassa API/webhook/referral secret
  files и валидный support email; migration `0057_referral_workspace_scope`
  оставляет catalog read доступным приложению, но запрещает catalog writes вне
  maintenance role.
- Billing UI теперь имеет явные `Применить`/`Удалить` для промокода,
  `Удалить способ оплаты` с guard при активном renewal, более полное checkout
  summary и различает pending/reconciliation-gap states. Эти изменения не
  закрывают внешние canary, human UX или product-market gates.
