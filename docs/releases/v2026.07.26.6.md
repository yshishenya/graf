## Миграция и совместимость

`.6` — ручной migration bootstrap для клиентов, установленных из исторической
local/self-signed цепочки `.5`. Пользователь один раз устанавливает
notarized `.pkg`; этот переход не выполняется через Sparkle и не меняет live
appcast. После bootstrap следующий релиз публикуется обычным Sparkle-путём
`Developer ID → Developer ID` с теми же bundle id, TeamIdentifier, designated
requirement, feed URL и Sparkle trust generation.

Local, ad-hoc и self-signed artifacts не являются частью текущего публичного
канала. Они допустимы только как архивные evidence или изолированные тестовые
fixtures.

## Ограничения

- Клиентам старой `.5` нужен ручной `.pkg`; публичный appcast не используется
  для смены Apple signing lineage.
- Следующий релиз нельзя выпускать local/self-signed или ad-hoc. Для него
  обязательны Developer ID identities, notarization/stapling/Gatekeeper и
  обычная same-lineage Sparkle validation.
