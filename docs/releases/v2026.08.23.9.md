# v2026.08.23.9 — надёжность автоматической записи

## Что изменилось

- Синхронизированы AudioHAL и системный индикатор: одна встреча больше не
  завершается из-за окончания только одного источника.
- Временный отказ consumer-а больше не поглощает trigger: detector повторяет
  предложение после bounded паузы, а принятые и terminal-решения не дублируются.
- Countdown и автоматический старт повторно проверяют актуальную policy,
  acknowledgement, target и auth/readiness непосредственно перед capture.
- Observer получает bounded snapshot, восстанавливается после сбоя и wake и
  не запускает параллельные `/usr/bin/log stream` процессы.
- WebKit same-origin cookie snapshot стал авторитетным для native session;
  stale replacement и logout удаляют старые применимые копии.

## Проверка

- Feature-focused macOS suite на синхронизированном base `42791b38`:
  `135/135` тестов.
- Full CI пропущен по явному решению владельца релиза; этот факт не считается
  успешным full-CI gate.
- Подпись, notarization, Sparkle continuity, production smoke и health checks
  фиксируются в deployment receipt после фактической выкладки.

## Совместимость и миграция

- Серверный API и схема данных не меняются.
- Обновление macOS-приложения сохраняет существующий bundle identity и
  Developer ID → Developer ID Sparkle trust chain.
- Production policy остаётся target-scoped; ручные Record/Stop сохраняются.

## Известные ограничения

- Проверка использует synthetic metadata и не записывает реальные встречи,
  аудио или расшифровки.
- Sleep/wake и deliberate stop проверяются детерминированными test seams;
  runtime evidence указывается отдельно.
