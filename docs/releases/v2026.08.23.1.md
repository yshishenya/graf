# ГРАФ v2026.08.23.1

## Что изменилось

- Исправлено подключение Яндекс ID и VK ID из настроек: строгий PostgreSQL RLS
  больше не приводит к HTTP 500 при создании callback state.
- Объединение профилей, повторный вход, отключение способа входа и устаревшие
  подтверждения получили provider-aware recovery без тупиков.
- Добавлена миграция `0076_account_linking_rls`, разделяющая callback,
  provider-link и account-merge контексты и устраняющая рекурсию RLS.

## Совместимость и migration impact

- Migration head в production: `0076_account_linking_rls`. Переноса встреч,
  workspace-данных или пользовательских credentials не выполняется.
- Для старых подтверждений требуется начать новый provider-aware OAuth/email
  путь; повторная отправка устаревшего подтверждения намеренно запрещена.
- Откат схемы назад не используется: для recovery применяется исправление
  вперёд с сохранением данных.

## Known limitations

- Отдельные playback-maintenance gates (`automatic_retry`, `backfill_inventory`,
  `normalization_cleanup`) имеют production evidence по пустому текущему
  inventory и audit-истории; они не относятся к account-linking acceptance.
- Upload-only synthetic fixture не создаёт canonical playback artifact, поэтому
  прямой byte-range запрос к этой fixture вернул `409`. Локальные playback
  contract/integration проверки проходят; это не заявляется как production
  user-playback PASS.
- Реальные email/Yandex ID/VK ID credentials пользователя не вводились и не
  сохранялись.
