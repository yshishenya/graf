# Измерение: потеря адреса перед ГРАФ

27.10.2026. Lane: read-only investigation; запись отчёта docs-only.
Рабочий source `7e32f0da25db5d78d742f9cde1ed59a49ffcaf1a`.

## Подтверждённые результаты

- Привилегированный `nginx -T`: синтаксис PASS,30/30 файлов, include graph
  разрешён,0 real_ip,3 замены XFF=$remote_addr и3 XFP=https.
  Configuration SHA256:
  `41ddf28c8cc57dee25d3a1ba7665b30b14c773d526f13bfe23e7884ccff4b7a2`.
  Совпадает с23.10; worker timing=false. Reload не выполнялся.
- Чтение доступного include graph:29 файлов,1 закрытый include не читался
  этим непривилегированным проходом. Вход443 использует stream/ssl_preread,
  направляет ГРАФ на loopback10444; PROXY protocol не включён. TLS listener
  ГРАФ10444 также не принимает PROXY protocol; real_ip восстановления нет.
  Это отдельный проход, он не объявляется полным чтением30 файлов.
- Один контролируемый внешний HTTPS health-запрос с обычной проверкой TLS
  дал200. Во время его удержания появилось ровно одно новое TCP-соединение
  на10444, peer loopback. Это подтверждение участка сети по разнице сокетов,
  а не непосредственное чтение `$remote_addr` из памяти nginx.
- От host-loopback до API наблюдался ровно один новый peer, он gateway
  Docker и пока вне native FORWARDED_ALLOW_IPS. CLI-перекрытие убрано.
- В обеих рабочих bridge-сетях прямые поддельные XFP от обычных соседних
  контейнеров игнорируются. Все4 попытки достучаться через адреса gateway
  к опубликованному loopback-порту API недоступны. Ничего не перезапускалось.

## Вывод и следующее действие

Изолированная прежняя матрица начиналась с nginx и не воспроизводила
предыдущий общий вход443. По наблюдаемой цепочке исходный адрес теряется
ещё до TLS10444: добавление точного Docker peer могло бы исправить HTTPS,
но не восстановило бы посетителя. Нельзя принимать это как operator/external
классификацию или добавлять loopback/gateway в INTERNAL_HOSTS.

[Независимое ревью](../../specs/273-paid-traffic-analytics/validation/t098-production-gate-review-2026-10-27.md)
подтвердило BLOCK env-only подхода до проверки полного ingress. Reviewer
сам прочитал network receipt, исходники и прежние ограничения; новый live
socket-delta и topology scan выполнены исполнителем после этого ревью и
не объявляются независимо воспроизведёнными reviewer.

Следующий срез существующей F273/T098: уточнить plan/scenario по фактическому
входу443, выбрать минимальное сохранение происхождения адреса без влияния
на соседние SNI-сервисы и пройти независимую проверку решения. После этого —
изолированная матрица полного пути, текущие обязательные PR/Full/CD gates
для изменённого кода/конфигурации и отдельная рабочая приёмка. Не добавлять
доверие к заголовку браузера и не объявлять loopback адресом посетителя.

Расширенная аналитика/IP выключены. Нормализация HTTPS со слешем,
классификация оператора, T118/T119 и сквозной отчёт не приняты.
TTL событий ClickHouse отсутствует по read-only наблюдению; ежедневный
контроль и другие категории хранения этим не подтверждаются.
