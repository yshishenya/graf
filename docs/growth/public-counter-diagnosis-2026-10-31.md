# Почему пустой отчёт Метрики не подтверждает отсутствие трафика

Проверка 31.10.2026, 19:12 UTC. Полоса: **read-only investigation**.
Настройки и данные рабочего сервера не менялись.

## Проверенные факты

Рабочая копия сервера находится на
`976f310f9fff09b96a1e6fcec99cb43f4bb706ae`. Чтение настроек внутри работающего
API и вызов `build_public_analytics_context(settings, "/")` дали:

| Условие | Фактическое значение |
| --- | --- |
| Окружение | `production` |
| Общий флаг публичной аналитики | `true` |
| Номер счётчика присутствует | `true` |
| Версия согласия в настройках | `2026-08-13.1` |
| Версия согласия, требуемая работающим кодом | `2026-10-22.1` |
| Итоговый `enabled` | `false` |
| Итоговый `consent_ui_enabled` | `false` |
| Итоговый `external_counter_allowed` | `false` |

В публичном HTML главной и руководства протокола нет блока
`graf-public-analytics-config` и подключения `analytics.js`. Запросы выполнены
с явно техническим `User-Agent: GRAF technical-check bot`; они не являются
новыми внешними посещениями. Отсутствие подключения объясняется итоговым
контекстом на сервере, а не предположением о поведении конкретного браузера.

В `public/analytics.py` общий флаг, допустимое окружение и наличие номера
недостаточны: `configured` требует совпадения версии согласия. Шаблон
`public/templates/public/_analytics.html` подключает выбор согласия и контроллер
только при `consent_ui_enabled=true`. Это работающая защитная проверка;
её удаление не требуется.

## Вывод и предел

Ранее записанное «публичная аналитика включена» описывает только общий флаг.
**Клиентское измерение публичных страниц фактически не включено.** Поэтому
ноль в кабинете Метрики за 24–30 октября нельзя использовать для вывода об
отсутствии посетителей или эффективности размещений. Начало расхождения
времени версий и полнота исторических периодов не установлены.

Обезличенный серверный агрегат работает отдельно; он считает запросы,
а не доказанные посещения людей. Его ограничения и `filters_verified=false`
сохраняются. Сквозная воронка, T0, регистрации и оплаты этим разбором
не принимаются.

## Независимый разбор границ

Проверяющий `public_counter_readiness_review` перечитал четыре действующих
чек-листа F273: 117 отмеченных пунктов, 0 открытых; отметки не менялись.
Это качество требований, а не подтверждение работающей аналитики.

Смена версии включает интерфейс согласия на всех публичных страницах и
попытки отправки в собственный `/analytics/public-event`. Внешний скрипт
Метрики остаётся ограничен `/` и `/download`; руководство Product Radar
использует собственный посредник в PostHog. При выключенной доставке
этот маршрут не подтверждает визиты на руководство. Фактические запреты
PostHog и внутренних провайдеров требуется проверить отдельно.

Перед восстановлением дополнительно проверяются флаг записи поведения,
актуальные четыре юридические страницы и настройки кабинета по F266.
Неизвестный `public_analytics_replay_enabled` нельзя описывать как выключенный.
Принятие узкой Метрики не закрывает Product Radar/T0, IP и регистрацию/оплату.
