# Feature Specification: Безопасный запуск macOS после обновления

**Feature Branch**: `codex/232-macos-resource-bundle-hotfix`

**Created**: 2026-09-02

**Status**: Draft

**Input**: После обновления до `v2026.09.02.1` GRAF завершается при каждом запуске. Нужно устранить корневую причину, закрыть пробел в релизной проверке и выпустить безопасное обновление.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - GRAF снова запускается (Priority: P1)

Пользователь, обновивший или переустановивший GRAF, может открыть приложение без немедленного завершения и пользоваться прежними функциями записи.

**Why this priority**: Текущий публичный релиз блокирует весь продукт до входа пользователя в приложение.

**Independent Test**: Установить новый подписанный пакет поверх сломанной версии и подтвердить, что приложение остаётся запущенным, показывает основной интерфейс и не создаёт новый startup-crash.

**Acceptance Scenarios**:

1. **Given** установлен `v2026.09.02.1`, **When** пользователь устанавливает hotfix и открывает GRAF, **Then** приложение запускается без аварийного завершения и сохраняет прежние локальные данные и разрешения в пределах гарантий macOS.
2. **Given** встроенный fallback-ресурс доступен в стандартной структуре приложения, **When** начинается наблюдение за встречами, **Then** ресурс загружается и проходит существующую валидацию.
3. **Given** fallback-ресурс отсутствует или повреждён, **When** приложение запускается, **Then** оно не завершается аварийно, использует допустимый cache/remote fallback или показывает ограниченное состояние обнаружения встреч.

---

### User Story 2 - Безопасное обновление для ещё не затронутых пользователей (Priority: P1)

Пользователь здоровой предыдущей версии получает только исправленный hotfix и после обновления продолжает работу без ручного восстановления.

**Why this priority**: Публичный канал обновлений не должен продолжать распространять версию, которая не запускается.

**Independent Test**: Обновить установленную предыдущую здоровую версию через публичный Sparkle feed и подтвердить версию, подпись, запуск и доступность основных ручных действий записи.

**Acceptance Scenarios**:

1. **Given** установлена предыдущая здоровая версия, **When** пользователь принимает обновление, **Then** устанавливается версия строго новее `2026.09.02.1` и успешно запускается.
2. **Given** публичные ZIP, PKG, checksum и appcast опубликованы, **When** они скачиваются заново, **Then** размеры, хеши, подписи и версия согласованы между release notes, GitHub и download host.

---

### User Story 3 - Релизный процесс ловит повторение ошибки (Priority: P1)

Оператор не может опубликовать macOS-релиз, который подписан и notarized, но завершается при обычном запуске из-за отсутствующего или недоступного ресурса.

**Why this priority**: Подпись, notarization и модульные тесты уже прошли для сломанного релиза и не проверили реальный runtime-путь упакованного приложения.

**Independent Test**: Собрать production-like `.app`, выполнить проверку структуры и реальный launch smoke из готового bundle; искусственно удалить обязательный resource bundle и подтвердить безопасное ограниченное поведение вместо crash.

**Acceptance Scenarios**:

1. **Given** готовый candidate `GRAF.app`, **When** выполняется release validation, **Then** основной бинарник запускается из упакованного bundle и остаётся жив не менее пяти секунд.
2. **Given** candidate не может запуститься или сразу завершается, **When** выполняется release gate, **Then** публикация блокируется с понятной причиной.
3. **Given** candidate успешно запускается, **When** выполняются подпись, notarization, stapling и Gatekeeper-проверки, **Then** evidence относится к одному exact SHA и одному набору артефактов.

### Edge Cases

- Resource bundle существует, но расположен не там, где его ищет runtime.
- Resource bundle отсутствует целиком, имеет неверный формат или не содержит baseline JSON.
- Приложение запускается из SwiftPM build directory, `GRAF Dev.app`, `GRAF Local.app`, production ZIP или установленного `/Applications/GRAF.app`.
- На машине уже запущен другой экземпляр GRAF; smoke не должен принять его за проверяемый candidate или завершить чужой процесс.
- Apple Silicon и Intel-срезы одного universal binary используют одинаковый безопасный путь поиска ресурса.
- Пользователь уже находится на сломанной версии и не может дождаться автоматического обновления из-за раннего crash.
- Публичный ZIP или checksum отличается от значения в release notes либо GitHub asset.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: GRAF MUST запускаться без аварийного завершения при доступном корректном baseline-ресурсе в стандартной структуре macOS-приложения.
- **FR-002**: Отсутствующий, недоступный или повреждённый baseline-ресурс MUST NOT завершать всё приложение; обнаружение встреч должно перейти к существующему cache/remote fallback или ограниченному состоянию.
- **FR-003**: Исправление MUST сохранять существующую трёхсостоянийную политику автозаписи, ручные Record/Stop, видимый индикатор и текущие privacy/capture gates без функционального расширения.
- **FR-004**: Release candidate MUST проходить проверку фактического расположения ресурсного bundle и baseline JSON внутри готового `GRAF.app`.
- **FR-005**: Release candidate MUST проходить реальный startup smoke из готового app bundle; процесс должен оставаться живым не менее пяти секунд, а проверка должна завершать только созданный ею процесс.
- **FR-006**: Startup smoke MUST блокировать release при немедленном crash, отсутствующем бинарнике, неверной структуре bundle или невозможности однозначно идентифицировать проверяемый процесс.
- **FR-007**: Hotfix MUST иметь CalVer `v2026.09.02.2` или более высокий свободный номер текущего дня и быть строго новее сломанной версии.
- **FR-008**: ZIP и PKG MUST быть Developer ID signed, notarized, stapled и приняты Gatekeeper до публикации.
- **FR-009**: Appcast MUST публиковаться последним и ссылаться на доступный подписанный ZIP hotfix-версии.
- **FR-010**: Публичные ZIP, PKG, checksum, appcast, release notes и GitHub Release MUST содержать согласованные версии, размеры и SHA-256; повторное скачивание с download host должно подтверждать эти значения.
- **FR-011**: Релиз MUST подтвердить Sparkle-обновление с предыдущей здоровой версии и документировать ручную установку hotfix поверх `v2026.09.02.1`, потому что ранний crash может не дать встроенному updater завершить обновление.
- **FR-012**: Validation evidence MUST быть metadata-only, привязано к exact source SHA и не содержать секреты, приватные пути, аудио или содержание встреч.
- **FR-013**: Сломанный `v2026.09.02.1` MUST оставаться исторически неизменным; исправление публикуется новой версией без перезаписи старого tag/release asset.
- **FR-014**: Release validation MUST оставаться воспроизводимой в worktree любой активной фичи и после появления новых CalVer tags; тестовые fixtures не должны зависеть от конкретного локального feature pointer или уже занятого публичного тега.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Десять последовательных запусков production-like candidate завершаются без startup-crash; каждый процесс остаётся живым не менее пяти секунд.
- **SC-002**: Установка hotfix поверх сломанной версии и Sparkle-обновление с предыдущей здоровой версии оба приводят к запускающемуся GRAF с ожидаемой версией.
- **SC-003**: Проверка отсутствующего baseline-ресурса даёт ноль аварийных завершений приложения и наблюдаемое ограниченное состояние функции обнаружения встреч.
- **SC-004**: Apple Silicon и Intel-срезы присутствуют в одном candidate и проходят заявленную runtime/совместимость проверку без расхождения ресурсного контракта.
- **SC-005**: Повторно скачанные публичные ZIP, PKG, checksum и appcast дают 100% совпадение опубликованных SHA-256, размеров, версии и Sparkle signature.
- **SC-006**: Full CI, signing, notarization, stapling, Gatekeeper, packaged-app smoke и public download verification относятся к одному неизменному release SHA.
- **SC-007**: Governance suite проходит с active Feature 232 pointer и не использует существующий production tag как тестовый candidate.

## Assumptions

- Корневая причина подтверждена crash report и точным совпадением UUID публичного arm64-бинарника.
- `v2026.08.28.11` является предыдущей здоровой desktop-версией; перед релизом это повторно проверяется по публичному артефакту.
- Hotfix не меняет backend, контракты данных, пользовательские настройки автозаписи или содержимое baseline registry.
- Пользователям `v2026.09.02.1` потребуется доверенный прямой PKG/ZIP либо иной ручной repair path, если приложение завершается раньше запуска Sparkle updater.

## Out of Scope

- Изменение алгоритма обнаружения встреч, состава registry или политики автозаписи.
- Изменение серверного API, хранения записей, авторизации, биллинга или AI-контура.
- Перезапись, удаление или подмена существующего tag и GitHub Release `v2026.09.02.1`.

## Legacy Impact

Classification: `untouched`

reason: исправление меняет только packaged-resource lookup и macOS release
gate; оно не добавляет и не сохраняет legacy runtime, fallback, alias или
compatibility path.

## Уточнение T023 от 2026-10-16: установленный Dev

Реализация появления главного окна принята в PR #7212. Issue #7209 остаётся
открытой до запуска самого валидатора на единственном установленном Dev.
Это продолжение US3; исходные критерии релизного режима не ослабляются.

- **FR-015**: Локальная проверка MUST использовать только `/Applications/GRAF Dev.app`
  через dev-harness. Копии, переименование, ссылки и прямой обход harness запрещены.
- **FR-016**: До изменения harness MUST проверить чистоту своего checkout,
  активный live manifest, отсутствие recovery, полный SHA, байты и подпись Dev.
  SHA инструмента и приложения фиксируются отдельно: старое приложение не
  доказывает новый код продукта.
- **FR-017**: Проверка наблюдает обычный запуск Dev через штатный LaunchServices
  путь harness, с существующими данными и настройками. Она не обещает изоляцию
  UserDefaults/WebKit/cookies через HOME. Очередь, recovery, retention, удаление
  и обнаружение встреч ведут себя как при обычном открытии этой версии.
  Временным является только пустой журнал запуска; evidence содержит результат
  и имена двух маркеров без содержимого журнала. HOME/Application Support не меняются.
- **FR-018**: Работающий Dev MUST отклоняться без явного `--restart-idle-app`.
  Оператор использует флаг только непосредственно после проверки отсутствия
  записи, её завершения, звонков и несохранённой работы. Это предусловие оператора,
  а не атомарная блокировка автозаписи; при неопределённой занятости тест отложен.
  Приложение может отказаться от graceful quit; принудительно завершать Dev нельзя.
  При успехе и ошибке MUST восстанавливаться исходное running/stopped состояние,
  удаляются только свои временные файлы; TCC, данные и настройки не сбрасываются.
- **FR-019**: Сам валидатор MUST подтвердить точный единственный PID Dev,
  живущий непрерывно не менее пяти секунд, и новые `app_launch_finished` и
  `app_main_window_presented` в журнале именно этого запуска. Старый, иной или
  заменивший процесс не засчитывается. Ошибка проверки/восстановления блокирует PASS.
- **FR-020**: Релизный режим MUST сохранить свой прямой дочерний процесс,
  временные каталоги, минимум пять секунд, два маркера и завершение только своего
  процесса. Наблюдение Dev не используется signing workflow и не заменяет выпуск,
  release-full, notarization или установленную приёмку другой фичи.
- **SC-008**: Положительные/отрицательные тесты проходят, реальный запуск самого
  валидатора и восстановление подтверждены после разрешённого commit из чистого
  checkout. До этого #7209 остаётся открытой.

Срез не меняет product Swift, capture, приватность, удаление или их разрешения.
Обычная приёмка не даёт нового разрешения на запись, платежи, аккаунты, письма
или изменение настроек автозаписи. Штатные фоновые действия остаются такими же,
как при обычном открытии установленной версии пользователем.
