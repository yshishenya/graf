# Feature Specification: «Поделились со мной»

**Feature Branch**: `codex/shared-with-me-134`

**Created**: 2026-07-27

**Status**: Draft

**Input**: Пользователь просит отдельный пункт меню «Поделились со мной», где
видны встречи, которыми с ним поделились.

## User Scenarios & Testing

### User Story 1 — Открыть список доступных мне встреч (Priority: P1)

Пользователь, которому уже открыт доступ к встречам, выбирает в меню
«Поделились со мной» и видит только актуальные встречи, доступные именно его
подтверждённой учётной записи.

**Why this priority**: Сейчас получатель может попасть на встречу только из
отдельной ссылки. Список делает повторный доступ понятным и не заставляет
искать старое письмо.

**Independent Test**: Подтвердить доступ для одной учётной записи, открыть
новый пункт меню и убедиться, что встреча показана; для другой учётной записи
тот же список остаётся пустым.

**Acceptance Scenarios**:

1. **Given** у пользователя есть действующий доступ к встрече, **When** он
   открывает «Поделились со мной», **Then** он видит карточку этой встречи и
   понятный уровень доступа.
2. **Given** у пользователя нет доступных ему встреч, **When** он открывает
   раздел, **Then** он видит спокойное пустое состояние без чужих метаданных.
3. **Given** пользователь выбирает карточку, **When** доступ всё ещё
   действует, **Then** открывается существующая ограниченная страница
   результатов этой встречи.

---

### User Story 2 — Видеть только текущий разрешённый доступ (Priority: P1)

Получатель не видит в списке отозванные, истёкшие или удалённые встречи; если
доступ меняется между отображением списка и открытием карточки, встреча не
открывается.

**Why this priority**: Раздел не должен становиться альтернативным способом
обойти отзыв, срок действия или удаление.

**Independent Test**: Открыть список с доступной встречей, отозвать или
истечь доступ, обновить список и проверить, что карточка исчезла, а прямое
открытие отклонено.

**Acceptance Scenarios**:

1. **Given** доступ был отозван, истёк или встреча удалена, **When** список
   обновляется, **Then** карточка не показывается.
2. **Given** доступ исчез после загрузки списка, **When** пользователь
   открывает карточку, **Then** система повторно проверяет доступ и не
   раскрывает результаты.

---

### User Story 3 — Не получить рабочую область отправителя (Priority: P2)

Получатель видит только минимальные метаданные встречи, необходимые для выбора
карточки, и не получает членство в рабочей области, возможность повторно
поделиться или сведения о владельце, календаре и служебных данных.

**Why this priority**: Удобный список не должен расширять существующие
границы приглашения.

**Independent Test**: Проверить список внешнего получателя без членства в
рабочей области и убедиться, что ему не доступны чужие рабочие пространства,
настройки или действия повторного доступа.

**Acceptance Scenarios**:

1. **Given** внешний получатель подтвердил адрес и получил доступ, **When**
   он открывает раздел, **Then** он видит только разрешённые встречи и их
   безопасные метаданные.
2. **Given** получатель открывает карточку, **When** он просматривает
   результат, **Then** доступные материалы соответствуют исходному уровню
   доступа, без новых прав.

### Edge Cases

- Пользователь ещё не подтвердил адрес из приглашения: встреча не появляется
  только по совпадению адреса; сначала требуется существующий безопасный
  вход/подтверждение.
- Для одной встречи есть несколько приглашений: в списке показывается одна
  карточка с наиболее полным действующим уровнем доступа.
- Встреча ещё обрабатывается: карточка остаётся доступной, но её состояние
  честно сообщает, что часть материалов может быть готова позже.
- Сеть или загрузка списка недоступна: раздел сохраняет навигацию и показывает
  понятное состояние повторной попытки без устаревших данных.

## Requirements

### Functional Requirements

- **FR-001**: В основном меню кабинета должен быть отдельный пункт
  «Поделились со мной», доступный авторизованному пользователю рядом с его
  собственными встречами.
- **FR-002**: Раздел должен показывать только встречи, для которых у текущей
  подтверждённой учётной записи есть действующий получательский доступ.
- **FR-003**: Карточка должна содержать только безопасные для получателя
  метаданные: название, дату/время, длительность при наличии, состояние
  готовности и уровень открытого доступа.
- **FR-004**: Карточка должна открывать существующую ограниченную страницу
  результатов, а не обычную страницу рабочей области владельца.
- **FR-005**: Перед показом списка и перед открытием каждой карточки система
  должна учитывать отзыв, срок действия, удаление и исходный уровень доступа.
- **FR-006**: Отозванные, истёкшие, удалённые и не подтверждённые для текущей
  учётной записи приглашения не должны показываться в разделе.
- **FR-007**: Несколько действующих приглашений к одной встрече не должны
  создавать дубликаты; отображается один результат с наиболее полным
  разрешённым доступом.
- **FR-008**: Раздел не должен выдавать членство в рабочей области, раскрывать
  владельца, календарь, служебные сведения или добавлять повторное
  приглашение/расшаривание.
- **FR-009**: Пустое, недоступное и загружаемое состояния должны быть на
  русском языке, доступны с клавиатуры и понятны вспомогательным технологиям.
- **FR-010**: Тот же пункт и список должны быть доступны во встроенном
  кабинете macOS без отдельного контракта доступа.

### Key Entities

- **Получательский доступ**: действующее право текущей подтверждённой
  учётной записи открыть конкретную встречу с исходным уровнем материалов.
- **Карточка «Поделились со мной»**: безопасное краткое представление одной
  встречи для списка получателя.
- **Уровень доступа**: набор уже разрешённых материалов встречи, например
  только итоги или запись с доступными материалами.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Пользователь с действующим доступом находит и открывает ранее
  открытую ему встречу из раздела не более чем за два действия после входа.
- **SC-002**: В проверочной матрице 100% отозванных, истёкших, удалённых и
  чужих приглашений отсутствуют в списке и не открываются через карточку.
- **SC-003**: В проверочной матрице 100% действующих приглашений одной
  учётной записи показываются без дубликатов и с исходным уровнем доступа.
- **SC-004**: В проверочной матрице получатель не получает доступа к рабочей
  области владельца, повторному расшариванию или служебным сведениям.
- **SC-005**: Клавиатурный и доступный текстовый путь покрывает меню, список,
  пустое состояние и отказ загрузки без потери смысла.

## Assumptions

- Первый релиз включает уже существующие получательские доступы: личные
  приглашения и внешние приглашения, которыми текущая учётная запись уже
  безопасно воспользовалась.
- Неактивные или ещё не подтверждённые приглашения не являются элементами
  списка и не раскрывают метаданные встречи.
- Существующие ограниченные страницы и правила материалов остаются источником
  истины; новый раздел только помогает их найти.
- Новые способы приглашать людей, поиск по контактам, уведомления и управление
  чужими приглашениями не входят в эту функцию.
