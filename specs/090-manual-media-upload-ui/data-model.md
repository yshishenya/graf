# Data Model: Manual Media Upload UI

This slice does not introduce new database entities. It adds user-interface
state and one cabinet route boundary around the existing `087` upload,
meeting, media revision, upload session, processing, and lifecycle entities.

## Manual Upload Entry

**Purpose**: Visible action that starts the upload sheet from the meetings
workspace.

**Fields**:

- `surface`: `browser` or `desktop_embedded`
- `enabled`: true only when the current cabinet context can perform unsafe
  upload actions
- `label`: Russian-first visible label, such as `Загрузить медиа`
- `disabled_reason`: safe localized reason when upload is not available

**Relationships**:

- Opens one `Upload Sheet`
- Does not create server state until the user starts transfer

## Upload Sheet

**Purpose**: Server-owned UI state for selecting one file, entering safe
metadata, validating the draft, and starting transfer. The sheet closes after
the user presses `Загрузить`; transfer truth then moves to an `Upload Activity
Row` in the meetings workspace.

**Fields**:

- `surface`: browser or embedded desktop mode
- `csrf_available`: whether unsafe-action proof is present in the page
- `selected_file_name`: display-only browser-provided file name
- `selected_file_size`: browser-provided byte count when available
- `selected_file_type`: browser-provided content type when available
- `title`: optional user-supplied meeting title
- `duration_seconds`: required positive integer, derived or manually entered
- `duration_source`: `media_metadata`, `manual`, or `missing`
- `local_recording_id`: per-draft idempotency identity generated by the UI
- `state`: see state transitions below
- `message_code`: safe UI code for validation before transfer

**Validation Rules**:

- Exactly one file must be selected.
- `duration_seconds` must be positive before transfer.
- `title` is optional and must fit existing title safety rules.
- `local_recording_id` is generated once per draft and reused for retries of
  the same draft.
- Upload must not start when CSRF/session proof is absent.

## Upload Sheet States

```text
idle
  -> file_selected
  -> duration_needed
  -> ready_to_upload
  -> create_upload_activity_row
  -> closed

idle/file_selected/duration_needed/ready_to_upload
  -> validation_failed
```

## Upload Activity Row

**Purpose**: Meetings-workspace row for one in-tab upload attempt after the
sheet starts transfer.

**Fields**:

- `selected_file_name`: display-only browser-provided file name
- `selected_file_size`: browser-provided byte count when available
- `title`: optional user-supplied meeting title used as the row title
- `duration_seconds`: positive integer submitted to the cabinet route
- `local_recording_id`: same per-draft idempotency identity created by the sheet
- `state`: see state transitions below
- `progress_percent`: 0-100 when computable
- `message_code`: safe UI code for progress, canceled, failed, or accepted
- `detail_href`: existing meeting detail path after server acceptance, when
  the response includes a meeting id

**Controls**:

- `Отменить` while `state=uploading`
- `Повторить` while `state=failed`
- `Продолжить` while `state=canceled`
- `Открыть` while `state=accepted` and `detail_href` exists

## Upload Activity Row States

```text
queued
  -> uploading
  -> accepted
  -> list_refreshing
  -> processing_visible

uploading
  -> canceled
  -> failed
  -> accepted

canceled
  -> uploading

failed
  -> uploading
```

**State Rules**:

- `canceled` and `failed` must not claim that a meeting exists.
- `Продолжить` and `Повторить` use the retained File object from the current
  browser tab and resubmit through the existing single multipart cabinet route;
  they do not promise byte-range resume.
- `accepted` must not claim that transcript or notes are ready.
- Processing and review readiness after `accepted` are owned by existing
  meeting list/detail states.
- After `accepted`, destructive/cancel-like actions route through existing
  deletion truth rather than "undo".

## Manual Upload Submission

**Purpose**: One transfer attempt from the upload sheet to the cabinet route.

**Fields**:

- `file`
- `title`
- `duration_seconds`
- `local_recording_id`
- `csrf_token`
- `surface_mode`

**Validation Rules**:

- Requires authenticated owner/workspace/device scope from the current cabinet
  session.
- Requires unsafe-action CSRF proof for cookie/session cabinet uploads.
- Must reuse the `087` backend size, manifest, storage, finalize, processing
  dispatch, and response behavior.

## Uploaded Meeting Row

**Purpose**: Normal meeting list representation after server acceptance.

**Fields**:

- `meeting_id`
- `title`
- `source`: manual upload/manual media equivalent
- `duration`
- `status`
- `processing_status`
- `upload_progress`
- `updated_at`
- `primary_action`

**Relationships**:

- Links to existing browser or embedded meeting detail route.
- Uses existing list filtering/search/status rules.
- Uses existing deletion/access behavior after acceptance.

## Upload Failure State

**Purpose**: Safe user-visible recovery state for validation, auth, network,
server, dependency, and processing failures.

**Fields**:

- `code`: stable safe UI code
- `severity`: `inline`, `blocking`, or `accepted_processing_failure`
- `message_ru`: Russian-first safe copy
- `recoverable`: whether retry/change-file/sign-in/detail action is available
- `primary_action`: retry, change file, sign in, open detail, or close

**Forbidden Fields**:

- MediaScribe credentials or job ids
- Signed URLs
- Object keys
- Raw audio/media bytes
- Raw transcript text
- Private local paths
- Secret names or live secret paths
- Internal storage bucket names
