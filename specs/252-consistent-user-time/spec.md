# Feature Specification: Единые даты и время пользователя

**Feature Branch**: `codex/252-consistent-user-time`
**Created**: 2026-09-06
**Status**: Clarified
**Input**: Привести список встреч, сортировку и всё пользовательское время приложения к единому удобному поведению.

## Clarifications

### Session 2026-09-06

Проверены область, данные, UX, ошибки, ограничения и критерии. Критических неоднозначностей нет. Уточнение пользователя: одно поле часового пояса с автоматическим исходным значением и возможностью сохранить другой пояс; отдельных режимов нет. Всё расширение остаётся в Feature 252. Неизвестное начало не восстанавливается по имени файла. Финансовая логика и технические UTC-значения не меняются.

## User Scenarios & Testing

### User Story 1 - Найти встречу в правильном порядке (Priority: P1)
Пользователь открывает встречи, выбирает новые/старые, длительность или название, ищет запись, открывает карточку и возвращается. Запись на Mac до и после отправки сохраняет дату начала; обновление обработки не меняет хронологический порядок.
**Independent Test**: смешанный список записей Mac и загрузок, одинаковые моменты с разными смещениями, несколько лет.
**Acceptance Scenarios**:
1. При поздней загрузке записи с известным началом сортировка и дата используют начало; если начало неизвестно, показывается «Загружено» и дата загрузки.
2. Смена направления сортировки меняет порядок по числовому моменту; равные моменты имеют стабильный дополнительный ключ.
3. Поиск по видимой дате находит строку и после локального перехода через полночь.
4. Локальные записи участвуют в применимой сортировке и фильтрации; состояния, недоступные локально, не подделываются.

### User Story 2 - Видеть своё время во всём приложении (Priority: P1)
Список, карточка, календарь, общие встречи, история, оплата, настройки аккаунта, сроки доступа и удаления, административные страницы используют одну политику отображения.
**Independent Test**: один момент 2026-09-05T21:30:00Z в Екатеринбурге отображается 06.09.2026, 02:30, в UTC — 05.09.2026, 21:30.
**Acceptance Scenarios**:
1. Дата и время встречи совпадают между списком, карточкой, общим доступом и нативным списком.
2. Полные отметки имеют формат ДД.ММ.ГГГГ, ЧЧ:ММ (24 часа), календарные даты — ДД.ММ.ГГГГ; год не пропадает.
3. «Сегодня/Завтра» вычисляются по локальному календарному дню. Точные сроки показывают также время и пояс; переход через сутки не скрывается.
4. При недоступном или неверном поясе показан явно обозначенный UTC; приложение не падает.
5. Обновлённые фрагменты и динамически добавленные строки используют тот же формат.

### User Story 3 - Доверять нативной записи и срокам (Priority: P2)
Локальная запись отображается по реальному началу, включая восстановленные записи. VoiceOver сообщает полную дату и время. При отсутствии сохранённого выбора системная смена пояса применяется при следующем отображении; сохранённый выбор имеет приоритет.
**Independent Test**: восстановленная сегодня старая запись остаётся на своей дате, срок хранения имеет точный локальный момент.
**Acceptance Scenarios**:
1. Дата появления в очереди используется только при отсутствии метаданных начала.
2. Даты в автоматически созданных названиях не противоречат дате строки; пользовательские названия сохраняются.
3. Длительность, позиция воспроизведения, countdown и срок выполнения серверных задач не смещаются с часовым поясом.

### User Story 4 - Выбрать свой часовой пояс (Priority: P1)
Одно поле изначально показывает пояс устройства. Пользователь находит город, видит текущее время, сохраняет выбор и получает одинаковое время во всех разделах; отмена оставляет прежнюю настройку. Независимые критерии — FR-012–015 и дополнение T006–T009 в quickstart.

### Edge Cases
Полночь, Новый год, 29 февраля, DST (23/25 часов в сутках), Z/явный offset/дробные секунды, пустые даты, отсутствующий JS/cookies, смена пояса, одинаковые моменты, восстановление после перезапуска, HTMX-обновление, авторизованный общий доступ, пустой список и фильтры без результатов.

## Requirements

### Functional Requirements
- **FR-001**: Единая эффективная дата встречи: начало; только для ручной загрузки без начала — дата загрузки/создания с подписью «Загружено»; отсутствие всех дат — «Без даты». Сортировка и поиск используют ту же дату.
- **FR-002**: Все сортировки сохраняют стабильный порядок, локальные записи не вставляются безусловно первыми; обновление прогресса не меняет порядок по началу.
- **FR-003**: Пользовательский пояс автоматически определяется по устройству; серверный пояс и смещение при записи не определяют время просмотра. Пока пользователь не сохранил выбор, используется пояс устройства; сохранённый выбор аккаунта имеет приоритет. В настройках одно поле без переключателя режимов.
- **FR-004**: Русский единый формат ДД.ММ.ГГГГ, ЧЧ:ММ, включая год и 24-часовое время. Календарная дата без времени не преобразуется как полночь UTC.
- **FR-005**: Локальные календарные дни, поиск и календарь согласованы с отображением; абсолютный порядок сохраняется при DST.
- **FR-006**: Полный момент доступен через семантическую разметку/описание VoiceOver; точные дедлайны не сокращаются до дня и содержат UTC-смещение на момент события, различающее повторный час при DST.
- **FR-007**: Динамические и серверные представления применяют один формат; неверный пояс безопасно даёт явно подписанный UTC. Входной пояс ограничен валидным IANA-именем.
- **FR-008**: Нативный список использует recordingStartedAt с fallback createdAt; произвольные названия не переписываются.
- **FR-009**: Не меняются сохранённые абсолютные моменты, финансовые расчётные границы, авторизация, приватность, capture, scheduler, интервалы, транспортные ISO-значения и технические UTC-логи.
- **FR-011**: Контекст пояса изолирован между параллельными запросами, сбрасывается после исключения и отсутствует вне запроса; фоновые расчёты не используют display formatter. Автоматический повтор разрешён только для явно перечисленных read-only HTML GET, исключая auth/callback и одноразовые действия; cookies blocked не вызывают циклов.
- **FR-010**: Новые проверки воспроизводят ошибки смешанной сортировки, пользовательского пояса, полуночи и летнего времени на синтетических данных.

- **FR-012**: Одно доступное с клавиатуры поле «Часовой пояс», поиск по русскому городу/региону, IANA и UTC-смещению. Подписи содержат UTC±ЧЧ:ММ и русское название; регионы с одинаковым текущим смещением не сливаются. Предпросмотр текущего времени не меняет настройку до «Сохранить»; «Отменить» восстанавливает выбор.
- **FR-013**: Выбор сохраняется в аккаунте через существующий CSRF-защищённый POST и имеет приоритет над cookie устройства. Неверное IANA даёт 422 без частичного изменения остальных предпочтений. Без JavaScript работает select и обычная отправка формы. Ошибка сети сохраняет редактируемую форму для повторной отправки.
- **FR-014**: Миграция сохраняет старый UTC и явно сохранённую Moscow (подтверждённую audit событием настройки); старый Moscow по умолчанию становится незаданным. Новые аккаунты начинают без сохранённого пояса. Downgrade останавливается при новых непредставимых поясах, не заменяет выбор молча.
- **FR-015**: macOS получает настройку из актуальной авторизованной страницы доверенного кабинета с origin/user/session. Выход/смена сессии снимает активное значение, старые callbacks не применяются. Временная потеря сети сохраняет подтверждённое значение в процессе; холодный запуск до подтверждения аккаунта использует устройство. Прежний пользователь не определяет пояс следующего.

### Key Entities
- Момент события: абсолютные дата и время с часовым поясом.
- Календарная дата: день без момента и часового пояса.
- Длительность: число секунд, не время суток.
- Пояс просмотра: сохранённое IANA-имя аккаунта либо пояс устройства; только для представления.
- Эффективная дата встречи: исходный момент и основание (начало/загрузка).

## Success Criteria

### Measurable Outcomes
- **SC-001**: В синтетической матрице 100% встреч имеют одинаковую дату между списком, карточкой и общим доступом.
- **SC-002**: Все варианты хронологической сортировки проходят для разных offsets, лет, загрузок без начала и восстановленных записей.
- **SC-003**: Все найденные пользовательские временные поверхности учтены в research.md с изменением либо обоснованным сохранением поведения.
- **SC-004**: Проверки UTC, Asia/Yekaterinburg, America/New_York и перехода суток проходят; сроки/длительности не меняются.

## Assumptions
- Язык интерфейса русский; формат даты единый цифровой, всегда с годом.
- Одно поле «Часовой пояс»: автоматическое исходное значение, сохранение выбора аккаунта, без двух режимов (явное уточнение пользователя).
- Мигрируется только настройка пояса, абсолютные времена не мигрируются; дата встречи без доказанного начала не угадывается из имени файла.
- Публикация, production, commit/push и изменение системного пояса не входят в реализацию без отдельного разрешения.
- Письма и выгружаемые документы без контекста устройства сохраняют явно обозначенный пояс; административные технические JSON/логи сохраняют ISO.

## Legacy Impact

Classification: untouched

Исторические моменты и транспортные ISO-контракты не мигрируются. Снимается старое ограничение настройки на Moscow/UTC; подтверждённые выборы сохраняются. Babel предоставляет стандартные русские названия CLDR, вместо собственного словаря городов.
