# Feature Specification: Echo-Free Speakerphone Recording

**Feature Branch**: `177-webrtc-aec3-recording`

**Created**: 2026-08-20

**Status**: Draft

**Input**: User description: "Устранить акустическое эхо собеседника в записях GRAF по проверенной модели MacWhisper, удалить конфликтующее capture-легаси, перепроверить инструменты и доказать результат без ANC и лишней обработки."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Запись через динамики без двойного голоса (Priority: P1)

Пользователь записывает встречу с включенными динамиками Mac и слышит в готовой записи по одному разборчивому экземпляру голоса каждого участника вместо чистого системного голоса, наложенного на его акустическую копию из микрофона.

**Why this priority**: Двойной голос делает запись и транскрипцию недостоверными; его устранение является основной ценностью фичи.

**Independent Test**: Контролируемая запись с дальним участником, воспроизводимым через встроенные динамики, сравнивается с необработанным измерительным эталоном и готовым пользовательским артефактом; итог не содержит слышимого повторного голоса и сохраняет исходную громкость системного звука.

**Acceptance Scenarios**:

1. **Given** выбран встроенный микрофон и звук встречи воспроизводится через встроенные динамики, **When** говорит только дальний участник, **Then** его акустическая копия подавлена в микрофонной составляющей и в итоговой записи слышен один голос.
2. **Given** локальный и дальний участники говорят одновременно, **When** запись финализируется, **Then** оба голоса остаются разборчивыми без обрывов тихой локальной речи.
3. **Given** пользователь работает в наушниках, **When** акустической утечки практически нет, **Then** локальный голос не получает заметного ухудшения и системный звук не меняет громкость.

---

### User Story 2 - Честный отказ вместо скрытого эха (Priority: P2)

Пользователь получает правдивое состояние записи, если обязательный тракт удаления эха нельзя запустить или продолжить после смены устройства, рассинхронизации либо внутренней ошибки.

**Why this priority**: Молчаливый переход на необработанный микрофон снова создаёт двойной голос, но внешне выглядит как нормальная запись.

**Independent Test**: В контролируемом запуске обязательный компонент делается недоступным до старта и во время записи; продукт не создаёт нормальный артефакт с необработанным микрофоном и показывает локально управляемый отказ или деградацию.

**Acceptance Scenarios**:

1. **Given** обязательная обработка микрофона недоступна до записи, **When** пользователь начинает запись, **Then** старт блокируется с понятным восстановлением и без создания ложного нормального артефакта.
2. **Given** обработка перестала быть достоверной во время записи, **When** ошибка обнаружена, **Then** запись получает явный integrity/degraded outcome, остаётся видимой и сохраняет однокнопочный Stop.
3. **Given** устройство ввода или вывода изменилось, **When** новый тракт ещё не готов, **Then** продукт не подменяет очищенный микрофон необработанным и не скрывает разрыв.

---

### User Story 3 - Один поддерживаемый capture-тракт (Priority: P3)

Инженер и пользователь работают с одним активным способом записи без старых запретов, отключённых экспериментальных сервисов, скрытых fallback-веток и противоречивых диагностических состояний.

**Why this priority**: Неработающие хвосты создают ложные пути восстановления и позволяют последующим изменениям случайно вернуть эхо.

**Independent Test**: Аудит исходников, тестов, контрактов, диагностики и package surface показывает один новый тракт для новых записей; старые записи остаются читаемыми, но старый runtime не может быть выбран или запущен.

**Acceptance Scenarios**:

1. **Given** новая версия приложения, **When** создаётся новая запись, **Then** существует ровно один production mic/system capture path и один канонический результат.
2. **Given** историческая запись поддерживаемого формата, **When** пользователь открывает её, **Then** она остаётся читаемой без запуска удалённого capture-кода.
3. **Given** инженер ищет старые экспериментальные и запретительные поверхности, **When** проводится repository audit, **Then** не остаётся достижимых runtime-веток, конфликтующих тестов или пользовательской копии, представляющей отсутствие echo cancellation как действующий контракт.

### Edge Cases

- Системный звук временно отсутствует, но локальный пользователь продолжает говорить.
- Дальний участник и локальный пользователь говорят одновременно, включая тихую локальную речь.
- Выход переключается между встроенными динамиками, проводными наушниками, Bluetooth и внешним дисплеем.
- Микрофон или system-audio источник меняет sample rate, channel count либо временную базу.
- Render reference приходит поздно, с разрывом, переполнением или несравнимой временной меткой.
- Микрофон насыщается из-за высокой громкости динамиков.
- Запись ставится на паузу и возобновляется либо приложение завершает запись после ошибки обработки.
- Защищённый контент или системное разрешение делает system audio недоступным.
- Старые пакеты открываются после удаления legacy runtime.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Для каждой новой записи с микрофоном и system audio продукт MUST удалять из микрофонной составляющей акустическую копию звука, воспроизведённого системой, до канонического сведения.
- **FR-002**: Продукт MUST сохранять локальную речь при одновременной речи локального и дальнего участников и MUST NOT использовать подавление по принципу «дальний участник говорит — микрофон выключен».
- **FR-003**: System-audio составляющая MUST сохранять существующую временную шкалу, громкость и содержимое; удаление эха MUST применяться только к микрофонной составляющей.
- **FR-004**: Новый тракт MUST NOT добавлять ANC, общий noise suppression, automatic gain control, VAD trimming, amplitude gate, speech inference или текстовую дедупликацию.
- **FR-005**: Необработанный микрофон MUST NOT использоваться как скрытый fallback или выдаваться за очищенный источник при ошибке и MUST NOT сохраняться как второй пользовательский аудиоартефакт.
- **FR-006**: До старта продукт MUST блокировать нормальную запись, если обязательный тракт недоступен; после старта продукт MUST завершать или помечать результат явным integrity/degraded outcome без сокрытия уже захваченных данных.
- **FR-007**: Смена устройства, discontinuity и clock drift MUST иметь однозначное поведение продолжения, переинициализации, остановки или деградации без молчаливого перехода на raw microphone; privacy Pause/Resume MUST сохранять PTS и обязательную обработку с нулевым микрофоном на паузе либо явно деградировать, если этот контракт нарушен.
- **FR-008**: Новые записи MUST продолжать создавать один канонический WAV для транскрипции, один M4A для воспроизведения и manifest без второго ASR job и без новой пользовательской raw-дорожки.
- **FR-009**: Поддерживаемые исторические пакеты MUST оставаться читаемыми, но удалённый legacy capture runtime MUST NOT восстанавливаться как fallback.
- **FR-010**: Продукт MUST удалить или заменить активные тесты, контракты, диагностику и документацию, которые запрещают обязательное удаление эха или описывают старый runtime как действующий.
- **FR-011**: Диагностика MUST быть metadata-only и MUST фиксировать готовность обработки, задержку, drift, underrun/overrun, saturation и причину деградации без raw audio, речи или transcript text.
- **FR-012**: Продукт MUST сохранять видимый индикатор активной записи, Pause/Resume и однокнопочный Stop при нормальной работе и при деградации.
- **FR-013**: Новый тракт MUST NOT менять выбранный output route, системную громкость или настройки аудио в приложении встречи.
- **FR-014**: Реализация и дистрибуция MUST использовать оригинальный код, публичные OS API и лицензированную зависимость; код или бинарники MacWhisper/Телемоста MUST NOT копироваться или включаться в GRAF.

### Key Entities

- **Echo-cleaned microphone source**: Единственная микрофонная составляющая новой записи после удаления system-audio reference; имеет общую временную шкалу, readiness и integrity state.
- **Render reference**: Временной system-audio сигнал, используемый только для удаления его акустической копии из микрофона и не создающий дополнительного пользовательского артефакта.
- **Echo-processing health**: Metadata-only состояние готовности, задержки, drift, переполнения, насыщения, переинициализации и причины деградации.
- **Canonical recording package**: Существующий пользовательский пакет из manifest, одного transcription WAV и одного review M4A, сформированный из очищенного микрофона и неизменённого system audio.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В контролируемом far-end-only тесте на встроенных динамиках акустическая копия system audio в микрофонной составляющей снижается минимум на 20 dB относительно синхронизированного необработанного измерительного эталона после начального периода сходимости.
- **SC-002**: Во всех принятых far-end-only контрольных записях экспертная прослушка итогового M4A не обнаруживает отдельного слышимого повторного голоса собеседника.
- **SC-003**: В double-talk матрице тихая и обычная локальная речь остаётся разборчивой во всех принятых сценариях; ни один принятый сценарий не содержит gate-подобных обрывов локальных слов.
- **SC-004**: В 60-минутной записи нет необъяснённого расхождения WAV, decoded M4A и общей временной шкалы более 100 ms, новых capture dropout и изменения уровня system-audio составляющей более 1 dB.
- **SC-005**: При недоступности или runtime-отказе обязательного тракта 100% тестовых сценариев блокируют нормальный старт либо создают явный integrity/degraded outcome; ни один сценарий не создаёт normal recording с raw-mic fallback.
- **SC-006**: Аудит production source, tests, contracts, diagnostics и user-facing copy находит ровно один активный mic/system recording path и ноль достижимых legacy AEC/Apple-processing/echo-cleanup fallback-веток или запретов на новый обязательный тракт.
- **SC-007**: Все поддерживаемые исторические package-форматы продолжают проходить regression reading/playback tests после удаления legacy runtime.
- **SC-008**: Согласованный локальный gate `infra/scripts/ci-local.sh --fast` и инструментальные audio-fixture проверки проходят без ошибок, а controlled-device matrix документирует встроенные динамики, наушники, wired/Bluetooth route changes, far-end-only, near-end-only и double-talk; full CI остаётся обязательным отдельным gate для release candidate.

## Assumptions

- Удаление эха обязательно для всех новых записей, где одновременно захватываются микрофон и system audio; пользовательский переключатель в первой версии не добавляется.
- Приоритетом является естественная запись и double-talk, а не максимальное подавление любой ценой.
- Первый production scope сохраняет действующий публичный контракт: один universal app для Apple Silicon и Intel на macOS 14.5+; Swift package может сохранять внутренний build floor macOS 14.0.
- Существующие имена и назначение v5 WAV/M4A/manifest сохраняются, меняется только источник микрофонной составляющей до сведения.
- Raw microphone может существовать только внутри контролируемого локального QA harness с синтетическим или явно разрешённым тестовым сигналом и не входит в пользовательский пакет, логи, диагностику или evidence.
- Динамические проверки с реальными встречами используют только специально созданные тестовые сигналы или явное согласие участников; приватная речь не сохраняется в repository evidence.
- Новая зависимость допустима только после проверки лицензии, reproducible build, notarization/signing compatibility и отсутствия внедрённых сторонних модификаций.
