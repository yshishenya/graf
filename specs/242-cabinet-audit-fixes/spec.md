## User Scenarios & Testing

### US1 — Сохранить персональные настройки (P1)

Пользователь меняет тему в меню профиля на любой странице кабинета, не теряя язык и часовой пояс.
Acceptance: en-US/UTC/dark → смена темы → en-US/UTC/light; старое меню во второй вкладке не откатывает другие настройки; browser и embedded deletion report показывают фактический профиль. Некорректный набор полей не сохраняется даже частично.

### US2 — Осознанно начать пробный период (P2)

Владелец личного пространства раскрывает условия, затем отдельной кнопкой запускает семь дней бесплатно.
Acceptance: раскрытие/отмена не меняют подписку; видны «Карта не нужна», «Автосписания не будет», один раз, затем Free; предварительные даты явно отличимы от фактического интервала, отсчитываемого от финального подтверждения. Выключенный checkout не запрещает cardless trial.

### US3 — Найти помощь и понять объём (P2)

Владелец открывает помощь из billing и получает реальный контакт либо честное сообщение об отсутствии настроенного контакта, включая пустую историю.
Acceptance: history help не перезагружает саму history; 0 и дробные MB/GB читаемы; точные байты и расчёт квот неизменны.

### US4 — Понять обработку без повторов (P3)

Пользователь видит общий статус обработки и краткий placeholder расшифровки.
Acceptance: большой заголовок/объяснение диаризации не дублируются; pending DOM hook, live region и recovery controls сохраняются; ready/failed/no-speech и сохранённый прежний результат не ломаются.

## Requirements

- **FR-001**: Authenticated billing, соседние referrals/fair-use и полный deletion report получают текущий профиль через существующий источник, включая embedded; при недоступной БД не придумывают данные. Shell без достоверного profile (в том числе narrow sharing) не показывает форму автосохранения темы с выдуманным system default.
- **FR-002**: Меню отправляет только theme и реально запускает существующий autosave (атрибут формы соответствует JS contract). Общий preferences handler валидирует все переданные поддерживаемые поля до записи; пропущенные поля сохраняются; пустой набор и неверные значения дают 422. Audit metadata перечисляет переданные сохраняемые поля. Session/CSRF/organization/row-lock проверки сохраняются.
- **FR-003**: Trial требует отдельного пользовательского подтверждения после раскрытия условий на overview/plans. До подтверждения показан предварительный интервал с секундами и МСК, явно рассчитанный на момент открытия страницы; фактический старт — момент финального подтверждения, срок ровно TRIAL_DAYS. Фактические даты видны после запуска. Без JS условия и кнопка доступны с клавиатуры. Повторное использование, owner/personal, verified identity, pending checkout, paid access и транзакционные guards неизменны.
- **FR-004**: Помощь ведёт из billing в history, а в history — к разделу помощи. Настроенный контакт доступен и при пустом списке. Без контакта нет обещания написать в неназванную поддержку: есть честный unavailable текст и возврат к тарифу. Приватные платёжные данные не раскрываются.
- **FR-005**: Decimal units: ниже 1000 — целые байты; далее KB/MB/GB/TB по порогу, максимум два десятичных знака без лишних нулей; ноль — «0 байт». При округлении к границе выбирается следующая единица. Точный счётчик отдельно не меняется.
- **FR-006**: Pending placeholder — короткая нейтральная строка без второго заголовка/объяснения состояния. Runtime hooks и доступность сохраняются.
- **FR-007**: Только синтетические проверки; без реальной оплаты, активации trial, удаления, приватных записей и скриншотов в git. Без новых зависимостей/миграций.
