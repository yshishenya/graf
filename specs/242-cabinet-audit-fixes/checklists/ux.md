## Независимое обоснование — 2026-09-06

Reviewer: отдельный Codex research/reviewer по поручению ведущего агента в рамках Spec Kit.
Оценены семь исходных пунктов двух чеклистов по документам F242 и относящимся
к ним контрактам F140/F210. `[x]` подтверждает качество требований до
реализации, а не пройденную браузерную проверку или готовность приложения.

- **CHK001 — удовлетворён.** FR-003/Clarifications и UI contract §3 однозначно
  разделяют предварительный интервал на момент открытия страницы и фактический
  интервал активации. У обоих есть секунды и МСК; предварительный явно
  помечен и не резервирует прошлый старт. По уточнению ведущего агента фактические
  даты читаются из существующего TrialActivation; срок равен TRIAL_DAYS.
  Это явное уточнение формулировки F140 «exact start/end», а не обещание
  сохранить предварительные даты после ожидания. Native details/summary,
  отдельная кнопка подтверждения и закрытие без записи соответствуют F210
  UI contract: клавиатура и отсутствие JS не препятствуют основному действию.
  Это раскрываемый блок, поэтому новый контроллер модального окна не требуется.
- **CHK002 — удовлетворён.** FR-004, US3 и UI contract §4 задают переход
  billing → history → #billing-help, контакт независимо от наличия платежей,
  честный текст при отсутствии контакта и возврат к тарифу без заявки.
  Требования F140 к безопасному номеру, доступному адресу при невозможности
  открыть почтовую программу и отсутствию ложного сообщения об отправке
  сохраняются; configured mailto не заменяет эти ограничения.
- **CHK003 — удовлетворён.** FR-005 и UI contract §5 содержат объективные
  правила decimal units, нуля, двух десятичных знаков и перехода через
  границу округления, включая 999999999 → 1 GB; точные байты и квоты не
  меняются. FR-006/US4 и UI contract §6 задают короткую строку без второго
  объяснения, сохранение data-transcript-pending/live region, recovery и
  ready/failed/no-speech/сохранённого результата. Покрытие — T001/T004/T005.
- **CHK004 — удовлетворён.** Non-goals и Clarifications отделяют F240 и
  снятые замечания от исправлений F242. Дополнительное поручение ведущего агента
  от 2026-09-06 ограничивает исправление autosave браузерной формой с
  `data-account-preferences-auto-save="true"`: существующий JS сравнивает
  значение с `"true"`. FR-002 и T001/T002 покрывают это поведение.
  Список разрешённых маршрутов native WKWebView принадлежит F243 и не входит
  в этот gate; проверка серверного desktop handler не доказывает работу WK.

Покрытие: FR-003 → T001/T003; FR-004–005 → T001/T004;
FR-006 → T001/T005; SC-001–003 → T006 совместно с T001–T005.
В T001/T002/T006 проверка autosave должна различать локальный предпросмотр
темы и отправку/сохранение синтетической формы; наличие атрибута само по себе
не доказывает FR-002. Для trial предварительный и фактический моменты следует
разнести в синтетических данных; реальная активация не нужна.

Блокеров по четырём критериям нет. Требования достаточны для реализации;
браузерные проверки, тесты, convergence и exact-SHA governance-fast остаются
последующими gates режима high-risk-product.
