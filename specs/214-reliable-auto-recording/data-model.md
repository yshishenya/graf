# Модель данных: надёжный полный цикл автоматической записи

## Принцип

Новых хранилищ и параллельных сущностей не создаётся. Изменения расширяют
существующие локальные настройки, описание записи и очередь отправки. Сервер не
хранит личный выбор автозаписи.

## 1. Локальное правило приложения

Источник в коде: `MeetingDetectionSettings.automaticRecordingRules`.

| Поле | Тип | Правило |
|---|---|---|
| `targetID` | строка | Точный устойчивый идентификатор проверенного приложения |
| `rule` | `always`, `ask`, `never` | Ровно одно значение; при отсутствии — `ask` |

Правила:

- новая установка заполняет известные приложения значением `ask`;
- новое приложение из проверенного реестра получает `ask`;
- изменение одной строки не меняет другие строки;
- общий выбор записывает одно из тех же трёх значений во все текущие строки;
- значение `Разные` только отражает разные строки и само не сохраняется;
- старые поля можно один раз прочитать для совместимости, но нельзя снова
  записывать или использовать при принятии решения;
- неизвестное или неоднозначное старое значение становится `ask`, но никогда не
  `always`.

## 2. Решение в окне вопроса

Состояние живёт только для одной текущей встречи и не требует отдельного
хранилища.

| Поле | Значение |
|---|---|
| приложение | точный `targetID` и отображаемое имя |
| встреча | идентификатор непрерывной встречи |
| срок | 8 секунд от показа окна |
| действие | `Записать`, `Не записывать`, истечение времени или отмена из-за окончания встречи |
| запомнить | применяется только к явной кнопке |
| завершено | не позволяет применить второе действие |

Переходы:

```text
ожидание
├─ Записать без галочки ──────────────> запуск текущей записи
├─ Записать с галочкой ───────────────> сохранить always + запуск
├─ Не записывать без галочки ─────────> пропустить текущую встречу
├─ Не записывать с галочкой ──────────> сохранить never + пропустить
├─ 8 секунд, встреча активна ─────────> запуск без изменения настройки
└─ встреча закончилась/проверка не пройдена -> отмена без изменения настройки
```

После первого исхода все поздние кнопки и событие таймера игнорируются.

## 3. Связь автоматической записи со встречей

Новая сохраняемая модель не нужна: используются текущая встреча, текущая
сессия захвата и минимальное состояние в оркестраторе приложения.

| Поле | Назначение |
|---|---|
| `targetID` | приложение, которое породило автоматический запуск |
| идентификатор непрерывной встречи | защита от повторного запуска и связь с окончанием |
| причина запуска | отличает автоматическую запись от ручной |
| состояние запуска | начало ещё идёт или захват уже активен |
| требование остановки | одно отложенное требование, которое нельзя потерять во время запуска |
| последнее подтверждение встречи | основа страховочной остановки через 10 минут |
| ручная остановка этой встречи | запрещает автоматический повтор до новой встречи |

Переходы:

```text
нет записи -> запуск -> активна -> остановка -> локальное сохранение
                 └─ встреча закончилась -> запомнить требование остановки
                                            и выполнить сразу после запуска
```

Окончание одного источника не завершает встречу, пока другой доверенный источник
для того же приложения активен. Автоматическое окончание не касается ручной
записи.

## 4. Локальный пакет записи

Источник в коде: существующий `LocalRecordingManifest` версии 5 и файлы в
каталоге записи.

Используемые поля: `sessionId`, `directoryId`, `startedAt`, `stoppedAt`,
`finalizedAt`, `status`, `tracks`, `failureReason`, `captureFailureCode`,
проверенные разрешения и безопасные метаданные отображения.

Целевой жизненный цикл:

```text
active
├─ saved ───────────────> можно отправлять
├─ degraded ────────────> можно отправлять с честным ограничением
└─ failed/blocked ──────> Запись повреждена, если восстановление невозможно
```

Правила:

- `active` manifest атомарно создаётся до приёма первого звука;
- основной WAV не реже одного раза в 10 секунд получает актуальный заголовок и
  закрепляется на диске;
- штатная остановка сначала закрепляет основной звук, затем производный файл
  прослушивания и окончательный manifest;
- запуск приложения повторно проверяет каждый `active` пакет ровно один раз;
- полезный основной звук сохраняется даже при ошибке производного файла;
- невозможность восстановления записывается безопасным кодом
  `recording_recovery_not_possible`; содержимое встречи и полный локальный путь
  в код не попадают.

## 5. Элемент очереди отправки

Источник в коде: существующий `DesktopUploadQueueItem`. Устойчивая личность
остаётся прежней и выводится из текущих `directoryId`, `sessionId` и
`localMediaRevisionId`.

К существующим состояниям добавляется только `saving`:

```text
saving -> queued -> uploading -> uploaded
             └────> retrying ────┘
             └────> blocked/failed -> Отправить -> queued
```

Правила:

- элемент `saving` создаётся или объединяется при начале остановки;
- `saving` не допускается к отправке;
- готовый manifest обновляет тот же элемент, а не создаёт новый;
- автоматический повтор и `Отправить` используют тот же `id`;
- повреждённый пакет остаётся видимым, но не допускается к отправке;
- успешная отправка сохраняет `meetingId`, по которому локальная и серверная
  строки объединяются.

## 6. Строка общего списка

Это представление существующего элемента очереди, а не новая сохраняемая
сущность.

| Условие | Текст/действие |
|---|---|
| локальное сохранение | `Сохраняется` |
| отправка | `Отправляется` и доступный процент |
| ожидается автоматический повтор | понятное ожидание и `Отправить` |
| отправка не удалась | понятная ошибка и `Отправить` |
| восстановление невозможно | `Запись повреждена`, только удаление |
| серверная строка уже появилась | одна объединённая строка без потери выбора |

В веб-версию кабинета вне приложения локальные строки не передаются.

## 7. Реестр проверенных приложений

Реестр содержит проверенные идентификаторы и исключения ложных целей, но не
пользовательские настройки. Порядок выбора: действующий ответ сервера →
действующий локальный кэш → встроенный базовый реестр. Любой источник проходит
одну и ту же проверку формата. Встроенный документ не имеет срока истечения: он
обновляется только вместе с подписанной версией приложения и используется,
когда более свежего действующего источника нет.
