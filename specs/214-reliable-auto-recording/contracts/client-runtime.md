# Договор клиентского поведения

Этот документ фиксирует наблюдаемое поведение macOS-приложения. Он не создаёт
новый программный интерфейс.

## Настройки

1. Для каждого проверенного приложения показывается один выбор: `Всегда`,
   `Спрашивать`, `Никогда`.
2. Новая установка и новое проверенное приложение используют `Спрашивать`.
3. Общий выбор принимает те же три значения. При разных строках он показывает
   `Разные` и ничего не меняет до явного выбора пользователя.
4. Настройки читаются и изменяются без сети.
5. Отдельные переключатели запроса и запуска после таймера отсутствуют.

## Решение о начале записи

| Настройка | Окно | Результат |
|---|---|---|
| `Всегда` | не показывается | одна попытка запуска после обязательных проверок |
| `Спрашивать` | показывается на 8 секунд | кнопка пользователя либо запуск по истечении времени |
| `Никогда` | не показывается | автоматического запуска нет |

Обязательные проверки: приложение входит в проверенный реестр, встреча всё ещё
активна, разрешения macOS доступны, локальное хранение безопасно, нет запрета
для текущей встречи, общие правила записи и согласия разрешают запись, видимый
индикатор и остановка одним действием доступны.

Серверное поле разрешения автозапуска и его подтверждение не участвуют в этом
решении.

## Окно `Спрашивать`

- видны имя приложения, 8-секундный отсчёт, `Записать`, `Не записывать` и
  `Запомнить выбор`;
- `Записать` с галочкой сохраняет `Всегда`, без галочки не меняет настройку;
- `Не записывать` с галочкой сохраняет `Никогда`, без галочки не меняет
  настройку;
- истечение времени никогда не сохраняет настройку, даже если галочка включена;
- окончание встречи закрывает окно без запуска и без изменения настройки;
- первое завершившее действие побеждает, остальные события ничего не делают;
- сохранённое явное решение сразу видно в настройках и его можно изменить.

## Остановка

- одна непрерывная встреча создаёт не больше одной автоматической записи;
- запись продолжается, пока существует хотя бы один доверенный активный источник
  этой встречи;
- после подтверждённого окончания формируется ровно одно требование остановки;
- если окончание пришло во время запуска, требование сохраняется и исполняется
  сразу после выхода из состояния запуска;
- после сна, пробуждения или перезапуска наблюдения активная автоматическая
  запись сверяется со свежим состоянием встречи;
- 10 минут без доверенного подтверждения останавливают detector-запись;
- ручная остановка запрещает автоматический повтор в той же непрерывной встрече;
- окончание обнаруженной встречи не останавливает несвязанную ручную запись.

## Локальное сохранение и восстановление

- активный manifest существует до приёма первого звука;
- WAV закрепляется с интервалом не больше 10 секунд;
- основной звук закрепляется до производного файла и постановки на отправку;
- после аварии каждый незавершённый пакет становится готовым, ограниченно
  пригодным или повреждённым;
- полезный основной звук не удаляется из-за ошибки производного файла;
- повторная проверка одной папки не создаёт вторую запись или отправку.

## Общий список и отправка

- запись появляется в общем списке со стадии локального сохранения;
- строка показывает сохранение, отправку и процент, ожидание повтора, ошибку или
  повреждение;
- автоматические повторы переживают перезапуск;
- действие называется ровно `Отправить` и запускает одну немедленную попытку
  через существующую очередь;
- повреждённая запись показывает `Запись повреждена`, не показывает
  `Отправить` и сохраняет существующее удаление;
- после успеха локальная и серверная строки объединяются без дубля;
- отдельная панель локальной сохранности удаляется только после переноса всех
  нужных состояний и действий;
- все действия доступны с клавиатуры и озвучиваются по смыслу; цвет не является
  единственным признаком состояния.

## Совместимость

Новый клиент одинаково работает со старым сервером, сервером без удаляемого
поля и без сети. Неизвестные дополнительные поля ответа игнорируются.
