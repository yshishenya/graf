# Договор поэтапного удаления серверного управления

## Цель

Сервер перестаёт хранить и выдавать личное решение, должна ли конкретная
программа записываться автоматически. Реестр поддерживаемых приложений,
исключения ложных целей, проверка версии, кэширование и безопасная диагностика
остаются.

## Шаг 1. Совместимый клиент

До изменения сервера выпускается клиент, который:

- принимает документ реестра как с полем `assistedAutoStartPolicy`, так и без
  него;
- не читает это поле при выборе `Всегда`, `Спрашивать`, `Никогда`;
- не отправляет и не хранит подтверждение этого поля;
- не требует сети для применения локального правила;
- сохраняет все общие проверки разрешений, хранения, согласия и видимого
  управления записью.

Старый сервер на этом шаге не меняется. Откат клиента безопасен, потому что
серверное поле ещё присутствует.

## Условие перехода

Серверную очистку можно выпускать только когда поддерживаемая минимальная версия
клиента уже не требует удаляемого поля. Это должно быть подтверждено матрицей:

1. новый клиент + старый ответ;
2. новый клиент + ответ без поля;
3. новый клиент + отсутствие сети.

Во всех трёх случаях локальная матрица поведения одинакова.

## Шаг 2. Серверная очистка

Удаляются только части, принадлежащие старому разрешению автозапуска:

- `assistedAutoStartPolicy` из ответа и схемы;
- построение и проверка значения разрешения;
- версия подтверждения, срок действия и связанные настройки;
- переменные окружения и примеры настройки только для этого разрешения;
- описание поля в OpenAPI;
- тесты, проверяющие выдачу и содержание этого поля.

Не удаляются:

- список поддерживаемых приложений и их режимы обнаружения;
- исключения ложных целей;
- версия документа, ETag и заголовки кэширования;
- проверка формата документа;
- границы входа и рабочего пространства;
- безопасная диагностика реестра;
- другие виды подтверждений, не связанные с автозапуском.

## Целевой ответ

Ответ сохраняет текущую форму реестра без `assistedAutoStartPolicy`. Точное
полное описание остаётся в основном OpenAPI проекта; этот документ фиксирует
только удаляемую границу.

Клиент должен терпимо относиться к дополнительным полям и не считать отсутствие
удалённого поля ошибкой.

## Откат

- до серверной очистки можно откатить только клиент;
- после очистки серверный откат возвращает старое поле, но новый клиент его
  игнорирует;
- возврат старого клиента после серверной очистки не считается безопасным и
  запрещён условием минимальной поддерживаемой версии.
