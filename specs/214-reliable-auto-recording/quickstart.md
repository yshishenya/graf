# Быстрая проверка: надёжный полный цикл автоматической записи

## Ограничения проверки

- использовать только искусственные идентификаторы и синтетический звук;
- не сохранять в доказательства звук, текст встречи, секреты и полные локальные
  пути;
- проверять установленное GRAF Dev отдельно от модульных проверок;
- публикация и развёртывание в эту проверку не входят.

## 1. Подготовка

```sh
.specify/scripts/bash/check-prerequisites.sh --json --require-tasks --include-tasks
swift test --package-path apps/macos --disable-swift-testing --list-tests >/dev/null
python -m pytest --collect-only apps/server/tests/contract/test_meeting_detection_api_contract.py -q
node --check apps/server/src/twobrain_rec_server/cabinet/static/cabinet/cabinet.js
```

Ожидается: документы Feature 214 найдены, проверки собираются, JavaScript имеет
допустимый синтаксис.

## 2. Настройки и окно вопроса

Проверить автоматизированной матрицей:

1. чистая установка без сети — все базовые приложения имеют `Спрашивать`;
2. новое приложение из действующего реестра — `Спрашивать`;
3. `Всегда` запускает без окна, `Никогда` не запускает и не показывает окно;
4. `Спрашивать`: обе кнопки с галочкой и без неё;
5. истечение 8 секунд с включённой и выключенной галочкой;
6. окончание встречи до 8 секунд;
7. одновременные кнопка, таймер и окончание встречи;
8. общий выбор и значение `Разные`;
9. перезапуск и изменение настроек без сети;
10. старый файл настроек становится безопасной трёхпозиционной картой и больше
    не записывает старые поля.

Ожидается: все исходы совпадают с
[клиентским договором](contracts/client-runtime.md), настройка меняется только
после явной кнопки с галочкой.

## 3. Запуск и остановка

Проверить искусственную непрерывную встречу:

1. обычный старт и обычное окончание;
2. окончание во время запуска;
3. повторные сигналы начала и окончания;
4. один источник исчез, второй остался;
5. сон/пробуждение и перезапуск наблюдения после окончания;
6. 10 минут без доверенного подтверждения;
7. ручная остановка с продолжающейся встречей;
8. несвязанная ручная запись при окончании обнаруженной встречи;
9. два приложения при ограничении в одну активную запись.

Ожидается: не больше одной автоматической записи, ровно одно завершение, после
подтверждённого окончания или страховочной границы запись не остаётся активной.

## 4. Сохранение и восстановление

С искусственным звуком прервать процесс:

1. после создания каталога, до первого кадра;
2. после первого пригодного звука;
3. между двумя 10-секундными закреплениями WAV;
4. во время закрепления;
5. во время остановки;
6. после основного WAV, до файла прослушивания;
7. после окончательного manifest, до обновления очереди;
8. повторно запустить восстановление той же папки.

Ожидается: каждая папка становится отправляемой, ограниченно отправляемой или
`Запись повреждена`; полезная запись видна; потеря восстановимого хвоста не
превышает 10 секунд; дублей нет.

## 5. Общий список и отправка

Проверить одну устойчивую личность записи в сценариях:

1. `Сохраняется` до готовности manifest;
2. отправка с процентом выполнения;
3. отсутствие сети и автоматический повтор;
4. перезапуск в ожидании повтора;
5. временная и постоянная ошибка сервера;
6. `Отправить` без сети и после восстановления сети;
7. сервер принял данные, но ответ потерян;
8. серверная строка появилась раньше локального согласования;
9. повреждённая запись — только удаление;
10. отсутствие отдельной правой панели после переноса всех состояний.

Ожидается: локальная строка не исчезает до согласования, ручная попытка идёт
через тот же элемент очереди, после успеха видна одна строка.

## 6. Совместимость сервера

Проверить шаги из
[договора удаления](contracts/server-removal.md): старый ответ, ответ без поля и
работа без сети. После серверной очистки проверить реестр, исключения, ETag,
кэширование, вход и безопасную диагностику.

## 7. Доступность и границы WebView

- пройти настройки, окно вопроса, `Отправить` и удаление только клавиатурой;
- проверить озвучивание состояния VoiceOver;
- убедиться, что состояние понятно без цвета;
- передать в WebView только ограниченную модель строки и устойчивый `id` в
  обратном действии;
- убедиться, что обычный браузерный кабинет не получает локальные строки.

## 8. Итоговые ворота

После точечных проверок:

```sh
infra/scripts/ci-local.sh --fast
```

Перед выпуском на точном кандидате отдельно требуется:

```sh
infra/scripts/ci-local.sh --full
```

Публичный выпуск macOS дополнительно требует Developer ID, нотариальное
подтверждение Apple, прикрепление подтверждения, Gatekeeper, подпись Sparkle и
проверку опубликованного appcast.

## 9. Фактический результат 2026-08-31

Проверка выполнена в ветке Feature 214 только на искусственных идентификаторах
и синтетическом звуке.

### Клиент

```sh

  --filter 'MeetingTargetRegistryTests|MeetingDetectionPolicyTests|MeetingDetectionCountdownTests|MeetingDetectionRecordingLifecycleTests|CanonicalRecordingManifestTests|LocalRecordingWriterTests|CaptureRecoveryServiceTests|DesktopMeetingShellWebViewBoundaryTests|AppControlAccessibilityTests'
swift test --package-path apps/macos --disable-swift-testing \
  --filter 'DesktopUploadQueueTests|CaptureControlTests'
```

Результат: 227 проверок, ошибок нет. Дополнительный повтор 18 проверок writer и
восстановления после упрощения общего построителя WAV-заголовка также прошёл.

Сквозная последовательность подтверждена существующими матрицами:

1. чистая установка, старые настройки и работа без сети;
2. три состояния и восьмисекундное решение;
3. запуск, окончание встречи, гонка запуска и остановки, пробуждение и
   страховочная остановка;
4. ранний manifest, десятисекундное закрепление, прерывание и повторное
   восстановление без дублей;
5. `Сохраняется`, автоматический повтор, ручное действие `Отправить`,
   повреждение, удаление и согласование с серверной строкой.

### Сервер и общий список

`assistedAutoStartPolicy`; реестр, исключения, вход и ETag сохранены.

### Проверка на переусложнение

`@ponytail-review` не обнаружил необходимости в новой службе, базе, очереди или
зависимости. Найденный повтор построения WAV-заголовка удалён: writer и
восстановление используют один существующий построитель.

### Быстрые общие ворота

Ветка синхронизирована с `origin/master` перед итоговой проверкой. Команда
`infra/scripts/ci-local.sh --fast` была запущена, но сама выбрала полный режим
из-за высокорисковых путей записи и серверного договора. Прогон сразу остановлен
и не считается успешным быстрым или полным CI.

По прямому решению владельца продукта до PR выполнен быстрый составной набор без
полного серверного набора:

- проверка отсутствия старого звукового драйвера — успешно;
- сборка macOS, 780 Swift-проверок и `ContractValidation` — без ошибок;
- быстрый серверный набор — 1347 проверок без ошибок;
- Ruff, компиляция Python, конфигурация Docker Compose, синтаксис JavaScript,
  согласованность документов и `git diff --check` — без ошибок.

Итоговое ревью дополнительно закрыло четыре риска: восстановление больше не
трогает текущую активную запись, запрос `Отправить` не теряется при уже идущем
обновлении очереди, контрольная сумма большого звукового файла считается
потоком, а удаление из общего списка доступно только повреждённой записи.

Полный CI, начатый ранее, был остановлен по прямой команде пользователя и также
не считается успешным. Новый полный запуск выполняется только на точном
кандидате выпуска. Установленное приложение, выпуск и развёртывание остаются
отдельными этапами.
