# Feature Specification: Закрытие эксплуатационных хвостов выпуска

**Feature Branch**: `290-post-release-hardening`
**Created**: 2026-10-17
**Status**: Clarified; independent requirements review PASS (13/13)
**Input**: Поручение пользователя последовательно проверить и завершить актуальные
issues; исходный полный объём — [#6501](https://github.com/yshishenya/graf/issues/6501).
Резерв номера: [#7646](https://github.com/yshishenya/graf/issues/7646).

## Clarifications

### Session 2026-10-17

- Номер F238 уже занят принятой работой формата локальных записей (PR #6504).
  Эксплуатационный объём #6501 не относится к ней; F290 штатно зарезервирована
  online allocator, без перенумерации или изменения принятой F238.
- Сохраняются все три исходных результата #6501: судьба серверного stash,
  поддерживаемый runtime Actions и четыре post-deploy проверки. Первый этап
  реализации — CI. Его готовность не закрывает остальные два результата.
- Чтение текущих источников и планирование разрешены поручением пользователя.
  Production stash не применять и не удалять автоматически; его будущий diff
  сначала изучается без изменения production. Запись на сервере, запуск
  изменяющих данные проверок, merge и выпуск требуют отдельного согласия.
- Состав обязательных проверок, exact-SHA/base/run/attempt, trusted metadata,
  исходные квитанции и Full не ослабляются ради обновления зависимостей.
  Swift остаётся 6.0.3; обновление runtime Actions не означает обновление
  версии Node.js приложения, semantic version Swift или SDK.
  Выбор Apple Swift6.0.3 вместо Swift.org6.0.3 меняет compiler build; это
  явно учитывается новым namespace кэша и настоящей hosted сборкой.
- Инвентаризация и конкретизация сохранённого stash и четырёх процедур —
  самостоятельные задачи до изменения соответствующего рабочего кода.
  Неизвестные факты не объявляются выполненными проверками.
- До кода: полная последовательность Spec Kit и независимый reviewer-owned
  checklist. Утверждённые ранее изменения других F290 не подразумеваются;
  исходный SHA этой работы `c6c5441c930b8c1ecffed6de9b80773aa0e757e5`.

Проверка clarify обязательной инфраструктурной области выполнена: роли,
объём, ошибки, безопасность, измерение и полномочия определены. Неизвестные
состояния сервера подлежат исследованию, а не пользовательскому угадыванию.
Новых продуктовых решений для начала первого этапа не требуется.

## User Scenarios & Testing

### User Story 1 — Поддерживаемые проверки CI (Priority: P1)

Владелец получает прежние обязательные проверки без устаревшего runtime
Actions и без потери доказательств исходного кода.

**Why this priority**: устаревшие действия используются всеми PR и выпусками.
**Independent Test**: выполнить реальные обязательные проверки на точном PR
SHA; проверить runtime, сохранение областей и квитанций, настоящий Swift.

**Acceptance Scenarios**:

1. Given действующий workflow, when обновлены действия, then сохраняются
   события, permissions, concurrency, required names и fail-closed условия.
2. Given применимый native scope, when выполняется hosted проверка, then
   используется Swift 6.0.3, реальные build/tests и прежние проверки контракта.
3. Given неверный или отсутствующий toolchain, when запускается его выбор,
   then job прекращается, подмена другим компилятором запрещена.
4. Given опубликованные квитанции, when их читает общий validator, then
   формат ZIP, run/attempt, SHA/base и identity остаются проверяемыми.

### User Story 2 — Доказанная судьба сохранённой ротации (Priority: P1)

Владелец знает судьбу каждой части отложенного изменения резервных копий,
не рискуя текущими данными или единственной копией изменения.

**Independent Test**: учёт каждого изменения stash, его назначения и решения;
полезный код проверен отдельно, непринятый stash сохранён.

1. Given сохранённый stash, when его читают, then production checkout не
   меняется и приватные данные не попадают в evidence.
2. Given полезное изменение, when оно переносится, then это отдельное
   проверенное изменение, сохраняющее обязательные backup/restore правила.
3. Given решение отказаться от изменения, when требуется удалить stash,
   then перед удалением есть доказанное основание и отдельное согласие.

### User Story 3 — Завершаемые post-deploy проверки (Priority: P2)

Оператор получает отдельный доказанный результат automatic_retry,
backfill_inventory, range_playback и normalization_cleanup вместо вечного
неопределённого `required_post_deploy`.

**Independent Test**: безопасная исполняемая процедура и запись каждого
результата с source SHA, условиями, временем и владельцем; ошибки видимы.

1. Given готовая разрешённая проверка, when она выполнена, then выводится
   фактический результат, без пользовательского аудио или текста встреч.
2. Given неполные условия, when исполнение невозможно, then сохраняется
   конкретный незавершённый результат, причина и проверяемый следующий шаг.
3. Given отдельное расписание вместо каждого deploy, when оно выбрано,
   then есть обоснование, владелец, реальная процедура и доказательство цикла;
   само слово «расписание» не заменяет исполнение.

### Edge Cases

- Новый major действия меняет значения по умолчанию, хранение credentials,
  структуру артефакта, скрытые файлы или область кэша.
- Swift нужной версии отсутствует на hosted image; версия 6.0.31 не равна
  6.0.3. Неверный SDK нельзя незаметно выбрать вместе с компилятором.
- Серверный stash изменён, отсутствует или содержит несвязанные/приватные
  изменения. Это требует нового фактического решения, а не удаления «мусора».
- Проверка затронула только часть сценариев, частично выполнилась или упала;
  незавершённость не превращается в PASS последующей проверкой.
- Hosted macos-14 выводится из поддержки 2026-11-02. Текущее обновление
  Actions не является доказательством готовности на другом runner image.

## Requirements

### Functional Requirements

- **FR-001**: Полный исходный объём #6501 связан с F290 и реальными task IDs;
  F238/PR6504, Windows/F200 и чужая незакоммиченная работа не изменяются.
- **FR-002**: Действия CI используют поддерживаемый runtime. Версии выбираются
  по актуальным стабильным выпускам и закрепляются проверенным точным commit;
  совместимость каждого изменённого major проверяется до использования.
- **FR-003**: События, trust boundary, permissions, постоянные required names,
  scope, concurrency, exact-SHA/base/run/attempt и срок/формат квитанций
  сохраняются. Новый текстовый PASS не заменяет исполнение исходного кода.
- **FR-004**: Native CI сохраняет Swift 6.0.3, реальную сборку, тесты и
  проверку контракта. Выбор другого Swift/SDK или пропуск native запрещены;
  неверная версия и ошибка выбора дают явный отказ до build/tests.
- **FR-005**: До изменения серверного кода сохранённый stash инвентаризируется
  без apply/pop/drop и без изменения production; для каждого изменения
  есть перенос в принятый PR или явно обоснованное решение об отказе.
- **FR-006**: Ротация сохраняет обязательные backup/restore, защиту от
  незавершённой записи, ошибок удаления, диска и конкуренции. Нельзя терять
  обязательные копии или несохранённые изменения; удаление stash отдельно
  согласуется после проверки принятой замены либо отказа.
- **FR-007**: Четыре post-deploy проверки получают отдельные результаты,
  привязанные к source и условиям. Невыполненное остаётся невыполненным;
  допустимое отдельное расписание имеет владельца и доказанный реальный цикл.
- **FR-008**: Процедуры используют существующие проверки/инструменты и
  изолированные синтетические данные. Production-запись и содержательные
  действия выполняются только после отдельного согласия на готовую процедуру.
- **FR-009**: В evidence только метаданные: SHA, публичные ссылки, статус,
  число сценариев, время и разрешённые digests. Нет секретов, сырых stash
  diff с приватными данными, аудио, транскриптов или пользовательских встреч.
- **FR-010**: До реализации есть независимый checklist, analyze и issue
  ownership. Implementation commit требует согласия после проверки; перед
  merge проходят три точных PR checks, перед новым выпуском — свой Full и
  отдельные release/deploy gates. Старый опубликованный Full не повторяется.
- **FR-011**: Не добавляются новые службы, зависимости, обходные флаги,
  legacy aliases или резервные пути, скрывающие отсутствие доказательств.

### Key Entities

- **Action selection**: repository, стабильная версия, commit, runtime,
  затронутые workflow и доказанная совместимость.
- **Stash disposition**: неизменяемая identity, разрешённый перечень областей,
  решение по изменениям, принятый PR либо основание отказа.
- **Post-deploy result**: одна из четырёх проверок, source SHA, условия,
  фактический исход, время, безопасное доказательство и владелец остатка.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Все затронутые обязательные CI проверки успешны на одном точном
  PR source/base, без предупреждений об устаревшем Node20 и без пропущенных
  применимых native или governance этапов; общий validator принимает квитанции.
- **SC-002**: Учтены 100% изменений сохранённого stash; для каждого есть
  проверяемое решение, рабочие данные и обязательные копии сохранены.
- **SC-003**: Все четыре эксплуатационных проверки имеют отдельный доказанный
  результат либо обоснованный доказанный отдельный цикл; неизвестных вечных
  `required_post_deploy` без владельца/процедуры не остаётся.
- **SC-004**: #6501 и umbrella #7646 закрываются только после всех трёх
  результатов, корректной task-связи и штатной проверки закрытия.

## Assumptions

- GitHub-hosted CI остаётся единственной обычной площадкой hosted проверки;
  локальные тесты являются диагностикой, не эквивалентом hosted evidence.
- Сохранённый stash может уже отличаться от старого сообщения #6501.
  Его существование и содержимое предстоит проверить, без предположений.
- Проектная конституция 7.1.0 и текущие release gates не меняются.
- Публикация приложения, изменение установленного GRAF Dev, обновление
  production и выполнение содержательных post-deploy действий в первый
  CI-срез не входят. Ручная macOS-приёмка при её необходимости — только GRAF Dev.

## Legacy Impact

Classification: remove

Убирается исполнение Actions с Node20 и внешний setup-swift, который всё ещё
требует Node20. Новых aliases/fallback flags/служб нет. Существующая граница
macos14 явно ограничена сроком поддержки; этот срез не добавляет обход её
отключения. Принятая F238, Windows/F200 и чужая работа сохраняются.
