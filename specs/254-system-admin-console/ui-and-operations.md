# Экраны, формы и правила операций

Нормативное приложение к [спецификации](spec.md). Все приведённые сроки, ограничения и состояния описывают целевое поведение. Они не являются снимком настроек действующего сервиса.

## 1. Общий интерфейс

Основная поверхность — браузер. Адреса на отдельном административном origin: /system-admin/login и /system-admin; точный origin задаётся операторской конфигурацией согласно contracts/security.md; существующая /admin остаётся корпоративной консолью. Обычная сессия не переносится в системную консоль. Из встроенного кабинета приложение открывает системную консоль во внешнем браузере, не передавая токен устройства.

Постоянная шапка: GRAF, название среды, состояние установки, версия сервера, поиск, административная роль, время истечения сеанса. В карточках чужих объектов постоянно видны владелец/пространство и отметка «Системный доступ».

Список по умолчанию содержит 25 строк, допускает 50/100. Сортировка стабильна, равные значения разрешаются по постоянному ID. Выборка выполняется на полном разрешённом наборе; загрузка всех встреч в память ради фильтрации не удовлетворяет требованию масштаба.

| Состояние | Требуемое поведение |
|---|---|
| Первая загрузка | Сохраняется структура экрана, обозначена загрузка; ложные нули не рисуются |
| Нет объектов | Объяснение и допустимое действие; пустое пространство не выглядит ошибкой |
| Фильтр ничего не нашёл | Активные фильтры и «Сбросить фильтры» |
| Недостаточно прав | Без выдачи скрытых полей/фрагментов и без подтверждения существования чужого объекта неавторизованному посетителю |
| Нет источника данных | «Данные не собраны» с указанием недоступного источника |
| Временный отказ | Код обращения, время последнего успеха и безопасный повтор чтения |
| Частичная недоступность | Остальные блоки работают; суммарное состояние не зелёное |
| Устаревший снимок | Время получения и явная отметка; не подменять новым пустым снимком |
| Конфликт изменения | Показать новые значения и сохранённый ввод; предложить пересчитать, не перезаписывать молча |
| Утрата роли/сессии | Скрыть содержимое, отменить будущие запросы; повторный вход не повторяет изменение |
| Долгая операция | Номер операции, прогресс/неизвестный прогресс, возможность вернуться позднее |

Содержимое не помещается в заголовок вкладки или всплывающие общесистемные уведомления. Причины/комментарии администраторов не используются как место копирования расшифровок. Просмотр больших расшифровок постраничный/частичный в интерфейсе, но без необъявленного усечения полного доступного текста.

## 2. Вход, приглашение, восстановление

Форма входа: адрес, пароль, затем второй фактор. Одинаковая внешняя ошибка для неизвестного адреса и неверного пароля. Не более 5 неудачных проверок за 15 минут на учётную запись; дополнительный предел 30 на сетевой источник за 15 минут. Ограничение снимается по времени, не деактивирует пользователя навсегда. Попытка повторно использовать тот же уже принятый одноразовый второй фактор отклоняется.

Первый выпуск использует пароль и приложение-аутентификатор. Требуется пароль не короче 14 символов без обрезания, разрешены вставка и менеджер паролей; точная допустимая верхняя граница не меньше 128 символов. Ключи доступа и корпоративный SSO — дальнейшее расширение.

При активации выдаются 10 одноразовых кодов восстановления с достаточной случайностью, показываемых один раз. Сброс пароля сам по себе не отменяет второй фактор. Использование восстановления отзывает предыдущие сессии и создаёт отдельное событие. При полной потере доступа действует операторская процедура из технического плана.

Карточка администратора: статус, роль, область, второй фактор настроен/нет, последнее действие, активные сессии, временные права, кто пригласил. Секрет второго фактора, пароль, коды и значения сессий никогда не отображаются повторно.

Приглашение: адрес, роль, область, срок назначения, причина. Перед отправкой — итог прав. Переотправка с ограничением не чаще раза в минуту, не более 5 раз за сутки на адрес; прежняя ссылка отзывается. Для последнего суперадминистратора не допускается назначение даты истечения без другого бессрочного активного суперадминистратора.

Продуктовая и административная личности могут принадлежать одному человеку, но их жизненные циклы различаются. Блокировка продуктового аккаунта не является неявным отзывом системной роли. При связанном администраторе форма блокировки предлагает отдельный явный отзыв системного доступа; закрытие продуктового аккаунта останавливается до явного решения о связанном административном доступе, сохраняя защиту последнего суперадминистратора.

## 3. Обзор

Три полосы: «Требует внимания», «Система», «Использование».

- Внимание: потеря/неподтверждённая сохранность записи, ошибки после выпуска, встречи без прогресса, неопределённые платежи, необработанные обращения, отказы удаления, необычные скачивания.
- Система: очередь и возраст старейшей задачи, задержки обработки, состояние зависимостей, место, backup и восстановление.
- Использование: активные пользователи, новые аккаунты, первые успешные встречи, часы записи, успешность обработки и время до результата.

Карточка содержит период, единицу, определение, время обновления и переход к выборке. Показатель текущего состояния, например очередь сейчас, не помечается суммой за выбранный месяц. Исторические денежные отчёты и производственные показатели используют явную временную зону.

## 4. Пользователи и пространства

Представления списка: «Все», «Подписки», «Проблемы», «Права и лимиты». Поля настраиваются на уровне административной личности, а не глобально для всех.

| Группа | Поля/фильтры |
|---|---|
| Личность | Имя, email, ID, дата регистрации, активен/блокирован/закрывается/закрыт |
| Доступ | Личный тариф/версия, доступ организации отдельно, основание, оплачено до, доступ до |
| Деньги | Последняя подтверждённая оплата, валюта, оплачено всего, возвраты, следующий платёж |
| Подписка | Период, автопродление, переход, пробный/подарочный интервал |
| Использование | Точное потребление, действующая квота, хранилище, открытые резервы |
| Поддержка | Версия приложения, последнее соединение, проблема, обращение |
| Исключения | Индивидуальные правила и ограничения с датой окончания |

Готовые фильтры: оплатил без доступа; доступ заканчивается за 3/7/30 дней; автопродление выключено; неопределённый платёж; административный подарок; превышение лимита; использованная акция; неактивен 30 дней; старый клиент; открытое обращение.

Карточка пользователя: Обзор, Пространства, Подписка, Платежи, Права, Встречи, Устройства и сессии, Интеграции, Обращения, История.

Временная лента сохраняет дату/источник изменения. Не показывать сегодняшнюю версию приложения как версию на момент вчерашнего сбоя.

Корпоративная карточка: ID, название, владельцы, участники, приглашения, объём/активность и действующие ограничения. Внутренний служебный anchor авторизации не становится организацией. Системный просмотр не меняет активное пространство пользователя.

Блокировка продукта:

1. Показать пользователя, пространства, активные загрузки, оплаты и связанные административные роли.
2. Зафиксировать причину; заблокировать новые входы/выдачи данных/новые платные действия и отозвать сессии.
3. Запретить ещё не отправленные автоматические списания. Отправленные операции сверить; не изображать их отменёнными.
4. Уже сохранённые записи и принятые обработки довести до учтённого состояния; не удалять их автоматически. Активная локальная запись не прерывается скрытой командой; клиент сохраняет данные и показывает состояние доступа.
5. Разблокировка возвращает допустимые продуктовые права, но не создаёт заново согласие на автосписание и не восстанавливает отозванную системную роль.

## 5. Встреча и проверка содержимого

Вкладки: Обзор; Расшифровка; Аудио; Итоги и форматы; Ход обработки; Диагностика; Получатели; Данные и удаление; Действия.

Обзор отвечает: кто владелец, где источник, что доступно, что не завершено, есть ли риск данных, какая следующая допустимая операция. Нужны отдельно начало/конец записи, продолжительность, серверное получение, этапы подготовки, время публикации.

Расшифровка: полный сохранённый текст, поиск внутри встречи, таймкоды, имена участников, источник этих имён, ревизия, язык при наличии. Редактирование пользовательского текста администратором не входит в этот выпуск.

Аудио: один канонический доступный плеер GRAF, перемотка по таймкоду, диапазон фактически доступного материала. Диагностика источников может различать микрофон и системный звук; это не обещает наличие двух отдельных скачиваемых дорожек.

Итоги: опубликованный набор, формируемый кандидат, формат/версия, канонический источник, ссылки на подтверждающие реплики, состояние проверки. Пользовательский формат не становится глобальной инструкцией проекта.

Системные полномочия позволяют скачать доступное аудио независимо от тарифа владельца. Это не восстанавливает уже удалённый файл и не превращает временный технологический файл в обещанную пользовательскую запись. Каждый выдаваемый класс должен быть явно разрешён текущим жизненным циклом.

Доставка скачивания проверяет текущие права до начала выдачи и при новых запросах частей. Нельзя обещать отозвать уже выданные байты. Скачанная копия находится вне управляемого серверного удаления; отчёт об этом сообщает.

| Состояние | Что показывать | Допустимое действие |
|---|---|---|
| Локальная запись без серверной встречи | Сведения последнего клиента, локальная сохранность, очередь | Открыть обращение/диагностику; не создавать фиктивную серверную встречу |
| Загрузка идёт | Последний подтверждённый прогресс, повторы | Обновить сведения; не запускать ASR до готового источника |
| Очередь обработки | Время ожидания, ближайшая попытка | Проверить состояние; не дублировать задачу |
| Внешний исход неизвестен | Где могла исполниться операция, что известно | Сверить провайдера; повтор запрещён до допустимого решения |
| Повторимая ошибка | Этап, причина, предел и следующая попытка | Допустимый ручной повтор после проверки текущей версии |
| Речь не распознана | Нулевой пригодный результат и доступность аудио | Прослушать, скачать, повторить при пригодном источнике; не рисовать успешную расшифровку |
| Формируется замена | Предыдущая публикация отдельно от кандидата | Просмотреть обе доступные версии; не запускать ещё одну замену |
| Итоги не прошли проверку | Причина, формат, исходная ревизия | Перегенерировать итоги без повторной расшифровки при допустимом состоянии |
| Удаляется | Состав и прогресс удаления | Только статус; новые обработки/экспорты запрещены |
| Удалено | Метаданные удаления и отдельно сохранённая диагностика | Читать допустимую диагностику; не восстанавливать пользовательский объект из неё |

## 6. Общий протокол административного изменения

Для всех форм:

1. Прочитать актуальную цель и права.
2. Показать намерение, последствия, основание, версию, сроки и стоимость/оценку.
3. Для финансового/массового предварительного расчёта установить срок действия 5 минут.
4. При подтверждении повторно проверить права, версии, источник данных и срок расчёта.
5. Зафиксировать одно логическое намерение и безопасный аудит до внешнего эффекта.
6. Вернуть номер операции. Состояния: принята; выполняется; ожидает зависимости; исход уточняется; завершена; частично выполнена; отклонена; отменена до исполнения.
7. После перезагрузки интерфейс находит тот же результат. Таймаут браузера не означает отказ.

Второе нажатие подтверждения и повтор доставки должны находить одну логическую операцию. Это не обещание однократного исполнения у любого внешнего провайдера: возможный внешний эффект без подтверждения обозначается неопределённым и сверяется.

Отмена возможна только до необратимого эффекта. Для уже выполненного изменения используется новая компенсирующая операция, если она допустима.

Перед массовым действием фиксируются выбранные ID, версии, число объектов и предварительные итоги. В первом выпуске массово допустимы отзыв выбранных сессий, назначение одинакового ограниченного по сроку бонуса и планирование перехода тарифа. Массовое удаление пользователей/встреч, массовое чтение содержимого и массовый повтор обработки не входят; единичные операции доступны.

Отзыв роли до исполнения отменяет ещё не начатые действия. После отправки денежной операции или начала удаления система завершает учёт/сверку без нового пользовательского полномочия, не повторяя внешний эффект.

## 7. Подписка и назначение доступа

Карточка подписки отображает тариф/версию, плательщика, получателя, цикл, оплаченные интервалы, подарочные интервалы, эффективные права сейчас, следующую дату изменения, согласие/автопродление и неопределённые операции.

Каждое назначение хранит происхождение: подтверждённая оплата; trial; акция; административный подарок; компенсация; корпоративное членство. Возврат и отзыв — отдельные записи, не уничтожающие историю.

Форма «Изменить доступ»:

- действие: назначить тариф / добавить дни / выдать квоту / задать ограничение / запланировать переход / отозвать своё прошлое назначение;
- конкретный пользователь и пространство-получатель;
- тариф/версия или функция;
- начало, окончание либо явное «бессрочно» для допустимого индивидуального правила;
- новое значение и источник;
- причина;
- блок «Сейчас → После» с тарифом, доступом, квотой, хранилищем и следующим списанием.

Подарки задаются на 1–365 дней за одну операцию. Это предел одной операции, не запрет суперадминистратору сделать последующее назначение. Исходное значение компенсации — 7 дней, обязательный просмотр до подтверждения.

Время:

- Месяц/год — календарный период с обработкой последнего дня месяца; 31 января + месяц даёт последний день февраля.
- Подарочный день — календарный день в зафиксированной зоне подписки; исходная зона для новых RUB-подписок Europe/Moscow. Во внутренних событиях сохраняются точные моменты.
- Число оплаченных дней не пересчитывается приблизительно из суммы; используется исторический интервал.
- Если у старого интервала известен только фактический момент окончания, он сохраняется без домысливания первоначальной зоны.

Подарок того же тарифа добавляется после непрерывной последовательности уже предоставленного оплаченного/подарочного доступа; для нового пользователя — с текущего момента. Подарок другого тарифа требует выбора: последующий интервал или временное повышение с показом базового тарифа после окончания. Оплаченный интервал не удаляется.

Автопродление переносится за добавленный непрерывный бонусный интервал, сохраняя согласованные условия и сумму. Если уже существует отправленный/неопределённый платёж, действие не исполняется до сверки. Не создаётся второй будущий платёж на прежней дате.

Понижение основного тарифа и платный переход без поддержанного денежного перерасчёта выполняются со следующего расчётного периода. Бесплатное немедленное повышение оформляется индивидуальным назначением. Существующий подтверждённый механизм доплаты за пакет хранения сохраняется отдельно.

## 8. Вычисление прав и квот

Панель показывает объяснение по каждому действию: роль → состояние объекта → политика пространства → тариф/назначения → индивидуальное правило → текущий лимит. Результат один и тот же для браузера, приложения и серверного действия.

Порядок:

1. Обязательные запреты: отсутствие авторизации, чужой объект без системного права, удаление, отозванный доступ, несоблюдённые условия записи. Коммерческие назначения их не отменяют.
2. Состояние аккаунта и действующие подтверждённые ограничения добросовестного использования.
3. Применимая политика выбранного пространства.
4. Базовое назначение тарифной версии на этот момент.
5. Дополнительные квоты/временные расширения функций.
6. Индивидуальный явный запрет на функцию; он имеет приоритет над индивидуальным разрешением. Снятие запрета выполняется явно, не новым конфликтующим разрешением.

Для одной функции и области не создаются два перекрывающихся правила одинакового типа; новое изменение заменяет действующее правило с сохранением истории и проверкой версии. Дополнительные квоты могут складываться, каждая расходуется отдельно.

Квоты обработки:

- Единица учёта — фактические секунды; интерфейс показывает минуты и точное значение по запросу.
- Допустимые окна: на весь период назначения, календарный месяц или платёжный цикл. Окно обязательно и сохраняется в версии тарифа.
- Резерв при принятии обработки уменьшает доступный остаток; терминальное завершение/подтверждённый отказ переводит резерв в расход/освобождение.
- Повтор той же ревизии не создаёт новый коммерческий расход.
- Изменение тарифа внутри текущего окна не обнуляет уже учтённое потребление. При повышении лимита остаток равен новому пределу минус расход и резервы.
- При смене вида окна первая граница нового окна наступает в явно рассчитанный момент; уже принятые операции остаются в исходном окне, не переносятся повторно.
- Дополнительная квота расходуется после базовой, из дополнительных — сначала истекающая раньше. Истечение квоты не отбирает уже выданный резерв; новый запрос не может пользоваться истёкшим остатком.
- Переход с безлимита сохраняет учёт фактического потребления; до следующей границы лимит применяется с предварительным объяснением, без отрицательного доступного остатка.
- Повторный пробный период может разрешить только явное административное назначение; самостоятельное создание/объединение аккаунтов не сбрасывает историю использованного trial.

Хранилище:

- Показывать активные байты, зарезервированные, ожидающие удаления и отдельно резервные/диагностические копии.
- Дополнительный пакет устанавливает общий предел; индивидуальная компенсационная прибавка отдельно суммируется и явно подписывается.
- При превышении запрещается новая операция, увеличивающая платное хранение; уже подтверждённые объекты не удаляются этой формой.
- Где продукт поддерживает обработку без сохранения архива, превышение архива не должно ложно запрещать саму обработку.
- Размер тарифа не является сроком хранения. Сокращение срока — отдельная политика и отдельное подтверждение.

## 9. Платежи и ограничения ручных операций

Состояния оплаты: не создана; ожидает; подтверждена; отменена; исход уточняется; подтверждена с расхождением выдачи. Возврат и чек имеют отдельные состояния.

История каждой операции: безопасный номер, вид, даты, плательщик, исходные условия, скидка, сумма/валюта, источник подтверждения, выданный период, маскированный способ, чек, возвраты, связанная административная сверка.

Итоги:

- Оплачено = сумма подтверждённых успешных платежей.
- Возвращено = сумма подтверждённых возвратов.
- Итог после возвратов = оплачено минус возвращено.
- Подарки, резервы, отменённые счета и неизвестные исходы не входят.
- Это денежный поток, а не бухгалтерское признание выручки. Валюты не складываются без отдельного утверждённого курса.

Суперадминистратор может проверить состояние, повторно применить подтверждённое основание доступа и выдать независимую компенсацию. Он не может сделать неподтверждённый счёт оплаченным или удалить возврат из истории. Полный/частичный возврат проводится существующим процессом провайдера.

При удалении пользователя финансовые записи сохраняются в необходимом минимальном объёме по действующей политике; отображается причина сохранения. Из этой записи нельзя открыть уже удалённое содержимое встречи.

## 10. Тарифы

Идентичность тарифа имеет уникальный код, не зависящий от названия. Версия объединяет возможности и предложения по периоду. Название можно локализовать без изменения кода; опубликованные экономические условия редактируются только новой версией.

Поля формы:

| Блок | Поля и правила |
|---|---|
| Основное | Код 3–32 символа: первая строчная латинская буква, далее строчные латинские буквы/цифры/подчёркивание; уникален; название 1–80; описание до 500 |
| Показ | Публичный / по приглашению / только администратору; порядок; одна рекомендованная карточка на одну аудиторию |
| Оплата | Бесплатный либо RUB; месячная и/или годовая цена в целых копейках; ниже допустимого платёжного минимума — отказ |
| Обработка | Квота/безлимит; для квоты — секунды и окно; значения неотрицательные, безлимит отдельно от большого числа |
| Хранение | Положительное число байтов; интерфейс явно использует десятичные ГБ |
| Функции | Из каталога реализованных возможностей: аудиоархив, скачивание, экспорт, обмен, поддерживаемые форматы/возможности ИИ |
| Trial | Допускается/нет, 1–365 дней, версия прав и поведение после окончания; согласие на списание отдельно |
| Публикация | Сейчас либо будущий момент; аудитория; версия условий; дата закрытия новых продаж необязательна |
| Акции | Разрешённые виды акций; совместимость с конкретными версиями; предварительная проверка |

Первый выпуск не вводит отдельное отключение базовой ручной записи тарифным переключателем. Продуктовые возможности выбираются только из утверждённого списка с серверной реализацией. Каждый пункт списка имеет пользовательское описание и условие фактического исполнения.

Состояния: черновик → запланирована → опубликована → закрыта для новых продаж → архивна. Черновик можно удалить, если он нигде не использован. Запланированную публикацию можно отменить до исполнения. Архив не препятствует чтению старых счетов.

Публикация проверяет одно действующее предложение на тариф, период, валюту и аудиторию. Старые подписчики могут оставаться на старой версии для продления: это отдельная привязка, а не второе противоречивое публичное предложение.

Перевод действующих подписок:

- По умолчанию отсутствует.
- Для выбранной группы фиксируются ID и версии, дата не раньше следующего продления, будущая цена/права и основание разрешённого перехода.
- Увеличение цены либо уменьшение оплаченных возможностей требует пользовательского подтверждения новых условий. Без него сохраняется прежнее предложение, если его обслуживание продолжается; иначе продление выключается после действующего срока с уведомлением.
- Нельзя заменять согласие записью «администратор согласовал».
- Если будущая цена не может быть определена, автоматическое списание не запускается.

Годовая экономия в карточке рассчитывается из опубликованной месячной и годовой цены; при отсутствии месячного предложения сравнение не выдумывается.

## 11. Акции и коды

Акция имеет внутреннее название, краткие пользовательские условия, тип, версию, тарифы/версии/периоды, аудиторию, начало/окончание, лимиты, бюджет, автора и ответственного.

Типы первого выпуска:

1. Процент 1–99% на одно оформление. Форма явно выбирает первую оплату или допустимую разовую покупку; автоматическая многопериодная скидка не включается.
2. Подарок 1–365 дней выбранной версии тарифа без платёжной операции.

Фиксированные скидки, бонусные минуты по кодам и повторяющиеся скидки — расширение после первого выпуска; индивидуальная выдача дополнительных минут суперадминистратором входит.

Общий лимит акции учитывает успешно применённые и активные резервы. Для скидки бюджет — максимальная сумма скидок в копейках, для подарка — общее число выдаваемых дней; денежную стоимость подарка нельзя выдавать за фактический расход.

Ограничение по умолчанию — одно успешное применение акции на цепочку подтверждённой личности и её личного плательщика, включая связанные историей объединения аккаунты. Один IP не используется как доказательство одного человека. Ранее действующие ограничения на пространство сохраняются для исторических акций.

Общий код задаётся вручную, нормализуется существующим правилом GRAF. Индивидуальные коды генерируются случайно, без email/ID человека и угадываемой последовательности, не менее 16 символов алфавита из 32 допустимых символов. Партия максимум 1 000 кодов.

Новые коды показываются/выдаются уполномоченному создателю один раз; в постоянной базе и аудите остаются проверочное представление, маскированный идентификатор и связь с акцией. Если выдача потеряна, можно отозвать неиспользованные коды и выпустить новые; отображение старого исходного кода не обещается. Экспорт партии не является обычным экспортом пользовательских данных и не уходит во внешние отчёты.

Предварительная проверка не расходует лимит. Финальное применение повторно проверяет пользователя, тариф, дату, предел, бюджет и версию условий.

Жизненный цикл применения:

- Скидка: допустим → зарезервирован при создании счёта → применён при подтверждении оплаты.
- Подтверждённая отмена до успеха → резерв освобождён.
- Нет отправки провайдеру и истёк срок предварительного резерва → резерв истёк.
- Платёж отправлен/исход неизвестен → резерв сохраняется до сверки, даже если акция завершилась.
- Подарок: допустим → одно назначение доступа и одно применение; сбой после фиксации не выдаёт второй подарок при повторе.

При запуске показываются примеры итоговой цены и следующей обычной оплаты. Пауза/окончание запрещают новые счёта/подарки, но не меняют условия уже принятого счёта. Для опубликованной акции нельзя уменьшить общий предел ниже применений и активных резервов.

Конкуренция скидок: существующее правило выбора одной наиболее выгодной допустимой скидки сохраняется; явно ошибочный код вызывает объяснение, а не цену без скидки. Действующая реферальная награда учитывается отдельно и не превращается во вторую скидку.

Возврат не восстанавливает применение автоматически. Возврат доступа по подарку возможен отдельной операцией с причиной, без удаления оплаченных назначений. Для мошеннического применения ограничение пользователя и отзыв подарка — два связанных, но самостоятельных действия.

## 12. Обращения, устройства и смежные сценарии

Обращение: номер, пользователь, предмет, проблема, приоритет, ответственный, описание, связанные объекты, снимки, действия, ожидаемая сторона, инцидент, исправление и доказательство закрытия.

Состояния: новое → разбираем → ждём пользователя/зависимости → исправление готово → проверяем результат → закрыто. Новое повторение после закрытия переоткрывает обращение либо связывается с новым, сохраняя историю. «Отправлено в GitHub» — состояние доставки, не решение проблемы.

Устройство: версия приложения/сборки, ОС/архитектура, последнее сообщение, разрешения, известные записи/загрузки, обновление, счётчики пропусков/сбоев. Название оборудования заменяется категорией; нет серийного номера и локального пути.

| Сценарий | Видимые сведения | Действия |
|---|---|---|
| Календарь не обновляется | Подключение, сроки доступа, последний успех/ошибка, выбранные календари без избыточного содержимого | Повтор синхронизации с ограничением частоты, отключение; повторный вход выполняет владелец |
| Не удаётся связать аккаунты | Стадия, доказательство владения действительно/нет, коды конфликтов, связанное обращение | Разобрать блокирующую подписку/роль; предложить пользователю повторить штатный процесс |
| Получатель не видит встречу | Приглашение, принятие, версия разрешения, срок, отзыв | Отозвать; объяснить следующий шаг; не принять за получателя |
| Не пришло письмо | Постановка, принятие провайдером, подтверждённая доставка при наличии, отказ | Повтор разрешённого служебного сообщения с пределом; маркетинг отдельно |
| ИИ-формат не работает | Версия формата, исходная ревизия, попытки/ошибка | Повтор генерации по разрешённым условиям; без редактирования глобального prompt |
| Ограничение использования | Возможность, причина, сроки, апелляция | Подтвердить/снять ограничение суперадминистратором; сохранить факты расхода |
| Реферальный бонус не появился | Привязка, подтверждённый платёж, ожидание, начисление/отмена | Сверить основание; компенсацию выдать отдельно, не подделывать факт приглашения |
| Автозапись не сработала | Поддерживаемая цель, локальное предпочтение, условия запуска, причина отказа | Диагностика; без удалённой смены локального решения и без скрытой записи |

## 13. Хранение и закрытие аккаунта

Для удаления встречи: владелец, состав доступных данных, активные процессы, необратимость, причина, обычное подтверждение без обязательной набираемой фразы. Для аккаунта — дополнительный список личных встреч, подписки/списания, членства, приглашений, интеграций и связанной административной личности.

Штатный период ожидания закрытия аккаунта сохраняется из текущей политики. Панель показывает точный крайний срок отмены; немедленная очистка вне этой политики не вводится скрыто.

Корпоративные встречи остаются собственностью соответствующего пространства. Закрытие последнего владельца требует предварительного допустимого решения по владению. Системная роль не разрешает автоматически присвоить организацию другому сотруднику.

| Класс | Как показывается |
|---|---|
| Основные серверные объекты | Ожидает / удаляется / удалено / ошибка; точное последнее подтверждение |
| Локальные копии | Задание создано / клиент подтвердил / клиент недоступен |
| Резервные копии | Известный срок окончания хранения; не маркируются очищенными раньше |
| MediaScribe | Подтверждено / ожидается / не поддерживается / неизвестно |
| Generation Call, Langfuse, Temporal | Сохраняется по действующей операторской политике; отдельный доступ |
| Уже скачанные копии | Вне последующего контроля GRAF; факт выдачи сохраняется |
| Финансовые записи и аудит | Минимально необходимое сохранение по применимой политике, отдельно от содержания |

Нельзя получить новую выдачу обычного аудио/экспорта после начала удаления. Уже отправленный ответ провайдера не публикует результат в удалённую встречу; его внешняя стоимость/диагностический учёт сохраняются согласно действующим правилам.

## 14. Настройки и зависимости

Разрешённые формы первой версии: контакты поддержки; пороги оповещений; получатели из настроенного списка; пределы административных выгрузок не выше системного потолка; сроки новых диагностических данных в утверждённых границах; приостановка приёма новых задач выбранного этапа; квоты/тарифы через профильные формы.

Все технически опасные параметры, не имеющие безопасной формы, показываются только для чтения с источником управления. Нет поля произвольного URL поставщика или свободного JSON, меняющего скрытые настройки.

Пауза очереди не прерывает локальную запись, не уничтожает активную задачу и имеет срок автоматического снятия не более 60 минут без явного продления. Показать ожидаемые задачи, пользователей, автора и причину. Уже принятые операции доходят до предусмотренного состояния.

ИИ: видеть активную утверждённую версию, маршруты, состояния доставки, резервный проверенный снимок и причины ожидания. Публикация инструкции остаётся в существующем операторском процессе с квалификацией и откатом; системная роль сама по себе не разрешает обходить его.

Резервные копии: время, охват, состояние, срок, последняя проверка восстановления. Не показывать реальные секретные пути и не предоставлять скачивание полного бэкапа через консоль.
