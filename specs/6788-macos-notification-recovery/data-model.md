# Существующие данные и переходы

Новая схема не нужна. Источники истины остаются прежними.

| Объект | Владелец | Изменение в этой фиче |
|---|---|---|
| Capture session/snapshot | Нативная сессия | Представление через F255, общий dispatcher; guards прежние |
| Local recording/custody | Очередь конкретного Mac | Состояние и действие в строке/карточке, без widget |
| Calendar occurrence | Текущий owner + календарный контекст | Запланированное сообщение и действие повторно проверяют revision/time/owner |
| Reminder reservation | Существующий dedup store | До due-time reservation можно заменить; после due повтор запрещён, показ ОС не подразумевается |
| Notification preferences | UserDefaults этого Mac | Прежние ключи/значения, новый прямой вход, без сброса |
| Server inbox event | Серверная запись + revision | Существующие producers/read/resolved, без Mac-дублирования |

Переходы записи не меняются: idle → starting → recording → stopping → idle;
mute касается микрофона, а не системного звука. UI не выводит active до
подтверждения. Отправка сохраняет собственный жизненный цикл независимо от окна.

Действия уведомления не являются источником прав: проверить текущий account,
событие, occurrence, срок и разрешённый URL. Удалённое, отменённое, чужое или
неизвестное действие не подключает и не начинает запись. Read снимает новизну,
resolved определяется актуальным результатом, а не закрытием карточки.

F258 добавляет самостоятельный summary_status к существующему sync/Codable
и сохраняет transcript_available отдельно от доступности страницы. Старые
очереди читаются благодаря optional полям. Итоги используют существующие
slot/attempt/source/media/revision, без новых таблиц. Event UUID/time для native
recap не нужны при отсутствии такого канала; не добавлять их ради будущего.
Проверенный notification-context содержит только user_id/workspace_id и no-store.

T023: существующий MeetingListItem получает optional summary_status из той же
summary projection; список не угадывает полную готовность по наличию stored_output.
Partial означает доступный результат с явно указанными ограничениями. Нового
хранения, фоновой обработки или разрешений нет; старые ответы без поля читаются.
