## Изменение

В существующем `activation_operator.py` штатный Docker Compose читает только
закреплённый источник с `--env-file /dev/null --no-interpolate
--no-env-resolution --no-path-resolution`; допустимый размер результата 2 МиБ.
Среда оператора, `.env` и содержимое `env_file` не становятся фактическими
настройками служб. Внешний ответ по-прежнему содержит только четыре поля;
конфигурация, пути и значения окружения в него не выводятся.

Для всех фактически присутствующих служб, включая остановленные инициализаторы,
сверяются argv/рабочий каталог/пользователь, исполняющие переменные окружения,
права и пространства имён, ограничения CPU/памяти/процессов, закрытые порты,
команда и параметры проверки здоровья, журналирование, временная файловая
система и подключения файлов/томов. Списки argv не разбиваются повторно;
каждый разрешённый `$` происходит из пары `$$` закреплённого источника.
Пустые команды обрабатываются по доказанной семантике Docker Engine merge.

Logical secret связан с одним canonical Source и полной идентичностью файла
у всех потребителей, включая aliases. Проверяются ancestry/права/ACL/обычный
файл с единственной ссылкой; содержимое ненастроенных секретов не читается.
Статический file связан с исходной декларацией; динамический допускается только
в предусмотренном целом `${NAME:-DEFAULT}`. Сгенерированное Compose поле `name`
допускается только в точном виде `twobrain-rec_<logical secret>`.

Именованный том проверяется отдельным read-only `docker volume inspect`:
точные name/Source/Mountpoint, driver=local, scope=local, пустые options,
защищённые ancestors и идентичность каталога. Это исключает заранее созданный
local volume с `type=none,o=bind,device=...`; содержимое тома этим не проверяется.
`AutoRemove=true` запрещён до остановки, RestartPolicy совпадает с source.

Политика выполняется до Settings и до любых мутаций. Перед итогом заново
читаются модель и параметры томов, заново проверяются secret registry и
метаданные путей; общий digest обязан совпасть. Прежние проверки runtime,
PID, release, source, сокета и Settings сохраняются.

## Проверки

- До реализации: 48 новых тестов дали RED на отсутствующей policy-функции.
  Для нового аргумента volumes 17 случаев дали TypeError старой сигнатуры;
  это RED контракта, а не доказательство 17 причинных обходов. Отдельно
  прежняя policy принимала AutoRemove/restart retry: 2 причинных RED-случая.
- Общий профиль operator/bootstrap/fence/provider config/config validation:
  **433 passed, 6 skipped**, два прежних предупреждения. Linux-пропуски
  отдельно отработаны соответствующими нативными проверками этой и предыдущей
  стадии Settings; это не означает выполнение всей рабочей T113.
- На настоящем Linux в собственном временном томе: **69 passed** текущих
  policy-тестов, без подмены ancestry/ACL. В Linux-варианте pytest используются
  обычные синтетические dictionaries для модели и Engine metadata.
- Финальная функция проверена на настоящих Config/HostConfig/Mounts двух
  собственных контейнеров, созданных Compose с точными multiline entrypoint
  из `rec-minio-init` и `rec-temporal`; скрипты не запускались. Ограничения,
  loopback-порт, healthcheck, tmpfs и именованный том приняли допуск; подмены
  argv/healthcheck/имени тома/tmpfs отвергнуты. Изменение каталога тома изменило
  digest. Подключения секретов и статических файлов в окончательной настоящей
  inspect-пробе не использовались; их матрица проверена отдельно на Linux.
- При промежуточной пробе общая папка Mac через Docker Desktop не предоставила
  listxattr для каталога (`EOPNOTSUPP`). Отказ сохранён; проверка ACL не ослаблена.
  Каталоги внутри daemon root также требуют rslave/rshared, поэтому не выданы
  за допустимые rprivate bind. Окончательная inspect-проба использовала свой
  настоящий Linux named volume. Предыдущая реальная file-bind проба Settings
  остаётся отдельным доказательством, а не приёмкой всей новой policy.
- Штатный Compose config с намеренно неверными host/.env/env_file значениями
  дал ту же исходную модель; runtime-команды при этом не выполнялись.
- Ruff с прежним исключением E721 для строгих проверок типов; whitespace и
  проверки управления разработкой проверяются перед сохранением.

Все свои контейнеры, сети, тома, временные файлы и копии тестовых зависимостей
удалены. Готовый образ использовался без build/pull; candidate source подключался
для проверки функции. GRAF Dev, рабочий сервис, права сервера и данные не менялись.
