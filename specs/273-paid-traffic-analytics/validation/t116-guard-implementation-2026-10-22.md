## Реализация

Существующий guard использует полный сборщик и оценку ёмкости. Под общим lock
он сначала сохраняет устойчивое защитное состояние с fsync, затем меняет
переключатели и читает действующую конфигурацию контейнера API. Ошибка применения
или чтения повторяется до подтверждённой защиты; исчезновение причины не включает
измерение. Успешная защита не перезапускает API повторно. Ручное восстановление
требует свежего полного замера, принятого бюджета, подтверждений и readback.
API читает состояние через read-only bind; каталог 2750 и файлы 0640 используют
существующую группу runtime. Ошибки состояния и оповещения не дают ложный успех.
Новые службы и зависимости не добавлены.
