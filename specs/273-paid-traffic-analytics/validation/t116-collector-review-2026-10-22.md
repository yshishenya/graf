## Блокирующие дефекты v1

### C1 — штатная прослеживаемая ссылка ClickHouse делает весь замер incomplete (HIGH)

В первоначальном helper `allocated()` отвергает каждый `S_ISLNK`, даже если
это штатный `data/table → ../store/part` внутри одного классифицированного
тома. Принятый контракт требует отказа для непрослеживаемой ссылки, а не для
любого внутреннего alias. Небольшая локальная проба с такой структурой дала
`Incomplete: unresolved_link_or_nested_filesystem`. На типичной структуре
ClickHouse это блокирует полный замер всех классов.

Минимум: считать выделенные блоки самой ссылки один раз; разрешить только
успешно разрешённую цель внутри уже классифицированных корней того же класса,
не обходить её второй раз (цель и так охвачена обходом корней); сохранять
отказ для dangling/cycle/outside/cross-class/nested unknown. Inode/device
дедупликация не должна считать target повторно. Нужен исполняемый тест штатной
внутренней ссылки и отказов выхода/неизвестной цели. Новая служба не нужна.

### C2 — общий filesystem пробуется много раз, поздний низкий запас отбрасывается (MEDIUM)

В `main()` цикл вызывает `filesystem(path)` для каждого корня плюс
analytics_path и host. Дедупликация через `resources.setdefault(identity, fs)`
происходит **после** statvfs, так что получаются несколько замеров одного
ресурса, а сохраняется первый. Это расходится с явным требованием «один общий
ресурс — один замер» и может отбросить уже полученный достоверный низкий запас.

Локальная управляемая проба пяти путей одного FS вернула5 вызовов; первый
available=500/1000, последующие50/1000. Collector записал complete с500,
отбросив более поздние50. Это не утверждение, что рабочий диск так менялся:
проба проверяет детерминированную логику обработки известных результатов.

Минимум: определить ресурс по метаданным пути и кэшировать одну statvfs-выборку
на идентичность ресурса, объединяя только роли. Разные FS сохраняют отдельные
выборки. Ошибка определения ресурса остаётся incomplete; известный низкий запас
не теряется из-за ошибки другого пути. Проверить число реальных probes и
объединение analytics/host, а не только конечную длину списка resources.

### C3 — повреждённые classes в суточном anchor могут вернуть measured (MEDIUM)

`measured_growth()` проверяет `anchor.classes` только **после** early return
для интервала<24часов. Если у корректного сохранённого anchor с last_growth
заменить classes на[], следующий минутный запуск возвращает cached
`result=measured`, а не incomplete. Существующий тест того же invalid classes
на интервале>24часов не покрывает этот путь.

Локальная проба: два корректных samples на100000/186400 сформировали
last_growth; при classes=[] и now186401 результат всё ещё measured. Минимум:
валидировать нужную схему anchor до любого использования/возврата cached
измерения. Добавить проверку повреждённого anchor как до24часов, так и после.
Это не требует нового состояния или отдельного сервиса.

## Что в v1 соответствует направлению требований

- Выделенные блоки `st_blocks×512`, directories/files, hardlink identity,
  same-class дубликаты и cross-class overlap; sparse file не принимается за
  логический размер. Реальные отдельные архивные копии и staging/failed
  попадают в обычный физический обход.
- Отдельные inventories service/destination и relations; detached volumes
  не забыты. Required missing/unknown/read errors закрывают полноту, optional
  отсутствие имеет отдельный статус. Runtime-классификация не читает payload.
- PostgreSQL recursive catalog query включает индексы, TOAST и наследуемые
  relations; файловые families включают forks/segments, а таблицы продукта и
  общий WAL/каталоги не складываются с аналитическими relations. Tablespaces
  за пределами подтверждённого отображения дают incomplete.
- Суточный anchor сохраняется при промежуточных вызовах; отрицательные разности
  не обнуляются, live/archive rates раздельны, первый sample не выдумывает рост.
  Events query делает count без payload; неизвестный/нулевой denominator не
  создаёт выдуманное per1000. Проекции unknown до измеренного роста.
- Командные ошибки/пути не печатаются в receipts, private paths хешируются
  внутри inventory_version, поля JSON/вывода — метаданные. SQL не читает строки
  встреч/событий, кроме агрегатного count по timestamp в ClickHouse.
- Wrapper вызывает соседний helper. Baseline задаёт совместную установку
  wrapper/helper/inventories и явный `GRAF_POSTHOG_STORAGE_INVENTORY_DIR` для
  установленного вызова. Эта инструкция осуществима; доказательства применения
  на сервере нет. Подключение guard к установленному collector — отдельный
  будущий срез, не текущий дефект непредъявленной реализации guard.
