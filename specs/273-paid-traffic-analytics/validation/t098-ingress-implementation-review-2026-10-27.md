## Соответствие кандидата согласованному решению

- Выделенный TLS-приёмник ГРАФ использует только loopback `10445` с
  `proxy_protocol`; старого `10444` в итоговом rec-блоке нет. Пустой источник
  из `PROXY UNKNOWN` отклоняется с 400, несовпадающий Host — с 421.
- В обоих фактических местах передачи запросов API адрес из PROXY заменяет
  входные `X-Forwarded-For` и `X-Real-IP`; схема передаётся как HTTPS. HTTP
  realip не включается. Логи не переводятся на новый адрес посетителя.
- Новый stream include направляет SNI ГРАФ в выделенный приёмник, а прежние
  default/special — через два loopback relay, принимающих и снимающих PROXY.
  Установленные публичные bind/upstream/log и их реальный контекст должны
  проверяться отдельно при рабочем переходе. Include не является установщиком.
- Платёжный вход 8443, ограничения его метода/источника и существующие правила
  частной ссылки не меняются. Отдельная замена итогового rec-файла во время
  перехода по-прежнему недопустима: нужен согласованный порядок поколений.
- Dockerfile, compose, пример production env и существующие модули auth audit,
  ограничения частоты и журналирования этим кандидатом не меняются.
- Восстановленный источник доступен существующим потребителям `request.client`:
  в том числе auth audit хранит существующий `actor_ip_hash`, а ограничение
  частоты использует существующие хэши областей. Неверно утверждать, что источник
  используется только аналитикой. Новый семипольный writer исходного IP этим
  кандидатом не включается; T110/T111 остаются отдельными условиями.

Изменённый compose-тест проверяет оба API proxy-location, запрет прежнего
приёмника и HTTP realip, ограничения приёмника и сохранение 8443. Это проверка
структуры текста; сетевое поведение подтверждает отдельный изолированный прогон.

## Обнаруженный и исправленный дефект

**P2, закрыт на текущем содержимом:** прежняя очистка проверочного сценария
завершала только master nginx. При принудительном завершении master его рабочие
процессы могли сохранить слушающие сокеты, хотя `process.poll()` уже показывал
успех очистки. Успешный обычный прогон не покрывал эту ветвь отказа.

Исполнитель добавил отдельную сессию/группу процесса, ограниченные по времени
TERM и KILL только собственной группы, проверку живых участников группы через
`/proc` и обязательную отрицательную пробу с дочерним процессом, игнорирующим
TERM. Код перечитан целиком; текущий receipt содержит
`forced_process_group_cleanup=true`, `isolated_process_group_stopped=true` и
`temporary_directory_removed=true`, а три его входных хэша совпали с кандидатом.
Установленный или чужой nginx не является целью сигналов.
