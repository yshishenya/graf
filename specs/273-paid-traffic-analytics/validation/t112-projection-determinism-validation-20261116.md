неизменность всех исторических выборов при совпадениях не заявляется.
Запросы используются существующими читателями; отдельный граф запросов
для предварительной проверки не добавлен.

## Дополнительные SQL-свидетельства для следующего guard

Два самостоятельных синтетических опыта PostgreSQL17.12 завершены EXIT0.
Контейнеры network-none/tmpfs, без опубликованных портов и рабочих данных;
удаление каждого подтверждено. Это испытания SQL-свойств, а не отсутствующей
защиты приложения.

- Один RR snapshot: date-only LIMIT50 дал разные наборы при Seq/Index
  и 350/262495 исходных байт; date+id дал одинаковые наборы.
  JSON с пробелами: 262152 исходных байта против15 после нормализации;
  повторные ключи:264007 против15. Журнал envelope-probe SHA-256
  `0ca6bde69f9039af466762ba67d25eb3720c9cf23d97eb757916f1c8176fc893`.
- Исходный JSON93 байта с глубоким ранним значением повторного ключа:
  ограниченный обход достигает depth33, нормализованный JSON показывает1.
  Другой JSON36007 байт:6002 узла до нормализации и2 после неё.
  Журнал json-shape-probe SHA-256
  `5dd8bdc5e83b7d5dbeee04f9c4338e939b4a72858ad5889a0781698db76cd79f`.

Эти результаты подтверждают необходимость сначала ограничить исходные
JSON::text bytes, затем исходную глубину и число узлов с сохранением
повторных ключей; одного to_jsonb недостаточно.
