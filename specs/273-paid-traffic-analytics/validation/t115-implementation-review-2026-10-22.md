## Миграция и конкурентная запись

Migration добавочная, с предыдущей ревизией
`0104_summary_share_scope_cascade`; исторические migration files не менялись.
Upgrade добавляет default `unknown` и заменяет только уникальное ограничение,
не переписывая ID/count. Серверный default позволяет прежнему writer,
не передающему регион, продолжать писать `unknown` после upgrade.

Downgrade берёт `ACCESS EXCLUSIVE` до проверки nonunknown строк и удерживает
блокировку в транзакции до изменения схемы. При наличии `ru/non_ru` выполняется
отказ; данные не сливаются и не удаляются. При одних `unknown` возвращается
прежний ключ и удаляется region. Настоящий PostgreSQL-тест проверяет сохранение
ID/count при upgrade, наращивание существующей nullable-корзины, успешный
обратный переход и неизменность данных после отказа lossy downgrade.

Отдельный PostgreSQL-тест запускает четыре конкурентных upsert одной
nullable-корзины: остаётся одна строка с count 4. Рядом сохранены малые корзины
разных регионов/часов. Сырой итог 11 даёт отчёт 4, в том числе по кампании;
фильтр будущей даты даёт 0. Reader возвращает только `ru:4`, а неправильный
регион отклоняется CHECK. Это подтверждает подавление до объединения, а не
допуск суммы малых корзин. Имеющийся тест reader проверяет обе границы даты.
