## Изменение и проверка

Штатная репетиция использует уникальные create-only БД и bucket. Очистка
удаляет только цели, создание которых завершилось успешно; общий временный
дамп заменён стандартным вводом pg_restore. Временный журнал закрыт
правами0700/0600 и удаляется. PASS появляется после успешной очистки и
отдельной проверки отсутствия обеих целей. Ошибки удаления или чтения
не превращаются в успех. Автоматический выбор копии исключает чужие типы,
ссылки, пустые и неполные комплекты.

Общий с выкладкой flock передаётся тем же файловым дескриптором дочернему
shell. Обрабатываемые сигналы передаются дочернему процессу; управляющий
процесс ждёт его завершения. После SIGKILL управляющего процесса дочерний
shell сохраняет блокировку до конца работы и очистки. Его поздний вывод
не меняет неуспешный код завершения убитого управляющего процесса.

## Поправки после ревью PR #7803

P1: четыре списка теперь ссылаются на сохранённую в Git
[самодостаточную матрицу требований](t113-rehearsal-safety-review-2026-10-28.md),
включающую все117 оснований и хеши проверенного источника. Ignored-каталог
не требуется для проверки текущего гейта. Исторический code PASS выше
не принимает обнаруженную позднее гонку создания.

P2: при HUP/INT/TERM между successful create и присвоением owned shell мог
пропустить очистку собственной цели. Теперь на этом узком интервале сигнал
сохраняет запрос остановки; после успешного create фиксируется владение и
исполняется обычная неуспешная остановка через cleanup. Неуспешный create
по-прежнему не даёт права удалять неизвестную цель. Supervisor устанавливает
обработчики до Popen, сохраняет ранний запрос и передаёт исходный сигнал
после появления child, продолжая ждать с тем же flock FD.

Добавлены15 причинных проверок: HUP/INT/TERM × DB/bucket × success/failure
и три ранних сигнала до child. На прежнем helper получены9 отказов/6PASS.
В исправленной изолированной среде все15 прошли за8,39с. Остаточная ошибка
INT первого прогона была локализована в дополнительном системном launcher,
которому тест посылал сигнал вместо supervisor. Учебная среда закрепляет
настоящий sys.executable и только безопасное окружение; системный launcher
не менялся. Обход INT→TERM и периодический wait в продуктовый helper не входят.
