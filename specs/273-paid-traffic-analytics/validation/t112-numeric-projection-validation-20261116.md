## Реализованная область

`ProjectionReadBudget.check` получает фактический Select и его параметры,
строит ограниченный cap+1 подзапрос и возвращает в Python только числовые
агрегаты. JSON измеряется как исходный UTF-8 до нормализации; JSONB учитывает
байт версии двоичного транспорта. Text/binary измеряются на стороне БД,
известные фиксированные scalar formats имеют консервативную оценку.
Numeric после исправления N1 измеряется через длину
`pg_catalog.numeric_send`, без доверия унаследованным precision/scale.

После разрешённого размера отдельный рекурсивный SQL обходит исходный JSON
с сохранением повторных ключей. Глубина и число узлов ограничены cap+1.
Каждая выбранная expression/alias учитывается, включая повторные поля.
Строки/байты/узлы накапливаются в одном состоянии; неизвестный исход
навсегда закрывает экземпляр. Неизвестные формы/типы, raw SQL, TypeCoerce,
literal columns, неизвестные/квалифицированные функции, mapped relationships
и явный streaming отвергаются. SQLAlchemyError даёт общий безопасный отказ.
Исходный ORM Select компонент не выполняет и не переписывает.

Пределы сохранены: 4096 строк на Q, 16384 суммарно, 8 MiB исходных байт,
512 KiB на строку, 256 KiB на поле, depth32, nodes65536.
SQL128, общий срок и охват всех чтений этим компонентом не реализованы.

Два контрпримера N1 работают на настоящем PostgreSQL: coalesce наследует
Numeric(1,0), но возвращает 50000 цифр; семь квадратов 1000-значного числа
сохраняют Numeric(1000,0), но дают 128000 цифр. Тест сначала получает только
фактическую длину двоичного числа и подтверждает превышение 512 KiB при
22/9 повторениях поля, затем проверяет отказ компонента. Старая константа
не отказывала в обоих случаях; исправленная версия отказывает. Ещё один
положительный тест сопоставляет точную длину numeric для SQL NULL, нуля,
дроби и большой scale без загрузки значения в Python.

Raw JSON профиль различает исходный Q и намеренно нормализованный другой Q:
пробелы, раннее глубокое/многоузловое значение duplicate key не исчезают из
проверки. Проверены Unicode, SQL NULL/JSON null, cap±1 bytes/depth/nodes,
полный scalar SQL без LIMIT, суммарные строки/байты, повторные aliases,
JSONB и пустой набор. 50 свежих компиляций контролируют прежнюю CTE ошибку.
Test-only do_orm_execute перед настоящим общим get_cabinet_meeting_review
сохраняет равный model_dump() ответ. Это не проверка всей Session/HTTP.

Ранние ошибки сохранены отдельно: initial fixture literal-colon/CTE,
second/third generic compile refusal, затем исправленные helper и явные
имена CTE. Их нельзя выдавать за причинный RED отсутствующего guard.
Первый новый numeric-wire-red также упал на неверном предположении теста

После исправления fixture отдельный causal-red подтвердил coalesce;
окончательный two-red подтвердил оба требуемых DID NOT RAISE.
Эти промежуточные журналы сохранены, успешными не объявляются.

Ruff, validate-agent-context.py, validate-changelog-fragments.py и
