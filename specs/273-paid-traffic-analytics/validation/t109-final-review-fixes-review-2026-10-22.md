## Ревью двух исправлений

### Передача отдельных сроков удаления

`lost_basis_dispositions` принимает необязательную mapping `deletion_deadlines`
и передаёт её существующему `plan_processing_stop`. Helper сохраняет дату
реестра и причину отзыва. Ни режим хранения, ни возраст данных, ни `now`
не подставляются вместо отдельного срока. Прежние callers без mapping
по-прежнему получают stopped/incomplete plan; это обратная совместимость,
а не разрешение его исполнить.

Проверены все найденные callers в source/tests/docs. В source helper имеет
одну реализацию; прямого нового рабочего executor/caller не добавлено.
Integration `_plan_for` теперь читает настоящий реестр и идёт через helper,
вместо обхода через прямой planner. Все категории получают переданный срок;
missing/partial оставляет общий deadline=None. `apply_basis_loss_disposition`
проверяет это до первого SQL. Внешний provider request остаётся с нулём
локально удалённых строк и не выдаётся за подтверждённое удаление провайдера.

### Раскрытие зарегистрированным пользователям и provider config

API `/telemetry-gate/disclosure` и cabinet context уже используют один
`build_required_disclosure`; builder теперь показывает canonical until_decision,
null вместо minimum=90, отдельное удаление и provider-controlled Yandex.
Default ProductTelemetryGateRecord, Settings, compose и example согласованы
на `2026-10-22.1`. Provider config получает policy из canonical `retention_rule`
вместо отдельного age setting. Старое поле/validator/env min90 удалены; поиск
runtime consumers не выявил оставшихся обращений к удалённому Settings-полю.
Сохранены выключенные defaults, различение прямого desktop egress и запреты
на содержимое/секреты.

Смена default copy version не доказывает повторное принятие всеми ранее
зарегистрированными пользователями. Существующие state-only gates и
server/offline writer coverage не исправляются этим diff и остаются T106.
Технический disclosure не является опубликованным юридическим подтверждением.
