## Что изменилось

`result_visibility.py` и существующий renderer переиспользуют один выбор
transcript rows, порядка разделов итогов, доступных items, разделов/частей
протокола и исходного текста его строки. `result_view_text_blocks()` создаёт
кандидата для отдельного тела строки, не для заголовка или всей панели.
Так скрытый текст внутри закрытого `<details>` не становится показом только
из-за видимого заголовка; фактическую видимость ещё должен проверить observer.

Для кандидата сохраняется исходный непустой текст, включая пробелы. `strip()`
используется только для исключения пустого тела. Заголовок встречи/темы,
имена спикеров, ответственные, сроки, source controls, динамические элементы,
пустые сообщения и error/placeholder не входят в digest.

Digest — SHA-256 канонического UTF-8 JSON с `ensure_ascii=False`, `sort_keys`
и separators `(',', ':')`: тип, собственные result ID/version, outcome-set ID
при наличии и упорядоченные исходные тексты. JSON и тексты живут только в
памяти текущего вызова; proof содержит digest, без текста.

`load_result_view_bindings()` принимает свежую разрешённую проекцию общего
`get_cabinet_meeting_review()`. Для transcript используется единственный точный
ID выбранных rows; смешанный/неизвестный ID не даёт этой ветви подтверждения.
Для итогов читается конкретный `review.template.outcome_set_id` с его
собственным `processing_result_id`, workspace/meeting/revision, активным
доступным состоянием и deletion epoch. Нет запроса нового «самого свежего»
итога и нет замены отсутствующего итога расшифровкой.

Обе ветви используют прежнюю полную проверку нового source/audit/ingest,
общую готовность результата и собственный result version. Manual upload
сохраняет capture=false. Действующий principal/session/access, locks, T113
readiness и бюджеты остаются обязанностью будущего защищённого вызывающего
пути; переданная проекция или дата сами по себе не разрешают admission.
Новая загрузка bindings не пишет БД и не создаёт событий.

## Что остаётся открытым

Это не реальное подтверждение показа: issuance в невидимые атрибуты,
browser/native visibility, защищённые оба POST, свежие проверки после locks,
бюджеты и атомарная пара через общую T113 ещё не подключены. Binding loader
вызывается только тестами; renderer уже использует общие чистые selectors.
Ни snapshot, ни source fact, ни HMAC не заменяют актуальные auth/access/fences.
Полный причинный DB/browser/Swift/failure профиль и converge ещё нужны.

Настоящие `activation_recovery_unverified` и client `trigger_unverified`
сохраняются. Нового PR/CI/merge/Full/CD, рабочего включения, T0 или публикации
нет. Тексты и вёрстка сохранены; рабочие почта/Postal, nginx/DNS/Compose,
службы, очереди и резервные копии не менялись. T112/T113/#7698 и коммерческая
цель остаются открытыми. Это разработка измерения, не новый трафик/клиент.
