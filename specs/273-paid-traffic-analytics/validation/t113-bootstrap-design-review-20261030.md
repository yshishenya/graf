## Решение и границы

**SCOPED PASS проекта для изолированной реализации и учебных проверок.**
Один `infra/scripts/activation-operator.py` со стандартной библиотекой Python,
единственным `--preflight`, закреплённой временной средой и существующим
deployment lock достаточен для этого среза. Завершение после проверки среды
обязательно сообщает `HOLD/full_preflight_not_implemented`; оно не может
выдать полную готовность. Изменять продуктовый `activation_operator.py` ради
пустого вызываемого режима сейчас не требуется.

Это разрешение написать и проверить ограниченную подготовку среды. Оно не
принимает её будущий код, рабочий запуск от root, весь preflight, передачу
унаследованного FD, initial/actual restore, готовность измерения или выпуск.
Рабочий запуск остаётся **HOLD** до подтверждения владельцем доверия к
существующему участнику группы установки UID1003 и всех обычных ворот выпуска.
Само это ревью не является таким подтверждением.

работать от `twobrain`. Требования0700/0600 этим проектом не ослабляются.

## Разбор алгоритма и совместимость

1. **Единственная существующая блокировка.** Предположение, что произвольный
   `git --git-path` всегда указывает в common-dir, неверно для linked worktree:
   локальное чтение показало `.git/worktrees/crisp4/twobrain-rec-deploy.lock`.
   Конкретный проект устраняет неоднозначность: принимает только основной
   canonical root с обычным `.git`, совпадающими gitdir/common-dir и точным
   shell lock; linked worktree отклоняется. Существующий inode открывается
   без create/truncate/chmod, проверяется до и после EX|NB и удерживается до
   завершения детей и очистки. Открытие shell через `>` само по себе inode
   не заменяет, поэтому flock остаётся общим. Неизвестная замена закрывает путь.

2. **Источник и установка.** Проверка HEAD40hex, чистоты отслеживаемых файлов
   и байтов собственного launcher связывает работу с принятой версией.
   `git archive` точного commit, запрет ссылок/выхода из каталога, собственный
   temp0700 и non-editable install исключают импорт из движущегося checkout.
   Frozen runtime без dev/default groups и скачивания Python повторяет ранее
   исследованный путь. Manifest каждого отслеживаемого файла установленного
   пакета до/после и фактический import в site-packages дают нужную проверку
   исходников. Это не обещание защиты от намеренных действий того же root.

3. **Сам запуск подготовки тоже должен быть изолирован.** Указанный в проекте
   `venv Python -I` применяется к проверке пакета. В реализации начальный
   stdlib launcher также запускается системным Python с `-I`; запуск без
   изоляции должен быть отклонён до чтения Git и вызова детей. Очищенное
   окружение применяется ко всем внешним инструментам, включая Git: не
   наследуются `GIT_DIR`, `GIT_WORK_TREE`, `GIT_CONFIG_*`, `PYTHON*`, `UV*`,
   `VIRTUAL_ENV`, `CONDA*`, влияющие на выбор источника/интерпретатора/установку.
   Пути системных инструментов не выбираются произвольным caller PATH.
   Это конкретизация обещания доверенной закреплённой среды, без нового
   сервиса, настройки или пользовательского режима.

4. **Ограниченный исход.** Пока нет полного preflight, наличие Python/package
   manifest не доказывает image/source/UID/config/DB/role/resource/access
   bindings. Проект прямо запрещает DB/Docker/product calls, stop/revoke,
   provisioning, T0/ready и supplied-pass/URL/SQL/commands. Metadata-only HOLD
   после bootstrap не может открыть измерение или продолжить восстановление.

5. **Отмена и очистка.** Конечный предел установки, собственная process group,
   ожидание/reap до освобождения lock и удаления temp, сохранение этого
   порядка при повторных сигналах соответствуют принятому владению ресурсами.
   Ошибка очистки остаётся HOLD. Права возвращаются только своим временным
   каталогам; чужие копии, данные, тома и образы не затрагиваются.

Новых противоречий spec/plan/контрактам в этой ограниченной стадии не найдено.
Требование прежней маркетинговой истории до T0 не возвращается. Наличие
проверенной среды не подменяет нынешние открытые проверки восстановления,
ресурсов, оснований и непрерывности после единственной T0.
