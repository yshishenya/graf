## Изменение

Один внутренний async context manager в прежнем activation_operator проверяет
ровно два существующих файла service/timer. Удерживаются no-follow read-only
FD; root:root0644, regular single-link, размер1–65536, отсутствие ACL, root
предки без записи группе/остальным. Проверки identity/bytes/предков и равенства
закреплённому источнику повторяются до/после каждого property await и при выходе.
Новый общий сканер, служба и зависимости не добавляются.

Фиксированный native busctl читает только свойства этих units. Строгие type/data,
запрет дубликатов JSON, размер65536 и отсутствие подмены адреса системной шины
проверяются отдельно. Canonical Id/Names/FragmentPath, loaded/static/enabled,
no reload/dropins/SourcePath/transient и допустимые active/sub пары не выводятся
из равенства исходника. Timer проверяет интервалы, точность1с, нулевую случайную
задержку и все перечисленные в проекте свойства. Service проверяет root/oneshot,
обе формы ExecStart и ExecStartEx с flags=[], отсутствие дополнительных команд,
окружения и mounts, прежний env-file и sandbox/write paths.

Семь dynamic history полей строго целые и не попадают в итоговый отпечаток;
absolute next ticks строго неотрицательные целые и тоже исключены.
Конфигурация перечитывается после yield. Штатный tick, порядок write paths и
завершение oneshot не считаются drift. Runtime удерживает guard context вокруг
DB и всех последующих ожиданий, возвращает успех только после успешного выхода
из всех contexts; результат включает только guard_units_sha256. Общие
operations access/config digests не переопределяются.

В существующий timer добавлена ровно AccuracySec=1s. Интервал1мин и предел
свежести строго менее120с сохранены. Это убирает намеренную минутную задержку
объединения пробуждений, но не обещает исполнения в реальном времени.
Runbook больше не предлагает drop-in как допустимый путь нынешнего preflight.

## Проверки

RED до source: contract отказал на отсутствии AccuracySec; Linux good отказал
на отсутствии helper; integration good отказал на входе DB без guard context.
RED относится к сохранённым байтам тогдашних тестов, не к конечным тестам.
Журналы `.dev/growth/t113-guard-units-{contract,linux,integration}-red-20261030.*`.

Конечный unit operator на Mac: **287PASS/96LinuxSKIP/2 прежних warnings**.
Linux root на прежнем image
`sha256:37d27de327e5876b4c890a7e6c3dd98ab8fd89476180d6deb42d262411c1ccbe`:
новые cases **59PASS/0SKIP**, вместе с прежними bound-files/settings/runtime
**167PASS/0SKIP**. Эти наборы пересекаются и не складываются.
Source/tests/deps read-only, сеть отключена, Docker socket не передан,
одноразовый volume с actual POSIX ACL и штатный --rm. Временные копии pytest
удалены TemporaryDirectory. Первая попытка новых cases дала58PASS/1FAIL из-за
отсутствия setfacl; тест использует прежний stdlib os.setxattr/struct способ,
а не добавляет пакет. Fixture mode0644 после ACL проверен.

Проверены file/path/source/ancestor/owner/group/mode/link/ACL/size drift;
malformed/duplicate/extra JSON, signatures, strict bool/int, flags/argv/history,
extra commands/env/dropins/calendar/delay, disabled/stopped/failed и exit drift.
Положительные tick и running→inactive проходят. Integration проверяет
удержание контекста до выхода DB, его поздний отказ и digest результата.
Cancellation прерывает именно property wait, запускает реальный owned child
через прежний _command, отменяет дважды и подтверждает reap. Это доказательство
владения child, не настоящий зависший запрос systemd.

На существующем astraglobal systemd259 конечные временные source units
проверены `systemd-analyze verify`: exit0. Есть сторонние warnings существующих
xfs units об удалённом CPUAccounting и недоступном для чтения hermes unit;
ошибок наших units не выдано. Временный каталог удалён; install/load/start/
reload не выполнялись. Это проверка source формата, не installed proof GRAF.
Native D-Bus JSON signatures отдельно наблюдались на безопасных системных units
до кода; ни приватные environments, ни данные GRAF не запрашивались.

Конечные полные contract alerting/retention: **222PASS/2 прежних warnings**.
Ruff, Spec Kit governance, development-process, changelog-fragments и
whitespace прошли. Independent code review обязателен до коммита.
Журналы/runner/контрольные суммы сохраняются ignored в
`.dev/growth/t113-guard-units-*`. Полный PG-профиль прежнего этапа не
приписывается этим байтам: DB reader/SQL/схема не менялись, удержание нового
внешнего контекста проверено полным unit operator и Linux integration fake.

## Остаток

Это guard-unit часть installed jobs. Полный host/cron/purge/retention каталог,
shell graf-local, local_only resource policy и верхние initial/backup/verify/
actual-restore/resume, CD/rollback/daily и рабочая приёмка ещё открыты.
Существующий script при отсутствии PostHog containers даёт
posthog_containers_missing; этот шаг его не меняет и не объявляет local_only
готовым. full_preflight_not_implemented и activation_recovery_unverified
сохранены. T113/#7804/T112 и AC01–AC06 не закрываются. Рабочих T0/ready,
включения аналитики/IP/получателей, выпуска, Dev или внешних публикаций нет.
Технические проверки не являются клиентским трафиком или продажами.
