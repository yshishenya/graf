# T113: согласованный исходный комплект копии — 29.10.2026

Полоса: `high-risk-product`, существующая F273/T113. Refs #7804.
Принят только участок создания копии. T113, первый локальный период,
аналитика и коммерческие критерии остаются открытыми.

## Изменение

Существующий `backup-rec-stack.sh` выполняет штатные `psql` и `pg_dump`
в одной экспортированной точке PostgreSQL. Транзакция READ ONLY /
REPEATABLE READ удерживается до завершения custom dump, schema-only dump
и подсчётов. Оба дампа получают один `--snapshot`. Полная maintenance-роль
и `row_security=off` исключают незаметное влияние фильтрации строк.

К прежнему `postgres.dump` добавлены закрытые `schema.sql`, `inventory.jsonl`
и `checksums.sha256`. Метаданные включают безопасные характеристики ролей
и membership, relations/owners/ACL/RLS, constraints, policies, точные количества
строк несистемных обычных, partitioned и materialized relations, количества
по двум состояниям получателей ledger. Пароли, account IDs, события и содержание
встреч не выбираются. Неизвестное состояние отклоняется до вывода агрегатов.
Сам комплект остаётся закрытым; его содержимое в Git не переносится.

После Docker copy проверяются непустота, строгий состав manifest и SHA-256
скопированных байтов. Отказ snapshot/dump/schema/copy/checksum запрещает PASS.
Прежние create-only цель, права 0700/0600, уникальный staging, зеркало объектов
и очистка перед PASS сохранены. Роли не восстанавливаются обычным pg_dump.

## Причинные проверки

Настоящий PostgreSQL 17, уже установленный образ `postgres:17-alpine`,
`--pull=never`, `--network=none`, без опубликованных портов и host mounts.
Данные вымышленные. Созданные тестом контейнеры и их тома удаляются.

- После экспорта снимка другое соединение добавляет identity: в live DB 2,
  в исходных подсчётах и настоящем восстановлении по 1.
- Отрицательный контроль убирает только `--snapshot`: при том же порядке
  операций подсчёт остаётся 1, восстановленная DB содержит 2. Проверка
  действительно различает общий и независимые снимки.
- Ограниченная роль видит 0 строк ledger, исходный полный подсчёт — 1.
- Неправильная DB, роль без полного доступа, отказ custom dump и schema dump
  дают ненулевой возврат и не создают manifest.
- Подставная Docker-обвязка проверяет повреждение скопированного inventory,
  пустой inventory и отказ snapshot, прежние права, cleanup и чужие цели.

Первый настоящий отрицательный прогон обнаружил, что PostgreSQL 17 игнорирует
аргумент `\quit 1` и возвращает 0. Вместо него используется статическая SQL
ошибка `DO/RAISE EXCEPTION` с `ON_ERROR_STOP`; отрицательные случаи повторены.

Команды профильной проверки:

```sh
python -m pytest -q apps/server/tests/integration/test_deployment_backup_snapshot.py apps/server/tests/integration/test_deployment_backup_restore_rehearsal.py apps/server/tests/integration/test_deployment_restore_safety.py
python -m pytest -q apps/server/tests/integration/test_deployment_backup_snapshot.py
```

Объединённый профиль до добавления отрицательного контроля без `--snapshot`:
**64 PASS, 1 прежнее предупреждение, 57,28 с**. Последняя версия native-профиля:
**6 PASS, 1 прежнее предупреждение, 9,41 с**. Это разные запуски, не один прогон
из 65 проверок. Ruff двух затронутых тестов, `sh -n` и `git diff --check` — PASS.

## Сходимость и границы

Срез покрывает исходную согласованную точку и проверку переноса файлов по
FR-025/034/035/036/048/049, operations §Приёмка первого локального периода
и существующей T113. Новых самостоятельных задач внутри среза не обнаружено.
Полная F273 не сошлась с требованиями; `tasks.md` и #7804 остаются открытыми.

Следующий обязательный участок той же T113: сверка полной восстановленной
GRAF schema/roles/settings/RLS/unique/FK/immutable, checksum/source/runtime,
количеств и состояний; карантин обоих получателей; повтор точных удалений
и проверка пропуска; проверенная очистка. Далее — защищённые readiness/fence,
`local_only`, обе admission-ветви, общий product drain при actual restore и T112.

Контрольные суммы сейчас охватывают три PostgreSQL-файла, не зеркало объектов.
Малый учебный schema не заменяет полный migration-профиль. `backup_result=pass`
не открывает writer. Рабочие аналитика, IP и получатели этим изменением
не включаются. Установка helper, exact-SHA PR gates и выпуск требуют отдельной
проверки; результаты прежнего выпуска на новый код не переносятся.
