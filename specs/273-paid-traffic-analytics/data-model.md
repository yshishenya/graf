# Phase 1 Data Model: Готовность аналитики к платному трафику

Модель описывает сущности трёх уровней измерения и инфраструктуры готовности.
Поля даны как контракт, а не как готовая схема: точные имена колонок и типы
определяются на этапе реализации с обязательным сохранением правил проверки.

## Правило, общее для всей модели

**Ни одна сущность уровня 1 не содержит идентификаторов.** Под идентификатором
понимается любое значение, которое остаётся стабильным между визитами или
позволяет отличить один визит от другого: адрес устройства, идентификатор
сессии, отпечаток устройства, строка пользовательского агента, постоянная
cookie, псевдоним из `product_analytics/identity.py`.

Сущности уровня 2 содержат псевдонимы и обрабатываются на основании договора.
Сущности уровня 3 существуют только при полученном согласии.

## Уровень 1 — обезличенный агрегат

### Обезличенный агрегат страницы

Хранилище: PostgreSQL. Одна строка на сочетание измерений; запись выполняется
вставкой-обновлением по ключу.

| Поле | Смысл | Правило |
| --- | --- | --- |
| `bucket_date` | Дата корзины | Обязательное |
| `bucket_hour` | Час корзины или пусто для суточной корзины | Необязательное |
| `surface` | Имя публичной поверхности | Обязательное, только из известного перечня |
| `landing_path` | Посадочная страница визита | Обязательное, только из перечня публичных маршрутов |
| `source` | Источник кампании | Нормализованное значение или пусто |
| `medium` | Канал | Нормализованное значение или пусто |
| `campaign` | Название кампании | Нормализованное значение или пусто |
| `content` | Объявление | Нормализованное значение или пусто |
| `term` | Ключевое слово | Нормализованное значение или пусто |
| `device_class` | Класс устройства крупно | Только `desktop`, `mobile`, `tablet`, `unknown` |
| `referrer_category` | Категория источника перехода | Только из известного перечня |
| `visits` | Число визитов в корзине | Целое, увеличивается |

**Правила проверки:**

- Запрещены колонки под адрес устройства, идентификатор сессии, строку
  пользовательского агента, отпечаток устройства и любые псевдонимы.
- Значения меток кампании приходят из адреса страницы и потому управляются
  извне. Обязательны ограничение длины, разрешённый набор символов и отбрасывание
  значений, не прошедших нормализацию. Метка, похожая на адрес электронной почты,
  телефон или имя, не сохраняется.
- Класс устройства вычисляется при обработке запроса и сохраняется только
  крупной категорией; исходная строка пользовательского агента не сохраняется
  нигде.

**Почему это не персональные данные:** определяемого лица в записи не остаётся —
нет ни одного значения, по которому визит можно отличить от другого или связать
с человеком. Основание уровня 1 — именно это, а не толкование пункта 9 части 1
статьи 6 152-ФЗ.

## Уровень 2 — атрибуция и данные своих пользователей

### Атрибуция визита

Хранилище: сессия визита на клиенте, серверная запись создаётся при передаче
меток с формой. Срок жизни — не более 90 дней, после чего запись непригодна.

| Поле | Смысл | Правило |
| --- | --- | --- |
| `attribution_ref` | Непрозрачная ссылка на запись | Не используется для слежения между визитами |
| `source`, `medium`, `campaign`, `content`, `term` | Метки кампании | Нормализованные |
| `yclid` | Идентификатор клика Яндекс.Директа | Только при наличии |
| `landing_path` | Посадочная страница | Из перечня публичных маршрутов |
| `first_seen_at` | Начало визита | Обязательное |
| `expires_at` | Конец окна атрибуции | `first_seen_at` + 90 дней |

**Правила проверки:** ссылка не должна быть стабильной между визитами;
`yclid` не передаётся в рекламную платформу без подтверждённого основания
(FR-028).

### Атрибут привлечения клиента

Хранилище: PostgreSQL, привязка к аккаунту. Создаётся в момент регистрации из
меток, переданных формой.

| Поле | Смысл | Правило |
| --- | --- | --- |
| `account_id` | Аккаунт | Обязательное, связь с существующей моделью |
| `source`, `medium`, `campaign`, `content`, `term` | Метки кампании | Нормализованные, могут быть пустыми |
| `yclid` | Идентификатор клика | Только при наличии |
| `landing_path` | Посадочная страница | Из перечня |
| `attribution_rule` | Применённое правило | Всегда `last_non_direct_90d` |
| `attribution_confidence` | Надёжность | `linked`, `weak`, `unknown` |
| `captured_at` | Момент регистрации | Обязательное |

**Правила проверки:** отсутствие кампании даёт `unknown`, а не `direct`;
`weak` ставится, когда связка восстановлена резервным путём.

### Веха активации

Хранилище: ClickHouse внутри PostHog. Отправляется из реальных путей продукта.

| Поле | Смысл | Правило |
| --- | --- | --- |
| `event_name` | Имя вехи | Только из каталога событий |
| `distinct_id` | Псевдоним | Существующий безопасный псевдоним |
| `attribution_confidence` | Надёжность атрибуции | `linked`, `weak`, `unknown` |
| `occurred_at` | Время | Обязательное |
| Свойства события | Разрешённый набор | Проверка запрещённых полей |

**Правила проверки:** повторная отправка одной вехи не увеличивает счёт;
событие без известной кампании помечается `unknown` и не получает выдуманную
атрибуцию.

## Уровень 3 — измерение по согласию

### Состояние выбора посетителя

Хранилище: клиентское хранилище согласия, необходимое для запоминания решения.

| Поле | Смысл | Правило |
| --- | --- | --- |
| `analytics` | Решение по аналитике | `granted`, `denied`, отсутствует |
| `advertising_attribution` | Решение по рекламной атрибуции | То же |
| `behavior_replay` | Решение по записи поведения | То же |
| `decided_at` | Когда решено | Обязательное при наличии решения |
| `copy_version` | Версия текста | Обязательное |

**Правила проверки:** запись существует только для того, чтобы соблюдать
решение, и не используется как источник данных измерения. Отсутствие решения
означает «не разрешено» для всех необязательных целей.

**Переходы состояний:**

```text
нет решения ──явное разрешение──▶ granted ──отзыв──▶ denied
     │                              │                 │
     └────────── явный отказ ───────┴─────────────────┘
```

## Инфраструктура готовности

### Правило хранения

Расширяет существующий `AnalyticsRetentionRule`.

| Поле | Смысл | Правило |
| --- | --- | --- |
| `category` | Категория данных | Включая три новые: агрегат, атрибуция визита, атрибут привлечения |
| `retention_days` | Срок | 365 для событий, 1095 для агрегатов |
| `storage` | Где применяется | `clickhouse` или `postgres` |
| `enforcement` | Чем применяется | Срок жизни строк или задача по расписанию |
| `last_enforced_at` | Когда применялось | Заполняется задачей |

**Правила проверки:** срок обязателен для каждой категории; отсутствие срока
считается ошибкой конфигурации, а не «хранить бессрочно».

### Правило оповещения

| Поле | Смысл | Правило |
| --- | --- | --- |
| `condition` | Условие | Из известного перечня |
| `threshold` | Порог | Числовой |
| `scope` | Область | `analytics` или `host` |
| `channel` | Канал доставки | Внешний, независимый от сервера |
| `owner` | Ответственный | Обязательное |
| `last_fired_at` | Когда срабатывало | Заполняется при срабатывании |

**Правила проверки:** правила области `analytics` срабатывают раньше правил
области `host`; правила области `host` не отключают измерение автоматически.

### Политика резервного копирования

| Поле | Смысл | Правило |
| --- | --- | --- |
| `schedule` | Расписание | Обязательное |
| `target` | Целевое хранилище | Обязательное, вне измеряемого узла |
| `offsite` | Выгрузка за пределы сервера | Обязательная |
| `last_success_at` | Последняя удачная копия | Заполняется задачей |
| `last_verify_at` | Последняя проверка восстановления | Заполняется проверкой |
| `verify_result` | Результат проверки | Обязательное при наличии проверки |

**Правила проверки:** заявление о готовности аналитики блокируется, если копия
отсутствует или устарела, либо если проверка восстановления старше 30 дней.

### Готовность отчёта

| Поле | Смысл | Правило |
| --- | --- | --- |
| `report_id` | Отчёт | Обязательное |
| `owner` | Владелец | Обязательное |
| `freshness` | Свежесть данных | Обязательное |
| `caveats` | Обязательные оговорки | Включая долю посетителей без согласия |
| `approval_state` | Состояние одобрения | `blocked`, `ready`, `approved` |

### Одобрение запуска

| Поле | Смысл | Правило |
| --- | --- | --- |
| `kind` | Вид одобрения | Правовое, приватность, безопасность, проверка, откат, доставка |
| `approved_by` | Кто подтвердил | Обязательное |
| `approved_at` | Когда | Обязательное |
| `scope` | Что именно подтверждено | Обязательное |
| `state` | Состояние | `missing`, `recorded`, `expired` |

**Правила проверки:** разрешение платного запуска вычисляется из записей об
одобрении и не может быть выставлено техническим флагом. Правовое подтверждение
получено 2026-09-18, но запись об одобрении обязательна.
