# Quickstart: проверка готовности аналитики

Руководство по проверке на живом стенде. Описывает, что запустить и что должно
получиться, без деталей реализации.

## Что нужно заранее

- Локальный сервер продукта поднят и отвечает на публичные страницы.
- Приложение `/Applications/GRAF Dev.app` собрано через существующий
  `infra/scripts/dev-harness.sh` — для сценариев с активацией.
- Доступ к базе продукта для проверки сохранённых записей.
- Для инфраструктурных сценариев — доступ к серверу аналитики.

## Команды проверки

```sh
# Модульные и контрактные тесты измерения
cd apps/server && python -m pytest tests/unit/test_public_analytics.py \
  tests/contract/test_public_analytics_contract.py -q

# Тесты агрегата, атрибуции и хранения
cd apps/server && python -m pytest tests/unit -k "aggregate or acquisition or retention" -q

# Сквозные серверные сценарии
cd apps/server && python -m pytest tests/integration -k "analytics" -q

# Браузерные сценарии согласия и меток
cd apps/server/tests/browser && node --test ./*.cjs

# Контракты приложения
cd apps/macos && swift test --filter ProductActivationAnalyticsContractTests

# Проверка страниц
infra/scripts/validate-product-analytics-provider-pages.sh
```

## Сценарий 1 — обезличенный счёт видит всех

**Шаги:** открыть публичную страницу в чистом профиле браузера, не давая
никакого согласия. Повторить для каждой публичной страницы.

**Ожидаемо:** каждый визит попал в обезличенный агрегат. В сохранённых записях
нет адреса устройства, идентификатора сессии, строки пользовательского агента и
отпечатка устройства. Проверка выполняется разбором записей, а не чтением кода.

**Требования:** FR-009 … FR-013, SC-001, SC-002.

## Сценарий 2 — метки кампании переживают переходы

**Шаги:** открыть лендинг с метками кампании, перейти на страницу загрузки,
нажать скачивание.

**Ожидаемо:** оба шага несут ту же кампанию, объявление и ключевое слово.
Постоянная cookie слежения не появилась. В агрегате метки сохранены
нормализованными.

**Требования:** FR-014, FR-019, SC-005.

## Сценарий 3 — регистрация переносит кампанию

**Шаги:** прийти на сайт с метками, перейти к регистрации, завершить её. Затем
посмотреть запись о клиенте.

**Ожидаемо:** у записи о клиенте есть атрибут привлечения с исходной кампанией,
применённым правилом последнего непрямого источника и уровнем надёжности
`linked`.

**Требования:** FR-015, FR-017, SC-005.

## Сценарий 4 — воронка активации

**Шаги:** прийти с метками, скачать установщик, открыть приложение, подключить
аккаунт, сделать первую запись, посмотреть результат.

**Ожидаемо:** в воронке видны все шаги, каждый несёт исходную кампанию.
Повторное прохождение того же шага не удваивает счёт. Шаг, который не удалось
связать, помечен `unknown`, а не `direct`.

**Дополнительная браузерная ветвь:** новый внешний учебный аккаунт с
разрешённым источником загружает синтетический файл, дожидается обработки
и открывает непустой результат. До обработки, при одном GET/предзагрузке,
при ошибке и у пустого результата активация не появляется. Новый файл
старого разговора подходит; мигрированный старый результат и служебный
аккаунт исключены из новых внешних активаций. Выполнить повтор из второго
процесса, после перезапуска, перезагрузки страницы и со второго устройства:
все вместе дают одну первую активацию аккаунта. Доказанный pre-send сбой
допускает безопасный повтор; неоднозначная передача отмечается отдельно.
Никакого создания рабочего аккаунта или загрузки частных встреч это
описание не разрешает: сценарий исполняется на согласованном стенде.

**Требования:** FR-021 … FR-025, SC-006, SC-007.

## Сценарий 5 — отказ соблюдается

**Шаги:** дать необязательное согласие, затем отозвать его. Пройти по сайту.
Закрыть и открыть браузер, вернуться на сайт.

**Ожидаемо:** после отзыва не отправляется ни одного необязательного события.
В последующих визитах отказ по-прежнему соблюдается. Обезличенный счёт при этом
продолжает работать.

**Требования:** FR-001 … FR-007, SC-003, SC-004.

## Сценарий 6 — деградация измерения

**Частичная деградация на живом сервере:** остановить контейнеры аналитики
на изолированном стенде. Открыть публичную страницу. Дождаться срабатывания
локальных правил. Повторить с управляемой нагрузкой на сервер.

**Ожидаемо:** внешнее оповещение пришло не позднее 15 минут. Публичная страница
и продукт продолжили работать. Измерение отключилось управляемо. Всплеск
нагрузки на сайт не отключил измерение, потому что причина не в аналитике.

**Полная недоступность цели — отдельная проверка:** наблюдатель и timer работают
на существующем `astraglobal`, а не на целевом стенде. Отключить только
согласованную изолированную цель/подставленный проверочный адрес, не рабочий GRAF.
Проверки GET/TLS/HTTP/JSON идут раз в 60 секунд с timeout 10 секунд; после двух
неуспехов прямой Telegram-путь должен доставить `target_unreachable` ≤15 минут
от начала непрерывного отказа. Целевая машина не исполняет отправитель и не
участвует в доставке. Подтвердить время начала, независимый host, фактическую
доставку, отсутствие ложного PASS при timeout/ошибке канала и восстановление.
При полной потере целевого сервера продукт недоступен — этот сценарий не должен
показывать «продукт продолжил работать». Реальная учебная отправка только после
конкретного разрешения владельца; до receipt T119 открыта.

На изолированном стенде дополнительно проверить: (1) общий filesystem при
свободном месте 19% и 9%, (2) одновременное превышение бюджета аналитики и
порога общего диска, (3) разные filesystem с тревогой только продукта,
(4) неизвестный замер/бюджет. Использовать управляемые сигналы/ограниченный
временный том; не заполнять рабочий диск. Сопоставить идентичность filesystem,
сумму классов и бюджет с `contracts/operations.md`: один ресурс не удваивается,
совместные причины сохранены, защитное действие одно, продукт доступен,
история не удаляется, автоматического возобновления нет. При достаточном
запасе отдельно проверить всплеск без отключения. Метаданные результата
содержат показатели/пороги/действие, без адресов посетителей и секретных путей.

Для нагрузочной части использовать только профиль `contracts/operations.md`
§Нагрузка сайта: полный минутный baseline/классификацию, 5/20/15 минут,
5×R, отсутствие повторов и отдельную пометку инженерного 1→5→1 запроса/с,
если R неизвестен/нулевой. Отчёт содержит входную/достигнутую частоты,
статусы/ошибки и задержки по фазам, доступность и guard каждые 15 секунд,
восстановление очереди и метаданные ёмкости. Неполный/сорванный прогон не PASS.
Проверка точного p95 и профиля не заменяет выполнение испытания T097.

**Требования:** FR-030 … FR-032, SC-009, SC-012.

## Сценарий 7 — хранение и восстановление

**Шаги:** проверить наличие свежей резервной копии и результат последней
проверки восстановления. Проверить явный режим хранения и установленные TTL/таймеры.

**Ожидаемо:** локальное хранилище и права соответствуют FR-052, последний запуск
успешен, полный набор проверен, пригодных наборов минимум 2, сохраняются последние
7. Неполные наборы и локальный `.offsite` не увеличивают счёт и не вытесняют хорошие.
Внешнего хранилища не требуется. Возраст от окончания копии неотрицателен и
меньше 26 часов; неизвестное время, будущее, ровно 26 часов, больший возраст и
failed после прежнего pass блокируют готовность. Проверка
восстановления выполнена не позднее 30 дней назад и зафиксирована. На учебном
наборе категории в режиме `until_decision` переживают прежние 365/1095 дней;
90-дневная атрибуция после окна не применяется к новой конверсии. Отдельное
учебное решение об удалении исполнено с охватом, сроком и результатом.
Проверены восстановление из старой копии, неизвестный режим и нехватка места:
ни один не возвращает возрастную очистку и не открывает готовность. Raw IP,
секреты и содержимое встреч не выводятся в доказательства. До включения IP
приняты место, основание, раскрытие, доступ, аудит и удаление по FR-061.
Состояние готовности заблокировано, если копии нет или проверка устарела.
Восстановление читает согласованный полный PostHog; tar/hash недостаточно.
Учебный сценарий потери всех локальных копий честно возвращает отсутствие
восстанавливаемой истории, без повреждения рабочих данных. Это сценарий приёмки;
рабочего результата ещё нет.

**Требования:** FR-033 … FR-036, SC-010, SC-011, SC-013.

## Полная проверка перед снятием блокировки

Перед запуском платного трафика дополнительно требуется:

1. Все сценарии выше пройдены и результаты записаны.
2. Обязательные проверки GitHub прошли на точном SHA pull request.
3. Записи об одобрении зафиксированы, включая правовое подтверждение.
4. Путь отката отработан на живом сценарии, а не только описан.
5. Тексты согласия на сайте, в коде и в документах совпадают.

Снятие блокировки платного запуска выполняется отдельным выпускным решением и не
входит в эту фичу.


## Сценарий 8 — доверенная цепочка адреса и схемы, T098

Все данные учебные; никаких рассылок, оплат или изменений аккаунтов.

| Проверка | Ожидаемый результат |
| --- | --- |
| Доверенный непосредственный peer + очищенные nginx XFF/XFP | Восстановлены адрес посетителя и HTTPS-схема |
| Недоверенный peer + поддельные XFF/XFP | Заголовки игнорируются, адрес/схема не подменены |
| Пустая/неправильная настройка доверия | Не расширяет доверие; приёмка заблокирована |
| Два внешних посетителя и оператор за одним посредником | Внешние записи не исключены по общему peer; оператор исключён по проверенному адресу/маркеру |
| Служебные/support/test маркеры | Исключены из клиентского отчёта и не маскируют настоящий внешний визит |
| HTTPS `/transcription/` и Zoom со slash | `Location` остаётся HTTPS и ведёт на канонический URL |
| Прямой доступ к API и соседний контейнер | Не могут обойти nginx и выдать поддельные XFF/XFP за доверенные |
| Docker recreate / смена peer | Требует повторной верификации, неизвестный peer не принимается молча |
| Настоящий writer → хранилище → отчёт | Внешний учебный запрос посчитан один раз, оператор не посчитан |

До стенда тестируется реальный `ProxyHeadersMiddleware`, затем проверяется
установленная полная конфигурация nginx и цепочка Docker. В доказательствах —
SHA, версия Uvicorn, тип сети, результаты сравнений, числа и HTTP-схемы без raw IP.
Только после этой матрицы можно принять T098; production-проверка и выпуск
остаются отдельными воротами. Требования: FR-013, FR-062.
