# Implementation Plan: Готовность аналитики к платному трафику

**Branch**: `273-paid-traffic-analytics` | **Date**: 2026-09-18 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/273-paid-traffic-analytics/spec.md`

## Summary

Измерение перестраивается по трём уровням правового основания, и одновременно
закрываются инфраструктурные риски, из-за которых сегодняшняя аналитика не может
пережить реальный трафик.

**Уровень 1 — обезличенный агрегат.** Новый серверный счётчик публичных
страниц, который сразу сворачивает визит в агрегат и не сохраняет ни одного
идентификатора. Работает для всех посетителей и даёт знаменатель, которого
сегодня нет.

**Уровень 2 — атрибуция через регистрацию.** Метки кампании переживают переходы
внутри визита, передаются вместе с формой регистрации и становятся атрибутом
записи о клиенте. Существующие, но мёртвые механизмы — мост атрибуции,
построитель события подключения аккаунта, клиент событий в приложении —
подключаются к реальным путям продукта.

**Уровень 3 — измерение по согласию.** Публичный скрипт начинает отправлять
события не только в Метрику, но и в PostHog, с обычными свойствами страницы;
запись поведения остаётся под отдельным согласием.

**Инфраструктура.** Внешний канал оповещений, автоматическое резервное
копирование с проверкой восстановления, явный режим хранения без возрастной очистки, разделение
порогов защиты на аналитические и общехостовые, подключение проверки страниц к
непрерывной интеграции.

Правовая конструкция подтверждена юристом 2026-09-18
([legal-basis.md](legal-basis.md)); это историческое подтверждение не разрешает
новую категорию IP автоматически. Основание и раскрытие T110/T111 остаются
неподтверждёнными; модель согласия не меняется.

## Technical Context

**Language/Version**: Python 3.13 (сервер), Swift 6.0 (macOS-приложение), Bash (инфраструктурные скрипты)

**Primary Dependencies**: FastAPI ≥0.115, SQLAlchemy 2.x (асинхронный), Alembic, httpx 0.28.1, Jinja2-шаблоны; self-hosted PostHog (ClickHouse, Kafka, Postgres, Elasticsearch) в Docker Compose; Яндекс.Метрика как внешний счётчик; cookieconsent v3.1.0 (локальная копия)

**Storage**: PostgreSQL — агрегаты уровня 1, атрибуция визита, атрибут привлечения клиента, состояние выбора посетителя, записи одобрений и готовности. ClickHouse внутри PostHog — события уровней 2 и 3, целевой режим `until_decision`. T113 добавляет в существующую GRAF DB одну product_activation_milestones для устойчивого принятия account-вех и двух состояний доставки; полный контракт — activation-milestones/data-model. Категория IP проектируется в отдельной таблице public.network_access_metadata существующей БД GRAF; writer закрыт до основания/раскрытия/прав/копий T110. Файловое хранилище сервера — резервные копии.

**Testing**: pytest (`apps/server/tests/{unit,contract,integration,browser}`), XCTest (`apps/macos/Shared/Tests`), node-тесты браузерных сценариев (`apps/server/tests/browser/*.cjs`)

**Risk / Validation Lane**: `high-risk-product`. Обоснование: работа затрагивает приватность, согласие, хранение и удаление данных, резервное копирование, развёртывание, публичные проверки здоровья и публичные контракты API. По `docs/agent-guidance/spec-kit-flow.md` это строгий путь с обязательными clarify, checklist и analyze.

**Release Gate**: развёртывание не входит в эту фичу. Изменения проверяются локально и на GitHub; включение измерения в продуктиве и снятие блокировки платного запуска выполняются отдельным выпускным решением (FR-044).

**Target Platform**: сервер `2brain.dev` (Linux, Docker), публичный сайт `https://rec.2brain.pro`, аналитика `https://analytics.2brain.pro`; macOS 14+ для приложения

**Project Type**: веб-сервис с публичным сайтом, кабинетом, админкой и отдельным desktop-приложением

**Performance Goals**: публичная страница не должна замедляться из-за измерения — запись агрегата не добавляет сетевых вызовов на пути отрисовки; публичный скрипт измерения не блокирует отрисовку. При принятой ёмкости и достаточном запасе ресурсов пятикратный всплеск нагрузки не отключает измерение и не влияет на доступность продукта (SC-012); защита общего диска по FR-032 имеет приоритет.

**Constraints**: запись агрегата не должна хранить адрес устройства, идентификаторы и связь между визитами (FR-010); отказ/отзыв обязан прекращать соответствующее измерение по согласию перед следующей записью/передачей; при деградации первой отключается аналитика, а не продукт (FR-032); IP и допустимая аналитика хранятся без возрастной очистки; отдельное обязательное удаление исполняется в собственный срок (FR-036, FR-048, FR-050, FR-061).

**Scale/Scope**: один сервер продукта, один узел аналитики, 33 контейнера PostHog;
независимая проверка доступности на существующем `astraglobal` без хранения копий. Ожидаемый порядок величин — сотни-тысячи визитов в сутки на старте кампании. Затронуто: публичный сайт (7 маршрутов), кабинет (регистрация и вход), приложение (вехи активации), инфраструктурные скрипты и защита, документация аналитики.

**Локальные точечные проверки:**

- модульные и контрактные тесты серверной аналитики — существующий набор
  `apps/server/tests/unit/test_public_analytics.py`,
  `apps/server/tests/contract/test_public_analytics_contract.py` и соседние,

- контрактный тест, доказывающий отсутствие идентификаторов в агрегате

- тест границ: после отказа не отправляется ни одного необязательного события
  (SC-004), включая повторный визит;
- XCTest на приложение: вехи активации отправляются из реальных путей, а не
  только из тестов;
- проверка страниц `infra/scripts/validate-product-analytics-provider-pages.sh`
  должна проходить и быть подключена к непрерывной интеграции.

**Проверка на живом стенде (quickstart):** сценарии из
[quickstart.md](quickstart.md) — обезличенный счёт, сохранение кампании,
регистрация, воронка активации, отказ от согласия, деградация измерения.

**Обязательные проверки GitHub:** `governance-fast`, `macos-pr`, `pr-metadata`
на точном SHA pull request. Один `release-full` на замороженном релизном
кандидате, когда фича войдёт в релиз.

**Выпускной гейт развёртывания:** не входит в эту фичу. `infra/scripts/cd-remote.sh
--dry-run` и `--execute` — только при отдельном выпускном решении.

**Почему более широкие проверки не требуются:** они требуются. Уровень риска
строгий, поэтому локальные проверки дополняются полным набором обязательных

## Phase 0 Research Output

Решения и открытые вопросы записаны в [research.md](research.md). Ревью 21.10.2026 выявило незакрытые требования; прежний раздел не является текущим PASS.

Ключевые решения:

1. **Граница между уровнями 1 и 2 проходит по идентификаторам.** Существующий
   `identity.py` строит псевдонимы (sha256 с солью) — это псевдонимизация, а не
   обезличивание, потому что соль и исходный идентификатор остаются у оператора.
   Уровень 1 обязан обходиться без этого модуля полностью.
2. **Запись агрегата выполняется в момент обработки запроса, без внешних
   вызовов.** Иначе публичная страница начнёт зависеть от доступности аналитики.
3. **Хранение без удаления по возрасту:** явный `until_decision` проверяется
   в `retention.py`, ClickHouse и PostgreSQL; прежние TTL и расписания требуют
   миграции T109. Окно атрибуции 90 дней не означает удаления истории. Ежедневное
   доказательство режима принимается только при 0 ≤ age <26 часов;
   после восстановления требуется новое доказательство.
4. **Внешний канал оповещений — Telegram-бот**, как самый быстрый канал с
   независимым от сервера путём доставки. Требует подтверждения владельца.
5. **Локальные резервные копии без отдельного узла**, решение владельца
   22.10.2026: `2brain.dev:/var/backups/graf-posthog`, последние 7 полных
   успешных наборов, минимум 2. Потеря диска/узла может уничтожить всю историю.
   Согласованное восстановление и строгая свежесть остаются обязательными;
   код и применение T117/T118 ещё открыты.
6. **Приём меток кампании — через сессионное хранилище визита**, без отдельного
   постоянного идентификатора слежения.
7. **Публичный скрипт остаётся собственным**, без перехода на `posthog-js`:
   переход потребовал бы менять модель согласия и добавлять внешнюю загрузку.

## Risks And Open Decisions

**Требует подтверждения владельца до реализации инфраструктурной части:**

1. Готового внешнего монитора нет по ответу владельца 22.10.2026.
   Для независимого наблюдения выбран существующий `astraglobal` и прямой
   Telegram-путь по research §5. Новый backup-узел не создаётся; реализация,
   закрытая конфигурация адресата и разрешённая учебная отправка — открытая T119.
2. Резервные копии приняты без отдельного узла 22.10.2026: локальный
   `2brain.dev:/var/backups/graf-posthog`, последние 7 полных успешных наборов,
   минимум 2. Внешней защиты от потери диска/сервера нет. T117/T118 ещё открыты;
   это решение больше не требует вопроса владельцу.
3. Второй оператор аналитики и включение второго фактора — требуется решение,
   кто именно.

## Уточнение T098 — доверенная граница, 21.10.2026

Наблюдение: опубликованный API слушает host-loopback, но в Docker непосредственный
peer не loopback. Явный `--forwarded-allow-ips 127.0.0.1` поэтому не принимает
установленные прокси `X-Forwarded-For/Proto`. Это объясняет проверенное
HTTPS→HTTP перенаправление slash-URL, но не доказывает верность всей конфигурации.

Второй участок пути: штатная переменная Uvicorn `FORWARDED_ALLOW_IPS` без
перекрывающего CLI-значения, с закрытым loopback-default и конкретными принятыми
адресами непосредственного посредника. Нельзя использовать `*`, CIDR всей сети
или включать общий Docker gateway в `INTERNAL_HOSTS`. Настройка адреса сама
по себе не доказывает безопасность: до принятия проверяются установленная
конфигурация nginx, очистка XFF и XFP, loopback-публикация и достижимость API
с соседнего контейнера. Если сосед может подать поддельные заголовки через тот
же доверенный peer, этот подход не проходит приёмку и доверие не включается.
Смена сети/peer после recreate требует повторной проверки. Полные IP остаются
в закрытой операторской конфигурации; в отчёт попадает только результат сравнения.

Проверки — настоящий `ProxyHeadersMiddleware` перед маршрутом, затем разрешённый
изолированный стенд с nginx/Docker и записью в отчёт. Один TestClient напрямую
на FastAPI и поиск строки в Dockerfile недостаточны. Обязательная матрица —
в конце `quickstart.md`. Существующий T098 остаётся источником задачи; новая
фича не создаётся. До PASS чеклистов, анализа и синхронизации issue код не меняется.

### Полный вход T098 — уточнение 27.10.2026

Проверка опубликованного source `7e32f0da25db5d78d742f9cde1ed59a49ffcaf1a`
обнаружила более раннюю потерю адреса: общий nginx stream443 передаёт TLS
на loopback10444 без PROXY protocol. Одного доверия Docker peer недостаточно.
[Независимое ревью кандидата](validation/t098-ingress-design-review-2026-10-27.md)
принимает принцип протокола, сохраняя BLOCK рабочего применения.

Clarify текущего среза: FR-013/061/062, роли, согласие, хранение и критерии
сохраняются; новых вопросов владельцу нет. Выбор директив и порядок перехода —
технические решения. Отсутствие безопасного обратного перехода или проверки
соседей блокирует реализацию/применение, а не заменяется допущением.

Минимальный кандидат для установленного nginx1.24.0:

1. Общий публичный443 принимает обычный TLS; исходящий `proxy_protocol on`
   передаёт адрес следующему участку. Точный SNI ГРАФ идёт на отдельный
   loopback10445; прежние default/special маршруты — через loopback10446/10447,
   снимающие envelope и передающие TLS прежним upstream без него.
   Эти три порта свободны по read-only наблюдению27.10, но не зарезервированы:
   перед конкретным испытанием/применением обязательна повторная проверка.
2. Итоговый `infra/nginx/rec.2brain.pro.conf` заменяет оба rec10444 listener
   точными IPv4/IPv6 loopback10445 с `ssl proxy_protocol`. В двух locations
   только этого сервера XFF/X-Real-IP заменяются `$proxy_protocol_addr`,
   XFP остаётся `https`. Пустой источник, в том числе PROXY UNKNOWN, даёт400
   до API. Несовпадающий HTTP Host на dedicated rec receiver даёт421,
   чтобы отдельный сокет не обслуживал чужое имя. HTTP realip не включается: `$remote_addr` и состав журналов
   не начинают сохранять visitor IP. Отдельный8443 не меняется.
3. Общий routing оформляется проверяемым include
   `infra/nginx/graf-sni-routing.conf` внутри существующего stream-контекста.
   Исходные public bind, log format и два прежних upstream берутся из полного
   проверенного конфига; реальные адреса/закрытая конфигурация не входят в Git.
   На strip relay исходящий PROXY явно off, access_log off; остальные параметры
   сверяются с прежними эффективными timeout/buffer/half-close/keepalive.
   Нового процесса nginx, зависимости, маршрутизации ядра или обновления nginx нет.
4. В конечной конфигурации rec отсутствует на shared10444. Unknown/noSNI
   сохраняет прежний маршрут соседей, но `Host: rec.2brain.pro` через него
   не достигает API ГРАФ. Доступ к публичному ГРАФ требует правильного SNI;
   внутренний потребитель старого порта, если обнаружен, блокирует снятие
   до отдельного решения о его миграции. Общий запрет неизвестного SNI не вводится.

Владение: существующий T098 и issue#7698; source указан активным указателем
рабочей копии. Файлы реализации: два nginx-файла выше, ограниченный исполняемый
стенд `infra/scripts/check-graf-sni-ingress.py`, существующие middleware/Compose
проверки и закрытая операторская конфигурация. `nginx.conf` общего сервера
меняется только проверенным согласованным набором под блокировкой, после ревью
полного include graph; соседние проекты не редактируются автоматически.
Оба ручных установщика `install-billing-webhook-edge.sh` и
`install-summary-share-edge.sh` также читают rec-конфиг. Они не вызываются
из штатного CD, но во время перехода их запуск запрещён: иначе один файл
может быть заменён вне согласованного набора. После конечного перехода
они сверяются с тем же rec-файлом; их отдельные платёжные пробы не запускаются
ради T098.

Переход и возврат проверяются до применения:

- A: добавить новые receivers/relay при прежнем публичном маршруте; прежний
  rec10444 временно сохранён только для перехода. Снять хеш всех входов,
  `nginx -t`, штатно reload, подтвердить новую генерацию и её доступность.
- B: переключить публичный map и исходящий PROXY, сохранив оба набора receivers.
  Дождаться завершения всех прежних stream workers, способных открыть старый
  upstream. Время наблюдения ограничено; долгие чужие сессии не обрываются.
  При незавершённом дренировании этап остаётся открытым, измерение не принимается.
- C: снять rec10444 и временный переходный набор; reload и дренирование
  поколения, ещё содержавшего старую rec-виртуалку. Проверить noSNI/Host bypass
  на реально обслуживающей генерации. Только после этого принять nginx-границу.
- D: отдельно применить точный Uvicorn peer тем же образом только rec-api,
  используя существующий `release-images.py current-override` и deploy lock.
  Сравнить эффективные Compose/inspect до/после; без build/pull/dependencies,
  смены остальных флагов или автоматического включения IP/provider.
- Возврат: сначала согласованный набор обоих receivers и relay, затем прежний
  public map/PP mode и прежний env. Не удалять новый receiver/relay, пока старое
  поколение ещё может обратиться к нему. После дренирования удалить временное;
  подтвердить старые соседние маршруты,8443 и отсутствие незавершённого cutover.

Временное сохранение rec10444 ограничено исключением в spec Legacy Impact;
оно не является принятой резервной дорогой. Финальная приёмка невозможна,
пока сохраняется старый обход или неизвестна обслуживающая генерация.

Constitution до/после проектирования: принципIII — нет нового получателя или

Остальные принципы не затрагиваются. Нарушений не выявлено; рабочий PASS
не заявлен. Матрица и ограничения — сценарий8 `quickstart.md`.

## T113 — первый локальный период, 28.10.2026

Clarify: цель, получатели, срок хранения и порядок владельца не меняются.
Исполняется локальный durable ledger с принятым 30.10.2026 фиксированным T0
для новых аккаунтов. Новая identity, таблица и внешняя передача не нужны. Полоса high-risk-product в существующей фиче,
storage/privacy; before-code независимый обзор четырёх checklist и scoped
analyze остаются обязательными. Один период с закрытием при непокрытом
restore/gap сохраняет FR-025; T0 не сбрасывается. Условие полной прежней
маркетинговой истории заменено проверкой новой группы, а не снятием lifecycle.
Проверка initial receipt использует общий product drain, доверенное время БД,
полный текущий снимок без RLS и отсутствие аккаунтов с created_at > T0;
повторный запуск не заменяет initial receipt. Trusted created_at проверяется
в общем admission, серверное происхождение новой записи — в T112. В отчёте
старые/служебные/неизвестные строки отделены, оплаты сверены с возвратами.
Изменение определения пока не означает реализацию или рабочий старт.

Порядок: GRAF DB backup/restore и проверяемая очистка → один защищённый
readiness/fence вне БД → local_only в существующих settings/ingest/legal gate
→ обе admission-ветви/отзыв/удаление/rollback → T112 видимый результат и
серверная lineage браузерной загрузки → отдельная рабочая приёмка. Договор
состояния/настроек/блокировок — activation-milestones; операции — operations.
Предыдущее общее требование внешней PostHog readiness остаётся для внешних
событий; local_only использует полную собственную GRAF DB readiness, сохраняя
правовое основание, раскрытие, хранение, точные удаления и общий ресурсный guard.
Это не выполнение исторического PostHog restore или независимого мониторинга.

Пути исполнения включают infra/docker-compose.yml и существующий CD/rollback
runbook: shared host directory монтируется read-only в процессы admission,
оператор использует тот же постоянный inode.
Переиспользовать текущие backup/rehearsal/CD/rollback, fcntl+atomic replace,
уникальную account+event таблицу и существующий набор тестов. Новых
зависимостей, таблиц, брокера и общего framework нет. Конституция II/III/IV/VI:
разрешённые поля/получатели прежние, продукт не зависит от измерения,
until_decision/отдельные удаления/restore и проверки сохраняются. Нарушений
проекта не выявлено; до независимого PASS реализацию не начинать.
