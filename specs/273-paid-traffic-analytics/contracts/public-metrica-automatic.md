# Автоматическая Метрика на публичном лендинге

Решение владельца 16.11.2026. Область риска: high-risk-product (privacy).
Спецификация и clarify: новая запись в `spec.md`; факты и источник запроса —
`validation/metrica-automatic-proposal-20261116.md`.

## Поведение

1. `public_analytics_automatic_enabled=false` по умолчанию сохраняет старый
   публичный режим. Включение — отдельная конфигурация рабочего выпуска.
2. При включённой настройке только `/` и `/download` используют автоматическую
   Метрику. Номер берётся из прежней настройки, без нового счётчика/получателя.
   У нового посетителя нет запроса выбора перед начальным просмотром и replay.
   Не создавать ложные записи grant/consent и не отправлять события в PostHog.
3. Старый отказ от analytics отключает Метрику. Старый отказ от behavior_replay
   исключает replay/карты; повреждённая сохранённая запись закрывает отправку.
   Явное отключение доступно кнопкой в footer без модального запроса согласия.
   Включение обратно — отдельное явное действие, не обычная перезагрузка.
4. После отказа прекратить запуск и вызвать штатный `destruct`, закрыв новые
   вызовы; отказ хранится локально. Изменение выбора другой вкладкой и возврат
   на открытую страницу повторно сверяют выбор. Блокировщики не обходятся.
5. Главный public-флаг, окружение и свежая проверка withdrawal register остаются
   обязательными. Редакция согласия в automatic-режиме не становится искусственным
   запретом: согласие не является заявленным основанием этой ветви. Старые relay/
   consent endpoints продолжают проверять свою точную редакцию и server epoch.
6. Никакой записи входа/регистрации, кабинета, встреч, встроенного приложения,
   полей форм, аудио, паролей, кодов и платёжных данных. Не передавать raw query,
   hash, полный referrer и свободные поля как параметры целей. Для SDK допускать
   только публичный адрес с разрешёнными безопасными campaign-параметрами;
   неизвестные/небезопасные параметры закрывают SDK, не меняя адрес пользователя.
   Поля и редактируемые элементы исключаются классами SDK; новые формы без
   подтверждённого исключения не расширяют область автоматически.
7. Один init и один начальный hit на документ, `defer=true`, разрешённый SDK
   Яндекса; public страницы и работа без SDK не зависят от его доступности.
   Цели используют существующие имена и закрытые метки, без произвольного текста.
8. Публичные cookies/privacy/analytics тексты при этом режиме описывают
   автоматическую Метрику, cookies, Вебвизор, область и отключение. Они не
   обещают согласие там, где его не было, и не заявляют универсальную законность.

9. Просмотр карт допускает встраивание только двух публичных страниц в HTTPS
   окна официальных metrika.yandex.ru, metrika.yandex.by, metrica.yandex.com,
   metrica.yandex.com.tr, webvisor.com и его поддоменов. Исключение работает
   только при разрешённом автоматическом replay: CSP перечисляет эти источники,
   X-Frame-Options удаляется только в этой ветви; формы/вход/кабинет не расширяются.
   Контроллер допускает такой frame по точному origin referrer, а чужие frame
   остаются закрыты. Это не доказывает рабочий показ карт до T121.

## Проверка и выпуск

- API читает постоянный реестр отзывов через read-only bind mount по
  стандартному пути существующего reader. До включения оператор проверяет
  существующий файл без замены; только если его нет, готовит начальный файл
  с одним `legal_basis_state_version=1` по принятому T106 формату. Файл не
  создаётся приложением, не подменяет основание и не стирает прежние отзывы.
  Runtime group получает чтение, запись из API запрещена. Missing/error/
  withdrawal остаются отрицательными сценариями. Проверяется доступность
  после штатного пересоздания контейнера; одного env-флага недостаточно.

- Качество требований и согласованность артефактов проверяются независимо до
  кода. Подготовка кода не включает передачу данных с рабочего сайта.
- RED/GREEN Python: default/automatic, обе страницы, исключённые страницы,
  отсутствующий счётчик, global off, неподходящее окружение и withdrawal.
- Node: новый посетитель/явный старый отказ/частичные категории, повреждение и
  недоступность storage, один hit/цели, отказ/повторный вход, чужая вкладка и
  небезопасный адрес. Исходящие обращения перехватываются; реальный счётчик
  локальные проверки не вызывают. Прежние consent/server/browser тесты остаются.
- До рабочего включения нужны основание и раскрытие для новой модели,
  независимая проверка реализации, точные PR checks и штатный выпуск.
  Реальное получение посещения, целей, Вебвизора и карт подтверждается отдельно
  в кабинете. Подготовка кода не считается этим подтверждением.
