# Feature Specification: Источник системного звука в индикаторе записи

**Feature Branch**: `codex/156-recording-source-indicator`

**Created**: 2026-08-16

**Status**: Draft

**Input**: User description: "В верхней части приложения, там где отображается индикатор записи, нужно показывать звук из какого приложения сейчас записывается."

## User Scenarios & Testing

### User Story 1 - Понять источник активной записи (Priority: P1)

Как пользователь, я хочу видеть рядом с индикатором записи, из какого приложения или источника сейчас берётся системный звук, чтобы быстро убедиться, что GRAF записывает нужную встречу.

**Why this priority**: Это напрямую отвечает на вопрос «что сейчас записывается» и снижает риск незаметно записать не ту встречу.

**Independent Test**: Запустить запись с известным приложением-целью и проверить, что в верхнем индикаторе видны статус записи и имя этого приложения.

**Acceptance Scenarios**:

1. **Given** запись запущена для известного приложения-цели, **When** пользователь смотрит на индикатор записи, **Then** рядом со статусом показана компактная строка с названием этого приложения.
2. **Given** запись поставлена на паузу или временно ограничена, **When** пользователь смотрит на индикатор, **Then** источник остаётся видимым и не меняется сам по себе.
3. **Given** запись останавливается и сохраняется, **When** пользователь видит состояние завершения, **Then** элемент управления остановкой сохраняет текущую доступность, а название источника не выдаётся за активную запись.

### User Story 2 - Доверять нейтральному состоянию источника (Priority: P1)

Как пользователь, я хочу отличать известное приложение от общего системного звука и неизвестного источника, чтобы интерфейс не создавал ложной уверенности.

**Why this priority**: В ручном режиме GRAF записывает системный звук в подтверждённой области, но не всегда может достоверно назвать одно приложение. Честное отображение важнее красивого, но неточного имени.

**Independent Test**: Запустить ручную запись без приложения-цели и проверить, что интерфейс показывает понятное нейтральное обозначение системного звука; смоделировать отсутствие имени и проверить безопасное fallback-состояние.

**Acceptance Scenarios**:

1. **Given** запись запущена вручную без конкретного приложения-цели, **When** пользователь смотрит на источник, **Then** отображается «Системный звук», а не вымышленное имя приложения.
2. **Given** имя источника недоступно или не прошло проверку, **When** запись активна, **Then** отображается «Источник не определён» без остановки записи и без подмены неизвестного значения.

### User Story 3 - Быстро проверить источник с клавиатурой и VoiceOver (Priority: P2)

Как пользователь с ограничениями зрения или небольшим окном приложения, я хочу получить полное название источника через доступное имя и подсказку, даже если визуально оно сокращено.

**Why this priority**: Длинные названия приложений и узкая ширина окна не должны ухудшать понимание активной записи.

**Independent Test**: Проверить строку источника на длинном названии, в увеличенном интерфейсе и через accessibility tree; полное значение должно быть доступно без изменения состояния записи.

**Acceptance Scenarios**:

1. **Given** имя приложения длиннее доступной ширины, **When** оно отображается в индикаторе, **Then** визуальный текст аккуратно сокращается, а полное имя доступно через accessibility label и системную подсказку.
2. **Given** включён повышенный контраст или Reduce Motion, **When** показывается источник, **Then** строка остаётся различимой и не требует анимации для понимания.

### Edge Cases

- Ручная запись с подтверждённой областью «текущий экран/системный звук» показывает нейтральное «Системный звук».
- Пустое, пробельное или неизвестное имя не попадает в интерфейс как пустая строка; используется «Источник не определён».
- Источник не меняется при переходах «начинаем», «идёт запись», «пауза», «ограничение» и «сохраняем запись».
- Длинные, локализованные и содержащие специальные символы имена не должны ломать ширину индикатора.
- Остановка записи должна оставаться доступной одной кнопкой; добавление строки источника не должно менять существующие действия.

## Requirements

### Functional Requirements

- **FR-001**: Во время подготовки и активной записи система MUST показывать в верхнем индикаторе отдельную компактную строку «Источник».
- **FR-002**: Если запись связана с известным приложением-целью, строка MUST показывать его проверенное отображаемое имя из текущей сессии.
- **FR-003**: Для ручной записи без приложения-цели система MUST показывать «Системный звук».
- **FR-004**: При отсутствии проверенного имени система MUST показывать «Источник не определён» и MUST NOT угадывать название приложения.
- **FR-005**: Значение источника MUST оставаться неизменным в рамках текущей сессии записи и исчезать из состояния, которое уже не представляет активную запись.
- **FR-006**: Визуальное оформление MUST сохранять иерархию: основной статус и доступная остановка важнее строки источника; строка не должна занимать место у кнопки остановки.
- **FR-007**: Длинное имя MUST сокращаться визуально без переноса в несколько строк; полное имя MUST быть доступно через accessibility label и подсказку.
- **FR-008**: Строка источника MUST быть доступна при повышенном контрасте и не зависеть от анимации, а существующие доступные действия паузы, продолжения и остановки MUST сохраниться.
- **FR-009**: Функция MUST использовать уже подтверждённый источник текущей сессии и MUST NOT добавлять отдельный фоновый сбор списка приложений, изменение громкости, изменение маршрута, сетевой вызов или содержимое аудио.

### Key Entities

- **Источник сессии записи**: проверенное отображаемое имя приложения-цели либо нейтральный тип «Системный звук»/«Источник не определён», действующий только в пределах текущей capture-сессии.
- **Индикатор записи**: существующая верхняя область приложения со статусом, состоянием видимости и действием остановки; новая строка источника является частью этого элемента.

## Success Criteria

### Measurable Outcomes

- **SC-001**: В 100% сценариев активной записи из известного приложения верхний индикатор показывает корректное имя этого приложения без ручного открытия настроек.
- **SC-002**: В 100% сценариев ручной записи без конкретного приложения интерфейс показывает «Системный звук» или «Источник не определён», не показывая неподтверждённое имя.
- **SC-003**: На поддерживаемой минимальной ширине capture-панели строка источника не вызывает горизонтального переполнения и не уменьшает интерактивную высоту кнопки остановки ниже существующего стандарта.
- **SC-004**: Полное имя источника доступно VoiceOver и системной подсказке даже при визуальном сокращении; основные действия записи остаются доступны с клавиатуры.
- **SC-005**: Время старта записи, число аудиодорожек, состояние разрешений и маршрут системного звука не меняются относительно существующего поведения.

## Assumptions

- Источник приложения берётся только из уже подтверждённой области и evidence текущей записи; отдельное определение приложения по каждому аудиофрейму не требуется.
- Для ручного режима «Системный звук» честнее, чем выбирать одно из приложений, поскольку текущий MVP записывает системный звук в подтверждённой области.
- В первой версии не добавляются иконки сторонних приложений, выбор источника из индикатора, изменение маршрута и история источников.
- macOS и существующая native capture UI остаются единственной целевой платформой этой фичи.
- Production deploy, notarization и изменение release versioning не входят в эту задачу.
