# Feature Specification: Достоверные устройства и сеансы

**Feature Branch**: `codex/248-trustworthy-account-sessions`
**Created**: 2026-09-06
**Status**: Draft
**Input**: Пользователь просит перепроверить весь раздел устройств и активных сессий, исследовать лучшие практики, продумать UX и достоверность, реализовать, проверить и создать PR.

## User Scenarios & Testing

### User Story 1 — Узнать свои входы (Priority: P1)
Пользователь видит GRAF для macOS отдельно от браузера и сразу узнаёт текущий сеанс.
**Independent Test**: Два независимых входа и обновление одного дают две различные записи, текущая первая.
**Acceptance Scenarios**:
1. При входе через приложение, включая отправку формы и возврат провайдера, отображается «GRAF для macOS».
2. При двух входах в браузере создаются отдельные сеансы; обновление токена не создаёт новое устройство.
3. Для старого входа без достаточных данных интерфейс честно сообщает неопределённость.

### User Story 2 — Завершить чужой вход (Priority: P1)
Пользователь завершает конкретный или все остальные сеансы и понимает последствия.
**Independent Test**: После подтверждения чужой токен не открывает API или кабинет, текущий работает.
**Acceptance Scenarios**:
1. Действие «Завершить остальные сеансы» оставляет ровно текущий разрешённый сеанс в области действия.
2. Отзыв регистрации блокирует все связанные сеансы и привязки; чужой аккаунт недоступен.
3. Переход из приложения в браузер для оплаты создаёт самостоятельный вход; выход в браузере не отключает приложение.

### User Story 3 — Понять состояние и время (Priority: P2)
Пользователь отличает действующий доступ от присутствия онлайн, завершённые входы от действующих и понимает время последней активности.
**Independent Test**: Действующие, истёкшие, отозванные, заменённые и неизвестные записи показаны без ложных состояний.
**Acceptance Scenarios**:
1. Истёкший сеанс не попадает в действующие даже при сохранённом статусе active.
2. Время отображается в выбранном часовом поясе с его названием; неизвестное время обозначено явно.
3. На узком экране, с клавиатуры и без JavaScript доступны подтверждение, отмена и понятная ошибка.

### Edge Cases
Старые общие browser-записи; отсутствие User-Agent; поддельный маркер; несколько одинаковых клиентов; истечение во время просмотра; повторный отзыв; отозванное устройство; неизвестный статус; отсутствующая привязка; переход оплаты с уже открытым браузерным сеансом; повторный callback; недоступная БД; запрос без CSRF; другой владелец; смена часового пояса; фоновая активность; локальная запись после потери доступа.

## Requirements

### Functional Requirements
- **FR-001**: Каждый независимый вход получает отдельную регистрацию клиента; обновление токена сохраняет регистрацию. Название клиента не является доказательством физического устройства.
- **FR-002**: Новый вход из macOS сохраняет тип приложения на полном пути формы/провайдера; маркеры клиента служат только отображению и не дают прав.
- **FR-003**: Старые неоднозначные записи не переименовываются массово и не считаются точно браузерными. Не собирать имя компьютера, аппаратный идентификатор, IP или геолокацию для этой функции.
- **FR-004**: Один основной список «Где вы вошли» показывает действующие входы, текущий первым, затем последние по активности. Способ входа вторичен; внутренние UUID, client_version=email-login и сырые User-Agent скрыты.
- **FR-005**: Действующий доступ к данным требует неистёкшего active-сеанса и разрешённой связанной регистрации/привязки; исключение ограниченного unbound API bootstrap описано ниже. Истёкший, завершённый, заменённый и неизвестный статусы не называются активными. Завершённые вынесены в сворачиваемую историю.
- **FR-006**: Отображаемая последняя активность отражает успешные авторизованные обращения к серверу с точностью до пяти минут. Фоновые запросы могут её обновлять; это не индикатор «онлайн». Выход не обновляет её. Время локализовано, часовой пояс указан, отсутствие данных явно обозначено.
- **FR-007**: Точечное завершение и завершение остальных входов сохраняют текущий, проверяют владельца/рабочее пространство и CSRF. Повторный запрос безопасен. Кнопки отсутствуют при отсутствии подходящих целей.
- **FR-008**: Отзыв устройства через существующие API/формы блокирует связанные сеансы и привязки; последующие запросы через все способы передачи токена не авторизуются. Существующий запрет отзыва текущего устройства из кабинета сохраняется.
- **FR-009**: Открытие оплаты во внешнем браузере не копирует действующий токен приложения. Одноразовый переход создаёт отдельный браузерный сеанс со сроком не позже исходного; повторное использование или отозванный исходный доступ отклоняются. Уже действующий браузерный вход того же пользователя может сохраняться, если безопасно проверен.
- **FR-010**: Перед завершением показываются точная цель, последствия и отмена, в том числе без JavaScript. Завершение прекращает доступ к серверу и требует нового входа, но не обещает удаление локальных файлов или остановку локальной записи. Ошибка не выдаётся за успех.
- **FR-011**: Раздел явно описывает область текущего рабочего пространства; не обещает глобальный выход из других пространств. История не является журналом всех событий входа. Отсутствие данных и недоступность различимы.
- **FR-012**: Интерфейс работает в браузере и WKWebView при ширине 375/768/1280 px, с клавиатурой, видимым фокусом, доступными именами действий и без утечки приватных данных в доказательства.

- **FR-013**: Раздел «Где вы вошли» начинает с «Проверьте входы и выйдите из тех, которыми больше не пользуетесь.». Постоянно видна область «Показаны входы в текущее рабочее пространство». Текущий вход первый, отличается фоном/рамкой и текстовой меткой «Вы здесь»; эта метка означает только вход, из которого открыта страница. Иконка необязательна: достаточно ясной типографики, рамки/фона и метки; новые сторонние активы не добавляются.
- **FR-014**: Строка входа содержит узнаваемое имя, «Последняя активность: сегодня, 14:20» / «вчера, 14:20» / полную дату и время для более ранних дней; сравнение календарных дней ведётся в часовом поясе профиля. «Нет данных» остаётся явным; будущая дата не превращается в «только что». Точное время, часовой пояс, способ входа и срок действия доступны в «Подробнее». Неизвестный клиент называется «Неизвестный вход»; законный unbound — «Устройство не подключено» с прежним ограничением доступа.
- **FR-015**: Для другого разрешённого входа действие называется «Выйти» с уникальным доступным именем, содержащим клиента и точное время входа. Массовое действие расположено после списка и называется «Выйти из остальных»; его описание и подтверждение называют остальные входы только в текущем пространстве. Подтверждение конкретного входа содержит имя и точную дату; текущий сохраняется. Короткий текст объясняет необходимость нового входа и сохранность локальных файлов/записи. Отмена получает первоначальный фокус; Enter на странице подтверждения сам по себе не подтверждает выход.
- **FR-016**: «Предыдущие входы» свёрнуты и содержат различимые завершённые/истёкшие/заблокированные/неизвестные состояния. В свёрнутом «Что означают эти данные?» остаются сведения о нескольких входах на одном компьютере, фоновой работе, точности до пяти минут и отсутствии гарантии присутствия онлайн. Основной экран не содержит многоабзацного объяснения серверных правил. При отсутствии других входов показано «Других входов нет.» Unknown-копия сообщает недостаток сведений, а не утверждает взлом. Другие разделы аккаунта не меняются. Недоступность, отсутствие данных и ошибка выхода остаются различимыми; подтверждение, отмена и подробности работают без JavaScript, на 375/768/1280 px, в браузере и WKWebView, с клавиатурой и видимым фокусом.

### Key Entities
- Сеанс: отдельное разрешение доступа, начало, последняя активность, срок, состояние, способ входа, связанная регистрация.
- Регистрация клиента: логический контекст входа или регистрации приложения; не инвентаризация физических компьютеров.
- Текущий сеанс: определяется сервером по токену текущего запроса.

## Success Criteria
### Measurable Outcomes
- **SC-001**: Все проверяемые новые входы приложения/браузеров отображаются раздельно и верно; старые неопределённые не получают ложную классификацию.
- **SC-002**: Все проверки отзыва, границ владельца, срока, CSRF и повторного callback проходят; текущий вход сохраняется.
- **SC-003**: В списке действующих нет ни одной истёкшей/заблокированной записи, нет вымышленных мест/имён; активность отличается от онлайн.
- **SC-004**: Проверены реальные формы в браузере и WKWebView, все обязательные проверки и PR привязаны к итоговому SHA; пропуски явно перечислены.

- **SC-005**: На синтетических 375/768/1280 px экранах текущий вход узнаётся по месту, выделению и «Вы здесь»; основные строки содержат имя, короткую активность и действие без технических идентификаторов. Скриншоты до/после проверены рецензентом.
- **SC-006**: Целевые проверки подтверждают today/yesterday в зоне профиля, полный fallback даты/unknown, уникальные доступные имена, фокус отмены и сохранение существующих подтверждения/CSRF/отзыва. Нет новых зависимостей, таблиц или клиентского JavaScript.

## Assumptions
Существующие сроки токенов и модели данных сохраняются. Релиз и production deployment не входят в этот запрос. В рамках текущей модели список ограничен текущим рабочим пространством. Физические устройства, удалённая очистка, новый журнал безопасности, новые провайдеры и переработка всего OAuth не входят. Старые общие регистрации сохраняются до истечения/нового входа; не повышать их достоверность догадками.

### Unbound API bootstrap
Законно не привязанным считается только сеанс с device_id=NULL и без каких-либо binding rows. Он сохраняет прежний ограниченный доступ к principal-only API (включая auth/me и регистрацию устройства); tenant/cabinet доступ без регистрации не разрешается. В списке другого действующего сеанса такого же владельца он показывается как «Устройство не подключено», с пояснением «Вход выполнен, устройство ещё не подключено», и доступен завершению. Он действующий по сроку/статусу, но не означает доступ к данным пространства. Если device_id указан, но устройство/binding отсутствует, или есть blocked/несогласованная binding, запрос отклоняется и UI не считает запись действующей. Историческая binding-only запись проверяется по этой связи; разрешённая trusted связь может восстановить контекст текущего запроса без изменения типа клиента.

## Legacy Impact

- Classification: `untouched`
- Новые legacy маршруты, aliases и зависимости не добавляются. Исторические записи читаются по сохранённым сведениям; их удаление и миграция не входят в фичу.
- `legacy_new=0`, `unowned_legacy=0`, `expired_exceptions=0`.
