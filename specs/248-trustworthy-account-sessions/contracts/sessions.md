# Contract
Новые поля публичного JSON API и migration не требуются. Существующие register/revoke/auth/me/cabinet/settings маршруты сохраняются.
- GRAFDesktop/<version> в WebKit applicationNameForUserAgent сохраняется при form POST, callback и navigation. Только display hint; не auth/trust credential.
- POST /settings/account/sessions/{id}/revoke и /sessions/revoke-others (и /desktop варианты): owner/workspace/CSRF как прежде; без confirm показать доступную страницу подтверждения; confirm=1 повторно проверяет цель и отзывает; отмена ведёт назад. data-confirm удалить для этих кнопок во избежание двойного диалога.
- Текущую session/device нельзя отозвать операцией для других; обычный logout остаётся отдельным способом выхода.
- Отзыв registration через API и bulk routes завершается атомарно для всех её session/bindings. Revoked токены не принимаются через Cookie, Bearer, X-Auth-Session; unbound registration bootstrap не сломан.
- GET /billing/handoff: прежний one-time state, отдельная браузерная cookie, не token приложения; expiry не продлевается.
- UI: «Устройства и сеансы»; «Этот сеанс»; «Завершить сеанс»; «Завершить остальные сеансы». Действующий означает разрешённый доступ, не онлайн. Подробности: способ входа, время начала/последней связи/истечения, timezone. Без токенов/UUID/raw UA/вымышленного местоположения.
- Свернутая история: завершённые/истёкшие/заменённые/неизвестные записи, без действий. Область текущего пространства описана. Недоступность БД не отображается как пустой список.

### Unbound API bootstrap
Законно не привязанным считается только сеанс с device_id=NULL и без каких-либо binding rows. Он сохраняет прежний ограниченный доступ к principal-only API (включая auth/me и регистрацию устройства); tenant/cabinet доступ без регистрации не разрешается. В списке другого действующего сеанса такого же владельца он показывается как «Клиент не зарегистрирован», с пояснением «Вход выполнен, устройство ещё не подключено», и доступен завершению. Он действующий по сроку/статусу, но не означает доступ к данным пространства. Если device_id указан, но устройство/binding отсутствует, или есть blocked/несогласованная binding, запрос отклоняется и UI не считает запись действующей. Историческая binding-only запись проверяется по этой связи; разрешённая trusted связь может восстановить контекст текущего запроса без изменения типа клиента.
