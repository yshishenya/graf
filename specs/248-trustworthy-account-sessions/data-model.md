# Data model
Схема БД неизменна. AuthSession связан с RegisteredDevice через device_id и trusted AuthSessionDeviceBinding; существующий API может временно иметь unbound session до регистрации.
Независимый browser/desktop login: device_public_id=login:<случайный UUID>; platform=macos или web; client_version для macOS строго ограниченная версия GRAFDesktop, для браузера ограниченная составная подсказка browser:<семейство>:<ОС> из allowlist. Неопознанный браузер browser:unknown:unknown. Старые browser-email/browser-login остаются неопределёнными. Нет raw UA, IP, hardware ID.
Новая регистрация не оживляет revoked. Workspace continuation сохраняет platform/client_version и остаток TTL, перед сменой RLS сохраняет metadata. Текущий сеанс определяется session.id авторизованного запроса.
Действующий = active и expires_at > now и связанное устройство/привязка допускают доступ. expired/revoked/replaced/unknown различаются; блокировка device/binding исключает active. last_seen обновляется после успешной проверки, conditional update с status/expiry и cutoff 300s; logout/revoke не являются активностью. Это точность записи, не продление TTL.
Отзыв device: все session по direct device_id или binding → revoked; все bindings → blocked; device→revoked. Отзыв session блокирует только bindings этого session. Истёкшие/уже завершённые операции идемпотентны. Текущий сеанс защищён для other operations.
Billing handoff: one-time callback, новый browser device/session, expiry <= source expiry, исходная сессия остаётся независимой; replay/revoked source fail closed.

### Unbound API bootstrap
Законно не привязанным считается только сеанс с device_id=NULL и без каких-либо binding rows. Он сохраняет прежний ограниченный доступ к principal-only API (включая auth/me и регистрацию устройства); tenant/cabinet доступ без регистрации не разрешается. В списке другого действующего сеанса такого же владельца он показывается как «Устройство не подключено», с пояснением «Вход выполнен, устройство ещё не подключено», и доступен завершению. Он действующий по сроку/статусу, но не означает доступ к данным пространства. Если device_id указан, но устройство/binding отсутствует, или есть blocked/несогласованная binding, запрос отклоняется и UI не считает запись действующей. Историческая binding-only запись проверяется по этой связи; разрешённая trusted связь может восстановить контекст текущего запроса без изменения типа клиента.
