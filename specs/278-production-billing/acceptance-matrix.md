## Форма доказательства

Для каждой строки: проверяемая версия/изменения, уровень Л/Т/П/У, время, безопасная ссылка на результат, ожидаемый и фактический исход, остаток, проверивший. Для П дополнительно сверка общей потраченной суммы с бюджетом; для У — поверхность и реальные размеры/тема/способ ввода. Общее число зелёных тестов не закрывает строку без привязки сценария.

В репозитории — только обезличенные результаты. Нельзя сохранять коды акций, секреты, идентификаторы платежей/возвратов провайдера, реквизиты, email плательщика, банковскую выписку и содержимое встреч. Подробное финансовое доказательство остаётся у владельца с безопасной локальной ссылкой.

## Правила завершения

1. Q1/Q2/Q3 разрешены. После проектирования — независимое ревью требований, задачи, анализ и синхронизация issues; только затем реализация.
2. Статус каждой обязательной строки — подтверждённый результат, а не обещание выполнить позднее.
3. Для реального продления нельзя молча сокращать период живой подписки вручную или выдавать подставной платёж за работу сохранённой карты.
4. Для повторяемых отрицательных сценариев достаточность Л/Т устанавливается планом; минимальные реальные платежи — подписка и дополнение, реальное сохранённое списание подтверждается отдельно по согласованным условиям.
5. Банковское зачисление может произойти позже платежа. До его подтверждения формулировка «деньги поступают» остаётся неподтверждённой.
