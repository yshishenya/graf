# Требования доставки писем оплаты T032

Создано: 2026-10-04. Reviewer-owned: [x] подтверждает качество требований независимым рецензентом, не выполнение кода или выпуска. Основание FR-027/028/032/033, US5/AC2, plan: Уведомления оплаты T032.

- [x] NTF001 Заданы действующий Postal, verified recipient, outbox и параметры всех трёх служб без нового адресата/шаблона/провайдера.
- [x] NTF002 Ограничено предоставление одним существующим Postal secret/сетью; DB роль/RLS/изоляция/защиты и запреты CSRF/MediaScribe/публичных портов сохраняются.
- [x] NTF003 CD проверяет включённую доставку, читаемость непустого ключа и соединение до финансового открытия; Postal POST/send запрещён в readiness, действительность ключа и принятие/доставка письма проверяются отдельно.
- [x] NTF004 Описаны fail-closed ключ/сеть/рассогласование и disabled только при отключённых оплате и почте; вывод не раскрывает секреты/пути/контакты/payload.
- [x] NTF005 Письма не меняют суммы/права/бюджет/согласие; регистрация чека, Postal принятие и доставка получателю различаются.
- [x] NTF006 Историческая очередь не сбрасывается автоматически; отдельный dry-run только проверочных писем владельца требует доказательства прежней неотправки.
- [x] NTF007 Повторение не касается delivered/ambiguous/чужих строк, не создаёт новый event_id и не выполняется при неизвестном исходе Postal.
- [x] NTF008 Определены локальные позитивные/негативные проверки, независимое ревью, новый SHA/полный выпуск и фактическое новое письмо; T032 остаётся открытой без этих доказательств.

Первичное независимое ревью требований до уточнения: 7 checked / 1 unchecked. NTF003 был открыт: план запрещал отправку письма, но требовал уточнения запрета любого Postal POST/readiness send. Детальные доказательства и границы — [notification-delivery-review.md](../notification-delivery-review.md). Это проверка требований, не runtime/выпуск/доставка девяти старых писем.

После уточнения основным агентом plan.md перечитан: readiness только читает конфигурацию/непустой ключ и открывает TCP-соединение, явно запрещает Postal POST/send/внешние изменения; валидность ключа и принятие письма проверяются отдельно. Итог независимого gate требований: 8 checked / 0 unchecked, PASS. Runtime/CD/отправка ещё не проверены.

- [x] NTF009 Неизвестный исход или остановка sender после начала POST не создаёт повтор; захват существующей строки фиксируется до внешней отправки, accepted отличается от inbox. Определены known retryable/ambiguous/crash/concurrency проверки, прежний лимит и отсутствие чувствительного exception text в логах.

Независимое ревью уточнения NTF009 до изменения sender, 2026-10-04: plan T032 задаёт row lock и commit захвата до POST, прежние состояния/идентичность, увеличение attempts, разрешение retry только при явном безопасном исходе в лимите пяти, ручную сверку unknown/crash и проверку конкурирующих процессов на настоящем PostgreSQL. Tasks фиксирует ту же область. Требование достаточно и проверяемо; качество требований **9 checked / 0 unchecked**, PASS. Это не приёмка будущего sender-кода. Подробности и исходный дефект — [notification-code-review.md](../notification-code-review.md).

Повторное независимое ревью реализации T032 завершено: bootstrap workspace и durable sender исправлены; общий локальный набор 164 PASS, включая настоящий production validator и PostgreSQL success/retry-limit/ambiguous/cancellation/concurrent/suppressed сценарии. Чеклист перечитан: **9 checked / 0 unchecked**. Подробности и точные границы доказательств — в заключительном разделе notification-code-review.md. Отметки остаются качеством требований; Postal принятие, получение письма, новый commit и полный выпуск здесь не подтверждаются.
