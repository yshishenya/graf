## Исправление и вызывающие пути

Последний helper наследует previous code при `promo_code=None` только при `not replace_promo`. Поэтому explicit emptyApply теперь даёт пустое значение и удаляет draft, вместо переноса старого кода с новымTTL. Исправление устраняет общий корень, не ослабляет тесты и не создаёт новый helper.

Все вызовы с replace просмотрены: discounts apply обозначает намеренный ввод, включая отказ; preview explicitApply/реальная непустая правка обозначают replacement, пустой Apply означает clear. Неизменённое period preview не обозначает replacement. Start/caller ошибки не задают replace и сохраняют проверенный предыдущий выбор как раньше. Поэтому изменение None не превращает обычную start-ошибку в очистку. Для отсутствующего/непригодногоB helper по-прежнему не возрождает rawA. Все operation redirects очищают выбор только при авторитетном переходе; statusGET не очищает его.

При недоступности разбор намерения и допустимого preview_action периода происходит перед ранним guard, результат `unavailable` передаёт намерение существующему helper. ExplicitApply/действительная правка сохраняют ограниченный новый ввод/период на300с; пустой Apply удаляет. Неизменённая старая форма использует проверенныйB и исходный expiry; явный period выбор допустим. Оба guard завершают запрос до расчёта акции/quote/провайдера. Не меняются денежные проверки владельца, цены, оферты, согласий, защиты повторов и ограничения провайдера. Подписанный draft содержит только ограниченный ввод/период/срок/связь, не финансовую полномочность; GET заново проверяет цену/применимость и не продлевает срок.

Сохранена предыдущая year withoutB поправка: прямые offer_changed/quote_changed используют B period при наличииB, иначе допустимый период формы. Код только из проверенногоB, согласия пусты, quote свежий. Две новые регрессии сохраняются вместе с настоящим Apply→start старого money-path теста без ослабления assertions.

FR017/018 и SC007 согласованы с текущим кодом и матрицей. Checker9/0 перечитан как качество требований, не как proof implementation. Новых задач реализации0; existingT017/T018 покрывают этот срез, T019/T011/T012/F278 не дублируются.
