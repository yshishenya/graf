# F280: тариф и оплата в одном месте

Дата: 16.10.2026. Основа: master2c7f93e6b, live v2026.10.16.3. Цель — меньше решений и переходов при сохранении всех денежных условий. Эта схема относится к кабинету оплаты; запись, встречи, AI-обработка и прочие настройки приложения не перерабатываются.

## Что мешает сейчас

Обзор → подписка повторяет состояние, обзор → usage → storage повторяет расход и лимит. «Продлить подписку» и «Оплатить следующий период заранее» представляют одно намерение двумя разными названиями способов списания. Номер INV на главной не помогает понять покупку. Все разделы выглядят равно важными. Четыре одинаковых интервала хранения вытесняют итог и согласие в подтверждении.

## Структура основного экрана

Сохраняется привычная оболочка GRAF. Одна ограниченная по ширине колонка, без сетки карточек показателей и отдельного внутреннего меню оплаты. Сверху вниз:

1. «Тариф и оплата».
2. Основная карточка: «Личный»/«Бесплатный»/«Пробный период», краткая ценность, оплаченная дата. Рядом одно главное действие: «Продлить подписку»/«Выбрать тариф»/«Проверить оплату» по фактическому состоянию. При включенном продлении можно оплатить следующий срок, но главное состояние — следующая сумма и дата. Сравнение тарифов — вторичная ссылка только там, где помогает выбору.
3. Строка автопродления: включено/выключено, следующая полная цена/дата либо отсутствие автоматического списания. «Настроить автопродление» раскрывает безопасное отключение и ссылку на явное включение. У отключения — пояснение сохранения доступа и отсутствия возврата. Для включения существующая страница служит подтверждением суммы/даты/карты, а не обязательной остановкой всего управления.
4. Хранилище: «715 МБ из 10 ГБ» + полоса, предупреждение при необходимости. «Изменить объем» раскрывает нативный select и расчет; «Открыть записи» — тихая ссылка. Без обязательного посещения usage/storage. Обработка без лимита или остаток бесплатного лимита — одна строка; резерв/точные размеры/правила и режим без аудио раскрываются, предупреждения не скрываются.
5. «Способ оплаты»: маскированная карта, раскрытие управления с подтверждением удаления и честным отсутствием замены. При необходимости — путь к подтверждению почты, без открытой полной частной почты в новых сводках.
6. «Платежи»: последняя сумма, статус, дата и ссылка «Платеж и чек». Номер INV остается внутри документа. «Все платежи» и помощь — обычные ссылки.

## Каждый путь и число обязательных переходов

| Намерение | До | После | Завершение |
| --- | --- | --- | --- |
| Понять срок/автопродление/расход | обзор + возможный переход в подписку/usage | обзор, 0 переходов | достоверное состояние |
| Продлить вручную | обзор → подписка → checkout | обзор → checkout | ЮKassa → существующий status |
| Добавить/уменьшить место | обзор → usage/storage → расчет | редактор на обзоре → расчет | существующее согласие/confirm |
| Отключить продление | обзор → подписка → submit | раскрытие на обзоре → submit | обратная связь и сохраненный доступ |
| Включить продление | обзор → подписка → раскрытие | раскрытие → существующее подтверждение | отдельное unchecked consent |
| Удалить карту | обзор → payment-method → раскрытие | раскрытие на обзоре → подтвердить | прежние серверные запреты |
| Найти чек | обзор → история → документ | обзор → последний документ; история для прежних | чек/безопасный refresh |
| Скидка | отдельная скидка либо checkout | промокод в конкретном оформлении | новая проверенная цена |

Старые URL работают для ссылок из писем/macOS и ошибок старых форм. Это совместимые специализированные входы; новые главные действия не требуют их посещения. Удаление прежних обработчиков и полная миграция уведомлений не нужны для сокращения пути.

## Подтверждение покупки

Заголовок говорит о действии. В начале: было → станет; срок; крупный итог сейчас; ниже полная цена следующего периода, автопродление и карта либо ЮKassa. Одинаковый по объему график скрывается в «Расчет по периодам»; график с разными объемами виден, так как меняет обещанную услугу. Срок и итог никогда не спрятаны. Один обязательный unchecked consent и одна финальная денежная кнопка с суммой. Назад ведет к редактированию объема на основном экране. Снижение: «Сохранить выбор без списания», 0 ₽ сегодня, дата после оплаченного срока, файлы не удаляются. Проверенная quote и все проверки сервера остаются прежними.

Checkout сохраняет месячную/годовую полную сумму, срок после предоплаченного времени, чек, скидку и обязательную оферту unchecked. Необязательное автопродление по утвержденному FR019 изначально checked: действие и последствия заметны, снятие сохраняется. Возврат ведет в основной обзор. Промокод остается необязательным раскрытием, автоматически открытым при применении/ошибке.

## Визуальная спецификация и доступность

Использовать действующие CSS tokens: цвета accent/surface/muted/border, размеры body/heading и радиусы GRAF. Основной контейнер сохраняет min-width:0; карточка плана отличается спокойной поверхностью и отступами, без новых шрифтов/иконок/изображений. Основной итог/название 24–28 px при базовом размере, второстепенный текст не меньше действующего body-compact; увеличивается пользователем. Отступы между смысловыми секциями 24–32 px, внутри 8–16 px. Данные выровнены, длинные подписи/цены переносятся; tabular-nums у сумм. Конкретные значения переиспользуют близкие действующие tokens/компоненты.

На ширине до760 px actions переходят под содержимое, длинная кнопка переносит текст и занимает доступную ширину. На320 px и zoom200% нет обрезания/выхода элементов и текста за окно; hidden overflow не считается исправлением. Sidebar изменения только в cabinet shell, admin не затрагивается. Основные цели около44 px, минимум24 px/допустимое расстояние по WCAG. Семантические section/h2, progress с названием, label/select/checkbox, native details, видимый focus-visible. Никаких hover-only данных или принудительного autoFocus. В раскрытии естественный Tab-порядок. Ошибки role=alert, подтверждения role=status; programmatic text фокуса и итог доступны. Без JS все главные формы/согласия/расчет работают; native +/- скрыты до JS, обычный select достаточен. Существующие reduced motion/forced colors сохраняются.

## Совместимость и реализация

Новые денежные POST/нативные маршруты не нужны. Сохраняются existing quote/idempotency/CSRF/owner/workspace locks/authority и почта чека. Shared builder для storage options переиспользуется главной и старой страницей; он только форматирует существующий каталог. Основной GET не создает quote/provider requests. Данные владельца добавляются в overview только после _can_manage_billing. Перенос формы не переносит ее деньги на GET. Возврат ошибок нового редактора различается фиксированным return_to=overview (только допустимый литерал); произвольного redirect нет. Старые формы без литерала сохраняют свое прежнее поведение. Функциональные handlers не переписываются.

## Почему не модальное окно и не один огромный экран

Нативные раскрытия сохраняют контекст без ловушки фокуса, закрытия клавишей и дополнительного JS. Отдельный серверный расчет полезен при сложной предоплате и без JS; это этап принятия денежного решения. История/документ/асинхронный статус самостоятельны по смыслу. Удаляются обязательные информационные остановки, а не возможность проверить условия. Это минимальный законченный срез, а не новый биллинг.

## Проверка качества

Обязательны browser/runtime-сценарии, собственный RED/GREEN, независимые обзоры требований/состояний/визуального результата. Человеческая SC005: объяснить без подсказки сколько/за что/до когда/повторные списания и найти отключение/чек. Технический PASS не подменяет этот результат. Сравнение дизайна с Krisp описывает наблюдаемую композицию, не приватный актуальный кабинет; код и активы GRAF независимы.


Уточнение перед реализацией FR061/062 по независимому замечанию: новые формы preview/purchases-confirm/cancel-storage-selection/cancel-renewal/delete-card передают только фиксированный `return_to=overview`. Сервер принимает только этот литерал как выбор места отображения, не произвольный URL; без него прежние формы и ссылки сохраняют свои redirects/error pages. Успех, conflict, renewal_on, unavailable и прочие действующие отказы возвращаются на основной обзор с понятным сообщением в соответствующем блоке; нужный editor/details открыт. Query/result сообщает результат попытки, но платежные, финансовые и разрешающие факты всегда читаются из текущего состояния БД. Метка сохраняется при повторной отправке формы ошибки. Redirect не создает новый quote/платеж. При потере прав срабатывает прежний owner_only и частные данные не раскрываются.

Для purchases-confirm метка влияет только на возврат сохранения объема без списания и прежних безопасных отказов. Успешная/ожидающая/неизвестная платная операция продолжает прежние hosted/status/recovery пути: обзор не заменяет подтверждение результата. Метка не сохраняется в денежных snapshot quote/operation/invoice.
