## Доказанное поведение

Шесть комбинаций: месяц → год и год → месяц, каждое направление — с `offer_changed`, `quote_changed`, `offer_required`. Каждая комбинация выполнена в Chromium и WebKit, при ширине 320 и 1280 пикселей, в двух вкладках.

Во вкладке A настоящий Apply сохраняет промокод на исходном периоде. Срок черновика фиксируется. Затем часы проверки черновика контролируемо сдвигаются на 42 секунды; вкладка B открывает настоящую GET-ссылку с другим `cycle`. Полученные HTML и cookie полностью формирует обработчик приложения. Проверены исходный expiry, новый подписанный период и правильная цена. Далее B открывает адрес без параметра периода и перезагружается: выбор остаётся новым, expiry не продлевается.

Старая вкладка A действительно отправляет старую форму. Для изменившейся оферты или расчёта POST получает 409; для непринятой оферты — 303 с настоящим последующим GET. Чтобы проверить серверный отказ при непринятой оферте, только временный браузерный сценарий устанавливает `noValidate` у старой формы; серверная проверка согласия остаётся включённой.

После ответа, адреса без параметра периода и настоящих перезагрузок обеих вкладок проверены:

- Промокод остался в поле и подписанном черновике.
- Выбранный период совпадает с более новым GET-выбором, даже когда старая вкладка отправляет иной период.
- При переходе на год: **9000 ₽ сегодня, 10000 ₽ за год при продлении**; при переходе на месяц: **900 ₽ сегодня, 1000 ₽ за месяц при продлении**.
- Первоначальный expiry не изменился, в том числе после контролируемого сдвига часов, POST 409/303 и перезагрузок.
- Оба согласия остаются пустыми после ответа; прежнее подтверждение не переносится на новый расчёт.
- Видно подходящее сообщение о следующем действии; списание или создание оплаты не имитируется.
- Нет горизонтального выхода за границы экрана.

На каждый движок получены **12 реальных POST 303 preview, 8 реальных POST 409 start, 4 реальных POST 303 start, 12 изменений периода через GET**. Действия проверяют обработчик ASGI с настоящими браузерными cookie и CSRF. Мост не рисует HTML, не следует за перенаправлениями и не использует собственный cookie jar вместо браузера.

Вызовы YooKassa запрещены существующей фикстурой: любой вызов платёжного клиента немедленно провалил бы тест. **Вызовов провайдера 0; внешних запросов браузера 0.** До и после каждого случая сравнены все столбцы заранее существующих `BillingOperation`, `BillingInvoice`, `PromotionRedemption`; снимки равны. Дополнительно проверены количества: одна историческая операция, один исторический счёт, ноль погашений промокода. Новые расчёты покупки допустимы и не являются денежными операциями.
