## Сверка реализации и требований

- FR-017 и уточнение отсутствующего draft: оба прямых отказа `offer_changed`/`quote_changed` передают допустимый период отправленной формы в renderer. Год без промокода не сбрасывается в месяц.
- Сохранение периода не возвращает старый код A: `checkout_promo_code` берётся только из проверенного B; прежнее присваивание промокода через request.state отсутствует. Нет переноса старых согласий, суммы или quote в draft.

Автоматическая проверка финансовых таблиц выполняется после каждого теста. Существующий денежный тест теперь действительно применяет SAVE10 до start; прежние утверждения 9 000 ₽/год/актуальная оферта/продление 10 000 ₽/согласия/provider0 сохранены.
- FR-018 не ослаблено: HMAC, ограниченный набор полей, code ≤48, срок `now < expiry`, связь с проверенными user/workspace/session и отказ при отсутствующем секрете/сессии сохранены. Код не переносится в URL, сохранение содержит только ввод/период/срок/связь; GET не обновляет срок. Цена и применимость проверяются заново. Согласия не сохраняются.

Start-ошибки не заменяют актуальный B старым A, подтверждённое продолжение существующего платежа прекращает draft. Последняя поправка этого поведения не меняет.
