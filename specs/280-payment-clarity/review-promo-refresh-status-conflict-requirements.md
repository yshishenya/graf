## Точная матрица, необходимая для реализации и окончательного обзора

1. **Просмотр старого платежа.** В синтетической проверенной сессии установить подписанный B с годовым периодом; открыть доступный старый failed и отдельно canceled status. Ответ не удаляет/не перевыпускает текущий черновик. Два последующих GET checkout без query сохраняют B, year и исходный expiry; цена свежая и согласия пусты. При такой проверке исторические invoice/operation уже существуют: доказательством отсутствия побочного эффекта служат неизменные записи/счётчики, а не неправдивое требование нуля всех строк. Провайдер не вызывается. Отдельно сохранить регрессии очистки на авторитетном operation redirect.
2. **Прямой offer_changed409.** Открыть форму A (код и период отличны от B), явно применить B в той же сессии, отправить прежний start A с устаревшей офертой. В409 отрисован B и период B, причина изменившейся оферты сохранена, расчёт выполнен заново, согласия пусты. Повторные GET не возвращают A; исходный expiry B не продлён. Старый quote не разрешает платёж.
3. **Прямой quote_changed409.** Аналогичная последовательность с устаревшим/несоответствующим расчётом при действительной оферте. Проверяется именно прямая отрисовка409, а не соседний303 обработчик. Сохраняются B/его период, причина изменившегося расчёта, пустые согласия, первоначальный срок и отсутствие новых финансовых записей/провайдера.
4. **Граница/непригодный B.** Для обоих409 проверить обычный неизменённый выбор и B на t+299/t+300; также отсутствие, повреждение и хотя бы релевантную смену проверенных границ B. Старый A не восстанавливается из request.state, не получает новый срок и не становится предварительно разрешённой скидкой. Причина409 остаётся причиной отказа; сообщение не утверждает успешный платёж.
5. **Изменившаяся акция B.** После применения B изменить его применимость и отправить старый start A. Система не использует A как незаметный запасной код и не разрешает оплату по старому расчёту. Ошибка B доступна для исправления. Сохранение причины409 должно проверяться вместе с ошибкой применимости, поскольку текущий шаблон сначала показывает promo_preview_error: сохранение только внутреннего result без доступного сообщения не доказывает ясность пользовательского пути.

Последний пункт является конкретизацией уже заданного «причина сохраняется»/FR-005/011/017, не новым платёжным требованием. Предварительное чтение выявляет существующий порядок сообщений, но реализация ещё не выполнена, поэтому этот отчёт не выдаёт новую кодовую ошибку за подтверждённое финальное замечание.
