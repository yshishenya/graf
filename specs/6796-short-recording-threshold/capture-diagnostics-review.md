## Проверка реализации T008

**Approved: подтверждённых замечаний к узкому diff нет.** Независимо
прочитаны изменения двух runtime файлов и двух проверок существующего
gap-prefix теста; смежный код проверен только для потока, валидации и
создания новой timeline. Имя runtime в плане исправлено.

- Источник использует один флаг на runtime, устанавливаемый до NSLog.
  Reset обоих диагностических полей выполняется на outputQueue до
  регистрации callbacks; чтение и обновление идут на той же serial queue.
  После первого события новые события не выводятся.
- Timeline использует один флаг на экземпляр, общий для обоих источников.
  Writer создаёт новый экземпляр на каждую запись и обращается к нему
  через существующую serial queue. Нового разделяемого состояния нет.
- В журнал попадают числа кадров, частота, число каналов, относительные
  интервалы, фиксированное имя источника и булевы признаки. PTS хранятся
  только в памяти и не форматируются. Аудио, пути, ID встречи, manifest
  и сетевые вызовы не добавлены.
- Форматы NSLog согласованы с передаваемыми значениями на целевом Darwin:
  `%lld` для Int64, `%ld` для Int, `%g` для Double, `%@` для имени источника;
  `%d` получает только 0/1. Фактическая строка timeline в тестовом журнале
  корректно показывает expected=480, requested=960, rate=48000, channels=1.
- Извлечение вызывается один раз. Его результат, исходные PTS/сэмплы,
  маршрутизация batch и существующие ветви отказа не изменены. Положительное
  число каналов проверяется до нового деления. Диагностика timeline вызывает
  чистую проверку прежнего допуска, затем прежний append без подмены значений.

Замечание reviewer о синхронных файловых операциях устранено:

с приоритетом utility; только внутри неё выполняется writeRaw. Очереди
ScreenCaptureKit и writer не вызывают запись/ротацию журнала. Бюджет
помечается до вызова обработчика на исходной serial queue и не зависит
от времени выполнения фоновой записи.

Подключение проверено по реальным путям запуска: ContentView передаёт
обработчик в SystemAudioCaptureService, который сохраняет его в фабрике
и передаёт ScreenCaptureKitSystemAudioRuntime. Общий Start создаёт новый
LocalRecordingWriter с обработчиком, затем writer передаёт его новой
RecordingAudioTimeline. Начальный пустой writer заменяется до startAsync;
он не оставляет рабочую запись без диагностики.

Все новые параметры optional, nonthrowing, по умолчанию nil. Параметр
timeline расположен перед echoProcessor/processEchoFrame, поэтому прежнее
назначение замыкания после вызова конструктора сохраняется. Ограничение
событий, reset, формат полей и проверки PTS остались прежними. Формирование
строки не включает сэмплы или абсолютные временные метки. AppLog использует
прежние очистку строки, путь и ограниченный writer; BoundedLogFileWriter
относительно базового коммита не изменён.
