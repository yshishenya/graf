Setter и применение политики сериализованы одним `interruptionLock`:
проверка флага и `applyShortRecordingPolicy` выполняются внутри одной

### CR1 — сохранить короткий фрагмент при Quit во время ожидания Stop

Место: `apps/macos/RecApp/App/TwoBrainRecApp.swift:2326`.

После `await systemAudioCaptureService.stop()` обычный Stop всегда передаёт
writer исходный `reason` (userRequested/meetingEnded). Пока этот await ждёт
закрытия аудиопотока, пользователь может вызвать Quit: обработчик выхода
установит `terminationCleanupInProgress=true` и запустит независимое
`releaseForTermination`. Если обычный stopRuntime завершится первым, writer
получит штатную причину и устойчиво пометит короткую запись для удаления.
Путь app-exit затем увидит `isRecording=false` и уже не сохранит фрагмент.
Выход, начавшийся до решения, таким образом может удалить аудио вопреки
FR-004.

Минимальное исправление: на границе вызова writer не разрешать политику
короткой записи, если уже началась termination cleanup; сохранить
доступный фрагмент через прежнюю семантику stopReason=nil. Отдельно назвать
момент, после которого штатное решение уже принято и не отменяется
позднейшим Quit. Добавить проверку Stop → ожидание остановки источника →
Quit → возврат источника, с сохранённым аудио и отсутствующим маркером.

## Проверенные опасные пути без подтверждённого дефекта

- Marker публикуется атомарно с итоговым manifest до возврата writer,
  статус blocked закрывает старый upload path.
- Ошибочные/неполные/восстановленные результаты не проходят предикат;
  точная граница — 480000 кадров канонического 16000 Hz WAV.
- Saving явно исключён из отправки, текущая очередь и marker повторно
  проверяются перед переходом в uploading.
- Прямой enqueue отвергает и переданный marker, и более свежий marker
  на диске. После полного удаления каталога старый непомеченный manifest
  не проходит существующий guard наличия manifest файла.
- Очистка отказывается от неизвестной/начатой передачи, проверки путей
  и символических ссылок выполняются до удаления строки. Строка
  сохраняется на диске как удалённая перед удалением аудио; manifest
  удаляется последним. При частичном удалении оставшийся marker даёт
  scanner повторить безопасную очистку.
- `completeStop()` расположен после writer, но подтверждённого текущего
  пути ошибки этого перехода не найдено: Start/Stop защищены флагами,
  обработка уровней повторно проверяет их после await, app-exit не
  меняет CaptureSessionController. Сам по себе порядок не оформлен
  отдельным замечанием. При будущих новых мутациях controller эта
  граница потребует повторной проверки.
- Notice не использует recordingBlocker, не делает окно key/main,
  отменяет предыдущий таймер и снимается при Start. Отдельная ручная
  проверка VoiceOver, скрытого окна и полного экрана остаётся в quickstart.
