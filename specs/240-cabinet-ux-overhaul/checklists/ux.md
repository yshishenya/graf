# UX Review Checklist: Полная переработка кабинета GRAF

**Purpose**: Проверка полноты, ясности, измеримости, согласованности и
прослеживаемости требований UX/UI/IA и сравнения с эталоном Krisp.

**Created**: 2026-09-04

**Feature**: [spec.md](../spec.md)

**Requirements review**: 2026-09-06, независимый рецензент по явному поручению
пользователя; рассмотрены Clarifications FR-009a–d, SC-007–008,
корректирующий проход плана и T036–T040.

**Targeted re-review**: 2026-09-06, повторно рассмотрены только
CHK002/CHK004/CHK005/CHK008 по подразделу спецификации
«Уточнение критериев представления для корректирующего прохода».

> Чеклист принадлежит рецензенту. `[x]` означает одобрение качества требований,
> а не завершение реализации или визуальной проверки продукта. Исполнитель
> читает отметки как условие допуска и не меняет их самостоятельно.
> По поручению пользователя исходные утверждения о готовом интерфейсе заменены
> вопросами о требованиях; все 15 идентификаторов и предметы проверки сохранены.

## Information architecture

- [x] [CHK001] Определены ли общая иерархия и обозначение текущего контекста для
  списка, detail, настроек, billing, shared и auth? [Полнота, Spec FR-002/FR-006,
  US1–US3; UI Surface Contract §Surface matrix]
  Основание: FR-002 перечисляет уровни иерархии, FR-006 распространяет их на
  остальные поверхности; сценарии описывают контекст списка, встречи и настроек.
- [x] [CHK002] Названо ли главное действие каждой поверхности и определено ли,
  как его визуальный приоритет отличается от вторичных действий в соответствующих
  состояниях? [Ясность, Spec FR-002/FR-004/FR-005, US1–US3;
  §Уточнение критериев представления для корректирующего прохода; PRD §29]
  Основание повторного решения: таблица задаёт главные и вторичные действия
  списка, готовой/ограниченной встречи, настроек, оплаты, общей встречи и входа.
  Приоритет выражается существующим заполненным акцентным оформлением;
  вторичные действия нейтральны. Серверные условия и набор действий сохраняются.
- [x] [CHK003] Заданы ли требования согласованности навигации standalone и
  embedded, допустимые различия и необходимость их обоснования? [Согласованность,
  Spec FR-008/FR-011, Edge Cases; UI Surface Contract §Review rules]
  Основание: требуется одна IA при возможных различиях размеров оболочки,
  отдельная проверка обоих режимов и объяснение намеренных отклонений.

## Visual hierarchy and interaction

  границ и состояний элементов управления, позволяющие объективно оценить их
  согласованность между крупными поверхностями? [Измеримость,
  Spec FR-003/FR-006/FR-009;
  §Уточнение критериев представления для корректирующего прохода;
  Plan Summary; PRD §29]
  Основание повторного решения: геометрия зафиксирована по F240
  `8eb1bb8078140d51ae910197a613ce0999a98ed9`, перечислены размеры текста,

  Это проверяемая граница корректирующего прохода, а не визуальное одобрение базы.
- [x] [CHK005] Однозначно ли требования охватывают различимость hover, focus,
  pressed, selected, disabled и error без опоры только на цвет, включая доступные
  действия, похожие на отключённые? [Полнота, Ясность,
  Spec FR-003/FR-009/FR-009a, US4;
  §Уточнение критериев представления для корректирующего прохода; PRD §29]
  Основание окончательного решения 2026-09-06: все состояния перечислены с
  признаками; выбранное состояние теперь MUST иметь видимый нецветовой признак
  (галочку, текст, подчёркивание или различимую форму/контур). Применимые
  `aria-current`/`aria-selected` явно дополняют его. Возможность заменить видимый
  признак только ARIA устранена; оставшийся пробел качества требований закрыт.
- [x] [CHK006] Определены ли требования к длинным заголовкам, email, ошибкам и

  [Граничные случаи, Spec Edge Cases, FR-008, SC-001]

  обязательные действия; размеры и отсутствие переполнения заданы явно.

## Accessibility and responsive behavior

- [x] [CHK007] Определены ли требования доступных имён, landmarks и отношений
  tab/tabpanel/dialog/menu для всех ключевых элементов управления?
  [Полнота, Spec FR-007, US2/US3, SC-002; UI Surface Contract §Functional no-change boundary]
  Основание: требования семантики, имён и сохранения идентификаторов и отношений
  сформулированы; охват включает клавиатуру и средства чтения с экрана.
- [x] [CHK008] Полностью ли определены видимость и порядок фокуса, его возврат
  после Escape/закрытия и поведение reduced-motion без потери понятности
  состояния? [Полнота, Spec FR-007/FR-009a, US3, Edge Cases;
  §Уточнение критериев представления для корректирующего прохода;
  Plan §Constitution Check; Quickstart §Review matrix; PRD §29]
  Основание повторного решения: требования фокуса дополнены явным отключением
  декоративного въезда, масштабирования и плавных переходов при reduce;
  содержимое, выбор, статус и доступные действия остаются видимыми без ожидания
  анимации. Ожидаемое поведение определено без изменения функциональности.
- [x] [CHK009] Определены ли измеримые требования отсутствия переполнения,
  обрезания обязательных действий и нечитаемого текста для 320/390/768/1024/1440,
  обеих тем, standalone/embedded и сочетаний явной/автоматической темы с ОС?
  [Измеримость, Покрытие, Spec FR-008/FR-009a–c, SC-001/SC-007/SC-008;
  Quickstart §Review matrix; PRD §29]
  Основание: размеры и охват заданы; обычный текст требует 4.5:1, значимые
  иконки и фокус — 3:1, с исключением действительно отключённых элементов.
  PRD требует WCAG 2.2 AA также для controls и границ, необходимых для их
  распознавания. Явная тема приоритетна, автоматическая использует ту же палитру;
  перечислены компоненты исправления, а полная исходная матрица обязательна.

  IA, плотность и состояния взаимодействия — и запрет извлечения закрытых

- [x] [CHK012] Однозначно ли запрещено ослаблять видимые запись/Stop, согласие,

## Решение рецензента и границы

- Качество требований: одобрены 15 из 15 критериев, открытых пунктов нет.
  Последнее рассмотрение 2026-09-06 ограничено уточнением selected в CHK005;
  остальные 14 решений сохранены без повторной оценки. Допуск high-risk-product
  по этому UX-чеклисту получен; это не заменяет analyze, issue-sync и последующие
  проверки реализации, PR и release.
- Историческая проверка реализации F240 остаётся неполной. Повторный аудит
  светлой темы от 2026-09-06 опроверг старый theme PASS. Отметки этого чеклиста
  не подтверждают исправление CSS, свежую визуальную приёмку, нативный WKWebView,
  выполнение T036–T040, завершение полной матрицы, готовность PR или merge.
- Фактические результаты принадлежат `light-theme-qa.md`, `design-qa.md` и
  `validation.md`; проверка `/desktop/` в браузере не заменяет нативный WKWebView.
  Для каждого замечания аудита требуется сохранить связь с требованием,
  корректирующей задачей и новым доказательством, не используя старый PASS.
- Рецензия оценивает тексты требований и не изменяет отметки задач. Дополнения
  других исполнителей в `spec.md`, `plan.md` и `tasks.md` сохранены без изменений.
  После изменения оснований затронутые критерии требуют повторного рассмотрения.
