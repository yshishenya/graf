# F224/T009: независимое ревью исправления selected lock

Дата: 27.10.2026. PR #7758, discussion_r4390265394.
Ветка `codex/224-preserved-archives`; проверена локальная дельта относительно
`d925a9a6444b6020300f0cd4f74e6fc4fe89c8db`. Lane: high-risk-product.

**Решение: APPROVE, открытых замечаний 0.** Исправление соответствует отдельно
принятым требованиям: классификация отказывает при отсутствующем безопасном
selected lock без создания файла и изменения исходных снимков.
Это приёмка узкого изолированного кода по контрольным суммам ниже, не текущих
GitHub SHA/base checks, реального принятия состояния или всей F224.

## Проверенная дельта и все callers

В `scripts/dev-harness.py` изменены ровно две строки: у classified operational
locks `create=False` для selected и preserved-state; диагностика общего
открытия без создания теперь `Dev state requires its existing safe lock`.
Параметры `os.open`, проверки owner/type/прав/nlink/inode, `flock`, выдача и
закрытие fd не менялись. Снимок root не исключает lock или метаданные каталога.

Проверены все четыре прямых caller `_state_file_lock` в проектном коде:

| Caller | Результат проверки |
|---|---|
| `operation_adopt_state`, registration lock | Прежнее создание только штатного `repository-registration.lock` вне классифицируемых roots; порядок регистрации сохраняется. |
| `operation_adopt_state`, classified entries | Все не-artifact-only locks открываются с `create=False`; `O_CREAT` отсутствует у каждого operational lock, включая selected. Полный план/деревья повторно сверяются после каждого ожидания. |
| `operation_adopt_state`, без классификации | Прежнее создание selected lock остаётся только при `classification is None`. Оно не достижимо из classified ветки. |
| `state_lock` | Прежняя инициализация обычных операций, запись held fd, повтор ownership и восстановление контекста не менялись; T010 не ослаблена. |

Первоначальная классификация сохраняет полный исходный root set, физическую
идентичность и tree SHA. Повторная проверка перед binding остаётся; публикация
binding не достижима после отказа открытия lock. `root.mkdir(exist_ok=True)`
не создаёт root в допустимом classified сценарии: первоначальная проверка
уже требует существующий root, полный снимок и существующий operational lock.
Повтор уже опубликованной идентичной привязки возвращает прежний результат
до classified lock loop; этот договор идемпотентности не изменён.

В `_classification_tree_digest`, `_classification_recheck`, `_load_active`,
`_validate_manifest` и runnable schema изменений нет. Современный полный
manifest обязателен; исторический четырёхкомпонентный ROOT1 не принят и не
получил совместимость, override или обход.

## Проверка шести новых случаев

| Случай | Что фактически проверяет код теста |
|---|---|
| Missing selected lock до снимка | План переснят уже без lock; ожидаются точная диагностика, отсутствие созданного файла, полное совпадение обоих tree SHA и отсутствие binding. Изменяющие внешние команды запрещены spy. |
| Selected lock удалён непосредственно до открытия | Детерминированная подмена на границе `_state_file_lock` удаляет файл; снимки для контроля собственных эффектов сняты после этой искусственной внешней мутации. Команда не должна создавать lock заново или менять roots. Это не самостоятельная межпроцессная гонка. |
| Обычная инициализация без плана | Несуществующий selected root получает штатный lock и действительный binding; классификация не затронула прежний путь. |
| Selected symlink lock | Ранний отказ до использования ссылки; полные снимки неизменны, binding и внешний файл отсутствуют. |
| Selected unsafe lock | Права `0666` дают отказ; снимки и отсутствие binding подтверждены. |
| Selected inode заменён во время ожидания | Настоящий отдельный процесс держит исходный `flock`, второй доходит до ожидания именно этого inode; файл переименован/заменён, после освобождения команда отказывает без binding. |

Последний случай расширяет прежнюю межпроцессную проверку preserved lock;
старые варианты tree/archive/build/link/metadata/root set/plan/inode сохранены.
Этот процессный тест проверяет отказ и отсутствие binding; он не сравнивает
полный root с исходным снимком после намеренной подмены inode. Сохранность
без собственных изменений отдельно подтверждают missing-lock тесты,
положительные полные снимки и прежние crash/невалидные-plan сценарии.

Положительный `test_classification_preserves_multiple_states_and_binding`
сравнивает независимо закодированные полные снимки до/после успешной
классификации и байты binding после идемпотентного повтора. Snapshot включает
inode lock; поверхностного сравнения только имён/manifest здесь нет.
У unsafe selected ранняя `_checked_state_path` не допускает external app/Docker
действий; изменяющих вызовов до этого отказа в прочитанном пути нет.
