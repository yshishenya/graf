# F224: исследование принадлежности и остатка исходной задачи

Дата: 2026-10-16. Исходник: `f4b38141af2fad64bae219e8c012b0a54f237491`.
Исследование выполняли два независимых read-only агента по Phase 0
`speckit-plan`. Код, приложение и живое состояние не менялись.

## Решение: сохранить физическое состояние и его блокировку

Принято для независимой проверки проекта: одна неизменяемая машинная запись
`repository-state.json` в общем каталоге GRAF Dev связывает канонический
репозиторий с одним существующим каталогом harness. Существующие manifests,
runtime.json, secrets, журналы, data_root, архивы и inode promote.lock остаются
на месте. Это источник принадлежности единственного стенда, без псевдонима,
символьной ссылки, дополнительного workflow или переноса файлов.

Основание: старые manifests вообще не содержат origin. Совпадение source SHA
не доказывает владельца: fork может иметь тот же коммит. Поэтому автоматическое
присвоение старого состояния текущему origin запрещено. Нужна явная одноразовая
операция adopt-state существующего harness после проверки оператором.
Её точный контракт: [contracts/state-ownership.md](contracts/state-ownership.md).

При принятии: registration lock, затем прежний promote.lock; перечитывание
ожидаемого active SHA и целостности состояния после ожидания; атомарная запись
binding. Registration lock сериализует только регистрацию, не является вторым
правом изменения приложения. Обычные операции сохраняют прежний promote.lock
и перечитывают неизменность binding после ожидания. Разные roots не принимаются
автоматически. Идентичный повтор регистрации не меняет состояние.

Принудительное завершение перед публикацией оставляет отсутствие binding;
после публикации — одну полную запись. Исходное состояние не перемещается.
Неуспешный/неполный binding не разрешает обхода; неизвестная запись требует
отдельного восстановления, а не перезаписи или удаления данных автоматически.

## Решение: ограниченная канонизация GitHub origin

Реализация остаётся в scripts/dev-harness.py и использует имеющиеся subprocess,
urlsplit и re. Допускаются HTTPS, SSH URL и SCP-форма GitHub owner/repo,
необязательные .git/конечный slash; host и GitHub owner/repo приводятся к одному
регистру. Ровно один raw origin и соответствующий effective origin; скрытая
Git insteadOf-подмена на другой репозиторий отвергается.

Отказ: Git error, отсутствующий/множественный origin, иной host/protocol,
неподдержанный порт, HTTPS userinfo, пароль, query/fragment, control characters,
неоднозначные escape/path forms. Исходный URL и ошибки с его содержимым в
диагностику не попадают. Внешняя сеть для определения принадлежности не нужна.
Нормализаторы claim-feature.py и issue_canon_common.py недостаточно строгие
для этой границы; новый общий слой/зависимость не нужен.

## Решение: сохранить закреплённые адаптеры без обхода startup guard

_checkout_adapter уже передаёт прежнему адаптеру self.state. Однако прежний
start-dev-runtime.sh запускает собственный schema-start-guard, который заново
вычисляет legacy root. Поэтому новый контроллер до stop/install/Docker mutations
проверяет resolver точного, проверенного по tracked bytes старого модуля в
subprocess с cwd его checkout. Несовпадение с binding root — ранний отказ,
без подстановки переменных, исправления frozen кода или пропуска guard.
Проверяется только resolver; преждевременный полный schema gate не вызывается.

Для независимых clones физическое равенство git-common-dir в _checkout_adapter
заменяется строгим равенством canonical origin. Clean exact SHA, проверка всех
tracked runtime bytes, подписей и runtime-definition digest сохраняются.
Используемые active/rollback checkouts сохраняются по действующим правилам.

Новый код не способен технически запретить произвольный самостоятельный старый
контроллер, который binding не читает. До реального принятия требуется
согласованное отсутствие старых controller jobs; guidance прямо запрещает их
самостоятельный запуск. Уже работающий старый процесс на сохранённом
promote.lock правильно сериализуется с принятием. Гарантия не распространяется
на произвольный старый бинарник, запускаемый в обход действующих правил.

## Решение: искусственный каталог не управляет общими образами

prune без --live сейчас может вызывать docker image rm; проверка global owner
выполняется после локальных удалений. Для явного изолированного состояния
самый короткий безопасный контракт — никогда не удалять общие Docker tags.
Файловые операции остаются внутри проверенного временного root. Canonical
операции требуют binding до первой записи/сборки/установки/удаления; запрет
live override должен срабатывать ещё до state_lock, который создаёт файлы.

## Отвергнутые варианты

- origin hash → новый root: теряет active state/старый lock и ломает frozen guard.
- Автоматический выбор по basename, последнему manifest, свежести или SHA:
  не доказывает принадлежность.
- Ссылка со старого пути, hardcoded graf→crisp, fallback на repo_root:
  создают псевдоним/обходной путь или сохраняют исходный fail-open.
- Новый механизм управления приложением/миграциями: уже имеется в текущем коде.

## Исследование T010, 26.10.2026

Текущая основа8037c448935441051998995c7a5444a4f9a549ad. Настоящий SIGKILL
контроллера с подменёнными внешними действиями подтвердил3неполные границы:
после stop — runtime остановлен; после install — appB/activeA;
перед pointer — appB/runtimeB/activeA и прежняя копия уже удалена.
Во всех трёх status ошибочно сообщает active, recovery receipt отсутствует.
Контрольный успех и прерывание после pointer согласованы. Все5 сохраняют
защищённые байты и inode lock. Это не доказательство причины отсутствия
настоящего установленного Dev. Probe исполняет реальные operation_promote,
GrafLocalAdapter.promote и operation_status, не создаёт app bundle и запрещает
внешние команды. SHA256 harness:
4d396a1ab7c3a7abaaee9b9f0cb97eca9872483ded9d81a1d18afdc545a31d50.

Независимый исследователь подтвердил ту же дыру в rollback, преждевременную
очистку, same-active bypass, прямые retention/build и окно Popen→runtime.json.
Отдельный опыт darwin с двумя настоящими процессами подтвердил: subprocess
без pass_fds освобождает flock после SIGKILL родителя; с наследованием того же
fd удерживает lock до своего выхода. Обе проверки сохраняют inode. Это
исследование механизма, ещё не приёмка настоящих installer/Compose scripts.

Решение: расширить существующую квитанцию и повторить существующую команду;
для коротких мутаций наследовать operational fd, для долгого backend повторно
использовать pipe gate. Причина: одна точная цель и один lock достаточны,
поэтапное продолжение/новая команда/вторая схема журнала не нужны.
Marker-only отвергнут: не исправляет runtimeB/activeA и first install;
try/except-only не ловит SIGKILL. Старый frozen controller как обход отвергнут.
Полный договор — [contracts/promotion-recovery.md](contracts/promotion-recovery.md).

Внешние воспроизводимые материалы: каталог Documents/Codex/2026-10-26/
graf-f224-crash-recheck, файлы probe.py/results.json и lock-probe.py/
lock-results.json. Долговечный профильный тест и собственная матрица будут
добавлены только после checklist/analyze/sync; старые результаты не станут
доказательством нового кода.


## T009, повторная проверка применимости — 27.10.2026

Решение: сохранить выбранный root и все пять соседей на месте; принадлежность
выбранного root доказывается отдельно, невыбранным не присваивается. Старый
проект требовал владельца каждого root и app-only состав, поэтому неприменим
без явного уточнения. Новый договор не делает проверенные app источником
доверия для build неизвестного происхождения.

Основание: metadata-only обход шести roots и 171 ссылки трёх build показал
относительные существующие цели с каждым префиксом внутри своего build;
absolute/escaping/broken/cyclic=0. Это проверка предикатов, не запуск классификатора.
ROOT0 имеет complete schema journal; отсутствие установленного Dev и неактивные
контейнеры не доказывают владельцев соседей или отсутствие будущих писателей.
Независимый предварительный разбор разрешает узкое архивное правило, но требует
отдельно принять уточнение unknown-соседей; прежние125/306PASS его не принимают.

Альтернативы отклонены: удалить/перенести build ради PASS; запустить архивный app;
присвоить все roots по общему SHA; игнорировать соседей; выбрать новое пустое
состояние. Они теряют данные, обходят принадлежность или заводят второй путь.
Новая подсистема не нужна: текущие registration/operational locks, snapshot,
проверки состояния и единственная immutable binding достаточны в объявленной
границе исключённых самостоятельных писателей. Реальное принятие ещё не выполнено.
Безопасные внешние результаты: Documents/Codex/2026-10-27/graf-repository-audit/
f224-classification-feasibility-current.json, f224-build-link-prefix-check-current.json
и f224-classification-design-review-current.md. Частное содержимое roots не копируется.

## T009: stopped same-active — исследование29.10.2026

Причина: на609633cd текущий `_ordinary_transition` требует SHA target для
controller, а schema transition требует живого predecessor. Active698ebfa
остановлен, установленного app нет. Проверены9/9 сохранённых image IDs и5/5
source labels, но это не проверка настоящей схемы БД или запуска.
Отдельная проба8/8 показала: frozen698eb guard не читает ordinary receipt,
текущий reader отвергает split SHA; обе версии сохраняют schema priority.
Границы пробы сохранены во внешнем f224-frozen-startup-compatibility-result-20261029.json.

Решение: существующий promote+previous-checkout, одно optional поле receipt
для фактического controller SHA и узкий допуск двух полных frozen файлов
по [договору](contracts/promotion-recovery.md#t009-восстановление-остановленного-same-active-текущим-инструментом).
Независимое source research подтвердило source-only образец
`_assert_launch_tooling`, готовый `_checkout_adapter` и проверку orphan
контейнеров `_schema_container_ids`; новый общий helper/менеджер не нужен.
Контроллер выполняет все мутации и проверяет durable runtime до pipe byte.
Отвергнуты самостоятельный старый controller, подмена SHA/root/guard,
классификатор AST, общий реестр startup и холодная миграция вместо отдельной
настоящей приёмки прежнего runtime. Код не реализован; прежний reviewer45/7
