## Принятая граница

FR-007 и договор явно сужают условия первоначального принятия с
`--classification`: безопасные operational locks выбранного и сохраняемых
состояний уже существуют до полного снимка; открытие без `O_CREAT`.
Отсутствие lock даёт отказ без создания и без изменения любого снимка root.
У artifact-only operational lock не требуется и не создаётся.
Обычная инициализация без классификации сохраняется. Договор отдельно
сохраняет идемпотентность уже опубликованного binding; новая проверка
не должна менять этот прежний путь.

Уточнение закрывает проектный пробел, выявленный при чтении текущего кода:
`operation_adopt_state` ещё открывает selected lock с `create=True`, после
чего собственная повторная проверка замечает изменение каталога. Нынешний код
не принят по новому условию. Изменить существующий аргумент открытия и точную
диагностику достаточно; новый параметр команды, дополнительный режим,
исключение lock/метаданных из снимка или переснятие эталона после мутации
не требуются. Сохраняются порядок registration → operational, inode,
передача fd T010 и повтор проверки полного плана/деревьев после ожидания
и перед binding.

Семь обновлённых документов полностью прочитаны и согласованы. Модель данных
не требует изменения: формат binding и состав снимка остаются прежними.
Исторические ограничения/разрешения плана относятся к явно датированным
прошлым этапам; текущий раздел T009 сохраняет общее разрешение владельца.

## Обязательные следующие доказательства

1. RED на нынешнем коде: план снят без selected lock; проверка должна обнаружить
   создание файла/изменение снимка, а не удовлетвориться любым исключением.
2. GREEN: точный управляемый отказ, lock не появился; полные снимки selected
   и всех соседей неизменны, binding и внешние действия отсутствуют.
3. Все существующие locks: успешная классификация с прежними inode и снимками.
4. Без классификации: прежняя разрешённая инициализация selected lock работает.
5. Удаление lock до открытия, подмена inode при настоящем ожидании и небезопасный
   selected lock дают отказ без пересоздания; прежние sibling случаи сохраняются.
6. Регрессии fd T010, schema/recovery/manifest и идемпотентности; независимое
   итоговое ревью реализации, converge и новые точные SHA/base проверки PR.

Исторический ROOT1 с четырьмя компонентами не получает нового допуска.
Полный современный manifest остаётся обязательным. Его текущий отказ означает
незавершённое реальное принятие; T009/#7640, T011/T012/T013 и #6180 открыты.
Результаты тестов, CI, binding, runtime, TCC, release или deploy этим отчётом
не подтверждаются. Тесты и приложение reviewer не запускал, GitHub не менял.
