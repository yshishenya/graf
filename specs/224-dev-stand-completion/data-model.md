# F224: данные принадлежности стенда

## Машинная привязка

Один файл repository-state.json в стандартном машинном каталоге GRAF Dev:

- schema_version: graf-dev-repository-state.v1;
- repository: canonical github.com/owner/repo без credentials;
- state_root: абсолютный реальный путь к единственному принятому harness;
- adopted_active_sha: полный активный SHA при принятии либо null для нового
  пустого стенда;
- adopted_at: время принятия UTC.

Запись создаётся атомарно под registration lock и прежним operational lock.
После публикации обычные операции её не меняют. Повтор с теми же repository/root
идемпотентен; другая привязка запрещена. Поля состояния проверяются строго,
неизвестный формат/повреждение/символьная ссылка означают отказ.

Принадлежность не является доказательством активного SHA или held lock;
они проверяются независимо. Подтверждение исторического владельца исходит от
оператора: это нельзя вывести из legacy manifest или совпадающего коммита.

## Существующее состояние

Форматы active-manifest.json, manifests/*.json, runtime.json,
schema-transition.json, rollback-required.json, data_root и secrets не меняются
ради принадлежности. Их содержимое, расположение и материалы отката сохраняются.
Принятие проверяет согласованность active pointer/manifest/runtime и отсутствие
незавершённого перехода. При требовании восстановления binding не публикуется.

У promote.lock сохраняются путь и inode. Новый контроллер отвергает symlink,
неправильный тип/владельца и подмену inode между открытием и получением lock.
Прежний процесс, удерживающий этот lock, завершает операцию до принятия;
ожидаемый active SHA проверяется заново после ожидания.

## Переходы принадлежности

1. UNBOUND: canonical/shared операции заблокированы; явные изолированные
   файловые проверки доступны без app/Docker/shared tags.
2. ADOPTING: registration lock → прежний promote.lock; проверка оператора,
   путей, всех стандартных непустых roots и ожидаемого active SHA.
3. BOUND: одна атомарно опубликованная полная запись. Исходные данные не менялись.
4. INVALID: повреждённая/чужая запись; отказ. Автоматической перепривязки нет.

Прерывание до публикации возвращает UNBOUND; после неё остаётся BOUND.
Временный файл публикации не принимается как binding и не выбирается по свежести.
Неизвестные старые roots не удаляются и не присваиваются автоматически.

## Операция продвижения и восстановление

Существующий schema-transition journal остаётся владельцем перехода схемы;
повторная машина миграций не создаётся. Отдельная задача US3 должна доказать
и закрыть пробел обычного продвижения при аварийном завершении, используя
существующие _write_json/_publish_active, compensation и recovery markers.
Её схема/фазы проектируются после воспроизводящего отказного сценария и
отдельного независимого уточнения требований до изменения кода US3.
Принадлежность US1 не объявляет эту задачу выполненной.

Уточнение T010 от26.10.2026: ordinary-operation хранится как дополнительный
объект существующей rollback-required квитанции. Состав, строгие ограничения,
жизненный цикл и совместимость старых квитанций определены единожды в
[contracts/promotion-recovery.md](contracts/promotion-recovery.md).
Формат binding, schema-transition и данные томов этим не меняются.


## T009: временный план классификации, 27.10.2026

Binding v1 не меняется. Локальный JSON вне state tree содержит ровно
`schema_version=graf-dev-state-classification.v1`, canonical `repository`,
абсолютный `selected_root`, массив `roots`. Каждая запись имеет ровно `path`,
целые `device`/`inode`, `kind` (`selected`, `preserved-state`, `artifact-only`),
`tree_sha256`, массивы `artifacts` и `build_archives`, непустое `evidence`.
Ровно один selected, paths уникальны и совпадают со всеми стандартными непустыми
roots. Selected/preserved-state имеют пустой `artifacts`; artifact-only перечисляет
каждый app: относительный `path`, полный `source_sha`, `signing_identity`,
`designated_requirement`, `entitlements_digest`. Эти факты не присваивают root.

`build_archives` — уникальные относительные POSIX пути `artifacts/<candidate>/build`
без пустых/точечных компонентов, с реальным sibling-каталогом `GRAF Dev.app`.
У `artifact-only` каждый app требует отдельной записи `artifacts[]` и проверки
bundle/SHA/подписи. У `selected`/`preserved-state` архивные app/build остаются
неизвестными неизменными байтами без права применения; проверяется безопасный
путь sibling, а не его идентичность. Одно название не разрешает использование;
правила границ заданы в контракте.
Состав plan, типы и поля строгие; неизвестное/подменённое значение даёт отказ.

`tree_sha256` — SHA-256 канонического JSON массива root (`path="."`) и потомков,
отсортированных по относительному POSIX path; UTF-8, `json.dumps(sort_keys=True,
separators=(",", ":"), ensure_ascii=True)` без newline. Для каждой записи:
`path`, `type` (directory/file/symlink), целые `device`, `inode`, `uid`, `gid`,
`mode` (полный st_mode), `size`, `mtime_ns`, `ctime_ns`; у file ещё `sha256`,
у symlink `target` readlink. Обход по ссылкам не идёт. Atime исключён, потому
что чтение само его меняет; иных метаданных ОС этот снимок не обещает.
Изменение любого перечисленного поля, байтов или состава дерева даёт иной снимок.


Уточнение metadata-only от27.10.2026 не меняет модель binding или классификации.
Внутри preserved-state читаются прежние pointer/manifest v1 как неисполняемые
архивные объекты, только при предусловиях и строгой структуре из
[договора](contracts/state-ownership.md#неисполняемое-metadata-only-описание).
Современный и исторический состав не мигрируют друг в друга. Архивные пути,
health и SHA не дают принадлежности, рабочего статуса или права использования.
