| Одна блокировка при смерти controller | `state_lock` (2895), `_command_lock_fds` (686), оба command helper и LaunchServices передают исходный дескриптор меняющим дочерним процессам. Долгоживущий backend его не получает. Вложенная/чужая блокировка отвергается. |
| Запуск после записи идентичности | `_start_backend` (1881), `_assert_ordinary_controller` (991), `_schema_start_guard` (1006): backend ждёт разрешающий байт; runtime записан до разрешения; controller и квитанция повторно проверены. Закрытие канала при смерти controller до разрешения не запускает backend. |
| Текущие тела всех мутаций | Frozen adapter используется только для проверки источника и resolver. | Существующее восстановление схемы | Сохраняется отдельный приоритет schema journal; обычная операция не отменяет его запреты и не превращает неизвестное прежнее состояние в разрешение на запуск. |

в `/Applications`. Проверка startup использует настоящий разрешающий канал,
запись runtime, exec и проверку принадлежности синтетического процесса;
долгоживущий процесс не сохраняет блокировку после смерти controller.
Проверка frozen/current использует объект, у которого обращение к старым
методам вызывает отказ теста, и текущий класс для всех изменяющих вызовов.
