# Research
## Recording root cause
Decision: refresh current microphone ownership from documented CoreAudio process properties every2s; use current CoreAudio snapshots exclusively in production composition, stop resetting detector on observer generations/failures. Full snapshots reconcile active and absent targets; native absence uses existing15s grace. Unknown does not refresh evidence, so600s remains.
Rationale: timestamps of edge transitions measure last change, not current activity. The5m log restart resets state while a3.5s2h snapshot can fail. The10m evidence timer consequently stops a still-active call. Captured sensor logs stayed active across the observed stops. Historical log query timed out at3.506s with0bytes, then completed with warmed cache; codec/queue errors followed requested stops.
Alternative: increase log timeout only (still dependent on journal load); retain an alive-process flag forever (not proof of target activity); disabled timeout (privacy regression). Rejected.
Platform: Apple documents kAudioHardwarePropertyProcessObjectList, kAudioProcessPropertyPID and kAudioProcessPropertyIsRunningInput. macOS AudioHardware.h defines input activity as running IO with active input stream. Read-only local probe returned status0 for40process objects; no input was active at probe time, so this is API availability, not a live-call proof. Resolve child executable's containing outer .app bundle, not Qt helper's bundleID. An unreadable or unresolvable individual process makes coverage incomplete; independently verified active bundleIDs from other processes remain available. Only failure or malformed size of the overall process list produces an unavailable snapshot. An incomplete snapshot never proves absence.
Reference: https://developer.apple.com/documentation/coreaudio/kaudioprocesspropertyisrunninginput

## Source authority and executable evidence timer
Complete current native snapshots replace all source states for each tracked target; absent targets become inactive with15s grace. Partial snapshots emit only independently confirmed current activity and do not replace absent source states. A partial empty snapshot is unknown and cannot refresh the600s evidence clock. Positive evidence from a partial snapshot refreshes only its verified target. Direct CoreAudio bundleID is permitted when path metadata is unavailable, but helper identity is never guessed or promoted to an outer bundle. Old/historical log transitions cannot enter the native stream, including after native failure. Native failure yields unavailable and does not fall back to log history. Legacy log mode remains only when explicitly injected snapshotProvider=nil in old tests. Repeated native active preserves accepted/terminal consumer outcomes and manual suppression. App uses a shared executable600s predicate, covered with a simulated clock; tests do not rely solely on source strings. Identity is exact outer-bundleID matched by existing verified registry; nested Qt helper and unknown/unapproved targets have negative cases.

Quota navigation uses the existing /billing overview (shared access); capacity-management actions remain guarded by billing_owner. Copy asks to contact the workspace owner when appropriate. No new authority or purchase action is introduced.
