## Проверка реализации

Общий safe writer охватывает один raw upsert вместе с default commit в `asyncio.timeout(0.25)`. Правовой шлюз, sanitization и закрытый каталог значений остались в исходном raw writer. Возврат `None` и журнал теперь означают неподтверждённый результат, а не гарантированное отсутствие записи; повтора, очереди и фонового задания не добавлено. Все три production caller — просмотр, шаг регистрации и доставка установщика — используют default commit и не запускают повтор записи.

`public_web_db_session` создаёт обычный SQLAlchemy AsyncSession синхронно, без подключения к БД; сетевой вход происходит в `apply_tenant_context` внутри бюджета подготовки. Стандартная `async_sessionmaker(..., expire_on_commit=False)` подтверждена в `db/session.py`. Из прежнего `__aenter__` не удаляется прикладная работа: у AsyncSession это выдача самого объекта. `yield` находится за пределами timeout подготовки, cleanup в `finally` имеет собственный timeout. Неудачная подготовка отдаёт `None`; сессия больше не используется обработчиком. После записи страницы выполняется только формирование/возврат ответа и cleanup; бизнес-чтение публичного тарифного каталога происходит до измерения.

Все изменённые обёртки ловят `Exception`, а не `BaseException`; внешняя `asyncio.CancelledError` проходит наружу. Проверены соседние границы: четыре anonymous-only пути по-прежнему не вызывают campaign-cookie/L2/optional-провайдеры; help/private inventory не расширен; нулевой tenant context не заменён привилегированным; тарифные проверки и принципы auth не ослаблены. Чтение тарифного каталога само по себе находится за пределами этого узкого бюджета: общий предел ответа страницы этим изменением не установлен.

Отдельно прочитан установленный SQLAlchemy 2.0.51 asyncpg dialect. Его отмена операции инвалидирует соединение; graceful termination использует внутреннее shield и до 2 секунд на закрытие. Поэтому `asyncio.timeout(0.25)` задаёт момент запроса отмены, но не доказывает жёсткую верхнюю границу времени при любом сетевом сбое. Unit-подмена session также не доказывает освобождение настоящего соединения. В реальной проверке ниже намеренно используется настоящий `pg_sleep`, чтобы проверить хотя бы исполняемый путь отмены и следующий запрос. Неопределённый результат настоящего commit отдельно не превращается в обещание отсутствующей записи.
