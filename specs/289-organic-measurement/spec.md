## Clarifications

### Session 2026-10-16

- Уровень изменений: сначала устранить пробел в обезличенном учёте входов; включение PostHog, новая идентификация и передача персональных данных требуют отдельного среза существующей F273. Одобрение продвижения не заменяет подтверждения правового основания.
- F282 сохраняла три поисковых входа вне измерения. Этот последующий срез явно разрешает только обезличенный счёт четырёх перечисленных ниже путей. Он сохраняет отсутствие чтения/записи campaign cookie, новых visit refs и внешних счётчиков.
- Отчёт различает HTTP requests, сессии Метрики, пользователей, результаты обработки и первую полезную встречу. Без связывающей воронки конверсия и выручка по источнику неизвестны.
- Маркетинговый план: действующие материалы и полезность, без покупки ссылок, рекламных расходов, массовой генерации страниц и непроверенных обещаний.

Проверка clarify: цель, акторы, источники, безопасность, отказы, данные, границы, проверка и выпуск определены. Требующих решения владельца неопределённостей внутри этого среза нет. Выбор бюджета/аудитории подтверждён ответом владельца; правовые решения для персональной аналитики не подменены предположением.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Видеть входы на полезные материалы (Priority: P1)

Владелец видит обезличенные запросы к `/transcription`, `/meeting-minutes`, `/record-without-bot` и `/guides/rasshifrovka-zapisi-zoom`, включая грубую категорию источника и технического трафика. Это исходная мера посещаемости, а не связанная воронка.

**Why this priority**: Три новых маршрута F282 ещё не опубликованы; руководство Zoom опубликовано без учёта. Остальные три руководства и `/guides` уже имеют серверный агрегат, несмотря на отсутствие JavaScript.
**Independent Test**: Изолированный GET каждого из четырёх путей создаёт один обезличенный бакет; повтор увеличивает requests; нет cookie и записей уровня 2.
**Acceptance Scenarios**:

1. **Given** подтверждённое существующее основание уровня 1, **When** человек открывает один из четырёх путей, **Then** учитывается его текущая страница и категория referer, без стабильного идентификатора.
2. **Given** имеющийся cookie кампании и новый URL с UTM, **When** открыт материал, **Then** cookie не читается для измерения, не создаётся и не заменяется; в агрегат могут попасть только проверенные метки текущего URL.
3. **Given** отзыв основания, выключенный агрегат или недоступная БД, **When** открыт материал, **Then** HTML остаётся доступным, ошибку записи нельзя выдавать за нулевой спрос.

### User Story 2 - Принимать решения по проверенным данным (Priority: P1)

Владелец получает актуальную исходную проверку и последовательный план на 90 дней с источниками, периодами, условиями принятия решений и следующими работами по продуктовой аналитике.

**Why this priority**: Наличие счётчиков и заготовленных панелей не доказывает измерение первой полезной встречи.
**Independent Test**: Отчёт содержит актуальные агрегаты production, состояние Search Console/Метрики, подтверждённые ограничения и календарь. Исторические числа явно отделены.
**Acceptance Scenarios**:

1. **Given** выключенная продуктовая аналитика, **When** читается отчёт, **Then** нельзя посчитать organic→activation из несвязанных чисел.
2. **Given** опубликован материал и доступны данные, **When** наступает недельная проверка, **Then** решение связано с показами, кликами и полезными результатами, а отсутствие данных обозначено отдельно от нуля.

### Edge Cases

- Неизвестные `/guides/*`, `/help`, `/news` и частные маршруты не добавляются в агрегат автоматически.
- Небезопасные метки URL, адреса почты, идентификаторы рекламы, заголовки встреч, IP и полные referer не сохраняются в бакетах.
- Отсутствие referer остаётся direct; отсутствие известного источника нельзя переименовать в переход из ИИ.
- Ошибка БД или основания не блокирует чтение и не создаёт внешнюю отправку; существующие флаги и правовой шлюз обязательны.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Добавить ровно четыре перечисленных пути в закрытый каталог только обезличенного учёта. Существующие каталоги внешнего/необязательного измерения и помощи не расширять.
- **FR-002**: Для этих путей учитывать только существующие поля уровня 1: текущую страницу, проверенные метки URL, грубый класс устройства, категорию referer и traffic_class. Существующие фильтры и порог раскрытия сохраняются.
- **FR-003**: Не читать campaign cookie для этого учёта, не создавать/заменять cookie, visit attribution row или связь с аккаунтом. Не добавлять JavaScript, replay, провайдеров и запросов к ним. Для прежних маршрутов поведение сохраняется.
- **FR-004**: Использовать существующие настройку отключения агрегата, правовой шлюз, безопасную запись и DB dependency. При недоступной БД/отключённом уровне или отозванном основании страница отвечает 200 без новой записи.
- **FR-005**: Сохранить HTML, заголовки, canonical, sitemap, безопасность, доступность без JS и первый экран главной. Не менять capture, тарифы, auth, оплату или идентификацию.
- **FR-006**: Записать актуальную исходную проверку и план продвижения на 90 дней: источник каждой метрики, одинаковые окна сравнения, брендовые/небрендовые запросы, измеримость activation/D7/выручки и правила отсутствующих данных. Не обещать позиции, трафик или цитирование ИИ.
- **FR-007**: Отделить готовую реализацию от публикации, индексации и роста. Коммит требует явного одобрения после локальной проверки; PR и выпуск проходят действующие exact-SHA и release gates.

### Key Entities

- Обезличенный бакет: существующая запись уровня 1 без идентификатора человека; схема и сроки хранения не меняются.
- Проверка источника: дата/период, источник, единица измерения, значение или причина отсутствия; только агрегаты и публичные сведения.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Все четыре входа учитываются изолированно с правильным текущим путём; два GET дают requests=2 без записи персонального профиля.
- **SC-002**: Во всех четырёх маршрутах нет нового cookie, чтения cookie для измерения, visit refs, внешних событий и скриптов; небезопасные данные отбрасываются.
- **SC-003**: Выключение/отзыв основания/сбой БД сохраняют HTML 200 и не добавляют бакетов. Существующие public и consent регрессии проходят.
- **SC-004**: План и исходная проверка опубликованы в документации проекта; каждое предложение роста имеет приоритет, срок, меру результата и ограничение вывода.
- **SC-005**: Локальная проверка не названа ростом; окончательный результат продвижения оценивается отдельно через 28/56/90 дней после выпуска.
