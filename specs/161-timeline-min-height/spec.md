# Feature Specification: Минимальная высота таймлайна спикеров

**Feature Branch**: `codex/161-graf-ux-regressions`

**Created**: 2026-08-18

**Status**: Ready for implementation

**Input**: Отзыв пользователя по задаче 1: минимальная высота панели дорожек
спикеров должна сразу показывать трёх спикеров полностью.

## User Scenarios & Testing

### User Story 1 - Сразу видеть трёх спикеров (Priority: P1)

Пользователь открывает расшифровку встречи и видит первые три дорожки
спикеров целиком, без внутренней прокрутки и без необходимости сначала
перетягивать разделитель.

**Why this priority**: Три дорожки — обычный минимальный сценарий встречи;
частично скрытая третья дорожка делает панель визуально неисправной и мешает
понять, что нужно слушать.

**Independent Test**: На синтетической встрече с тремя спикерами открыть
панель воспроизведения и проверить, что все три подписи и дорожки видимы в
начальном состоянии. На встрече с большим числом спикеров проверить, что
панель по-прежнему расширяется только в существующих границах.

**Acceptance Scenarios**:

1. **Given** встреча содержит один, два или три спикера, **When** панель
   воспроизведения открыта, **Then** начальная высота не меньше высоты,
   необходимой для трёх полных дорожек, а при меньшем числе спикеров пустая
   область не создаёт дополнительного управления.
2. **Given** встреча содержит больше трёх спикеров, **When** панель открыта,
   **Then** первые три дорожки полностью видимы, внутренний overflow остаётся
   доступным, а resize-разделитель появляется только когда есть что
   расширять.
3. **Given** пользователь расширяет панель указателем или клавиатурой,
   **When** достигнут предел содержимого или доступного viewport, **Then**
   высота не превышает этот предел и воспроизведение не меняет позицию.

### Edge Cases

- При отсутствии дорожек или недоступном воспроизведении существующее пустое
  или статусное состояние не должно получать новый resize-контрол.
- При смене размера окна текущая высота не должна перескочить выше нового
  viewport-предела или опуститься ниже минимальной высоты.
- Повторная инициализация после частичного обновления страницы не должна
  добавлять второй обработчик resize или менять высоту без действия пользователя.

## Requirements

### Functional Requirements

- **FR-001**: Панель таймлайнов MUST иметь единый минимальный размер,
  достаточный для трёх полных двухстрочных дорожек, и этот размер MUST быть
  одинаково отражён в разметке, стилях и клиентской логике.
- **FR-002**: Для одной, двух или трёх дорожек панель MUST не прокручиваться
  во внутреннем scroll-контейнере в начальном состоянии.
- **FR-003**: Для более чем трёх дорожек существующая возможность расширить
  панель MUST сохраняться; максимальная высота MUST оставаться минимумом из
  полной высоты содержимого и доступного viewport.
- **FR-004**: Resize-контрол MUST оставаться доступным с клавиатуры и указателя,
  сообщать актуальные `aria-valuemin`, `aria-valuemax` и `aria-valuenow` и не
  менять состояние воспроизведения.
- **FR-005**: Изменение MUST использовать существующие HTML/CSS/JavaScript
  контракты, не добавлять постоянное хранилище, новые зависимости или новый
  аудиомаршрут.

### Key Entities

- **Панель таймлайнов**: визуальный контейнер дорожек с минимальной высотой,
  текущей высотой и ограничением viewport.
- **Дорожка спикера**: подпись, доля времени и отрезки активности одного
  спикера; данные не изменяются этой функцией.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Синтетический рендер с 1–3 спикерами показывает все три
  доступные дорожки без вертикального overflow в начальном состоянии.
- **SC-002**: Синтетический рендер с 4, 12 и 40 спикерами сохраняет resize,
  внутреннюю прокрутку и ограничение высоты viewport без выхода за пределы.
- **SC-003**: focused contract/unit checks подтверждают единое значение
  минимальной высоты во всех трёх слоях и один обработчик resize после
  повторной инициализации.
- **SC-004**: Валидация не содержит реальных аудиофайлов, расшифровок или
  пользовательских данных.

## Assumptions

- Двухстрочная дорожка — текущая структура подписи и полосы из shared shell;
  новая функция не меняет их дизайн.
- Значение `120px` принимается как минимальный размер для трёх дорожек по
  текущим метрикам CSS и остаётся простым единым контрактом для адаптива.
- Пункт про генерацию итогов и отдельный дефект сохранения имени спикера в
  этой функции не входят.

## Out of Scope

- Переписывание логики воспроизведения или генерации итогов.
- Сохранение пользовательского размера между встречами или запусками.
- Изменение цветов, подписей, порядка спикеров или модели данных.
