# Contract: Phase 2 Product Activation Analytics

**Feature**: 093-public-landing-analytics

This is a planning contract only. It does not authorize Phase 1 implementation
of PostHog or any product activation tracking code.

## Purpose

Phase 2 connects public campaign acquisition to actual product value after a
separate privacy and product analytics spec is approved.

## Required Funnel

```text
public_installer_download_clicked
-> desktop_first_opened
-> desktop_account_connected
-> desktop_autorecord_enabled
-> first_recording_completed
-> first_result_viewed
-> first_value_session_completed
```

## Event Contract

| Event | Surface | Safe Fields | Forbidden Fields |
| --- | --- | --- | --- |
| `desktop_first_opened` | desktop | app_version, platform, install_channel, safe campaign link state | local path, device name, account ID |
| `desktop_account_connected` | desktop/server | auth_method_category, workspace_kind, safe identity hash | email, account name, OAuth tokens |
| `desktop_autorecord_enabled` | desktop/cabinet | policy_state, surface, previous_state | calendar event title, meeting link |
| `first_recording_completed` | desktop/server | duration_bucket, capture_mode, completion_state | raw audio, transcript, local path |
| `first_result_viewed` | cabinet | result_state, surface, time_bucket | meeting title, transcript, participants |
| `first_value_session_completed` | product analytics | milestone booleans, elapsed_bucket | names, content, raw identifiers |

## Identity Boundary

Phase 2 must choose one safe identity strategy before implementation:

- provider pseudonymous person ID generated by the product analytics provider;
- server-issued hashed user/workspace ID with a documented salt/rotation
  policy;
- campaign/session bridge token that expires and cannot reveal email/account
  identity.

Rejected identity values:

- email address;
- full name;
- organization/company name;
- workspace name;
- raw account ID;
- device name;
- local user path;
- OAuth/provider tokens;
- meeting or calendar identifiers.

## Consent And Notice Boundary

Phase 2 must define whether product analytics is controlled by the same public
analytics consent, a separate product telemetry notice, workspace policy, or an
admin setting. It must also define:

- opt-out behavior;
- internal/test-user filtering;
- retention expectation;
- deletion/reporting truth;
- whether desktop and web share one analytics project;
- whether self-hosted PostHog is required.

## Provider Direction

PostHog is the preferred Phase 2 candidate because it supports UTM
segmentation, funnels, paths, dashboards, and session replay privacy controls.
The Phase 2 spec must still decide cloud vs self-hosting, egress, retention,
identity, replay settings, and deletion participation before implementation.

## Out Of Scope For Phase 1

- Adding PostHog script or SDK.
- Capturing product events.
- Linking public anonymous visitors to authenticated accounts.
- Sending desktop events to any analytics provider.
- Recording cabinet or meeting session replay.
- Optimizing ads against first result viewed.
