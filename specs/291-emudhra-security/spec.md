# Feature Specification: Обновление доверенных сертификатов

**Feature Branch**: `291-emudhra-security`
**Created**: 2026-10-23
**Status**: Draft
**Input**: Пользователь разрешил обновить зависимости безопасности и выпустить ГРАФ; сохранить данные, настройки и обязательные проверки выпуска.

## User Scenarios & Testing

### User Story 1 - Защищённые исходящие соединения (Priority: P1)

Оператор обновляет пакеты доверенных сертификатов, чтобы приложение отклоняло сертификаты скомпрометированных посредников eMudhra и продолжало обращаться к обычным HTTPS-сервисам.

**Independent Test**: HTTP-клиенты работающих API и workers отклоняют оба опубликованных тестовых адреса с ошибкой проверки сертификата; обычный HTTPS-запрос проходит.

**Acceptance Scenarios**:
1. Given старый набор доверия, When пакеты штатно обновлены и сервис выпущен, Then оба тестовых сертификата отвергаются.
2. Given обычный действительный сертификат, When приложение обращается к нему, Then TLS-проверка проходит.

### User Story 2 - Проверяемый безопасный выпуск (Priority: P1)

Оператор получает отдельное изменение ГРАФ, проверки точного SHA и подтверждение версий в production.

**Independent Test**: PR, Full CI, release decision, dry-run и runtime receipt относятся к одному кандидату.

**Acceptance Scenarios**:
1. Given чужой черновик выпуска, When готовится security-релиз, Then он не считается опубликованным и его изменения не теряются.
2. Given отсутствующее обязательное разрешение резервирования или restore evidence, When планируется execute, Then выпуск блокируется с точной причиной; исходные исправления и проверки продолжаются.

### Edge Cases

Ошибка DNS/timeout не доказывает отклонение сертификата. Переадресация не должна скрывать начальный TLS результат. Недоступный сервис отмечается непроверенным. При провале здоровья используется штатный откат образа без удаления томов или автоматического отката данных.

## Requirements

### Functional Requirements

- **FR-001**: Нижняя граница certifi в pyproject и certifi во всех применимых lock/constraints ГРАФ должен быть не ниже 2026.10.19 с корректными артефактами; production constraints воспроизводимо экспортируются из uv.lock.
- **FR-002**: Все применимые Node 22 в workflow должны быть не ниже 22.23.4; существующие проверки синхронизируются. Прочие зависимости меняются только при необходимом разрешении совместимости, с явным отчётом.
- **FR-003**: Образы API и workers получают штатный актуальный пакет системных CA; ручное изменение trust store, отключение TLS и обход проверки запрещены.
- **FR-004**: Runtime-проверка использует HTTPX, Requests и применимые aiohttp/default SSL пути, два адреса из advisory и обычный HTTPS-контроль с ограничением времени. Сохраняются версии пакетов и результаты, без секретов и содержимого встреч.
- **FR-005**: Выпуск сохраняет обязательные review, три точных PR checks, authoritative release-full, candidate/train/decision, dry-run, backup, restore readiness, health, smoke и повторную worker/Temporal readiness. Никакие gates не обходятся.
- **FR-006**: До production проверяются чужие изменения, владельцы и текущие релизы. Единственный оператор F291 координирует выпуск. Не включать аналитику, не выполнять реальные платежи/возвраты и сторонние SMTP-тесты, не менять DNS/VPN/права и не удалять данные.
- **FR-007**: Новое резервирование допускается только после установления применимости существующего разрешения пользователя. Если оно отсутствует или неясно, execute остаётся заблокированным; новая инфраструктура не создаётся. Это ограничение не блокирует исходные исправления и изолированные проверки.
- **FR-008**: Отдельный серверный релиз сохраняет текущие опубликованные macOS assets/appcast; новый клиент не выпускается без его signing/notarization gates. Финальный отчёт различает исходное исправление, опубликованный релиз и фактический runtime.

### Key Entities

Кандидат выпуска: точный SHA, состав PR, digest changelog, авторитетная CI-проверка. Runtime receipt: сервис, образ/digest, версии, результаты TLS и health, ограничения. Пользовательские модели и схема БД не меняются.

## Success Criteria

- **SC-001**: Оба недоверенных сертификата отвергаются всеми применимыми проверенными HTTP-клиентами production, а обычное HTTPS-соединение успешно.
- **SC-002**: Во всех целевых работающих сервисах подтверждены исправленные версии и health; обязательный smoke проходит без регрессий.
- **SC-003**: Каждое заявленное завершение имеет readback; отсутствующие разрешения и проверки явно отмечены как блокеры.

## Assumptions

Сфера ограничена исправлением eMudhra и существующим выпуском сервера. AIRIS и LiteLLM проверяются отдельно, без общей реализации. Advisory: https://render.com/docs/advisory-emudhra .
