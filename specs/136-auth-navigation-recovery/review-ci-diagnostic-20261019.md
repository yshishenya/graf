## Сохраняющийся отдельный продуктовый блокер

Живое замечание прочитано через GitHub API:
https://github.com/yshishenya/graf/pull/7668#discussion_r4311975859 .

Содержание подтверждено текущим кодом: `observeNavigationRequest` добавляет URL
небезопасного запроса в `unsafeHistoryURLs`, а последующий безопасный GET добавляет
его в `safeHistoryURLs` только если URL отсутствует в unsafe-множестве.
`isSafeHistoryDocument` по-прежнему требует отсутствия URL в unsafe-множестве.
В пределах той же сессии настоящий последующий GET не восстанавливает обычную
Reload/Back/Forward навигацию этого URL. Это противоречит сохранению обычной
навигации FR-006/US2 и остаётся **Request Changes для продуктового PR**.

Исправление должно различить настоящий новый безопасный GET и синтезированный
GET для ответа POST; простое безусловное удаление из unsafe-множества не
одобрено. Текущий диагностический diff не меняет эту логику, не снимает P2 и
не даёт разрешения закрывать связанные issues.
