# F136: независимая оценка опытов с порядком WebKit

Дата: 2026-10-18. Reviewer: `review_f290_infra`.
Режим: high-risk-product. Только чтение исходника, отчёта и журналов.

## Результат

Проверены все семь записей `SHA256SUMS`, все контрольные суммы совпали.
Журналы подтверждают **пять различных завершившихся XCTest: 5 PASS / 0 FAIL**.
Продуктовый исходник и тесты F136 не изменились относительно предыдущего ревью.
Новый пакет не зависит от GRAF и наблюдает сам WebKit; его PASS не является
приёмкой контроллера GRAF.

Диагностика подтверждает невозможность надёжного различения новой action и
перенаправления по одному navigationType/методу/sourceFrame request.
В опыте overlap исходная последовательность синтетического finding **не
возникла**. Поэтому доказана ошибка переходов состояния контроллера при
вручную заданной последовательности; достижимость этой последовательности
в настоящем WebKit и пользовательский сбой пока не доказаны.

## Что непосредственно видно в исходнике и журналах

| Сценарий | Подтверждено |
|---|---|
| POST303 | type1/POST → type1/GET, один объект WKNavigation на start/redirect/commit/finish |
| POST307 | type1/POST → type1/POST, один объект; action request показывает длину тела 3 на обоих шагах |
| GET-форма302 | type1/GET → type1/GET, один объект; классификация по методу не разделяет шаги |
| JavaScript302 | type-1/GET → type-1/GET, один объект; `.other` встречается у начала и продолжения |
| Overlap | `start A → HTTP POST /slow → fail A → policy B → allow B → start B → commit B → finish B`; redirect/finish A после policy B в этом журнале отсутствуют |

Во всех четырёх простых цепочках `sourceFrame.request` и `targetFrame.request`
сохраняют исходную страницу `/source`; они не предоставляют отдельный номер
цепочки. В redirect action `view.url` уже равен новому целевому адресу.
Это наблюдение одной среды, а не универсальное обещание WebKit для любых
возможных гонок, одинаковых URL, версий и способов запуска.

## Границы доказательства

1. В первых четырёх тестах программно проверяются завершение expectation и
   конечный path `/result`. Сведения о типах, методах и identities подтверждены
   чтением журналов, а не отдельными XCTAssert каждого инварианта.
2. Для POST307 показаны сохранённые метод и длина `httpBody`; побайтовое
   равенство тела тест не проверяет. Listener не дожидается Content-Length
   после заголовков и не сравнивает полное тело. Поэтому формулировка
   «тело сохранено» здесь означает наблюдаемую длину, не отдельную проверку байтов.
3. В overlap `DelayedResponse.reply` вызывает completion независимо от ошибки
   `NWConnection.send`. Expectation `late old response delivered` доказывает
   завершение попытки записи, а не доставку ответа WebKit. A уже завершена
   ошибкой до policy B; отсутствие поздних A-callbacks в этом опыте ожидаемо
   и не является экспериментом с доставленным A303 после policy B.
4. `oldNavigation` не проверяется через XCTUnwrap и отсутствие старых callbacks
   не проверяется ожиданием с отдельным окном наблюдения после finish B.
   Однако журнал прямо показывает start `/slow` и его fail с той же identity:
   этот конкретный запуск не является пустой проверкой из-за nil identity.
5. Сохранённый окончательный исходник содержит пять сценариев; первый журнал
   собирался до добавления overlap (позиции строк отличаются). Имена четырёх
   тестов и их трассы совпадают с первыми четырьмя методами итогового файла.
   Отдельный хеш точного исходника первого запуска не сохранён; нельзя
   представлять финальный hash как проверенный per-run source hash обоих запусков.
6. Среда: macOS 26.6.2 (25G83), arm64, Swift 6.3.3. Минимальная поддерживаемая
   macOS14 и другие версии этим наблюдением не аттестованы.

Эти ограничения не обесценивают диагностику: она точно запрещает наивное
исправление по типу/методу и показывает, почему синтетическое воспроизведение
нельзя выдавать за подтверждённый пользовательский сценарий.

## Следующее решение по реализации

Не следует строить новую перехватывающую подсистему или менять server contract
только ради порядка событий, достижимость которого ещё не показана.
Перед следующим изменением продукта нужны либо реальная причинная цепочка,
либо явно обоснованный защитный инвариант с узким решением без регрессий.

Самый полезный следующий ограниченный опыт — повторить overlap через настоящий
Coordinator GRAF, сохранив native callbacks без ручной подстановки, и проверить
его состояние после наблюдаемого `fail A → policy B`, затем после завершения B.
Это подтвердит, что контроллер действительно корректно снимает A до B.
При необходимости отдельно проверить A, чей redirect callback уже поставлен
в очередь к моменту нового пользовательского действия; успешность записи
ответа при этом нельзя выдавать за получение WebKit. Повторять бесконечно
один и тот же неподходящий delayed-response опыт не требуется.

Если реальный сбой не воспроизводится после ограниченной причинной проверки,
следует явно решить судьбу первоначальной находки: сохранить её как
защитный инвариант с проверенным минимальным ремонтом либо снять статус
продуктового блокера как неподтверждённый достижимый сценарий и описать границу
контракта. «Не воспроизведено» не означает «исправлено». Reviewer пока не
принимает ни один из этих исходов без конкретного результата; прежний
Request Changes сохраняется до отдельного решения и итогового ревью.

Для любого предложенного ремонта обязательны:

- Новый app-owned load имеет явное происхождение и связывается с возвращённым
  WKNavigation; старую identity нельзя возрождать из позднего redirect.
- Redirect A не потребляет pending B на основании только совпавшего URL,
  HTTP-метода или navigationType; наличие счётчика без доказанного назначения
  владельца недостаточно.
- Сохраняются настоящие POST303, POST307, GET-form302 и JS302; оригинальный
  action не воспроизводится приложением. Для 307 это не запрещает законный
  запрос к Location, который сохраняет POST по серверному протоколу.
- Явно разделяются synthetic state-machine regression и реально полученный
  native callback order. Прохождение первой нельзя назвать сетью или manual PASS.
- После ремонта проверяются ordinary200/error/cancel, current/stale terminal
  identity, login/logout ordering, 401/reselection, controls, billing/download
  и более поздние изменения авторизации.
