# Проверка требований трёхзначной нумерации

Независимый проверяющий: агент number_sources, 2026-09-11.
Объём: FR-027–FR-029, SC-008–SC-009 и уточнение владельца от 2026-09-11.
Проверены требования до реализации; отметки не означают приёмку кода или CI.
Старые списки проверок и их состояние не меняются.

- [x] Диапазон новых номеров задан явно: 001–999; ограничение относится к GRAF, общий алгоритм без верхней границы сохраняется.
- [x] Большие исторические номера исключены только из начала последовательности, остаются занятыми и не перенумеровываются.
- [x] Ошибка политики и исчерпание диапазона прекращают создание issue, claim и указателя; нужны регрессионные проверки отсутствия записей.
- [x] Точный повтор исторического резервирования и его переход из чернового состояния сохраняются; простое наличие исторического каталога не разрешает новый большой номер.
- [x] Ветка, каталог спецификации и указатель имеют один зарезервированный номер; независимое вычисление max(specs) запрещено.
- [x] Явный каталог проходит проверку границ пути и совпадения номера до записи; полный указатель сохраняет владельца, исходный SHA и остальные метаданные.
- [x] Исходный bootstrap и установленные инструкции синхронизируются; повторная генерация не возвращает старый алгоритм.
- [x] Пути --number, --timestamp, GIT_BRANCH_NAME, dry-run и GRAF_SKIP_FEATURE_CLAIM не могут обходить ограничение проекта.
- [x] Старый create-new-feature.sh в проектах с распределителем останавливается до записи и указывает действующий путь speckit-git-feature → speckit-specify; общий режим без распределителя сохраняется.

Результат проверки требований: блокирующих неоднозначностей не найдено.
При реализации отдельно подтвердить ограничения явного номера и отсутствие
побочных записей. Проверка кода, локальные тесты и точный SHA GitHub checks
остаются самостоятельными этапами; этот список их не подменяет.
