# Исследование B019

Решение: разделить начало последовательности и множество занятых номеров. Начало берётся из specs проекта; реальные refs/reservations/GitHub исключают коллизии, но одиночный большой номер не повышает начало. Причина: max всех refs дал 6789 вместо ближайшего свободного номера после F258. Ограничивать ID тремя цифрами нельзя: реальные F1000+ должны оставаться валидными.

Все вызовы: CLI suggestion, --allocate и explicit claim; Bash, Python и PowerShell оболочки. Вспомогательные _parse_ids не участвуют в выборе. _git_refs ранее читал все namespaces и tags, ID_RE находил числа внутри пути. Чтение только heads/remotes и конечного сегмента устраняет эту причину.

Неполные/ошибочные GitHub ответы не разрешают создание. Повторный выбор под общей блокировкой предотвращает двойное резервирование из параллельных предложений. Отсутствие feature:N — отдельная наблюдавшаяся причина остановки; метку нужно создать идемпотентно, не изменяя существующую.

Известная граница: реальная спецификация с большим номером является источником последовательности; её исправление требует содержательного решения владельца. Этот patch не угадывает, какие уже зарегистрированные фичи ошибочны.
