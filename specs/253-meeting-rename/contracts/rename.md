# Контракт переименования

## Интерфейс

Одно поле вместо заголовка, стилизованное как заголовок; h1 и невидимая
подпись «Название встречи» сохраняют семантику. В покое нет дополнительной
панели. При фокусе видна рамка/подчёркивание. Enter и уход фокуса сохраняют
изменение; Esc возвращает исходное и выходит без запроса. IME учитывается.
Пустое/длинное/запрещённое имя остаётся в поле с короткой ошибкой, не сохраняется.
Обычное сохранение не показывает подписи, счётчик или сообщение об успехе.
Результат доступен экранному диктору; ошибки связаны через aria-describedby.
Во время запроса поле readonly; Enter+blur отправляют один запрос.
Esc во время pending игнорируется. После неопределённого результата Esc
отбрасывает лишь локальный черновик и перечитывает только имя/версию без перезагрузки карточки; это не отмена
запроса, не откат сервера и не подтверждение сохранения исходного имени.

При ошибке текст остаётся; повтор — Enter. При конфликте обычный blur ничего
не перезаписывает: только отдельное Enter, о чём говорит пояснение. Esc
при конфликте принимает уже сохранённое текущее имя и выходит без запроса.
Уход внутри кабинета с изменением запускает/ожидает сохранение и продолжает
навигацию только при успехе; исправимая ошибка удерживает карточку.
При 401/403/404/deletion-active повтор запрещён, блокировка перехода снята,
существующий переход к списку/входу работает без сохранения. Browser unload с
несохранённым изменением вызывает штатное предупреждение. Список не получает
новых кнопок или меню.

## HTTP

- `POST /meetings/{meeting_id}/title`
- `POST /desktop/meetings/{meeting_id}/title`
- Form: `title`, `expected_version`, `csrf_token`.
- Авторизованный контекст и защита CSRF обязательны для обоих путей.
- `Accept: application/json`: JSON, `Cache-Control: no-store`.
- Успех 200: `meeting_id`, `title`, `title_version`.
- 409 `meeting_title_conflict`: текущее `title`, `title_version`, только после
  проверки доступа. Клиент сохраняет свой черновик отдельно от текущего имени.
- 400/422: `meeting_title_empty`, `meeting_title_too_long`,
  `unsafe_meeting_title`; сообщения не отражают отвергнутое значение.
- 404: встреча отсутствует, удалена или недоступна автору.
- 409 `meeting_deletion_active`: удаление началось; запись не выполняется.
- 401/403/503: действующая семантика авторизации, CSRF, недоступной базы.

Без JSON Accept успешная форма возвращает 303 на каноническую карточку;
исправимая ошибка — HTML карточки с редактором, черновиком и сообщением,
а не необработанный JSON. Приватные ответы не кэшируются. Для 401/403/404/deletion-active недоступная
карточка/черновик не рендерятся; используется штатная безопасная ошибка/вход.

Тайм-аут клиента 15 с оставляет неопределённый результат и доступный повтор.
Ответ применяется только к исходному подключённому редактору той же встречи.
Не использовать innerHTML для названия. Повтор с тем же текущим именем
успешен без лишнего изменения. Пустое имя не означает сброс к автоматическому.

## Сообщения

| Состояние | Текст |
|---|---|
| Пусто | Введите название встречи |
| Превышение | Название должно содержать не больше 500 символов |
| Запрещённые метаданные/путь | Укажите название без ссылок, адресов почты, секретных данных и пути к файлу |
| Сеть/тайм-аут | Сохранение не подтверждено. Проверьте соединение и нажмите Enter ещё раз |
| Сервер | Не удалось сохранить название. Попробуйте ещё раз |
| Конфликт | Название изменилось в другом окне |
| Нет доступа | Встреча больше недоступна |
| Удаление | Встреча удаляется. Переименовать её уже нельзя |

При конфликте пояснение предлагает Enter для сохранения своего имени и Esc
для принятия текущего. Новая версия принимается только для явного Enter.
Без JavaScript Enter отправляет обычную форму; blur/Esc требуют JavaScript,
поэтому noscript-подсказка честно сообщает «Введите название и нажмите Enter».

При неудаче сверки после Esc результат остаётся неопределённым; старое имя
не считается подтверждённым. Можно GET текущей карточки и прочитать поля
имени/версии, не заменяя HTML и не прерывая плеер.
