## Подтверждённые требования

- CHK001: FR-002, SC-001 и контракт задают одно поле без новых постоянных кнопок,
  карандаша, меню и подписи успеха. Уточнения пользователя сохранены буквально по смыслу.
- CHK004: конфликт требует нового Enter с актуальной версией; blur не перезаписывает
  чужой результат; Esc принимает текущее имя. Автоматического повтора нет.
- CHK005: FR-004/011/013 и quickstart задают Unicode-кодовые точки, IME,
  экранный диктор, фокус, темы, ширины, масштаб и честное ограничение JS-off.
- CHK007: research отделяет наблюдения Krisp от выбранных гарантий GRAF и
  прямо указывает разные аккаунты и непроверенные состояния. Код/ресурсы Krisp
  не используются; браузерная проверка не подменяет WKWebView.
- CHK008: доступ ограничен активным автором и текущей организацией;
  CSRF требуется на обоих маршрутах, роль администратора сама по себе недостаточна.
- CHK010: plan/research явно сохраняют ручное название против stale ingest,
  обоих порядков календарной записи и повтора старого запроса без fingerprint;
  неизменяемые проверки запроса остаются, реальные PostgreSQL-гонки обязательны.
- CHK011: предел проверяется до обрезающего helper; запрещённые метаданные не
  отражаются в сообщении; шаблон экранирует, DOM использует textContent,
  журналы/аналитика не содержат названий.
- CHK012: FR-009 и граница no-deploy исключают изменение идентичности,
  медиа, обработки, прав и внешнего календаря; публикация не считается выполненной.

## Замечания до начала реализации

1. **R1 · HIGH · CHK006/009**. US2.6 оставляет ссылку «Мои встречи» при
   недоступности/удалении, но контракт пропускает внутреннюю навигацию лишь
   после успешного rename. При окончательном отказе пользователь не сможет
   выйти. Требуется конечное состояние недоступности/удаления, в котором
   повтор rename прекращается, а существующий выход работает без сохранения.
2. **R2 · HIGH · CHK002/003/009**. Общая отмена Esc возвращает исходное имя,
   но не описывает уже отправленный или завершившийся по тайм-ауту запрос.
   Сервер мог сохранить имя, поэтому нельзя обещать его отмену. Требуется
   явное поведение pending и неоднозначного результата, сохраняющее честность
   отображения и возможность выйти без ложного отката серверного значения.
3. **R3 · MEDIUM · CHK002**. US1.3 запрещает запрос для неизменённого поля,
   а data-model требует ручного подтверждения одинакового автоматического
   имени. Требуется отделить no-op focus/Enter/blur от семантики явного
   серверного запроса; новое действие/кнопка для этого не нужны.
4. **R4 · HIGH · CHK009**. Контракт без JSON обещает HTML карточки с черновиком
   для любой ошибки, включая недоступность встречи/отзыв доступа. Требуется
   исключение: безопасная штатная ошибка/вход без повторного вывода защищённой
   карточки и текущего названия при отсутствии доступа.

## Решение первого прохода

UX: 4/7; security: 4/5. Требования ещё не допускают реализацию.
Нужны только уточнения перечисленных состояний, без расширения интерфейса.
После правок рецензент повторно проверит соответствующие пункты; отметки
реализационных tasks принадлежат основному агенту и здесь не меняются.


## Повторная проверка и окончательное решение

Повторный проход 2026-09-06 выполнен тем же независимым рецензентом после
изменений основного агента. Открытых CRITICAL/HIGH/MEDIUM замечаний к
рассмотренным требованиям: **0**. UX **7/7**, security **5/5**.

- **R1 закрыто / CHK006 принят**: US2.6 и контракт выделяют окончательную
  недоступность/удаление; повтор запрещён, блокировка перехода снята,
  существующая ссылка к списку/входу работает. Исправимые ошибки сохраняют
  защиту черновика. Поздний ответ и история остаются в матрице quickstart.
- **R2 закрыто / CHK003 принят**: US1.3 и контракт явно игнорируют Esc при
  выполняющемся запросе; после неопределённого результата отменяется только
  локальный черновик, имя/версия перечитываются без замены HTML и остановки
  плеера. Ошибка сверки не превращается в подтверждение старого имени.
- **R3 закрыто / CHK002 принят**: data-model различает неизменённое поле
  (без запроса/смены источника) и явно пришедший серверный запрос с тем же
  автоматическим текстом. Enter/blur/Esc/IME и повторная отправка согласованы
  с этими исключениями без дополнительной кнопки.
- **R4 закрыто / CHK009 принят**: contract HTTP и plan, шаг 4, разрешают HTML
  карточки с черновиком только для исправимой ошибки при действующем доступе;
  401/403/404/удаление используют безопасную штатную страницу. Версия,
  блокировка строки, удаление и безопасный повтор остаются обязательными.
- Дополненная проверка полного 500-символьного названия в новом документе
  соответствует существующему FR-008. Ограничение имени скачиваемого файла
  отделено от заголовка документа; новая функция не добавлена.

**Gate проверки требований пройден; T001 можно принять основному агенту
после фиксации этого решения. Реализация разрешена в пределах утверждённых
требований и остальных действующих Spec Kit gates.** Это не приёмка кода,
браузера, WKWebView, выпуска или production. Реализационные tasks рецензент
не отмечал. Изменены только ux.md, security.md и этот requirements-review.md.
Проверка `git diff --check` прошла без ошибок.
