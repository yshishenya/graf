# Данные переименования

Новые таблицы не нужны. `Meeting.title` — строка до 500 символов;
`title_source = user_confirmed`; `title_updated_at` — момент успешной записи.
`updated_at` обновляется существующим механизмом. Время записи, состояния
обработки, revision IDs и fingerprint первоначального запроса не меняются.

Версия формы строится из ID/title/source/title_updated_at. Сравнение — под
`SELECT FOR UPDATE` с обновлением ORM-объекта из базы (`populate_existing`).
Сначала доступ/удаление, затем версия/валидация, затем изменение и commit.
Если присланное имя уже равно сохранённому и источник `user_confirmed`,
повтор считается успешным без новой записи. Это покрывает потерянный ответ.
Неизменённое поле на focus/Enter/blur не отправляется и не меняет источник.
Если явная операция с тем же автоматически заданным текстом всё же пришла
на сервер, она устанавливает `user_confirmed`; обычный вход/выход из поля
такой операцией не считается.

Несовпавшая версия с отличающимся именем даёт конфликт. Ответ включает
текущее разрешённое для просмотра имя и новую версию. Повтор поверх изменения
требует отдельного Enter; клиент не отправляет его автоматически.

Состояния редактора: просмотр → редактирование → сохранение → просмотр;
сохранение → ошибка/конфликт → редактирование/повтор/отмена.
Черновик хранится только в живом DOM. При переходе он защищён предупреждением;
при закрытии с подтверждённым отказом от изменений не сохраняется.

Валидация: trim краёв; 1–500 кодовых точек, не UTF-16 единиц; без
управляющих символов, запрещённых метаданных и абсолютных файловых путей.
HTML экранируется шаблоном, обновление DOM выполняется через textContent.
Название не записывается в audit/logs/analytics. Если нужен факт изменения,
событие содержит только ID, действие, автора и результат.
