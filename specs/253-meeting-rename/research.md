# Исследование переименования встречи

Дата: 2026-09-06. Код GRAF: `a389657e607ef8389fcf947b26b158cee6928884`.
Метод: наблюдение интерфейса Krisp, чтение исходников GRAF. Здесь нет
реальных названий встреч, персональных данных и снимков приватного кабинета.

## Krisp: непосредственно наблюдавшееся поведение

| Поверхность | Наблюдение | Достоверность |
|---|---|---|
| Установленный Krisp 3.15.6, `ai.krisp.krispMac` | Основное окно содержит HTML-оболочку и встроенную страницу `desktop.krisp.ai`; название карточки — текстовое поле, доступное для редактирования | Подтверждено деревом доступности и экраном |
| Приложение | Клик в название ставит текстовый курсор без отдельного диалога; Esc без изменения оставляет фокус в поле | Подтверждено; приватная встреча не изменялась |
| Веб `app.krisp.ai` | Та же структура заголовка; редактирование доступно на учебной встрече | Подтверждено |

| Веб | Исходное учебное название восстановлено; после полной перезагрузки поле и вкладка показывают исходное имя | Подтверждено |
| Веб | Создание новой заметки закрыто предложением Core/Advanced | Подтверждено; тариф не менялся |

Ограничения: установленное приложение и веб были авторизованы в разных
аккаунтах. Межаккаунтную/межустройственную синхронизацию этим опытом доказать
нельзя. Ошибки сети, 500-символьный предел, серверный конфликт и права других
ролей в Krisp не проверены. ASAR, код, двоичные файлы и закрытые API не читались.

## Решения для GRAF

### Редактор в заголовке

**Decision**: по уточнению пользователя — одно редактируемое название,
Enter/blur сохраняют, Esc отменяет. Без постоянных кнопок и меню.
**Rationale**: минимальный путь как в Krisp; пояснение появляется только при ошибке. Отмена и ошибки определены явно и не требуют отдельного диалога.
**Alternatives**: форма «Сохранить/Отмена» отклонена пользователем как лишняя;
модальное окно и отдельная страница не нужны.

### Общий кабинет

**Decision**: один серверный обработчик с двумя путями `/meetings` и
`/desktop/meetings`, общий шаблон и JS.
**Rationale**: существующие `web_routes/speakers.py` и `rendering.py` уже
используют такой способ. Нативный код и новая библиотека не нужны.

### Данные и ограничения

`db/models/meeting.py` уже содержит `title` (500), `title_source` и
`title_updated_at`. `cabinet/view_models.py` считает `user_confirmed`
авторитетным источником. `calendar/matching.py::_apply_calendar_title`
заменяет только `generic`, `app_context` и выбранное календарное название.
Переименование должно устанавливать `user_confirmed` под блокировкой строки.

`domain/metadata_text.py` отклоняет ссылки, адреса почты, признаки секретов,
управляющие символы. `safe_metadata_text` обрезает слишком длинное значение:
поэтому предел проверяется ДО этого helper, без молчаливой обрезки.
`_authoritative_title` скрывает абсолютный путь; редактор должен отклонять
такое значение, чтобы принятое имя не изменялось при отображении.

### Доступ и конфликт

**Decision**: только `created_by_user_id` текущего активного пользователя и
текущая организация, CSRF как у остальных форм. Блокировка строки Meeting,
повторная проверка удаления; сравнение версии названия до записи.
**Rationale**: `_authorized_lifecycle_meeting` разрешает администратора и
не проверяет удаление, поэтому его недостаточно применять без дополнительной
проверки авторства/состояния. Read-only доступ не становится правом записи.

Версия — непрозрачный SHA-256 от ID, текущего title, title_source,
title_updated_at; это сравнение состояния, а не новая авторизация. В ответ
конфликта текущее имя попадает только после повторной проверки доступа.

### Жизненный цикл и отображение

Проверить обоих писателей названия: calendar matching и очистку контекста
календаря. В `ingest/meetings.py` повтор первоначального запроса использует
`create_request_fingerprint_sha256`; его нельзя пересчитывать после rename.
У старых встреч без fingerprint сравнение идёт с изменяемым title — отдельный
обязательный сценарий исследования/регрессии.

Переименование меняет только поле заголовка, document.title и версию редактора.
Полная перерисовка карточки при успехе недопустима: она прервёт плеер.
На возврате к списку нужна загрузка актуальных данных с теми же фильтрами.
Новые экспорты должны читать авторитетный заголовок; прежние файлы не меняются.

### Границы проверки

Проверка встроенного HTML в браузере не равна проверке установленного GRAF.
Локальная проверка WebKit/реального dev-клиента и production остаются
отдельными свидетельствами. Требования UX/security должны быть проверены
рецензентом до изменения продуктового кода.

## Проверка писателей названия на этапе plan

`processing/fences.py::lock_meeting_fence` уже реализует нужную блокировку.
Исследование всех 9 production callers `ingest/store.py::persist_meeting`
показало, что existing-ветка безусловно пишет title/source/timestamp из снимка.
Это общий риск отката ручного названия; удалить именно эти присваивания при
обновлении, сохранив создание. Calendar matching и `calendar/service.py`
пишут название напрямую после блокировки. Очистка календарного названия
вызывается при удалении под той же блокировкой; disconnect его не меняет.
Для старого retry без fingerprint после user_confirmed исключить лишь
сравнение изменяемого названия, сохраняя остальные guards; не выдумывать
исходное имя или fingerprint. Проверить отдельными регрессиями.
