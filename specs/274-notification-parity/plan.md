# Implementation Plan: Паритет уведомлений GRAF с Krisp

**Branch**: `274-notification-parity` | **Date**: 2026-09-18 | **Spec**: [spec.md](spec.md)
**Input**: Спецификация фичи из `/specs/274-notification-parity/spec.md`
**Research**: [research.md](research.md) — реверс-инжиниринг наблюдаемого Krisp 3.16.8

## Summary

До этой фичи основные уведомления GRAF показывались через
`UNUserNotificationCenter`: они подчинялись разрешению macOS и режиму «Не
беспокоить», жили несколько секунд, несли ограниченный набор действий и не
разделяли «подключиться» и «начать запись». Наблюдаемый эталон устроен иначе —
собственная карточка поверх окон, которую GRAF рисует сам.

План приводит поверхность показа к одному понятному правилу: GRAF получает одну
собственную карточку AppKit для полезных событий (напоминание о встрече, вопрос о
записи, проблема сохранения или отправки, короткая запись). Карточка имеет окно
448 точек, карточку 420 точек, скругление 16 и не забирает фокус. Постоянное
состояние записи не выносится в отдельное плавающее окно: оно остаётся в самом
приложении, строке меню и панели управления.

Логика показа управляется собственным согласователем: встреча показывается до
120 секунд и исчезает в начале встречи, вопрос о записи — 8 секунд с обратным
отсчётом и автоматическим решением по окончании, проблема и короткая запись —
20 секунд. Крестик вопроса означает «Не записывать сейчас» для текущей встречи;
для остальных карточек он закрывает конкретное сообщение. Кнопка «Проверить
уведомление» показывает ту же карточку 6 секунд как предварительный просмотр,
без системного баннера и побочных эффектов. Системный баннер не дублирует
карточку и не используется для рутинных состояний записи. Проверка из настроек
имеет отдельный безопасный контент и не меняет состояние реальных уведомлений.

## Technical Context

**Language/Version**: Swift 6 (языковой режим пакета), AppKit + SwiftUI-хост,
macOS 14+
**Primary Dependencies**: AppKit (`NSPanel`, `NSStackView`, `NSButton`),
`UserNotifications` (резервные календарные запросы; полезные карточки не дублируются), Combine
(подписка на снимок состояния), SwiftPM
**Storage**: файл настроек уведомлений в контейнере приложения
(`DesktopNotificationPreferencesStore`), состояние показа — в памяти процесса
**Testing**: XCTest, `apps/macos/Scripts/run-swift-tests.sh`; новые тесты
`DesktopNotificationCardTests` проверяют правила показа, содержимое, действия,
геометрию и поведение окна
**Risk / Validation Lane**: high-risk-feature — пользовательская поверхность,
рядом с записью и приватностью; полный путь Spec Kit и обязательные
clarify/checklist/analyze
**Release Gate**: без публикации из этой ветки — фича входит в обычный
релизный поезд, отдельного развёртывания не требует; релизная подготовка
выполняется после проверок
**Target Platform**: macOS 14+, один экран или несколько, светлое и тёмное
оформление
**Project Type**: desktop-app (macOS-клиент внутри монорепозитория GRAF)
**Performance Goals**: показ полезной карточки без заметной задержки относительно
момента срабатывания; не более одного окна карточки одновременно; отсутствие
постоянного плавающего окна записи; отсутствие постоянного опроса — пересчёт по
таймеру до срока и по изменению состояния. Карточка встречи появляется за 15
минут до начала и живёт не более 120 секунд; далее исчезает в начале встречи.
**Constraints**: карточка не забирает клавиатурный фокус
(`canBecomeKey == false`), не перекрывает строку меню, не выходит за рабочую
область экрана, не зависит от разрешения macOS, не использует чужие ресурсы.
Карточка появляется только для полезных событий; рутинные переходы записи не
создают ни карточку, ни системный баннер. Вопрос о записи живёт 8 секунд, имеет
видимый отсчёт и по тайм-ауту запускает текущую встречу в соответствии с
выбранной политикой; крестик отказывает только для текущей встречи.
**Scale/Scope**: один пользователь на Mac; до нескольких встреч в час; одна
единая карточка поверхности, один изменённый согласователь, тесты правил,
жизненного цикла и безопасного предпросмотра

## Constitution Check

*GATE: проверка до Phase 0 и повторно после Phase 1.*

| Принцип | Как соблюдается |
|---|---|
| I. Capture-first, честные состояния | Карточки показывают только полезные события; постоянное состояние и «Идёт расшифровка» видны в приложении и строке меню по подтверждённому снимку состояния |
| II. Приватность и согласие | Карточка не раскрывает содержимое встречи, если пользователь отключил показ названий; ссылка открывается только после проверки владельца и актуальности события |
| III. Локальность и офлайн | Карточка работает без сети; для встреч нужен только уже полученный календарный контекст |
| IV. Один контроллер записи | Кнопки карточки отправляют те же команды модели, что и существующие элементы управления; второго контроллера не появляется. Тайм-аут вопроса запускает текущую встречу только после проверок Feature 214 |
| V. Проверяемость | Правила показа вынесены в чистые функции и покрыты тестами; геометрия измеряется на настоящем окне |
| VI. Простой и надёжный путь | Новый код — небольшой слой AppKit; системные уведомления остаются резервным каналом для совместимых календарных сценариев, а полезные карточки не дублируются |
| VII. Reference-Fidelity | Воспроизводится наблюдаемое поведение и внешний вид эталона; исходный код, ресурсы и бинарники Krisp не переносятся, реализация написана независимо, чужие торговые марки не используются |

Нарушений, требующих обоснования, нет.

## Validation Plan

1. **Модульные проверки**: `swift test --package-path apps/macos --filter
   DesktopNotificationCardTests` — правила окна показа, содержимое карточки,
   безопасность ссылки, иерархия действий, однократность закрытия, отсутствие
   карточки для рутинных переходов, геометрия карточки и окна, сроки показа и
   изоляция предпросмотра.
2. **Регрессия уведомлений**: существующие `DesktopNotificationControlTests` и
   `DesktopLocalNotificationDeliveryTests` остаются зелёными; отдельная проверка
   подтверждает, что предпросмотр не добавляет системный запрос и не меняет
   `dismissedCards` или реальные напоминания.
3. **Полный набор macOS-тестов**: `bash apps/macos/Scripts/run-swift-tests.sh`.
4. **Быстрый репозиторный шлюз**: `infra/scripts/ci-local.sh --fast`.
5. **Ручная проверка в единственном приложении** `/Applications/GRAF Dev.app`
   через `infra/scripts/dev-harness.sh` (build → promote → status → smoke):
   карточка встречи, отсутствие карточек при переходах состояния записи,
   вопрос с отсчётом и отказом по крестику, предпросмотр из настроек, поведение
   при выключенных системных уведомлениях, тёмное и светлое оформление, закрытие
   основного окна и завершение процесса без оставшейся панели.
6. **Проверка в PR**: `governance-fast`, `macos-pr`, `pr-metadata` на точном SHA;
   `release-full` — на замороженном кандидате релиза.

**Structure Decision**: поверхность уведомлений остаётся внутри модуля
`TwoBrainRecAppCore` рядом с существующими презентерами; отдельный модуль не
вводится, потому что карточка использует те же модели календаря и состояния
записи, что и текущий презентер, и не должна тянуть новые зависимости.
Постоянный плавающий индикатор записи не является частью этого модуля: его источник правды
— существующие приложение, строка меню и панель управления.

## Текущий результат реализации

Базовая поверхность карточки и жизненный цикл реализованы; после уточнения
цели этап 7 живым доказательством остаются T044 и T045. Вызов
`updateRecordingIndicator` сохраняет состояние только для основного интерфейса и
не создаёт карточку; отрицательные тесты T038 это подтверждают. Текущий результат
соответствует следующим правилам:

- карточка 448 точек используется только для встречи, вопроса о записи, проблемы
  сохранения/отправки и короткой записи;
- постоянного плавающего окна записи нет: состояние и остановка доступны в самом
  приложении и строке меню;
- сроки различаются по смыслу: 120 секунд/до начала для встречи, 8 секунд для
  вопроса, 20 секунд для проблемы и короткой записи;
- крестик вопроса — отказ от текущей встречи без изменения постоянной настройки;
- переходы состояния записи не создают карточек и системных баннеров;
- после закрытия окна и завершения процесса GRAF панель исчезает.

Полный набор macOS-тестов и обязательные проверки считаются доказательством только
после того, как они будут обновлены под T038–T045 и подтверждены в живом
`/Applications/GRAF Dev.app`; исторические результаты старого кандидата не
заменяют текущую проверку.
