## Воспроизведение обхода до исправления

Временный синтетический репозиторий содержал обе mapped цели с единственным
`def test_other(): assert True`, без обязательного
`test_sc017_one_hundred_warmed_atomic_consumptions_are_within_50ms_p95`.
Текущий `select_tests` принял эту выборку. Затем временный JUnit содержал по
одному `test_other` с правильным classname обоих файлов; `check_execution`
принял его без SC017. Явный `<skipped/>` был отвергнут. Временный каталог
автоматически удалён. PostgreSQL, приложение и production не запускались.

Причина: AST принимает любой test_ календарного файла, а JUnit подтверждает
любой testcase этого файла. `ci-local.sh` отключает отдельную performance
проверку уже по присутствию имени целого файла в behavior targets. Поэтому
удалённый/переименованный SC017 либо выборочный deselect только SC017 оставляют
формально успешную общую выборку. Существующий запрет skipped этого не покрывает.

Минимальный ожидаемый результат исправления: обязательный именованный SC017
должен существовать до запуска и иметь доказательство успешного выполнения в
JUnit именно календарного integration модуля; одного testcase модуля или
одноимённого testcase постороннего модуля недостаточно. До приёмки нужны
направленные отрицательные проверки отсутствия/переименования определения,
отсутствия SC017 в JUnit/его пропуска и подмены модулем; положительный случай
с реальным SC017 и прежние command/skip/failure регрессии. Реальное выполнение
календаря с `GRAF_PERFORMANCE_GATE=required` остаётся отдельным доказательством.
