# Data model: F264

Новых постоянных сущностей нет. UserIdentity хранит имя/тему/часовой пояс, существующие календарные предпочтения и выбор источников — календарь, BillingNotificationPreference — необязательные уведомления с version; локальные stores — правила приложений и уведомлений Mac; существующие summary templates — личные форматы.

В памяти страницы: confirmed (подтверждённые значения), draft (текущий ввод), pending (последний ожидающий снимок), inFlight, owner/scope, version, error. Один последовательный writer на ресурс; dirty определяется относительно confirmed. Только успешное подтверждение обновляет confirmed/version. Более свежий draft не заменяется старым ответом. При ошибке draft остаётся; при внешней смене области очередь прекращается. Ключ очереди — владелец + область + существующий ресурс, а не DOM-форма; меню темы и форма аккаунта разделяют одну очередь. Ответ содержит подтверждённые нормализованные поля, область и существующую версию. Клиент сверяет их с отправленным снимком и актуальным контекстом; HTTP 200 без такого подтверждения не означает успех.

Жизненный цикл: idle → pending → saving → saved либо error/conflict. Новый ввод во время saving обновляет pending; по окончании отправляется последний снимок. Навигация ждёт flush, ошибка препятствует тихой потере. Закрытие/уход при ожидающем сохранении получает штатное предупреждение. Нет обещания гарантированно записать данные при принудительном завершении приложения.

Существующие сроки хранения/удаления и аудит остаются прежними. Не сохранять содержимое полей в журналах или исследовательских снимках.

## Единицы записи и конкуренция

| Ресурс | Владелец / область | Единица записи и защита |
|---|---|---|
| Имя профиля | Текущий user | Только display_name; существующая нормализация и допустимое пустое имя |
| Тема, часовой пояс, доступная локаль | Текущий user | Только изменённые поля; обе точки темы используют одну очередь |
| Письма и подсказки | Текущий user | Существующая группа BillingNotificationPreference, текущая version и проверка конфликта |
| Выбранные календари | Текущая tenant scope + source | Полный набор выбранных ID одного источника, включая пустой; сравнение исходного набора под блокировкой, валидация доступных ID/лимита |
| Календарные предпочтения | Текущая tenant scope существующего ресурса | Изменённые поля; если сервис требует полную группу, сравнение исходного состояния под блокировкой |
| Формат новых итогов | Текущее пространство, существующие права управления | Существующая ссылка на формат и его версию; повторно проверить доступ к формату, не менять опубликованные итоги |
| Существующий личный формат | Текущий владелец + template_id | Существующий валидный документ, expected_version; изменения не запускают генерацию итогов |
| Правила записи и уведомления Mac | Текущий Mac и существующая привязка store к владельцу | Запись через текущий store/bridge; подтверждение фактического результата, общий статус и повтор |

Версионные ресурсы не теряют expected_version при повторе. Ресурсы с частичным обновлением сохраняют существующее правило последней принятой записи одного поля между устройствами; это не обещание глобального разрешения конфликтов. Остальные поля не передаются из устаревшей формы. Для сравнения неделимой группы сервер использует текущее состояние в той же транзакции и блокировке, что и запись; сравнение только на клиенте недостаточно.

Потерянный ответ/тайм-аут (15 секунд) переводит запись в неподтверждённое состояние. Перечитывание не затирает draft: совпавшие отправленные значения можно подтвердить; при отличии свежего ресурса от исходного требуется явное разрешение конфликта. Повтор после непринятой записи отправляет последний валидный draft того же владельца. Уход без сохранения отбрасывает только ещё не подтверждённый ввод, не откатывает уже принятые записи и не обещает отмену запроса на сервере.
