# Проверки F264

## До реализации

1. Проверить spec/plan/contracts и reviewer-owned checklists; открытые high-risk пункты блокируют код.
2. Analyze: нет нерешённых CRITICAL/HIGH; taskstoissues связывает задачи с GitHub.
3. Сверить текущий SHA и незавершённые соседние ветки настроек; не переносить чужие изменения без проверки.

## Поведение

- Проверить профиль, тему в двух точках, timezone, обе группы календарных настроек, выбор 0/1/20 календарей, уведомления с version, личные форматы, локальные правила.
- Быстрые изменения A→B→C; задержка первого запроса; ввод во время запроса; несколько полей; IME; переход раздела и закрытие диалога.
- Пустое имя профиля сохраняется; невалидный личный формат не отправляется; из обоих видов формы можно выйти осознанно без бесконечной блокировки. Escape/крестик/фон, Enter в textarea, возврат фокуса и закрытие embedded окна проверяются отдельно.
- Ошибка до записи и потерянный ответ после записи; 401/403/409/422/503; редирект на login; неподходящий HTML; смена владельца и пространства; повтор и конфликт.
- Проверить 15-секундный тайм-аут и read-back перед повтором; конфликт expected_version личного формата; сравнение исходной неделимой календарной группы под блокировкой; две точки темы с одним writer; отказ локального диска/моста без ложного сохранения.
- Проверить server validation, CSRF, version/owner fences, календарные контекстные ограничения и 8 секунд/три правила записи.
- Проверить no-JS: обычные настройки недоступны, явные формы работают штатно.

## Автоматические проверки

Запускать в существующем окружении проекта по release-and-validation.md, не устанавливать новое тестовое окружение без необходимости.

Семь страниц × web/desktop × 360/540/768/1024/1440 px × light/dark/system; 200% zoom; длинные подписи; клавиатура; доступность; ошибка у каждого вида элемента. Использовать существующий settings_visual_ui_harness с синтетическими данными, а после прочтения local-development.md — единственный /Applications/GRAF Dev.app через dev-harness. Нельзя подменять это отдельной копией или swift run. Реальные приватные данные не сохранять в git.

## Завершение

В validation.md записать фактические команды/результаты, отличая макет от серверного и установленного результата. Converge фиксирует оставшееся. Коммит после отдельного одобрения пользователя; governance-fast относится к точному PR SHA. Выпуск требует отдельного разрешения и release-full. Пока код/установленная приёмка не завершены, задача не закрывается.


## Повторяемая проверка единого оформления

Запустите существующий синтетический макет из `apps/server`:

```sh
.venv/bin/uvicorn tests.fixtures.settings_visual_ui_harness:app --host 127.0.0.1 --port 8874
```

Затем из корня с установленным Playwright (при необходимости укажите `NODE_PATH` своего окружения):

```sh
node apps/server/tests/browser/settings-consistency.test.cjs
node apps/server/tests/browser/settings-combobox.test.cjs
BROWSER=webkit node apps/server/tests/browser/settings-combobox.test.cjs
```

`SETTINGS_PREVIEW_URL` задаёт адрес синтетического макета; `SCREENSHOT_DIR` сохраняет снимки тестовых данных. Проверка единого выбора использует Jinja из `apps/server/.venv`, созданного через `uv sync --frozen --extra dev`. Рабочие аккаунты и настоящий мост приложения в макете не используются.
