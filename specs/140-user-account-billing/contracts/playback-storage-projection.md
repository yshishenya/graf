# Единая проекция занятого архива при замене записи

Уточнение реализации существующих F140 FR-094–096, S1/S9 и T070/#4926,
T068/#4922 от 11.11.2026. Полоса high-risk-product. Это часть действующего
Plan «Источники и минимальный состав» и Quickstart «Storage 80/95/100»,
а не новая задача, коммерческое правило, политика хранения или приёмка.

## Основание и выбор

Причинная проверка рабочей публикации обнаружила двойной учёт: после замены
24 байт на33 `used` увеличивался на33 вместо9. Старые канонические строки
нельзя глобально пометить superseded: кабинет ещё может читать ревизию
принятых итогов, а READY job сохраняет собственное восстановление. Раздельные
правила квоты и чтения уже нужны для сохранения F099/F292/F286.

Решение: вычислять один логический учитываемый primary на встречу в общем
`billing/storage.py:project_active_playback_storage`. Это производная SQL
проекция существующих строк, без нового указателя, инвентаря, миграции,
фонового процесса или записи в canonical/job/source metadata.

Отклонённые варианты: сумма всех ревизий сохраняет дефект; глобальный
supersede разрушает старое чтение/восстановление; выбор по последнему времени
worker допускает вытеснение новой записи старым recovery; max(byte_length)
не освобождает уменьшение; чтение текущего outcome подменяет quota выбранным
пользователем материалом. Отдельный расчёт для писем расходится с допуском.

## Определение primary

1. Точный workspace; TrackArtifact относится к тому же Meeting и MediaRevision
   по workspace_id, meeting_id и media_revision_id. Чужая или несогласованная
   lineage не участвует. Встреча должна существовать.
2. Кандидаты — только опубликованные `TrackArtifact`: track_role=playback,
   status=stored, профиль `review_m4a_aac_lc_48k_mono_64k_v1`, конечный сегмент
   ключа ровно `meeting-review.m4a`. Временные/невалидные/удалённые/superseded
   строки и исходные WAV не кандидаты. Новая queued/failed ревизия без такого
   опубликованного canonical не освобождает прежний primary.
3. В каждой встрече выбрать наибольший неизменяемый
   `MediaRevision.revision_number`. Детерминированный порядок при равенстве:
   revision UUID, затем artifact UUID, оба по убыванию; время публикации,
   validated_at и размер не определяют победителя. Уникальность нормальной
   ревизии/канонического artifact сохраняется, tie breaker не разрешает
   создание дублей. Поздняя публикация или восстановление старой ревизии
   не вытесняет уже опубликованную более новую.
4. **Сначала выбор primary, затем no-archive фильтр.** Если у выбранной
   ревизии есть finalized UploadSession с archive_audio=false в той же
   workspace/meeting/revision, её вклад равен0. Старый архив при этом не
   возвращается в квоту. Одна новая finalized no-archive сессия без нового
   опубликованного canonical не делает старый архив no-archive primary.
   Временный canonical для обработки остаётся lifecycle-учтённым, не даёт
   права на пользовательское воспроизведение и подчиняется FR-106.
5. `used` — сумма точных byte_length выбранных учитываемых строк. Замена
   после commit видна как `old used − old bytes + new bytes`; до commit
   прежний snapshot, после rollback прежний primary. Промежуточный двойной
   учёт не публикуется. Новых коммерческих счётчиков нет.

## Допуск и жизненный цикл

Полный declared_bytes нового нормализованного объекта резервируется по
существующему FR-095: `used + reserved + incoming <= capacity`. Резерв
не уменьшается на прежний размер. Commit проверяет полный actual stat;
превышение reservation по-прежнему отказ. Поэтому около capacity замена
может не пройти admission даже при меньшей чистой разнице. Разрешение по
разнице требует отдельного долговечного replacement credit и защиты от
конкуренции, которых этот срез не добавляет. При полном архиве большая
замена отклоняется, прежняя запись и локальная custody сохраняются.

Никаких изменений canonical statuses, job pointers, ASR/source fingerprints,
проверок источника, purge deadlines или исходных объектов ради квоты.
Логическое удаление встречи освобождает quota через существующее удаление
всех playback; физический purge/backup/recovery остаются самостоятельной
истиной. Потеря проверки источника обрабатывается существующей политикой,
а не новым выбором billing primary.

Старый outcome-reader вправе читать старый readable canonical, пока он
разрешён действующей политикой. Публичный F292 reader сохраняет выбор
текущей принятой ревизии, media_version/409 и отсутствие fallback к старому
аудио; F286 summary_only не меняется. Эти выборы не заменяются quota selector.

## Охват реализации и проверок

Общий helper уже вызывают reserve_storage, кабинет usage/overview, auth usage,
billing monitoring/maintenance и storage observer. Перед кодом сверить все
вызовы; отдельные копии вычисления не добавлять. Точечный predicate
`is_chargeable_playback_artifact` остаётся проверкой одного объекта при
commit reservation; он не может решать межревизионное первенство.
`logically_release_playback_quota` по-прежнему очищает все старые объекты
для lifecycle, а возвращаемое число не становится новым счётчиком квоты.

Проверки после допуска независимого checklist и Analyze:

| Группа | Причина и ожидаемое доказательство |
| --- | --- |
| Рабочая публикация | Существующий RED24→33 на80/95 становится точным old−24+33, rollback не меняет used; по100 сохраняется полный admission отказ. Observer→commit→outbox→один stub не подменяется ручным enqueue. |
| Выбор | Уменьшение, queued/failed/invalid новая ревизия, поздняя старая публикация/recovery, независимые встречи и чужая lineage; порядок по revision_number, а не времени/размеру. |
| Атомарность | Новые сеансы до/после commit и rollback, сериализованные конкурентные публикации/попытки; итог один, все роли RLS остаются ограниченными. |
| No-archive/удаление | Выбор до no-archive исключения, исходные WAV/temporary не учитываются; logical delete освобождает primary, purge не возвращает старую ревизию. |
| Чтение | Старый outcome продолжает читать свой canonical; текущая публичная версия даёт новое аудио, старый media_version409; summary_only неизменен. |
| Допуск | Полный резерв, exact-boundary и недопустимое превышение, уменьшение не даёт недоказанного credit; original commit stat и local custody. |

Применять существующий одноразовый PostgreSQL runner с настоящими RLS ролями
и подставными media/почтовыми транспортами, без реальных данных и provider calls.
Проверить фактические имена тестов перед запуском. Один набор итоговых
результатов привязать к точным хешам исходников; промежуточные разные снимки
не складывать в общий PASS. Независимое code review, Converge, F140 fragment,
точные PR SHA/base/common остаются обязательными; T070/T068 `[ ]`, #7524,
сервер, выпуск и GRAF Dev имеют отдельную приёмку.
