# Независимая проверка требований к реферальным уведомлениям F140

**Дата:** 10.11.2026. **Объём:** только реферальная часть T068/#4922 и T070/#4926 до реализации.

**Решение после повторной проверки: требования допущены к реализации.** Подтверждены 8 из 8 пунктов, открытых пунктов в этом списке нет. Первая проверка приняла CHK001, CHK006 и CHK008; изменения контракта и quickstart закрыли пять замечаний. Проверены FR-062–074, FR-101 и FR-108, строки T067–T071, матрица уведомлений, новый раздел контракта, план и сценарий quickstart. Для проверки границ сопоставлены существующие правила лимита, маршрут кабинета и отправщик.

| Пункт | Решение и основание |
|---|---|
| CHK001 | Подтверждён. Доступность, применение и отмена различаются. При немедленном применении в одной транзакции ставится только письмо о применении; повтор обработки доступной записи не создаёт письмо. |
| CHK002 | Подтверждён. Для Free доступный бонус ждёт собственного подтверждённого платного периода либо истечения. Ожидание, открытая проверка, истечение и отклонение не создают писем. При частичном остатке лимита письмо сообщает фактически применённые дни; при нулевом остатке переход в отклонение не создаёт письма. Это соответствует существующему порядку в `billing/referral_rewards.py`: положительный остаток ограничивает дни применения, нулевой ведёт в `rejected`. При отменённом продлении меняется только последний срок обслуживания, новое списание не планируется. |
| CHK003 | Подтверждён. Письмо привязано к первоначальному пригласившему, пока он активен и владеет тем же личным пространством журнала. Получатель в очереди неизменен. После объединения не следуют `merged_into_user_id` и не создают письмо по прежней привязке; новый владелец, плательщик или приглашённый не заменяют получателя. Отдельная действующая атрибуция проходит обычную проверку. |
| CHK004 | Подтверждён. Для всех трёх видов требуются активный подтверждённый адрес и разрешение на необязательную почту; исключения FR-072 сохраняются. Подтверждённая утрата права, адреса или согласия означает отсутствие постановки либо терминальное `suppressed`. Ошибка чтения при постановке откатывает переход и очередь; штатный источник может повторить переход. Сбой проверки после взятия письма, но до транспорта, сохраняет счётчик и повтор не ранее 60 секунд, максимум пять суммарных попыток с терминальным `failed` при исчерпании; несохранённая попытка не разрешает вызов транспорта. Неопределённый исход после обращения к транспорту повторять нельзя. |
| CHK005 | Подтверждён. По видам событий заданы поля: дата истечения без обещания числа дней; сохранённые дни и интервал применения; дата отмены. Все даты в МСК. Ссылка ведёт на настроенный адрес GRAF, путь `/referrals` без параметров и без смены пространства. Штатный выбор пространства сохраняет проверку владельца и RLS. В письмо не попадают идентификаторы, токены, данные приглашённого и материалы встреч. |
| CHK006 | Подтверждён. Постановка в очередь и переход связаны одной транзакцией. Ключ включает внутренний UUID записи бонуса и вид перехода. Откат не оставляет письмо, повтор не создаёт дубликат, неопределённый результат транспорта не запускает повтор. |
| CHK007 | Подтверждён. Quickstart отделяет прямую пробу очереди от проверки рабочего источника через commit и подставной транспорт. Есть отдельные ожидания для Free, частичного и нулевого остатка, неизменности получателя, подавления после объединения и потери права, отката источника с повтором, сохранения счётчика, исчерпания попыток и неизвестного исхода транспорта. |
| CHK008 | Подтверждён. Остальные семейства событий T068/T070 остаются открытыми. План ограничивает роль обслуживания, исключает новые права, миграции, переписку о возвратах, смену транспорта и обратную рассылку. Фактическая доставка #7524 и выпуск остаются отдельными. |

Проверка требований не подтверждает реализацию. При проверке кода отдельно подтвердить чтение полномочий и терминальную обработку отсутствующего адреса под действующей ролью обслуживания: существующий отправщик выбирает адреса через внутреннее соединение, поэтому исчезнувший адрес может исключить строку из выбора вместо перевода в `suppressed`. Прежняя изолированная проба прямой постановки подтверждает только возможность работы с очередью, откат и отсутствие дубля; она не проверяет необходимые чтения полномочий, рабочий источник и доставку. Тесты, GitHub и почта в этом обзоре не использовались.
