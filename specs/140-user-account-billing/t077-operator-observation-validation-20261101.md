## Изменение

Вместо неиспользуемой модели с нулевыми показателями появился сбор агрегатов
из объявленных источников и внутренний CLI:

```sh
python -m twobrain_rec_server.cli.billing_monitoring --date 2026-10-31
```

Используются существующие Settings, SQLAlchemy, maintenance guard, контекст
и registry_status. Схема БД, службы, зависимости, Admin, readiness и F254
не менялись. Legacy Impact: remove — старая модель и её суммирование
удалены вместе с двумя тестовыми потребителями; рабочих потребителей не было.
Новые пути совместимости и исключения не добавлены.

Команда читает один READ ONLY REPEATABLE READ снимок. Режим и таймауты
действуют уже при установлении PostgreSQL соединения, до dialect/tenant
SELECT. Все возраста используют один UTC as_of. Неподключённые семейства
имеют null/unavailable; весь отчёт всегда partial. Операции без списания,
очередь webhook и сохранённые попытки писем не выдаются за успешные оплаты,
задержку транспорта или число HTTP-запросов.

При истечении срока завершается фактическое соединение; закрытие сессии
и освобождение пула также проверены. Ответ не содержит исходных строк
неизвестных состояний, платёжных данных, идентификаторов или SQL-ошибок.

## Проверки и исправленные отказы

Штатный одноразовый PostgreSQL runner выполнил профильный набор:

```sh
bash apps/server/scripts/run_local_postgres_tests.sh --focused -q \
  tests/integration/test_billing_monitoring_postgres.py \
  tests/unit/test_billing_monitoring.py \
  tests/contract/test_billing_safety_contract.py
```

Итог: **26 разных проверок PASS; 0 FAIL/ERROR/SKIP** по последнему исходу
каждой пары classname/name. После исправлений повторялись затронутые случаи;
повторные исполнения не прибавлены к числу разных проверок.

- Подтверждены настоящий CLI и повтор из нового процесса, forced RLS,
  отказ app/worker/superuser/SET ROLE/неверного контекста и запрет DELETE.
- Подтверждены успешный ноль против unavailable, закрытые группы, времена
  из будущего, совместимость чтения, отдельные очереди и безопасный вывод.
- Под registry lock изменены настоящий receipt и gap. Старый читатель
  после ожидания видит прежний registry; новый процесс видит новые данные.
- Подтверждены connection/query/lock timeout, предел 501 gaps и 64 KiB,
  несовместимый запрос, настоящий SIGINT и ошибка dispose.
- При зависшем close/dispose после срока фактический driver закрыт,
  прежний pool.checkedout() равен 0, транзакция сессии отсутствует.
- Проверены неизменность синтетических строк до/после и отсутствие HTTP.

Первый запуск остановлен на ошибке очистки тестового TCP-сервера:
Server.wait_closed в Python 3.13 ожидал ещё открытые соединения. Исправлен
порядок закрытия. Следующий отказ теста отмены был вызван закреплённым
снимком pg_stat_activity; наблюдение заменено динамическим pg_locks.
При проверке очистки выявлено, что Session может потерять ссылку на
Connection раньше неудачного rollback. Исправлено освобождение сохранённого
Connection через invalidate; предупреждение об оставшемся checkout
сохранено в исторических журналах, затем устранено и проверено напрямую.
Ошибки не скрывались фильтром предупреждений или подавлением исключений.

Внешние доказательства: f140-t077-postgres-final.xml/log,
f140-t077-cleanup-pool-final.xml/log, f140-t077-registry-time-final.xml/log
и f140-t077-implementation-validation-summary-20261101.json. Предыдущие
запуски сохранены отдельно; ранние PASS не объявляются новым исполнением.
Ruff выбранных файлов, governance, development-process, changelog fragments
и git diff --check прошли. Это локальная проверка незакоммиченных файлов,
не квитанция обязательных GitHub проверок точного SHA и основы.
