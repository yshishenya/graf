## Замечания, переданные до окончания проверок

### R1. Безопасная отмена и завершение CLI

В первичной версии `asyncio.CancelledError` пробрасывается, `main()` не
обрабатывает KeyboardInterrupt, а `engine.dispose()` выполняется в finally
вне обработчиков ошибок. SIGINT или ошибка cleanup могут обойти безопасный
schema_version/result_code, напечатать traceback вместо предусмотренного
отказа. Общий timeout также не ограничивает finally. Нужна минимальная
безопасная обработка с настоящей проверкой отмены процесса и ошибок cleanup;
rollback/закрытие нельзя пропустить ради красивого JSON.

Основной агент независимо сообщил, что уже исправляет эти границы.
До чтения окончательного diff и доказательств замечание не снято.

### R2. Ограничения до первого SELECT dialect

Execution options задают readonly/RR до tenant hook, но начальная dialect
инициализация соединения может читать версию/default schema раньше этих
options. O2 требует режим до первого SELECT. Основной агент сообщил о
добавлении protocol-level defaults; нужно проверить сами параметры и тест,
который наблюдает также dialect initialization, а не только Session event.

### R3. Проверка снимка должна читать изменяемый registry после lock

Первичный `test_repeatable_snapshot_after_registry_lock_and_lock_timeout`
вставляет BillingOperation, чей SELECT в collector происходит **до** ожидания
registry lock. Поэтому различие count старого/нового запуска получилось бы
и при READ COMMITTED и само по себе не доказывает RR для поздних registry
чтений. Для O2/O7 нужен настоящий изменившийся принятый registry receipt
или gap под удерживаемым lock: старый читатель после ожидания должен вернуть
прежние registry данные, новый процесс — новые.

### R4. Синтетический registry seed обязан проходить реальные ограничения

Первичный `seed_registry` вставляет receipt через superuser без заданных
maintenance identities; server defaults нарушают CHECK registry_identity
0107:47. Второй accepted receipt с тем же digest нарушает
uq_registry_accepted_digest; повтор `(scope, kind, part, reason, generation)`
и detected part0 нарушает уникальность; part_index выше64 нарушает CHECK
registry_gap_key. Такой вход не докажет preflight 501, даже если collector
корректен. Нужны допустимые синтетические строки с точными identities,
разными digest/ключами и part_index в границах. Ограничения БД не ослаблять.

### R5. Канонический формат даты

Первичный `date.fromisoformat` допускает compact/week формы, хотя вход O1
задан как YYYY-MM-DD. Основной агент сообщил о строгом parser. Итоговую
правку и отрицательные случаи ещё предстоит перечитать.
