## Уточнение CHK003: сеанс чтения и физическое соединение — 31.10.2026

**SCOPED PASS сохраняется: 6 отмечены / 0 открыты.** Изменена только
формулировка CHK003; прежний текст отчёта выше оставлен историей. Его слова
«новое подключение» и первоначальный hash спецификации не являются текущим
заявлением о физическом соединении. Теперь требуется новый `AsyncSession`
для чтения PostgreSQL после commit; отдельный физический socket не заявляется.

Уточнение допустимо для исходной цели — проверить сохранённый результат,
а не повторное чтение из прежней карты объектов ORM. `_session(factory)`
создаёт новый `AsyncSession` через `factory()` в отдельном контекстном блоке
и применяет прежний maintenance-контекст (integration:58–62). Конструктор
`create_sessionmaker` привязан к тому же engine и использует
`expire_on_commit=False` (db/session.py:19–29); новый сеанс не разделяет карту
ORM-объектов предыдущего сеанса, но пул вправе переиспользовать физическое
соединение. Новый socket, PID PostgreSQL и восстановление после разрыва
транспорта этим сценарием не требуются и не доказаны.

Точечно сверена только соответствующая последовательность существующего
сценария (integration:578–608): commit планирования, выход из контекстного
блока, новые сеансы handler/повтора/чтения operation, invoice и subscription.
Это подтверждение терминологии и качества требования, не повтор независимого
code review и не самостоятельная приёмка исполнения. Новые spec/validation
также явно исключают заявление об отдельном socket. Оплаченный срок/права,
три отказа, повтор без новой отправки, остальные пять критериев, граница
синтетического транспорта и открытая полная T074/#4928 сохраняются.

В обновлённой спецификации при чтении замечена грамматическая опечатка
«новое сеанс»; владельцу передано исправить на «новый сеанс». Она не меняет
смысл уточнения; рецензент spec не редактировал. Код, остальные документы,
Git/GitHub, тесты и приложение этим уточнением не менялись и не запускались.
