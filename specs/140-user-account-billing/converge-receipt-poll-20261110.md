# T075/T077 — ограниченный опрос чеков

Maintenance сверяет старые оплаты после окна существующего опроса покупок.
В одном порядке идут логический чек оплаты и отдельные чеки подтверждённых
возвратов. Терминальный чек и чек без подтверждённой привязки не дают GET.
Проход доступен только штатной роли billing reconciliation. Адресная
проверка счёта владельцем сохраняет прежние правила.

На проход до 10 GET, общий предел 60 секунд, предел GET 5 секунд, повторная
резервация не раньше 300 секунд. Порядок: без попыток, затем по времени
предыдущей резервации, при равенстве — по счёту и ключу чека. Резервация
фиксируется до запроса. После неё счёт, родитель, магазин, среда, состояние
и резервация проверяются снова. В одном проходе логический чек не получает
второй GET. Ошибка сохранения результата не отменяет резервацию.

Если ID чека уже есть, опрос запрашивает его, иначе — подтверждённый
платёж и его фискальный статус. Полный ответ оплаты должен снова
подтвердить магазин и среду. Свежий терминальный факт применяется до
проверки 72 часов. При недоступном ответе просрочка может опираться
на последний подтверждённый pending с признаком неизвестной свежести.
Порог считается по одному проверенному UTC-времени PostgreSQL после GET.
Откат между замерами до и после GET не даёт нового фискального основания.

Опрос не использует выдачу оплаченных прав, списание или возврат.
Для штатного письма о готовом чеке сохраняются прежние получатели для
соответствующих источников. Наружу возвращаются только счётчики; в
результат не добавляются ID чеков и счета или тело ответа.

Остаются передача в O16, проверка тестового магазина и приёмка получателем.
