## Независимое ревью требований — 03.11.2026

Проверены все18 пунктов по текущим spec/plan/research/model/quickstart/tasks
и O16/A1–A7. Отмечены только требования с достаточным обоснованием.

- **R1, высокий риск — не определено стабильное основание по каждому kind.**
  `../data-model.md:11–34` включает в sample время и общий event_count,
  а `../contracts/operator-observation.md:802–803,861–865` говорит counters>0
  и count increase без выбора счётчика. Обычный успех/новое время чтения
  не должны создавать failure, новый message key или аннулировать конкретное
  решение владельца. Нужны точные стабильные поля basis для каждого kind,
  правила bootstrap/продолжения/нового поколения и явная семантика версии.
  Поэтому **CHK006/CHK008/CHK013** остаются открытыми.
- **R2, высокий риск — неопределённая очередность допускает голодание писем.**
  `../contracts/operator-observation.md:847–849` и `../quickstart.md:25–29`
  ограничивают POST одним за tick и выбирают «старейший eligible», но не
  определяют поле старшинства. Выбор по detected_at позволяет одной старой
  failed/unknown попытке занимать каждый следующий tick, пока новые никогда
  не отправляются. Нужны однозначная сохраняемая очередность без такого
  голодания и предметный сценарий минимум с двумя тревогами; лимит retry≥300с
  и accepted dedup сохраняются. **CHK010** остаётся открытым.
