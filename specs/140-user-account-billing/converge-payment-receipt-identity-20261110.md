# T075 — неизменный ID чека оплаты в счёте

Отдельный GET чека может подтвердить состояние только уже привязанного
чека оплаты или впервые установить привязку в счёте без такой записи.
Если в карте есть другой чек оплаты, если переход противоречит верхнему
статусу или если элемент карты имеет неверную форму, прежняя проекция
сохраняется. Фоновый обработчик уже оставляет конфликт на повторную сверку.
Два разных чека одного подтверждённого возврата по-прежнему различаются.

Перед правкой воспроизведены четыре отказа: второй ID оплаты,
противоречие верхнему статусу, две старые записи оплаты, повреждённый
элемент карты. После правки проверены те же случаи и сохранение двух чеков
одного возврата, включая прежние интеграционные проверки в отдельной
PostgreSQL с действующим RLS и подставной YooKassa.

Это часть R1. Межсчётная неизменность привязки, общий переход для GET
платежа и GET чека, проверка остальных полей исторических записей,
основание отмены чека оплаты, сроки, O16 и test-shop остаются открытыми.
Действующие T074/T075/T077 уже охватывают остаток; новых задач нет.
