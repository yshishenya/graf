# T075 — общий переход состояния чека оплаты

Полный GET платежа и отдельный GET чека используют один монотонный переход.
Полный ответ обновляет уже связанную запись только при совпадении оплаты,
магазина и среды; ID чека и ранее сохранённое время регистрации остаются.
Если GET платежа пришёл первым, отдельный GET связывает первый ID с уже
известным состоянием. Само добавление ID не ставит второе письмо о готовности.
Для отдельного GET оба поля привязки исходной операции обязательны.
Событие о чеке старой операции без полной сохранённой привязки остаётся
на повторную сверку; ранее сохранённые данные не переписываются.

При конфликте верхнего статуса и карты подтверждение чека не принимается.
Некорректное поле регистрации в ответе о платеже не делает его финансовые
поля невалидными. Для начальной покупки и других покупок сохраняются
прежние финансовые переходы, без письма о готовности на основании конфликта.
Вебхук не выбирает операцию по ID, который не совпал с запрошенным.
Неполный GET старого платежа не меняет состояние чека и не ставит письмо.
Опрос завершённой операции не повторяет финансовый переход.

Область доказательств: локальная проекция счёта, четыре вида завершённой
покупки, начальная покупка при конфликте и оба порядка перехода. Полное
отдельное доказательство межсчётной идентичности, сохранение проверенной
привязки старого счёта без receipt ID, основания отмены чека оплаты и часы
ожидания, ограниченный опрос, передача в O16 и test-shop остаются в
существующих T074/T075/T077. Новых задач и закрытия не требуется.
