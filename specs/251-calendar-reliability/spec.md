# Feature Specification: Надёжные календари Google и Яндекс

**Feature Branch**: `codex/251-calendar-reliability`
**Created**: 2026-09-06
**Status**: Specified
**Input**: Исправить все результаты аудита; не ограничивать данные, полученные от провайдера; перепроверить пользовательский путь целиком.

## Clarifications
### Session 2026-09-06
- Владелец прямо разрешил сохранять и показывать все полученные от провайдера данные. PRIVATE/CONFIDENTIAL и похожие на URL/email слова не являются причиной удаления названия, описания, места, участников или ссылок.
- Это разрешение не расширяет права других пользователей, не разрешает автоматическую рассылку/публикацию и не отменяет HTTPS/SSRF/HTML escaping, защиту credentials и подтверждение открытия ссылки.
- Пользовательские настройки видимости сохраняются как явный выбор владельца. Отсутствующие у провайдера данные не выдумываются. Автоматическое назначение приватного контекста общей записи сохраняет отдельную действующую границу; личный календарь не скрывает доступные подробности.
- Исправления и локальная проверка разрешены. Коммит, публикация и production deploy не включены в эту команду.
- Clarify: все категории проверены; критических неразрешённых вопросов нет. Порог нормальной свежести ниже принят как проверяемое инженерное значение, не внешняя гарантия доступности провайдера.

## User Scenarios & Testing
### User Story 1 - Полные сведения встречи (Priority: P1)
Владелец видит полученные названия, время, описание, место, участников и ссылки независимо от приватности; серии и переносы сохраняют смысл.
**Independent Test**: синтетические ответы Google/CalDAV и сравнение владельческого результата с входом.
**Acceptance Scenarios**:
1. PRIVATE событие с названием/email/URL и длинным описанием сохраняет содержание без фильтрации; чужой пользователь его не получает.
2. Серия с исключением, переносом, отменой, TZID и событие на весь день отображаются в правильные даты без дублей.
3. Удаление Google без start удаляет только нужное событие; остальные события страницы импортируются.
4. Ссылка в описании/месте распознаётся, а полный исходный текст сохраняется защищённо и доступен владельцу.

### User Story 2 - Обновление без кнопок (Priority: P1)
Google и Яндекс автоматически подхватывают создание, изменение, удаление событий и изменение списка календарей.
**Independent Test**: очередь, worker, PostgreSQL, provider doubles; перевод времени без реального ожидания.
**Acceptance Scenarios**:
1. Событие создано при открытой пустой главной: оно появляется без перезагрузки страницы и без потери ввода.
2. Сохранение выбора сразу запрашивает синхронизацию любого поддерживаемого источника.
3. Остановка worker и возврат старого ответа не приводят к вечному syncing или перезаписи нового результата.
4. Изменение каталога обнаруживается; один неисправный источник не скрывает встречи исправного.

### User Story 3 - Понятный полный путь (Priority: P2)
Подключение, отмена формы, выбор, обновление, подсказки, переход по ссылке, отключение и повторное подключение имеют понятное состояние.
**Independent Test**: web/embedded UI с синтетическими данными плюс native focused tests.
**Acceptance Scenarios**:
1. Экран ждёт длинное обновление без сброса формы; ошибка и устаревание объяснены, повтор доступен.
2. Пустое название показано как отсутствие названия; данные провайдера не названы скрытыми из-за фильтра GRAF.
3. Отключение очищает источник и будущие данные; поздняя синхронизация не восстанавливает их.
4. Кнопки обновления в web и macOS не вводят в заблуждение; ручная запись независима от календаря.

### Edge Cases
401/403/429/5xx, timeout, expired token/cursor, несколько страниц, пустой каталог, 0 выбранных календарей, смена выбора во время sync, конкурентные worker, sleep/wake/offline, HTML в тексте, ссылки с кодом доступа, несколько событий с одной ссылкой, повторения DST/EXDATE/RDATE/RECURRENCE-ID, событие удалено до полного чтения.

## Requirements
- **FR-001**: Не отбрасывать доступное владельцу содержание по PRIVATE, email, URL, словам или прежним искусственным пределам длины.
- **FR-002**: Сохранять все компоненты календарного ресурса, участников, время/TZID, recurrence identity, переносы и отмены в ограниченном временном окне.
- **FR-003**: Обрабатывать Google tombstones без времени и читать conference URL также из описания и места.
- **FR-004**: Обновлять оба источника раз в минуту, сразу после выбора; обновлять каталог без сброса сохранённого выбора.
- **FR-005**: Восстанавливать просроченные sync после 5 минут с защитой от позднего старого результата, отключения и изменения выбора.
- **FR-006**: Обновлять видимый календарный блок каждые 30 секунд, после возврата/восстановления сети; сохранять форму, фокус и работоспособность экрана при ошибке.
- **FR-007**: Показывать рабочие источники при ошибке другого, устаревание после 3 минут и честные пустые/ошибочные состояния.
- **FR-008**: Различать экземпляры серии с общей ссылкой и корректно сохранять пользовательские фильтры; private с полученным содержимым не считать freebusy.
- **FR-009**: Сохранять tenant/owner checks, безопасное открытие ссылки, sealed credentials, отсутствие содержимого/секретов в логах; исходные тексты с кодами доступа хранить защищённо без потери владельческого доступа.
- **FR-010**: Проверить полный путь от подключения до повторного подключения, browser/embedded/native, без изменения частных рабочих событий.

## Key Entities
CalendarSource, ExternalCalendar, CalendarEventSnapshot, CalendarParticipant, credential envelope; существующие tenant-scoped ownership и lifecycle.

## Success Criteria
- **SC-001**: В контролируемом сценарии доступное событие появляется без кнопок не позднее 90 секунд после планового момента обновления; после ручного/selection запроса не позднее одного цикла worker и UI.
- **SC-002**: Все случаи FR-001..FR-010 покрыты исполняемыми проверками; отключённый/чужой источник не раскрывает данные.
- **SC-003**: Название/описание/место/участники владельца совпадают с переданным провайдером содержанием; полный повторный импорт восстанавливает ранее отброшенные сведения.
- **SC-004**: Потерянный исполнитель освобождается не позже 5 минут плюс интервал очереди; старый исполнитель не пишет после нового захвата.

## Assumptions and scope
Google и Яндекс используют текущие read-only permissions, без нового consent. Legacy impact: untouched. Установка production, публичный выпуск Mac и внешняя Google OAuth verification являются отдельными release gates. Проверка локальной сборки не называется production acceptance.

## Design clarification 2026-09-06
Полное owner content (title, description, location, participants, attachments) сохраняется в encrypted envelope. Индексные/plaintext текстовые поля могут сохранять обычный текст, но тексты с URL/кодом доступа хранятся только в envelope и восстанавливаются исключительно для авторизованного owner read, без ORM flush открытого содержимого. Никакого усечения при шифровании/дешифровании. Проверять claim и исходный выбор под source row lock ДО любого изменения каталога, событий, cursor или error state; claim не изменять в текущем исполнителе до финального результата. Для floating time сначала использовать timezone компонента/календаря X-WR-TIMEZONE; при отсутствии зоны явно сообщать limitation, не назначать UTC молча. Открытие ссылок только HTTPS, исходный текст сохраняется. Владелец разрешил использовать подключённые production календари для отдельно помеченных тестовых событий без участников; existing private meetings не менять.

## Legacy Impact

Classification: `untouched`

Изменяются действующие календарные интеграции и их фоновые задачи. Удалённый аудиотракт и другие ранее снятые компоненты не восстанавливаются. Новых совместимых обходных путей нет.
