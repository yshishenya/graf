# Calendar behavior contract
Owner API retains provider-authorized text and private content, HTML escaped in browser; credentials never returned. FREEBUSY and missing fields remain absent without pretending private. User visibility switches remain explicit overrides. Personal event content cannot be read by a different owner/workspace or grant access to a recording. HTTPS validated links open only after user action; original description/location roundtrip through protected storage.
Both enabled providers receive periodic sync after 60s, queue loop <=15s; visible sections refresh every 30s and on visibility/online. Failed requests retain existing display with honest freshness; one provider error cannot hide another. Refresh changes only calendar display/status, never inputs/dialog/focus. Manual refresh has accepted/already running/retry semantics and does not mean the provider has completed.
Incremental tombstone marks source+calendar+provider id deleted; no date required. Full import reconciles only its bounded horizon. Expired claims older than 5m can be reclaimed; result and failure writes require same claim and active source. New selection/catalog removal cannot be undone by old I/O. No hidden timeout after four UI polls. Labels in Russian.

## Design clarification 2026-09-06
Полное owner content (title, description, location, participants, attachments) сохраняется в encrypted envelope. Индексные/plaintext текстовые поля могут сохранять обычный текст, но тексты с URL/кодом доступа хранятся только в envelope и восстанавливаются исключительно для авторизованного owner read, без ORM flush открытого содержимого. Никакого усечения при шифровании/дешифровании. Проверять claim и исходный выбор под source row lock ДО любого изменения каталога, событий, cursor или error state; claim не изменять в текущем исполнителе до финального результата. Для floating time сначала использовать timezone компонента/календаря X-WR-TIMEZONE; при отсутствии зоны явно сообщать limitation, не назначать UTC молча. Открытие ссылок только HTTPS, исходный текст сохраняется. Владелец разрешил использовать подключённые production календари для отдельно помеченных тестовых событий без участников; existing private meetings не менять.
