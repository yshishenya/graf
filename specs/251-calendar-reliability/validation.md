# Проверка календарей Google и Яндекса

Дата: 2026-09-06. Ветка: `codex/251-calendar-reliability`. Исходный HEAD: `6ff8db3ee18dc7faf52fd8a31c8bade97c5ca548`. Изменения не закоммичены и не установлены на production. Полоса проверки: high-risk-product, полный Spec Kit и целевые проверки до разрешения на коммит/выпуск.

## Подтверждённые причины и исправления

| Область | Причина | Исправление |
|---|---|---|
| Названия Яндекса | GRAF удалял SUMMARY из PRIVATE событий | Содержание сохраняется полностью; PRIVATE не превращает доступное название в скрытое событие |
| Google | Планировщик выбирал только Яндекс | Оба источника проверяются раз в минуту; полный импорт восстанавливает потерянные поля, ежедневный полный импорт продвигает временное окно |
| Экран | Обновление привязывалось к окончанию уже показанной встречи | Опрос каждые 30 секунд, включая пустой список; возврат вкладки и сети запускает обновление |
| Формы | Полная перезагрузка и предел четырёх повторов | Меняются только календарные сведения; ввод, диалоги и фокус остаются |
| Серии и время | Первый VEVENT, без полноценного TZID/recurrence | Все компоненты, RRULE/RDATE/EXDATE, переносы, отмены, TZID/VTIMEZONE/DST и стабильная идентичность экземпляров |
| Удаления Google | Tombstone без времени ломал нормализацию страницы | Отдельное применение удалений по provider ID или UID в своём календаре |
| Зависшие синхронизации | Потерянный исполнитель оставался syncing | Возврат задачи через пять минут; старый результат/ошибка не перезаписывает новый захват или выбор |
| Каталог | Перечитывался только при отсутствии выбора | Перечитывается каждый цикл; новый календарь не выбирается автоматически, удалённый выключается |
| Ссылки | Не читались description/location, при сохранении терялся приоритет звонка | Общий разбор ссылок, приоритет конференции, отдельные хеши идентичности; разные даты с общей ссылкой не склеиваются |
| События на весь день | Терялся признак all_day при проекции в интерфейс | API, кабинет и macOS показывают календарную дату и «весь день», без ложного времени и сдвига даты |
| Частичная ошибка | Один неисправный источник скрывал весь список | Рабочие события остаются; показана ошибка и признак устаревания |
| Восстановление конфигурации | Временная ошибка ключа/Google config давала вечный failed_closed | Повтор после восстановления, без возобновления отозванных credentials |
| Зависимость от Temporal | Calendar loop не стартовал до подключения Temporal | Независимый запуск, отмена и восстановление; снята только соответствующая зависимость rec-maintenance в Compose |
| Полные данные | Фильтры слов, email/URL и длины; URL в незашифрованном описании | Полный защищённый owner envelope, API и кабинет читают его без ORM записи открытого текста; Text-колонки, безопасный откат |
| Подключение | Повторный немедленный CalDAV catalog read после уже успешной проверки | Используется полученный при проверке каталог; дальнейшая синхронизация проходит через общую очередь |
| Ресурсы parser | Плотная старая RRULE способна блокировать процесс | Полный REPORT раскрывается в отдельном завершаемом процессе; ошибка целиком без частичной публикации, время/память ограничены |

## Реальные подключённые аккаунты

Проверка на сервере отдельным краткоживущим процессом с новыми адаптерами, транзакцией `READ ONLY` и только агрегированным выводом. Рабочие контейнеры и исходные файлы не заменялись. Временные модули/зависимости удалены после проверки. Частные названия, адреса, ссылки и credentials не записывались в evidence.

- Google: 6 календарей, 6 выбраны, 9 событий в окне, 8 названий, включая 2 приватных, 14 участников, 2 экземпляра повторений. Ошибок чтения нет.
- Яндекс: 2 календаря, 2 выбраны. В текущем окне от минус 7 до плюс 365 дней провайдер вернул 0 событий. Дополнительное чтение исходных ресурсов нашло 7 VEVENT с 7 SUMMARY: при нормализации каждого ресурса в окне его исходной даты **7 из 7 названий совпали** с ответом провайдера.
- Эти 7 записей не названы будущими встречами. Нулевой текущий ответ Яндекса отдельно отличён от работоспособности parser.
- Существующие встречи не изменялись. Создание/переименование/перенос/удаление тестовых событий на production не выполнялось. Пользователь разрешил такие события без участников; полный изменяющий путь на обновлённом production остаётся после выпуска.
- До исправления живой Google cache не обновлялся около четырёх дней; ручная синхронизация в установленном GRAF сработала. Яндекс обновлялся раз в пять минут. Это доказательство исходного дефекта, не приёмка нового выпуска.

## Независимый просмотр и упрощение

`calendar_research` отдельно проверил требования (5/5 reviewer-owned checklist) и поток фоновой синхронизации. Найденные им четыре замечания — приоритет ссылки, верхняя граница удаления, восстанавливаемые ошибки конфигурации, движущееся окно Google — исправлены с регрессиями. Отдельно реализована изоляция тяжёлого recurrence parser.

Ponytail review: удалены дублирующий reconciliation каталога, повторное чтение каталога при подключении и неиспользуемые синхронные обёртки; проверка ключа использует общий helper. Нет нового job framework, UI библиотеки или самописного recurrence engine. Новые две зависимости заменяют неполный iCalendar parser; отдельный процесс нужен для действительного прекращения вычисления, поток этого не гарантирует.

## Границы приёмки

- Данные, которых провайдер не предоставляет, GRAF восстановить не может. Явные пользовательские переключатели сохранены.
- Показ владельцу не расширяет доступ других пользователей и автоматическое включение приватных данных в общую запись. HTTPS/проверка перехода и защита credentials сохранены.
- Ограничения parser — 15 секунд по часам, в Linux 10 секунд CPU и 256 MiB адресного пространства (с запасом для родительского процесса в контейнере 512 MiB), 32 MiB сериализованного входа/выхода. Превышение даёт ошибку всего импорта, без молчаливого усечения и удаления ранее сохранённых событий.
- Обновление раз в минуту плюс опрос экрана каждые 30 секунд — целевая нормальная работа, не гарантия при недоступном провайдере/очереди.
- Обновлённый macOS-бинарник не установлен пользователю; внешний переход по настоящей ссылке и полный OAuth/reconnect на production после выпуска не объявляются пройденными.
- Формальный `governance-fast` на точном SHA и release-full/CD dry-run требуют разрешённого коммита и отдельного выпуска. Full CI и production deployment сейчас не выполнялись.
