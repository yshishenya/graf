# F255 T021: подменю профиля

2026-09-07, active Spec Kit slice / high-risk UX. Основание — скриншот владельца после возврата прежней навигации.

Причина: независимые `details` открывались штатным кликом и не закрывали соседей. Исправление находится в общем `initCabinetProfileMenus`, используемом web и embedded документами: mouse pointerover открывает один пункт, обычная строка закрывает подпункты, уход закрывает их через 150 мс. Задержка позволяет пересечь зазор. Клавиатурный фокус защищён от закрытия при случайном уходе мыши; summary activation и Escape сохранены.

Внешний контур стал мягче, радиусы контейнеров — 8 px, строк — 4 px. У вариантов темы нет отдельных рамок; текущий выбор обозначен галочкой. Увеличенный контраст сохраняет видимый контур. Состав и порядок меню, формы темы/выхода, доступность команд не изменены.

## Проверки исходников

- Новая регрессия в существующем WKWebView suite до исправления воспроизвела 8 ошибок поведения. Окончательный повтор с компактным режимом: 7/7 PASS, `/tmp/graf-f255/hover-after.log`. При дополнении теста синтетический HTML приведён к реальному `popover="manual"`, чтобы проверять доступность строк в верхнем слое, а не fallback без popover.
- Сервер: web shell, template sections, settings UI — 116 PASS; одна существующая PytestAssertRewriteWarning. Лог `/tmp/graf-f255/hover-server.log`.
- `node --check cabinet.js`, `git diff --check`: PASS.
- Живой синтетический браузер с production templates/assets: hover без клика, переключение «Вид» → «Решение проблем», переход внутрь, уход за меню, Escape; светлая/тёмная темы проверены. Личные настройки не менялись.
- На 720×640 обнаружено прежнее обрезание бокового подменю: mobile profile имеет overflow:auto. Использовано существующее inline оформление подпунктов внутри меню. После исправления строки видимы и доступны. Добавлена проверка hit testing в тот же WKWebView тест.
- Локальные синтетические снимки: `/tmp/graf-f255/audit/graf-hover-{dark,light,compact}.png`. В git изображения не добавляются.
