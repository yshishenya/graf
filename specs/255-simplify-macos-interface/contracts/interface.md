# F255: контракт оболочки desktop-shell/v1

## Единственный владелец навигации

Сервер определяет доступные разделы, подписи, порядок и формы. В браузере их отображает HTML; в совместимом Mac — native после подтверждения. EmbeddedCabinetNavigationController владеет маршрутами, историей и session boundary. Снимок меню не является источником авторизации. Основные разделы остаются доступными в настройках; категории настроек — отдельная группа ниже них.

До подтверждения HTML-панель видима и доступна с клавиатуры. После подтверждения native показывает тот же набор, HTML sidebar убирается из визуального дерева и дерева доступности, фокус переносится в соответствующий native пункт только если был в скрываемой панели. Основное содержимое, формы и их обработчики остаются в документе. Не прятать sidebar по одному наличию window.webkit.

## Формат и границы

Контракт `desktop-shell/v1`: версия, идентификатор поколения документа, массив существующих пунктов `{id, label, route, group, selected}`, разрешённые команды профиля, отображаемое имя/инициалы профиля и предпочтение темы `light|dark|system`. Имя используется только для показа, не логируется. Секреты, CSRF, cookies, содержимое встреч и произвольный JavaScript в снимок не входят.

Ограничения v1: до 32 пунктов, уникальные ID до 64 символов из букв/цифр/дефиса/подчёркивания, подпись до 160 символов без управляющих символов, имя до 256, маршрут до 2048; общий payload до 32 KiB. Неизвестная версия, неверные типы/лимиты, дубли ID или неоднозначный выбранный пункт отклоняют весь снимок и сохраняют HTML. Группы только main/settings. Native символы выбираются по фиксированной карте известных ID; неизвестный разрешённый пункт получает нейтральный системный символ, не удаляется.

Bridge принимает только main-frame сообщение текущего доверенного кабинетного origin, разрешённого маршрута, поколения и sessionBoundaryID. Поколение назначает native при committed navigation; это привязка ко времени жизни документа, не замена проверки origin/сессии. Native открывает route только через существующую DesktopCabinetRoutePolicy: никакой произвольной схемы, нового host, userinfo или обхода политики query/fragment. Не снижать текущую строгость route policy.

## Передача управления и восстановление

1. Native объявляет поддержку v1 в доверенном документе существующим WKUserScript/message handler и выдаёт идентификатор его поколения.
2. Документ при готовности отдаёт снимок. Native проверяет его, готовит sidebar и подтверждает принятие того же поколения.
3. Документ применяет передачу управления только для своего поколения; native использует существующий lifecycle/evaluateJavaScript completion для подтверждения применения. Отказ/ошибка оставляет HTML и скрывает неподтверждённую native панель. Произвольная задержка и постоянный polling запрещены.
4. При новом committed document, смене сессии, logout, выходе на login/public URL, ошибке навигации или WebContent termination native снимает старый snapshot. Старые сообщения и старые нажатия отклоняются. Новый документ по умолчанию показывает HTML; сохранённый документ восстанавливает HTML при отмене передачи управления.

В steady state один навигационный набор. Capture controls не зависят от согласования. Если сеть оборвалась без смены текущего документа, меню остаётся связано с ним и обычная обработка network error сохраняется; session boundary всегда очищает его.

## Команды профиля и тема

Допустимы только фиксированные `account`, `settings`, `theme(light|dark|system)`, `logout`, `update`, `quit`, причём документ публикует только существующие доступные команды. Account/settings используют проверенный маршрут. Theme/logout запускают существующую конкретную форму через requestSubmit, с текущими CSRF и проверками; никакого нового HTTP клиента. Native передаёт enum и значение, не JavaScript из payload. Update/quit используют существующие native callbacks и защиту активной записи.

Theme preview и результат сохранения используют текущий механизм preferences; native следует тому же отображаемому значению. Ошибка сохранения видима через существующий feedback, подтверждённое значение/откат синхронизируется, preview не считается сохранением. System следует ОС, включая её изменение во время работы. Preferences не копируются в UserDefaults. После перезагрузки источник — подтверждённый профиль сервера.

## Материал, геометрия и состояния

- macOS 26, новая совместимая пара: стандартная sidebar с системным Liquid Glass. Не добавлять glass layer поверх каждой строки.
- macOS 14.5 и Reduce Transparency: непрозрачная семантическая поверхность, те же команды. Веб/старый сервер: матовый HTML.
- Для web: общий внешний отступ 8–12 px и радиус 14–16 px; строки 36–40 px. Native сохраняет системные метрики. Ширина подбирается по полной подписи «Поделились со мной» при стандартном масштабе, не по старым 240 px.
- Main/detail/settings/billing имеют общие роли фона, заголовков и действий, но плотность проигрывателя и таблиц сохраняется. Нельзя глобально ослаблять --line: decorative separator отделён от input/focus/status.
- Focus/значимая граница ≥3:1, обычный текст ≥4.5:1, крупный ≥3:1. Выбор обозначен не одним цветом; навигация сообщает текущий пункт, иконки имеют имена. Hover, pressed, selected, focused и disabled для реально временно недоступных действий различимы.
- На 1040×680 и при 200% не перекрывать содержимое двумя панелями: второстепенная панель может сворачиваться с видимым возвратом; Stop и состояние записи остаются видимыми. Изменение компоновки не пересоздаёт WebView и не теряет фокус.
- Веб 320/390/768/1024/1440 px сохраняет существующие скрытие/rail и рабочий no-JS доступ. Native может использовать стандартное полное скрытие; путь ≤2 действия. Меню профиля доступно на каждом размере, Escape закрывает его и возвращает фокус.
- Reduce Motion убирает декоративные переходы. Increase Contrast и неактивное окно проверяются отдельно в обоих исполнениях.

## Совместимость и замещаемые контракты

| Клиент / сервер | Ожидаемое оформление |
|---|---|
| Новый / новый v1 | Native; Liquid Glass только при macOS 26 и разрешённой прозрачности |
| Новый / старый | Рабочая HTML-навигация, матовая; стекло не заявляется |
| Старый / новый | HTML, новая матовая геометрия |
| Неизвестная версия / ошибка payload | HTML, без старого native snapshot |
| Browser / no-JS | HTML; ссылки/формы доступны |

F159 замещается только в требовании одинакового способа отрисовки sidebar: серверные пункты, href, формы/CSRF, один владелец и подсветка сохраняются. F033 (независимая запись/стоп), F198 (безопасная история) сохраняются. Постоянные disabled пункты F201 удаляются по новому запросу владельца; рабочий вход settings и issue #5804 не закрываются этой заменой.

Откат нового клиента или сервера возвращает HTML без миграции данных. Гейт релиза — quickstart.md, включая обе стороны смешанной пары.
