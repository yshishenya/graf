## Решение: системная sidebar и стабильный WKWebView

Apple рекомендует стандартные split views для боковых панелей. Они получают актуальное системное оформление при сборке новым SDK. Дополнительные собственные фоны могут перекрыть материал. Поэтому основной вариант — native navigation рядом с одним WebView. Стекло относится к навигации/управлению; содержимое встречи, текст, финансовые таблицы не покрываются отдельными glass effects.

Альтернативы: CSS blur мал, но не является системным Liquid Glass. `NSGlassEffectView` под прозрачным HTML сохраняет структуру, однако `WKWebView.underPageBackgroundColor` не обещает прозрачность всего compositor. Private KVC `drawsBackground` исключён. Полный перенос кабинета в SwiftUI несоразмерен задаче.

В установленном SDK `NSGlassEffectView` доступен с macOS 26.0, поддерживает regular/clear, cornerRadius/contentView; гарантированное размещение внутри материала относится к contentView. Сначала стандартная sidebar, без отдельного glass effect поверх неё. Реальный запуск со старым titlebar accessory обязателен, документация его не заменяет.

## Решение: одна компоновка и автоматический материал

На macOS 26 совместимая пара клиент/сервер использует системное стекло. На macOS 14.5 и при Reduce Transparency — законченное матовое исполнение. Старый сервер сохраняет HTML fallback. Light/dark/system берётся из существующего профиля; System остаётся предпочтением следовать ОС. Новых настроек/хранилищ и переключателя «стекло» нет.

Веб использует матовую панель. Предлагаемые GRAF отступы 8–12 px, радиус 14–16 px и строки 36–40 px — проектные ориентиры, а не требование Apple. Системные native метрики имеют приоритет; итог измеряется читаемостью и доступностью, а не пиксельным совпадением с вебом.

## Решение: убрать пустые выборы, сохранить рабочие входы

Подтверждены десять постоянных disabled-команд, два пустых подменю. Их удаление — сокращение ненужного выбора. Не создавать вместо них новые разделы. Общие встречи доступны из настроек напрямую: 2 → 1 действие. Аккаунт: 2 действия из закрытого меню; тема: 3. Существующий рабочий вход настроек в профиле остаётся, поскольку его удаление не сокращает путь.

Историческая issue #5804 не совпадает с нынешней записью T002 F201; не закрывать по чужой отметке. F240 #6588 владеет доступностью профиля на узких экранах. F245–F253 имеют смежные владельцы; точный реестр в inventory.md.

## Решение: безопасная передача меню

Серверные CabinetNavigationItem, cabinet_navigation/settings_category_navigation остаются источником. Controller сохраняет историю/route policy/session boundary. Новый небольшой snapshot метаданных не копирует данные встреч. HTML скрывается после подтверждения native готовности, с привязкой к текущему документу. Theme/logout используют существующие формы и CSRF; новая HTTP реализация не нужна.

## 2026-09-08 — T029: быстрый вход через строку macOS

Повторно прочитаны официальные Apple HIG:

- [The menu bar](https://developer.apple.com/design/human-interface-guidelines/the-menu-bar): menu bar extra даёт быстрый доступ к функциям приложения; предпочтителен обычный menu, popover допустим для содержимого сложнее меню. Apple рекомендует шаблонный символ для автоматического контраста. По прямому решению владельца здесь используется собственная AppIcon.icns GRAF со своим фоном, в пределах высоты строки, без нового изображения и без подмены бренда значком обновления.
- [Popovers](https://developer.apple.com/design/human-interface-guidelines/popovers): несколько связанных действий, размер по содержимому, закрытие вне области; предупреждения не следует помещать в легко закрываемый popover.
- [Loading](https://developer.apple.com/design/human-interface-guidelines/loading): полезное содержимое показывается сразу, остальные действия доступны во время фоновой загрузки. Apple не запрещает индикаторы: они уместны, когда пользователь действительно ждёт результат длительного действия.

Решение для GRAF: это быстрый вход и необязательный список встреч, поэтому отдельные загрузка/ошибка/вход/повтор здесь не нужны. Два постоянных действия доступны сразу. Заголовок, период и список появляются вместе только при наличии данных; после сбоя список скрывается до следующего успешного запроса. Удалена ручная кнопка обновления, чтобы не создавать действие с невидимым результатом отказа. Ошибки подключения и восстановление уже находятся в настройках календаря (`fragments/calendar_settings.html`). Это продуктовый выбор на основе рекомендаций, а не утверждение о запрете индикаторов Apple.

Существующий popover сохраняется для нескольких строк события, безопасной ссылки и уже действующего уведомления об обновлении приложения; переход на другую оконную реализацию не нужен для исправления. Не добавляются вложенные окна, новые настройки или действия записи. Публичная запись/Stop и её ошибки остаются в своих существующих элементах управления.


### T030 — монохромный знак и запись

Владелец заменил решение о цветной AppIcon требованием собственного знака для строки macOS. Рисунок взят из геометрии GRAF `outputs/logos/graf/final-symbol/svg/graf-symbol-dark.svg` (кольцо, два выступа, три полосы), заново построен NSBezierPath в 22 pt без тёмной заливки/цвета/растрового уменьшения. Это собственный векторный ресурс в коде CalendarTray.swift. isTemplate=true реализует рекомендацию Apple о символе с автоматической обработкой светлой/тёмной/выбранной строки. Платформа определяет цвет по системной строке, а не по теме веба.

Запись обозначается отдельной точкой, пауза — двумя полосами; круг остаётся до завершения остановки. Текст уточняет состояние в tooltip/AX и открытом меню. При запуске до localRecordingActive=true значок не заявляет идущую запись. Используются существующие локальные состояния capture, без собственного таймера и подписки на сеть. Обновление отмечено стрелкой, отличимой от точки записи. Настройки записи и Stop остаются в прежнем управлении.

## 2026-09-08: меню быстрых команд (T031)

Прочитаны официальные Apple HIG [The menu bar](https://developer.apple.com/design/human-interface-guidelines/the-menu-bar), [Menus](https://developer.apple.com/design/human-interface-guidelines/menus), [Popovers](https://developer.apple.com/design/human-interface-guidelines/popovers). Apple прямо рекомендует menu вместо popover для menu-bar extra, если команды не требуют сложного интерфейса; важные действия первыми, системные метрики, короткие подписи, минимум вложенности, black/clear template для темы macOS. Для динамических списков допускается системная прокрутка.

[CleanShot — Features](https://cleanshot.com/features) подтверждает отдельный видимый статус записи в строке меню и быстрый доступ к capture. [Screen Studio](https://screen.studio) разделяет запись и последующее редактирование/экспорт; описание сайта не доказывает точный состав их меню. Установленный Krisp повторно прочитан через CUA без изменений: основная навигация/рабочее содержимое отделены; его системное меню не получено, состав не выдумывается. Статья помощи Krisp вернула HTTP 403. Референсы используются для принципов, код и графические ресурсы не копируются.

Принято NSMenu без custom views: штатное закрытие/выбор/контраст/размер, без карточек и ручной геометрии. Старт/Stop первыми; микрофонную паузу оставляем в существующей панели, где её область подписана. Таймер уже виден в панели записи: не расширяем им значок и не вводим ещё один ticker. Отдельные Quit/account/devices отсутствуют в быстром меню; действующие app menu и профиль сохраняются.
