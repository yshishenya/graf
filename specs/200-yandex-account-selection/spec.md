# Feature Specification: Yandex ID account selection

**Feature Branch**: `200-yandex-account-selection`

**Created**: 2026-08-25

**Status**: Draft

**Input**: User description: "При входе через Yandex ID пользователь с несколькими аккаунтами должен выбрать нужный аккаунт"

## User Scenarios & Testing

### User Story 1 - Вход с выбором аккаунта (Priority: P1)

Пользователь с несколькими аккаунтами Yandex ID начинает вход в GRAF и получает возможность выбрать нужную учётную запись, а не молча продолжает вход под уже активной учёткой провайдера.

**Why this priority**: Неправильный аккаунт создаёт риск входа не в тот профиль и может привести к работе с чужими встречами или данными.

**Independent Test**: В браузере с двумя доступными аккаунтами пройти Yandex ID login и подтвердить, что после выбора аккаунта GRAF открывает соответствующий профиль.

**Acceptance Scenarios**:

1. **Given** пользователь не вошёл в GRAF и в Yandex ID доступно более одной учётной записи, **When** он выбирает вход через Yandex ID, **Then** провайдер предлагает выбрать или подтвердить учётную запись до возврата в GRAF.
2. **Given** пользователь выбрал аккаунт Yandex ID, **When** провайдер возвращает результат входа, **Then** GRAF открывает профиль, связанный именно с выбранным идентификатором Yandex ID.
3. **Given** пользователь отменил выбор или вход у провайдера, **When** он возвращается в GRAF, **Then** активная GRAF-сессия не создаётся, а доступен обычный повторный вход.

### Scope boundaries

- В scope входит только browser login через Yandex ID.
- VK ID, Mail.ru, Одноклассники, Telegram, desktop token custody, provider logout и production deploy находятся вне scope.

### Edge Cases

- Если у пользователя одна активная учётная запись Yandex ID, вход сохраняет текущую успешную логику.
- Если провайдер не может показать выбор аккаунта, GRAF не подменяет аккаунт собственным выбором и не создаёт сессию под непроверенным идентификатором.
- Если провайдер недоступен или пользователь отказал в доступе, остаётся email-вход и bounded error без токенов и профиля провайдера в UI/logs.

## Requirements

### Functional Requirements

- **FR-001**: При начале входа через Yandex ID система MUST запрашивать у провайдера интерактивный выбор или подтверждение аккаунта, если это поддерживается текущей сессией провайдера.
- **FR-002**: Система MUST сохранять существующую серверную проверку callback, state, client binding и идентификатора пользователя Yandex ID.
- **FR-003**: Система MUST создавать GRAF-сессию только после успешной проверки callback выбранного аккаунта.
- **FR-004**: Система MUST оставить текущий email fallback и bounded provider error без раскрытия OAuth-кодов, токенов, секретов и сырого профиля.
- **FR-005**: Изменение MUST затрагивать только Yandex ID и не менять параметры или поведение других провайдеров.

### Key Entities

- **Yandex ID account**: Внешняя учётная запись, выбранная пользователем у провайдера и идентифицируемая проверенным provider subject.
- **GRAF browser session**: Внутренняя сессия, создаваемая только после успешного callback выбранной учётной записи.

## Success Criteria

### Measurable Outcomes

- **SC-001**: В сценарии с двумя аккаунтами пользователь может завершить вход именно под выбранным аккаунтом в 100% повторений acceptance-теста.
- **SC-002**: Сценарий с одной аккаунтной сессией продолжает завершаться успешным входом без дополнительной ошибки в 100% focused regression tests.
- **SC-003**: Отмена выбора у провайдера не создаёт GRAF-сессию ни в одном focused negative test.
- **SC-004**: В diff и validation evidence отсутствуют OAuth-коды, access/refresh tokens, client secrets, email/phone и сырой профиль пользователя.

## Assumptions

- Yandex ID остаётся владельцем отображения и выбора своих аккаунтов; GRAF не получает список аккаунтов и не реализует собственный selector.
- Для обычной авторизации используется существующий server-side OAuth callback и текущая custody boundary.
- Acceptance-тест с двумя аккаунтами требует ручного browser/provider evidence; synthetic tests не заменяют его.
- Коммит, PR, release и production deploy в этой работе не выполняются.
