# Feature Specification: Единое поле выбора и фильтрации в настройках

**Feature Branch**: `6793-unified-settings-combobox`
**Created**: 2026-09-11
**Status**: Ready for planning
**Input**: Одно поле, в котором можно выбрать или написать для фильтрации; проверить все настройки, в том числе приложения.

## User Scenarios & Testing

### User Story 1 — Найти приложение и изменить его правило (Priority: P1)
Пользователь открывает поле «Приложения», видит все варианты, печатает часть названия и выбирает приложение. Список правил ниже фильтруется тем же полем.
**Independent Test**: Выбрать приложение щелчком без ввода, затем найти другое вводом, очистить поле и увидеть все правила.
**Acceptance Scenarios**:
1. Пустой фильтр → щелчок → список всех доступных приложений.
2. Ввод части имени → только совпадения; выбор → соответствующее правило ниже. Ввод не меняет правила записи.
3. Очистка → все приложения; «Для всех приложений» по-прежнему меняет все известные приложения, включая скрытые.

### User Story 2 — Единообразно выбирать настройки (Priority: P1)
Пользователь выбирает часовой пояс, шаблон, язык, подробность и время напоминания в одном поле с вводом и выпадающими вариантами.
**Independent Test**: Найти Екатеринбург, выбрать, отменить форму: прежний пояс восстановлен.
**Acceptance Scenarios**:
1. Открытие → все варианты; ввод → фильтрация по названию и коду (город, IANA, UTC для поясов).
2. Ввод/навигация без выбора → исходное значение настройки сохранено; Enter или щелчок выбирает только доступный вариант.
3. Escape/уход фокуса → список закрыт, неподтверждённый запрос настройки отменён; Tab переводит фокус дальше.
4. Ошибка сохранения → выбранный черновик доступен для повтора; отмена формы восстанавливает прежнее значение.

### User Story 3 — Просторное резервное окно и компактные строки (Priority: P1)
Дополнение пользователя: резервное окно должно сразу вмещать содержимое обеих вкладок; строки приложений не должны иметь огромных отступов.
**Acceptance**: начальный размер учитывает доступную область экрана, обе вкладки сохраняют достаточное место при переключении; длинный каталог прокручивается. Обычная строка приложения занимает около 40–44 px, длинное имя переносится без обрезания.

### Edge Cases
Нет совпадений: видимое русское сообщение, Enter не выбирает произвольное значение. Нет вариантов/ошибка загрузки: доступное объяснение и существующий повтор. Длинные названия: перенос; узкое окно: нет горизонтального выхода. Обновление каталога/правил не сбрасывает активный ввод; исчезнувший вариант не создаёт новое значение. Недоступные варианты не выбираются. При отключённом JavaScript работают прежние select.

## Requirements
### Functional Requirements
- **FR-001**: Для каждого одиночного выпадающего выбора в настройках показывать одно редактируемое поле с выпадающими вариантами: приложения/их правила, пояс, шаблон, язык, подробность, напоминания. Радиокнопки, флажки и карточки пространств сохраняются.
- **FR-002**: Ввод фильтрует по подстроке без учёта регистра; пустой запрос показывает весь каталог, включая текущий вариант. Поиск часового пояса поддерживает название, IANA и UTC с нормализацией знака минус.
- **FR-003**: В настройках значение меняется только явным выбором; произвольный текст никогда не сохраняется. В поле приложений текст сам является фильтром строк, выбор имени уточняет фильтр, очистка восстанавливает все строки.
- **FR-004**: Поддержать мышь, стрелки вверх/вниз, Enter, Escape, Tab, доступное имя, раскрытость, активный и выбранный варианты, сообщения об отсутствии совпадений; фокус остаётся в поле при навигации.
- **FR-005**: Сохранить прежние формы, отмену, повтор после ошибки, disabled состояния, локальный мост и три правила записи; общие изменения охватывают скрытые приложения.
- **FR-006**: Одинаковое поведение в обычном кабинете, встроенном кабинете macOS и локальных настройках при недоступном кабинете. При отсутствии JS остаётся штатный select.
- **FR-007**: Не выводить меню за ширину контейнера; длинные строки переносятся, список прокручивается. Использовать существующие светлую/тёмную темы и видимый фокус. Фильтрация выполняется локально, без запросов и журналирования текста.
- **FR-008**: Зафиксировать полный перечень настроек и проверки, оставить один changelog fragment, независимую проверку требований и кода. Установка только через GRAF Dev после разрешённого коммита.

- **FR-009**: Резервное окно открывается просторным, в пределах доступного экрана; переключение вкладок не уменьшает его. Строки приложений компактны в локальных настройках и кабинете, без потери переноса названий и доступности элементов.

- **FR-010**: Для завершения приёмки штатная сборка GRAF Dev должна использовать уже имеющиеся образы двух датированных версий MinIO, сохраняя измерение image ID, архив, ограничения Dev и все проверки promote. При отсутствии образа неуспешная загрузка останавливает сборку. Политика загрузки Postgres/Temporal и production не меняется.

- **FR-011**: Раскрытые списки настроек имеют компактную прямоугольную оболочку без указателя, отдельных округлых плашек вариантов и вложенной рамки редактора. Три правила видны полностью; длинный каталог прокручивается без обрезания доступной последней строки. Поле приложений имеет ограниченную ширину, список привязан к его краю и остаётся в доступной области экрана. Выбранное значение обозначается отдельно от варианта, по которому перемещаются стрелками.

### Key Entities
Вариант: стабильный код, видимое название, доступность. Черновик настройки и текст фильтра — разные состояния. Фильтр приложений не является правилом записи.

## Success Criteria
- **SC-001**: В каждом одиночном выборе из перечня одно видимое поле; отдельная строка поиска перед выбором отсутствует.
- **SC-002**: Все сценарии US1/US2 проходят мышью и клавиатурой; неподтверждённый ввод создаёт ноль сохранений.
- **SC-003**: Ввод по каталогу из 600 вариантов обновляет список в пределах 100 мс в локальном браузерном тесте.
- **SC-004**: Отмена, ошибки и скрытые приложения проходят регрессионные проверки; установленный GRAF Dev проверяется отдельным этапом после разрешённого коммита.

## Assumptions
Изменяется интерфейс существующих настроек, без новых значений, API, схем хранения и логики запуска записи. Выбор приложений используется для фильтрации существующих правил; новый список разрешённых приложений не вводится. Карточки/флажки календарей, пространства, тема и простые переключатели не являются одиночными выпадающими списками. Конкурентные source updates должны сохранять ввод до завершения редактирования.
