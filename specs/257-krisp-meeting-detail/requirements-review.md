## Замечания первичной проверки

### RQ-001 — HIGH: состав копирования итогов противоречит существующему контракту

В `contracts/ui.md`, раздел «Контролы», записано: `data-detail-copy` выбирает `outcomes` для вкладки `outcomes`. Но `outcomes` — имя вкладки, а действующий экспорт итогов использует `summary`. Кроме того, формулировка `option[data-export-scope]` ошибочно приписывает атрибут option: в текущем `initContentExport` он принадлежит select, а доступность определяется его `option[value]`.

Последствие: прямое копирование может отправить неподдерживаемый состав либо ошибочно определить его доступность. FR-010 и SC-005 требуют действующего проверенного экспорта, поэтому противоречие нужно устранить до T007.

Исправление: во всех design/contract/test описаниях зафиксировать `outcomes → summary`, `recording → transcript`; выбирать существующий option по `value` из select `[data-export-scope]`, требовать существование и отсутствие disabled. Не менять выбранный пользователем состав в диалоге из-за прямой кнопки. T006 должен покрыть обе пары, запрет отсутствующего/disabled состава и неизменность захваченного состава при смене вкладки.

Связь: security CHK001; spec FR-010/018, SC-005; plan §Design 6–7; tasks T006/T007.

### RQ-002 — HIGH: точная метрика соответствия опирается на неподтверждённый масштаб

Plan §Design 4 и contracts §Геометрия задают 600 px для документа и 20/14/12 px для текста. Обоснование plan — приблизительные 82% масштаба. Reference-audit прямо обозначает координаты визуальными оценками и не устанавливает CSS-масштаб. SC-003 одновременно требует отклонения не более 8/1 CSS px, но не перечисляет измеряемые блоки, их опорные точки и исходное состояние прокрутки.

Последствие: два проверяющих могут получить разные результаты, а предположение о масштабе превращается в требование точного совпадения.

Исправление: подтвердить нормализованный viewport и zoom через обычный интерфейс либо явно пометить размеры предварительными и включить обязательное измерение до фиксации CSS T004. Описать единую систему координат, набор опорных точек блоков и типографических ролей, состояние вкладки/прокрутки и способ сравнения синтетического содержимого. Положение контента, зависящее от различной длины текста, не считать безусловно сравнимым. Если остаётся оценка, сохранить её погрешность и не объявлять SC-003 PASS. Разрешённые отклонения должны иметь конкретную причину GRAF.

Связь: UX CHK002; spec FR-001/014, SC-003/004; reference-audit §Геометрия; tasks T001/T004/T009.

### RQ-003 — HIGH: отмена позднего копирования описана только для отсоединённой формы

Plan §Design 6, data-model и contracts определяют проверку подключения формы после await. Однако `replacement-active` может стать true до фактической замены `#cabinet-main`: текущий CSS скрывает действия, не отсоединяя форму. `updateProcessingExportVisibility` также меняет disabled у option без замены формы. Проверка одного `form.isConnected` не различает эти переходы. Не определена и координация нового прямого копирования с уже существующими кнопками копирования/скачивания при общем pending-состоянии.

Последствие: запрос, начавшийся до известной странице недоступности, может позднее записать старое содержимое в буфер; повторные действия и finally могут восстановить кнопку, которая уже запрещена текущим состоянием страницы.

Исправление: описать проверку исходных формы и trigger, актуальной доступности захваченного состава и отсутствия replacement-active непосредственно перед записью текста в буфер. Смена вкладки сама по себе не отменяет разрешённый захваченный состав. Все пути экспорта/копирования должны разделять один pending-gate; busy завершение не должно снимать запрет текущей готовности или политики. После отмены/ошибки повтор доступен только для актуального разрешённого состояния. Проверки T006 должны отдельно покрывать отсоединённую форму, replacement-active при подключённой форме, disabled scope во время ожидания, повторный клик и смену вкладки. Это требования клиентской согласованности; серверная авторизация и существующий recovery остаются обязательными, новый запрос проверки прав не нужен.

Связь: security CHK002; spec FR-010/013/018, SC-005; data-model §Переходы; contracts §Контролы; tasks T006/T007/T008.

### RQ-004 — MEDIUM: последнее уточнение исследования не отражено явно в перечне

Пользователь отдельно запросил устройство редактора итогов и действия удаления/переназначения говорящего. R02 содержит лишь общее утверждение о редактируемом документе; R13/R14 — распределение и фильтр голосов. FR-017 и T001 не называют эти новые исследовательские сценарии. Существующие функции GRAF включают изменение подписи голоса; это не равнозначно удалению голоса, переназначению реплики или установлению личности приглашённого.

Исправление: добавить отдельные записи матрицы исследования для структуры/элементов итогов, входа в редактор, выбора/изменения/удаления фрагмента, сохранения/отмены и восстановления, а также меню голоса, переименования, переназначения отдельной реплики/всех реплик и удаления. Для каждого указать наблюдённое действие, доступный объём, результат и ограничения; неподтверждённые варианты оставить неизвестными. Отразить это в требованиях T001, сохранив уточнённый объём реализации. Новые редакторы или операции с голосами не становятся разрешённой реализацией из-за исследования. Не выполнять необратимое удаление, изменение доступа или отправку содержимого в исходном Krisp по разрешению только на обратимые изменения.

Связь: UX CHK008; spec Clarifications, FR-001/016/017; reference-audit R02/R13/R14; tasks T001.
