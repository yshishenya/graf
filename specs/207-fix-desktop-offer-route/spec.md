# Feature Specification: Safe Desktop Offer Route

**Feature Branch**: `codex/207-fix-desktop-offer-route`

**Created**: 2026-08-28

**Status**: Draft

**Input**: User description: "В production GRAF ссылка на оферту в desktop checkout приводит к экрану «Функция недоступна»; переход должен работать безопасно и не затрагивать платёж."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Прочитать оферту перед оплатой (Priority: P1)

Пользователь открывает выбор тарифа в приложении GRAF и нажимает ссылку «оферту», чтобы прочитать действующие условия до принятия и оплаты.

**Why this priority**: Пользователь должен иметь доступ к условиям до согласия на регулярное списание; тупиковый экран мешает осознанному checkout.

**Independent Test**: Открыть desktop checkout, нажать «оферту» и подтвердить, что действующая публичная оферта открылась в браузере, а checkout в приложении остался доступен без создания платежа.

**Acceptance Scenarios**:

1. **Given** пользователь находится на desktop checkout, **When** он нажимает ссылку «оферту», **Then** действующая публичная оферта открывается в браузере и приложение не показывает «Функция недоступна».
2. **Given** пользователь не отметил согласие и не запускал оплату, **When** он открывает оферту, **Then** платёж, подписка и согласия не изменяются.
3. **Given** пользователь вернулся в GRAF после чтения оферты, **When** он продолжает checkout, **Then** экран выбора тарифа остаётся доступен.

### Edge Cases

- Неподдерживаемые same-origin страницы по-прежнему блокируются и не становятся разрешёнными из-за этого исправления.
- Параметры запроса и fragment не переносятся при открытии публичной оферты во внешнем браузере.
- Не-HTTPS и сторонние legal-ссылки не разрешаются автоматически.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Ссылка на действующую публичную оферту из desktop checkout MUST открываться в браузере без показа desktop-состояния «Функция недоступна».
- **FR-002**: Открытие оферты MUST NOT создавать платёж, менять подписку или фиксировать согласие пользователя.
- **FR-003**: Переход MUST сохранять существующую fail-closed политику для неизвестных, сторонних и небезопасных маршрутов.
- **FR-004**: Во внешний браузер MUST передаваться только проверенный origin и путь оферты без query, fragment и пользовательских данных.
- **FR-005**: Desktop checkout MUST оставаться доступным после внешнего открытия оферты.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В 100% проверок production desktop checkout нажатие «оферту» открывает действующую оферту и не показывает «Функция недоступна».
- **SC-002**: Во всех проверках перехода до и после него отсутствуют новые платежи, изменения подписки и новые согласия.
- **SC-003**: Все существующие проверки блокировки неизвестных и небезопасных маршрутов продолжают проходить.
- **SC-004**: Пользователь может вернуться к checkout и продолжить работу без перезапуска приложения.

## Assumptions

- Публичная оферта остаётся browser-owned документом по каноническому HTTPS-пути `/offer` на origin GRAF.
- Существующая desktop-сессия, каталог и YooKassa checkout не изменяются этой feature.
- Выпуск исправления потребует штатного подписанного macOS-релиза; серверный production deploy сам по себе не обновит установленный desktop-клиент.
