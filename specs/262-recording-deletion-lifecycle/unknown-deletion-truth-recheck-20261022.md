# F262/T005 — неизвестное состояние не подтверждает удаление

Дата: 2026-10-22. Issue: #6880. Основа: `8e37e0e3570372d7375151bf6624d5f0dcc3e627`.
Lane: active-spec-kit; область высокого риска — удаление и диагностические сведения.
Это исправление существующей T005, без новой фичи, схемы или внешней зависимости.

## Что найдено и исправлено

Четыре участка DesktopUploadCustodyProjection трактовали любую строку
`deletionState`, отличную от `none`, как серверное удаление. Для `unknown`,
будущего кода и пустой строки это давало ложные `server_deleted`,
`custody.server_meeting_deleted`, `deleted` и `server_deletion`, несмотря на
сохранённые локальные файлы. Физическая потеря файлов этим дефектом не доказана.

Переиспользован существующий точный список 12 известных серверных состояний
из общего lifecycle guard. Новый `hasConfirmedServerDeletion` включает этот
список и `serverMeetingDeleted`; общий `hasConfirmedDeletion` сохраняет прежнее
логическое выражение с локальным terminal и принятой операцией. Неизвестное
состояние остаётся `accessBlocked`: просмотр и отправка по-прежнему запрещены.
Код проблемы, серверная копия и этап отчёта теперь используют одну проекцию.
Подтверждённое серверное удаление проверяется раньше неизвестного доступа.
Локальное удаление и отмена ещё не созданной встречи не подтверждают удаления
серверной копии. Полномочия файловой очистки не расширены.

## Требования, проверка и сходимость

Независимый проверяющий заново сверил действующую конституцию, spec/plan/tasks,
контракт и оба списка требований: 10/10 + 10/10; CRITICAL 0 / HIGH 0,
обязательных новых вопросов нет. Все T001–T023 имеют по одному открытому
владельцу; новый дубликат issue не создавался. Перед/после implement hooks
автоматического коммита отключены, hooks converge отсутствуют.

## Границы принятия

Исправление ещё требует трёх обязательных GitHub checks точного PR SHA/base
и защищённого слияния. #6880 остаётся открытой: прежний продуктовый PR #6911
имеет отсутствующий/истёкший артефакт governance-fast; повтор GitHub отклоняет
как слишком старый запуск. Новая проверка не заменяет историческое доказательство
задним числом. Выпуск, фактическая установка нового клиента, полный операторский
restore и новая ручная матрица F262 не подтверждены этим отчётом.

Production, данные встреч и общий установленный GRAF Dev этим исправлением
не менялись. Согласованное окно выпуска сохраняется: до его освобождения
слияние не выполняется. При PR используется Refs #6880 с этими остаточными
критериями, а не автоматическое закрытие.
