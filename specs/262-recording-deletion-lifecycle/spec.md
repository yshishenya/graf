# Feature Specification: Согласованная запись и удаление

**Feature Branch**: `codex/262-recording-deletion-lifecycle`
**Created**: 2026-09-09
**Status**: Реализация завершена; PR #6911, итоговая приёмка выполняется
**Input**: Продумать правильное архитектурное и пользовательское решение удаления записей, включая полный обоснованный рефакторинг и все существенные сценарии.

## User Scenarios & Testing

### User Story 1 — Удалённая запись не возвращается (Priority: P1)

Владелец удаляет запись и больше не видит её как доступную встречу. Локальные файлы, обновление списка и перезапуск не отменяют принятое удаление.

**Why this priority**: Сейчас после исчезновения серверной строки может появиться локальная копия без флажка выбора, открывающая внешний плеер.
**Independent Test**: Удалить серверную встречу с локальными файлами, обновить страницу, доставить устаревшее состояние, перезапустить приложение.
**Acceptance Scenarios**:

1. **Given** одна встреча с локальной копией, **When** сервер принял удаление, **Then** она исчезает из основного списка и закрывается во всех управляемых GRAF представлениях после получения события.
2. **Given** подтверждённое удаление, **When** приходит старый ответ загрузки или списка, **Then** запись не возвращается, воспроизведение и отправка недоступны.
3. **Given** очистка файлов не завершена, **When** пользователь открывает результат операции, **Then** видит оставшуюся очистку, но не доступную запись.

### User Story 2 — Одна понятная запись на всех этапах (Priority: P1)

Пользователь видит одну запись во время сохранения, загрузки и обработки. Технические копии не создают дубли и не меняют смысл выбора или удаления.

**Why this priority**: Исправление только последнего нажатия оставит тот же дефект в других переходах.
**Independent Test**: Провести одну запись через локальное сохранение, загрузку, получение серверного подтверждения, фильтрацию и отсутствие сети.
**Acceptance Scenarios**:

1. **Given** локальная запись отправляется, **When** появляется связанная серверная встреча, **Then** в текущем представлении остаётся не более одной строки, а выбранность сохраняется для этой записи.
2. **Given** серверная встреча уже подтверждена, **When** она не вошла в фильтр или текущую страницу, **Then** её локальные файлы не создают обход фильтра.
3. **Given** локальная запись ещё не отправлена, **When** сервер недоступен, **Then** запись остаётся доступной владельцу локально, с честным статусом.

### User Story 3 — Удаление при загрузке и отсутствии сети (Priority: P1)

После подтверждения удаления GRAF прекращает новые действия с выбранной записью и доводит запрос до результата без повторного создания встречи.

**Why this priority**: Потерянный ответ или поздняя загрузка не должны превращать удаление в потерю данных либо восстановление встречи.
**Independent Test**: Разорвать соединение до отправки запроса, после принятия запроса и во время создания серверной встречи.
**Acceptance Scenarios**:

1. **Given** доказанно только локальная завершённая запись без начатой серверной отправки, **When** пользователь удаляет её без сети, **Then** GRAF выполняет локальное удаление и не пытается отправить её после подключения.
2. **Given** запись связана с сервером либо результат отправки неизвестен, **When** нет сети, **Then** запрос сохраняется со статусом «Удаление ожидает подключения», а серверный успех не заявляется.
3. **Given** сервер мог принять запрос, но ответ потерян, **When** связь восстанавливается, **Then** GRAF выясняет результат той же операции; не создаёт новую встречу и не делает вывод об удалении только из отсутствия записи.
4. **Given** запись ещё активно записывается или сохраняется, **When** пользователь пытается включить её в массовое удаление, **Then** действие недоступно с объяснением «Сначала остановите запись» или «Дождитесь сохранения»; ручной Stop сохраняется.

### User Story 4 — Прозрачное массовое удаление и ошибки (Priority: P1)

Пользователь выбирает локальные и серверные записи одинаковым способом, подтверждает действие один раз и получает точный результат по каждой записи.

**Why this priority**: Общий ответ «готово» скрывает частичные ошибки и создаёт повторные разрушительные действия.
**Independent Test**: Удалить смешанный набор с успешным результатом, отказом в правах и потерянным ответом.
**Acceptance Scenarios**:

1. **Given** смешанная выборка, **When** открыто подтверждение, **Then** показано число записей и отдельно количество записей только на этом Mac; копии не считаются отдельными записями.
2. **Given** часть запросов принята, **When** другой запрос завершился ошибкой, **Then** успешные записи исчезают; повтор предлагается только для незавершённых с учётом неизвестного результата.
3. **Given** окно подтверждения открыто, **When** меняется список, **Then** удаляются только первоначально выбранные записи, после повторной проверки прав; новые записи автоматически не включаются.
4. **Given** работа клавиатурой или экранным диктором, **When** строка исчезает, **Then** фокус переходит на следующую доступную строку или заголовок; результат объявляется без захвата фокуса.

### User Story 5 — Другое устройство, доступ и завершение очистки (Priority: P1)

Удаление распространяется на связанные управляемые копии после получения подтверждённого состояния. Недоступное устройство и ошибка очистки отражаются честно.

**Why this priority**: Удаление — действие над встречей, а не только текущим окном.
**Independent Test**: Удалить встречу через браузер, вернуть отключённый Mac после истечения задания очистки, затем проверить отчёт.
**Acceptance Scenarios**:

1. **Given** встреча удалена через другое устройство, **When** Mac получает подтверждение, **Then** прекращает управляемое воспроизведение и выполняет очистку без повторного пользовательского удаления.
2. **Given** очистка завершилась после истечения задания, **When** устройство отправляет проверенное подтверждение, **Then** отчёт может перейти из незавершённого состояния в подтверждённое с сохранением истории.
3. **Given** поменялся пользователь, сервер или рабочее пространство, **When** возобновляются отложенные команды, **Then** они не выполняются от имени нового контекста.
4. **Given** доступ отозван или встреча не найдена, **When** сервер не сообщил подтверждённое удаление, **Then** это не основание физически удалять локальные файлы.

## Requirements

### Functional Requirements

- **FR-001**: Для одной записи в одной выдаче MUST быть не более одной доступной строки. Локальная копия не является второй пользовательской записью.
- **FR-002**: Отсутствие в выдаче, недоступность сервера и отказ в доступе MUST отличаться от подтверждённого удаления.
- **FR-003**: Подтверждённое удаление MUST запрещать возврат записи в список, открытие, отправку, экспорт, повторную обработку и публикацию результатов после получения этого состояния.
- **FR-004**: GRAF MUST различать запрос пользователя, принятие сервером и физическую очистку; успех одного этапа не доказывает успех другого.
- **FR-005**: Подтверждённый пользователем запрос в приложении MUST сохраняться до сетевых действий и переживать перезапуск; невозможность сохранения MUST отображаться как ошибка до начала операции.
- **FR-006**: Для серверной либо потенциально отправленной записи при отсутствии сети MUST сохраняться ожидание подтверждения. Автоматическая повторная отправка аудио MUST быть остановлена.
- **FR-007**: Физическое удаление MUST иметь основание: подтверждённое локальное удаление доказанно локальной записи либо проверенное серверное удаление/существующую разрешённую политику очистки. Новый запрос MUST NOT расширять существующие политики.
- **FR-008**: Повтор операции MUST сохранять исходную запись и область действия. Потерянный ответ MUST выясняться без создания новой встречи.
- **FR-009**: Права и контекст MUST проверяться при выполнении каждого действия; доступность кнопки не является разрешением.
- **FR-010**: Флажок выбора MUST иметь одинаковый смысл для всех записей, доступных для удаления. Недоступность MUST иметь объяснение; «Выбрать все» означает только допустимые записи текущей загруженной выдачи, а не все записи сервера.
- **FR-011**: Подтверждение массового удаления MUST фиксировать набор записей. Результаты и повтор MUST рассчитываться по записи, а не общим логическим успехом.
- **FR-012**: Списки, поиск, счётчики, выделение, карточка, управляемый плеер и очереди MUST сходиться к одному результату удаления без перезагрузки вручную.
- **FR-013**: Очистка MUST восстанавливаться после закрытия приложения, обрыва сети, частичного удаления файлов и потери подтверждения. Истечение задания само по себе MUST NOT считаться доказательством удаления файлов.
- **FR-014**: Подтверждённое удаление MUST иметь приоритет над устаревшими ответами. Повторное сканирование каталога и восстановление локальной очереди MUST NOT создавать доступную запись из уже удалённого объекта.
- **FR-015**: Контроль воспроизведения локальных записей MUST оставаться внутри GRAF, чтобы GRAF мог прекратить его после получения удаления. Ранее экспортированные файлы и уже открытые сторонними программами копии не управляются GRAF.
- **FR-016**: Активная запись MUST оставаться под явным ручным контролем; массовое удаление не останавливает и не удаляет незавершённую запись скрыто.
- **FR-017**: Интерфейс MUST показывать краткий результат и доступ к существующему отчёту. Постоянный успешный баннер внизу списка не возвращается; ошибки остаются видимыми до решения.
- **FR-018**: Подтверждение и отчёт MUST раскрывать пределы: выгруженные файлы, резервные копии, недоступные устройства, MediaScribe, сохранённые Generation Call / Langfuse / Temporal. Нельзя обещать удаление всех копий повсюду.
- **FR-019**: Смена аккаунта/пространства MUST отключать старые проигрыватели и команды; неподтверждённая принадлежность старой локальной записи MUST вести в восстановление, а не в автоматическую отправку или удаление.
- **FR-020**: Обновление MUST обработать уже существующие «вернувшиеся» записи через проверку состояния; нельзя массово удалять файлы по отсутствию строки или совпадению названия.
- **FR-021**: Сервер и поддерживаемые клиенты MUST сохранять запрет повторной публикации после удаления при параллельной загрузке, транскрипции, генерации итогов и повторе задач.
- **FR-022**: Неуправляемый откат на несовместимую версию MUST NOT считаться поддерживаемым способом восстановления. План выпуска MUST отдельно проверить совместимость сохранённого состояния и старых клиентов.

### Key Entities

- **Запись**: пользовательский объект с устойчивой принадлежностью и связью локального происхождения с серверной встречей.
- **Копия**: конкретные управляемые файлы на устройстве/сервере; наличие файла не доказывает право его открыть.
- **Запрос удаления**: намерение пользователя, область действия, этап выполнения и причина ожидания/ошибки.
- **Подтверждение удаления**: полученный авторитетный факт, запрещающий возврат записи; не содержит содержимое встречи.
- **Результат очистки**: проверенный результат по управляемым копиям и ограничениям.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Во всех сценариях [scenarios.md](scenarios.md) удалённая запись ни разу не возвращается как доступная, включая 100 повторных обновлений и перезапуск.
- **SC-002**: После получения подтверждения удаления строка и открытый управляемый контент исчезают/закрываются не позднее 1 секунды в контрольной среде; ни одно новое действие не разрешается в этом интервале.
- **SC-003**: Для открытых или видимых записей в активном подключённом приложении удаление с другого устройства отражается не позднее 60 секунд при исправном сервере; после восстановления подключения проверка запускается не позднее 5 секунд. Остальные записи проверяются до раскрытия содержимого и фоновыми порциями. Сон, отсутствие сети и недоступность сервера исключены и отражаются как неизвестное состояние.
- **SC-004**: Все 100 операций смешанного массового удаления имеют индивидуальный результат; ни одна ошибка/неопределённость не объявляется успехом.
- **SC-005**: Ни один из тестов потери ответа, повторной отправки, восстановления очереди и параллельной обработки не создаёт новую встречу для удалённой записи.
- **SC-006**: Очистка файлов на подключённом исправном Mac с 100 тестовыми пакетами до 100 МБ каждый заканчивается в пределах 60 секунд после получения разрешения; превышение отображается как незавершённая очистка. Серверный предел очистки остаётся действующим, до 24 часов для допустимых объектов.
- **SC-007**: Все основные операции доступны клавиатурой и экранному диктору без потери фокуса; флажки, количество и результат описывают записи, а не копии.

## Assumptions

- 2026-09-09 пользователь разрешил начать реализацию; удаление его существующих данных, коммиты и выпуск этим разрешением не предписаны.
- Сохраняется существующее удаление всей встречи без корзины и обещания восстановления. Отдельное «освободить место на Mac, сохранив встречу» не добавляется.
- Предлагаемое поведение без сети: долговечный ожидающий запрос для серверных записей, непосредственное локальное удаление только доказанно неотправленной завершённой записи. Это проектное решение, а не ранее данное пользователем отдельное подтверждение.
- Управляемый встроенный локальный плеер заменяет автоматическое открытие сторонней программы; сложные функции серверного плеера не дублируются.
- Существующие нормы хранения наблюдений, политика доступа и серверный механизм очистки сохраняются.
