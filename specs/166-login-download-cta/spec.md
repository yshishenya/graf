# Feature Specification: Контекстная ссылка на приложение на экране входа

**Feature Branch**: `codex/161-graf-ux-regressions`

**Created**: 2026-08-18

**Status**: Draft

**Input**: User description: "В версии для приложения убрать ссылку на скачивание приложения с экрана логина; в веб-версии сделать её более заметной, например в левом нижнем углу."

## User Scenarios & Testing

### User Story 1 - Веб-пользователь видит приложение, но не теряет вход (Priority: P1)

Пользователь открывает веб-версию GRAF и видит заметную, но вторичную ссылку на приложение. Ссылка не конкурирует с полем email и кнопкой входа и ведёт на уже существующую публичную страницу скачивания.

**Why this priority**: Веб-пользователь может ещё не установить GRAF, поэтому ссылка помогает перейти к основному сценарию записи, не перегружая форму авторизации.

**Independent Test**: Открыть `/login?next=/meetings` в браузере и убедиться, что CTA виден в нижней левой части экрана, доступен с клавиатуры и ведёт на `/download`, а форма входа остаётся главным действием.

**Acceptance Scenarios**:

1. **Given** пользователь открыл обычный веб-экран входа, **When** страница отрисована, **Then** на ней есть одна заметная ссылка на скачивание GRAF в нижней левой области, а в карточке входа нет дублирующего CTA.
2. **Given** пользователь открыл обычный веб-экран входа с ошибкой входа, **When** ошибка показана, **Then** ссылка на приложение остаётся доступной и не закрывает сообщение об ошибке или юридическую информацию.
3. **Given** пользователь перемещается по странице клавишей Tab, **When** фокус доходит до ссылки на приложение, **Then** ссылка имеет видимый focus state и понятное имя.

### User Story 2 - Пользователь приложения не получает бесполезный призыв скачать приложение (Priority: P1)

Пользователь macOS-приложения проходит встроенный экран входа, чтобы открыть кабинет. Экран не предлагает скачать уже открытое приложение и не показывает пустой или неработающий заменитель этой ссылки.

**Why this priority**: Лишний CTA в embedded-окне создаёт сомнение, что пользователь находится не в том продукте, и отвлекает от авторизации.

**Independent Test**: Открыть `/login?next=/desktop/meetings` в embedded-поверхности и проверить отсутствие download-ссылки и её текста при обычном входе и при ошибке входа.

**Acceptance Scenarios**:

1. **Given** приложение открыло экран входа с целевым desktop-маршрутом, **When** страница отрисована, **Then** на ней нет ссылки `/download`, текста «Скачать GRAF» или другого CTA, предлагающего скачать приложение.
2. **Given** встроенный экран входа показывает ошибку авторизации, **When** пользователь повторяет попытку, **Then** отсутствие download-CTA сохраняется, а поле email, ошибка и юридическая информация остаются доступными.

### Edge Cases

- Прямой `/login` без параметра `next` считается веб-входом и показывает CTA.
- Небезопасный или внешний `next` после существующей нормализации становится обычным веб-входом и показывает CTA; новая логика не ослабляет проверку redirect-пути.
- Любой безопасный `next`, начинающийся с `/desktop/`, считается embedded-входом и не показывает CTA, включая страницы настроек.
- Экран ввода одноразового кода, регистрация, referral landing и публичные страницы скачивания не входят в изменение и не получают вторую ссылку.
- Узкое окно не должно обрезать ссылку, перекрывать форму или юридический текст; CTA может перейти в компактное вертикальное представление.

## Requirements

### Functional Requirements

- **FR-001**: В обычном веб-входе GRAF MUST показывать ровно один доступный CTA на существующую страницу `/download`.
- **FR-002**: Веб-CTA MUST быть визуально отделён от формы авторизации и размещён в нижней левой области доступного viewport на широком экране.
- **FR-003**: Embedded-вход для любого безопасного маршрута `/desktop/...` MUST не показывать download-ссылку, её текст или пустой placeholder.
- **FR-004**: Различие web/embedded MUST использовать существующую нормализацию `next` и MUST NOT менять проверку внешних redirect, auth-сессии, invitation flow или провайдеров.
- **FR-005**: Веб-CTA MUST иметь понятное доступное имя, видимый focus state, рабочую ссылку на публичный `/download` и не перекрывать auth alert, форму, legal copy или элементы управления при ширине от 320 px.
- **FR-006**: Поведение CTA MUST быть одинаковым для первоначального login-экрана и его HTML-ответов после ошибки входа.
- **FR-007**: Изменение MUST оставлять без CTA referral landing, signup, email-code, публичные landing/download страницы и уже существующий download CTA в кабинете после входа.

### Key Entities

- **Login surface context**: Эфемерный контекст отображения экрана входа, определяемый безопасным целевым маршрутом: `web` для обычного входа и `embedded` для `/desktop/...`. В базе данных не хранится.
- **Download CTA**: Доступная ссылка из web login на публичную страницу `/download`; не является новым auth- или download API.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 100% focused render checks для web login (обычный вход и auth error) содержат ровно один `/download` CTA, а embedded login (обычный вход и auth error) не содержит ни одного.
- **SC-002**: В 100% ручных визуальных проверок web login при ширине 1440 px и 768 px CTA остаётся читаемым, видимым и не перекрывает форму, alert или legal copy.
- **SC-003**: В 100% ручных проверок embedded login при ширине 1120 px и 720 px download CTA отсутствует, а форма входа и ошибка остаются доступны.
- **SC-004**: Публичная страница `/download` и существующие download CTA в кабинете сохраняют текущие маршруты и тексты; focused regression suite не выявляет изменений вне login surface.

## Assumptions

- Существующая публичная страница `/download` является единственным назначением CTA и не требует нового API или аналитики.
- Безопасный `next` уже нормализуется текущим auth-кодом; эта функция только выбирает presentation context после нормализации.
- Встроенное приложение использует `/login?next=/desktop/...` для восстановления сессии, поэтому отдельный заголовок клиента для рендера не добавляется.
- Релиз и production deploy не входят в этот slice; функция войдёт в общий release train после проверки остальных пользовательских задач.
