в один SQLAlchemy SELECT со связанными параметрами. Сохранены все конструкторы,
валидация, имена/значения настроек, session.info/connection.info,
transaction-local=true, after_begin и явный rehydrate. Пустой сохранённый словарь
не выполняет SELECT. Новых зависимостей, миграций и изменений политик RLS нет.

## Измеренное поведение

- 12 классов/14 видов представлены 19 наборами полей через session и connection:
  точные current_setting, один SQL на непустой проход; два прохода первого
  session apply остаются двумя SQL. В активной транзакции rehydrate — один SQL.
- Commit/rollback и явный rehydrate после границы проверены на полном worker
  контексте. Остальные виды проверены при первом after_begin и внутри активной
  транзакции; отдельная полная матрица всех видов × всех границ не заявляется.
- Отсутствующий/пустой контекст — ноль настроечных SQL. Смена контекста,
  одновременные сессии и повторное использование того же pg_backend_pid
  не смешивают значения. После commit/rollback настройки локальной транзакции
  на переиспользованном соединении пусты.
- Направленный отказ SQL проверен через rehydrate: следующая SQL-команда
  отклоняется до rollback; затем прежний сохранённый контекст восстанавливается.
- Та же синтетическая полная страница `/meetings/{id}`: **84 → 68 SQL**,
  из них set_config **20 → 4**; HTTP 200. Остальные 64 SQL не изменились.
- `/shared-with-me` и `/desktop/shared-with-me`: **26/26 SQL** при 5/50
  встречах вместо предыдущих 58/58. Пустые страницы — 11/11; одиночная
  встреча — 25/25. Для пустой/одиночной сравнение с отключённой предвыборкой
  на текущем контексте не обнаружило роста.
