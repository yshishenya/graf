# F270: полная страница встречи в пределах 25 SQL

Полоса: `high-risk-product`, существующая F270, T032/T033 в составе T025.
Исходник — `5395cfd5e45f3cd4aa3fbdee91fdbc2973256dae`; новые изменения
не закоммичены. Разрешение на предыдущий коммит использовано; новый коммит
потребует отдельного разрешения после проверки. Слияние и выпуск не выполнены.

## Реализация и границы

Использован существующий `CabinetReadPrefetch`: один ограниченный запрос
одиночных связей детали с `LATERAL LIMIT 1`, без нового слоя и зависимостей.
Коллекции расшифровки, голосов, имён и пунктов итогов читаются отдельно.
Сохранены отдельные правила порядка latest/effective, выбранный и основной
слоты, отображение основного формата при отсутствии выбранного, версии и
проверки происхождения, источник расшифровки и повторная авторизация календаря.
Запрос канонического аудио ограничен workspace/meeting/revision/id.

Доступ не кэшируется: `cache_access=False` сохраняет чтение членства, выдач
доступа и подтверждённых адресов получателя. Независимое ревью обнаружило
оставшийся кэш адресов; оба места чтения/записи исправлены. Подтверждён
результат True→False после отзыва, два чтения, пустой кэш адресов.
Контекст детали очищается до авторизации и в `finally`, восстанавливая
предыдущий контекст при вложенном вызове и исключении.

API, схема, права доступа, RLS и пользовательский интерфейс не меняются.
Legacy Impact: `untouched`; исходный путь сохранён для остальных потребителей,
контрольное отключение предвыборки существует только в тестах.

Счётчик включает все SQL полного HTTP-запроса с авторизацией и настройкой

### Матрица результата

- Сравнение API со старым чтением: ready/processing/failed/partial/foreign,
  отсутствие видимой ревизии или результата, опубликованные итоги, личный и
  отсутствующий формат. Один явный request_id делает служебное поле стабильным.
- Доступ: member/full/summary-only/revoked/expired/deleted, одновременная
  выдача пользователю и рабочему пространству. Невозможный дубль с тем же
  audience_id не создаётся: его запрещает ограничение базы.
- Прямое сравнение полного helper для `source_result_id` вместе с выбранным
  личным форматом. API этот параметр не передаёт, поэтому API-строка не
  выдаётся за проверку источника. Настоящие браузерные ссылки и чужие версии
  проверены существующим `test_transcript_export_egress.py`.
- Resolver: 4 состояния × 36 сочетаний параметров, до/после предвыборки;
  сохранены include_non_publishable, allow_legacy_read_only, запрошенная
  версия результата и отсутствующий формат.
- В одной сессии повторный полный вызов после отзыва выдачи или начала
  удаления отказывает в доступе; адрес получателя читается заново.
- Вложенность, исключение и восстановление чужого предыдущего контекста;
  latest/effective сохраняют разные порядки imported_at/result_version.

## Полный прогон и остаток

На Mac менее 50 GiB свободно. Штатная очистка старых свободных Docker images
и build cache освободила 632 МБ, но места для большого локального прогона
недостаточно. Тома, рабочие копии и пользовательские данные не удалялись.
Отдельная проверка обнаружила отсутствие единственного GRAF Dev. Он восстановлен
штатным promote того же активного manifest и исходника
`698ebfa5202986f1a681fd46eb4f12e505352ded`: 13/13 проверок dev-harness PASS,
без новой сборки, миграции или изменения данных. Это восстановление прежней
среды F280, а не установленная приёмка новой F270. Его временный чистый checkout
сохранён, пока активная среда использует его; production не менялся.

Полный серверный прогон перенесён на `dev-p4`, в одноразовый каталог.
Основа клонирована по точному SHA выше, шесть файлов кода/теста перенесены
отдельным архивом 68 КБ; 6/6 контрольных сумм проверены до старта. Python 3.13
и зависимости из frozen uv.lock установлены изолированно. Команда:

```sh
GRAF_TEST_WORKERS=4 GRAF_PERFORMANCE_GATE=required \
GRAF_TEST_REPORT_DIR=<temporary-report-directory> \
  bash apps/server/scripts/run_local_postgres_tests.sh --full -q
```

Первая попытка не прошла: strict — 94 passed / 55,70 с; performance —
2 passed / 17,82 с; parallel — 6834 passed, 90 failed, 7 errors,
103 skipped / 1128,65 с. Все 90 отказов сопоставлены с журналом: 54 вызваны
отсутствием Node.js, 36 — FFmpeg/ffprobe. Семь ошибок подготовки требуют
Playwright/Chromium. Это ошибки неполного временного окружения, а не успешный
полный результат; исходные журналы сохранены. Runner удалил свой контейнер.

В том же одноразовом каталоге отдельно подготовлены Node.js 22.22.3,
FFmpeg/ffprobe 8.0.1, Playwright из package-lock и Chromium; версии
Specify 1.0.7 / bootstrap 0.9.10 совпадают с CI. Проверены официальные
контрольные суммы Node/bootstrap, зависимости Ubuntu скачаны с проверкой apt
и распакованы в изолированный каталог без системной установки. Chromium
открыл синтетическую страницу. Продукт и ожидания тестов не менялись.

Вся parallel-фаза повторена штатным режимом
`--focused --partitioned --phases parallel -q`; успешные strict/performance
сохранены на тех же шести файлах. Collection count 7130 и digest
`47314009d9a5e9bd30b8007cf45b3f977bb441a7545f4dc2676440bdb88e8368`
совпадают. Вторая попытка: 6911 passed, 38 failed, 85 skipped / 1135,57 с.
Исходный отказ сохранён, отдельный непрерывный `--full PASS` не заявляется.

Разобраны все оставшиеся отказы среды:

- 36 медиа-проверок: защитный запуск намеренно исключает LD_LIBRARY_PATH.
  Изолированный FFmpeg запускался из обычной оболочки, но его ffprobe с тем же
  очищенным окружением завершался кодом 127 из-за недоступной библиотеки.
  Подготовлен временный запуск тех же пакетов через штатный динамический
  загрузчик с явным каталогом библиотек. Защитное окружение и код приложения
  сохранены. Все ровно 36 ранее отказавших случаев — PASS / 27,39 с;
  совпадение выбранных идентификаторов и setup/call/teardown проверено.
- Две браузерные проверки использовали обычный `require('playwright')`.
  Указания GRAF_NODE_MODULES для них недостаточно; добавлен стандартный NODE_PATH
  к тому же изолированному Playwright. Проверка оплаты — 1 PASS / 145,75 с;
  проверка фокуса — 1 PASS / 14,29 с. Сохранены фактические журналы; первая
  имеет отдельную запись результата одного точного случая, вторая — штатный
  отчёт событий pytest. Условия и ожидания проверок не менялись.

Совокупное покрытие проверено по идентификаторам:
94 strict + 2 performance + 7034 parallel = **7130 различных случаев**;
итог **7045 PASS / 85 SKIP / 0 неразрешённых отказов**. Повторные 38 случаев
заменяют собственные прежние отказы, а не прибавляются к числу различных.
Все три фазы не пересекаются, состав parallel совпал с первой попыткой,
шесть файлов кода/теста совпали по SHA-256 до и после всех этапов.

85 пропусков предусмотрены исходным составом: 56 проверок возврата после
оплаты, 28 проверок промокодов и один сценарий на отдельно разрешённых записях.
Их параметры включения не задавались; частные записи не читались и не
копировались. Ошибки окружения не превращались в пропуски. Доказательство:
