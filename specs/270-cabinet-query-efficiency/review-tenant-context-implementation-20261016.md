## Покрытие нового предохранителя

Новый файл содержит 19 вариантов контекста (12 классов / 14 видов с минимальными/полными необязательными полями). Они выполняются через session и connection: 38 случаев проверяют точный info, бюджет 2/1 и реальные current_setting. Session-ветка каждого варианта дополнительно проверяет явный rehydrate в существующей транзакции: один SQL и те же значения.

Еще 11 случаев дают в сумме 49: commit/rollback с автоматическим replay и с явным rehydrate (4), замена контекста в активной транзакции (1), отсутствие/пустой контекст (2), очистка после commit/rollback при повторном использовании того же pg_backend_pid (2), одновременные сессии с барьером ожидания (1), отказ SQL с необходимостью rollback и восстановлением (1).

Проверки бюджета отделены от current_setting-проб: значение len(statements) проверяется до пробы либо ее единственное чтение учтено явно. Два SQL при явном rehydrate после границы транзакции сохраняются и вместе с пробой дают 3; автоматический replay и проба дают 2. Слушатель хранит текст операторов без значений parameters. Все идентификаторы/значения синтетические, URL проверяется существующим validate_rls_test_database_url; соединение создано только с одноразовой loopback-базой, engine освобождается в finally.

Тест повторного использования соединения удерживает второй слот пула и проверяет равенство backend PID. Он подтверждает очистку transaction-local полей, включая необязательные идентификаторы, до применения нового пространства. Конкурентный сценарий ждет установки обоих контекстов до чтения, поэтому не сводится к последовательным вызовам.

Такой журнал не доказывает отдельный отказ каждого входа.
2. Новые current_setting-проверки проверяют настройки и транзакции, но сами не читают защищенные пользовательские таблицы под ограниченной ролью. Доказательство RLS дает отдельный выбранный прогон 61 случая, а полный серверный прогон остается T026. Проверки значений не заменяют проверку прав.

Остальные виды проверены при первом after_begin и rehydrate внутри транзакции; отдельная матрица commit/rollback для всех 14 видов не запускалась. Общий механизм читает тот же сохраненный словарь, builders не меняются.
