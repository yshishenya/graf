# Implementation Plan: Предсказуемая скорость страниц кабинета

**Branch**: `270-cabinet-query-efficiency` | **Date**: 2026-09-17 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/270-cabinet-query-efficiency/spec.md`

## Summary

Страница списка встреч обращается к базе по каждой встрече отдельно: 144 обращения
при пяти встречах, 299 при десяти, 609 при двадцати. При пределе списка 50 это
порядка 1500 обращений и больше двух секунд серверной работы, то есть главный экран
продукта деградирует вместе с накоплением записей.

План заменяет обращения «на каждую встречу» на пакетную предвыборку: один запрос
на каждый вид связанных данных для всей страницы вместо запроса на встречу.
Решения о доступе, признаки удаления, содержимое, порядок и тексты не меняются —
меняется только способ получения данных. Отдельно устраняется доказанная
избыточность: членство зрителя читается один раз на запрос вместо чтения на каждую
встречу. Добавляется детерминированная проверка-предохранитель, которая падает,
если число обращений снова начнёт расти вместе с числом встреч.

Ожидаемый результат: около 25 постоянных обращений вместо 144 при пяти встречах,
и такое же постоянное число при пятидесяти вместо примерно 1500.

## Technical Context

**Language/Version**: Python 3.13, FastAPI, SQLAlchemy 2.x async (asyncpg)

**Primary Dependencies**: `select()` и `DISTINCT ON` из SQLAlchemy, существующие
помощники `cabinet/queries.py` и `cabinet/access.py`; новых зависимостей нет

**Storage**: PostgreSQL; схема, миграции и индексы не меняются

**Testing**: pytest с реальной PostgreSQL в контейнере; проверка-предохранитель
считает обращения слушателем `before_cursor_execute`; существующий полный прогон
`apps/server/scripts/run_local_postgres_tests.sh --full` служит основным
доказательством неизменности поведения

**Risk / Validation Lane**: `high-risk-product` — затрагивается путь чтения кабинета,
в котором принимаются решения о доступе к записям встреч, о признаках удаления и о
доступности выгрузки. Работа не меняет правила, но проходит рядом с ними, поэтому
обязательны clarify, checklist и analyze.

**Release Gate**: `no deploy` в этой ветке. Перед слиянием нужны обязательные
GitHub-проверки `governance-fast`, `macos-pr`, `pr-metadata` на точном SHA. Полный
прогон `release-full` выполняется на замороженном кандидате выпуска.

**Target Platform**: серверная часть кабинета (self-hosted развёртывание)

**Project Type**: web-service (серверная часть продукта)

**Performance Goals**: страница списка из 50 встреч — не более 300 мс серверного
времени; число обращений к базе не растёт более чем на 25 процентов при росте числа
встреч с 5 до 50

**Constraints**: решения о доступе, признаки удаления, состав, порядок, фильтры,
сортировка, предел и тексты неизменны; каждое пакетное чтение ограничено рабочим
пространством запроса; схема и публичные контракты не меняются

**Scale/Scope**: до 100 встреч на страницу, рабочие пространства с большим числом
записей; объём изменений — путь чтения списка встреч в `cabinet/queries.py`,
чтение членства в `cabinet/access.py`, одна новая проверка

## Validation Plan

1. **Проверка-предохранитель** (новая): считает обращения к базе для страницы списка
   при 5 и при 50 встречах, падает при росте более 25 процентов, называет экран.
2. **Замер до и после**: замер из `quickstart.md` фиксирует число обращений при 5,
   10, 20 и 50 встречах, а также для страницы детали.
3. **Полный серверный прогон**:
   `GRAF_TEST_WORKERS=4 GRAF_PERFORMANCE_GATE=required bash apps/server/scripts/run_local_postgres_tests.sh --full`
   — основное доказательство того, что поведение доступа, удаления, хранения и
   выгрузки не изменилось. Сравнение с сохранённым эталоном таймингов
   (`/tmp/graf-baseline/parallel.jsonl`: 4454 случая, 7583 с тела, 1166 с подготовка).
4. **Фокусированные проверки доступа**: приватность шаринга, ограничение только
   итогами, отзыв доступа, отказ в загрузке аудио, недоступная встреча.
5. **Обязательные GitHub-проверки** на точном SHA: `governance-fast`, `macos-pr`,
   `pr-metadata`.

## Доработка 2026-10-16 — #7142

Путь `list_shared_with_me_meetings` общий для браузера и встроенного кабинета.
Внутри существующей группы owner workspace установить отдельный `CabinetReadPrefetch`,
пакетно прочитать права через `batch_active_user_grants` и оба варианта
`batch_workspace_audience_grants`, ревизии через `batch_latest_media_revisions`.
`decide_meeting_access` продолжает получать прежнее подтверждение получателя.
Членство читается прежним помощником с `populate_existing=True` один раз на эту
сессию. Полный набор итогов, аудио и результатов для карточки не требуется.
Очистка контекста обязательна через `finally`; контекст не передаётся между
пространствами. Схема, зависимости и интерфейс не меняются.

До исправления предохранитель обеих страниц с 5/50 реальными общими встречами
должен воспроизвести рост; после — рост не более 25% и не более 80 SQL. Дополнительно
сравнить результат с исходным одиночным путём на смешанных правах, просрочке,
отзыве, удалении и чужом пространстве; сохранить существующие проверки без изменения
ожиданий. Полный серверный прогон и точные GitHub-проверки остаются обязательными
перед полной приёмкой. При недостатке места на Mac полный прогон переносится на
подходящий сервер; фокусированные проверки используют одноразовую PostgreSQL и
существующее окружение без копирования зависимостей.

Если в одном из пакетных чтений обнаружено несколько кандидатов для одной встречи,
нельзя выбирать более широкий доступ или произвольный новый приоритет ради скорости.
Для неоднозначной группы сохранить исходный одиночный выбор: исключить её из
предвыбранного словаря, чтобы общий помощник выполнил свой прежний запрос.
Предохранитель 5/50 проверяет корректные выдачи (один user grant на адресата
согласно частичному уникальному индексу workspace/meeting/audience_id, где
audience_id == grantee_user_id). Для workspace audience отсутствие уникального
ограничения учитывается сохранением одиночного пути при нескольких кандидатах. Неоднозначные устаревшие данные проверяются
на эквивалентность результата, а не используются для оправдания изменения прав.

Пустая группа не читает связанные сущности; для одной встречи остаётся одиночный
путь, поэтому SQL не превышает исходный. При 2+ встречах контекст создаётся и
удаляется только в локальной source_db сессии; отдельные запросы получателей
используют отдельные сессии. Граница включает одновременно workspace_id группы,
meeting_ids уже отобранных встреч и viewer_user_id получателя.

Доказательство SC-005 разделяет метрики: исходные 2214 секунд — длительность
серверной части полного прогона (не суммарное время всего workflow; целевой предел 1881,9 секунд); 7583 секунд — сумма длительностей
тел параллельных тестов, не длительность прогона. Их нельзя сравнивать друг с другом.
Исторические числа сохраняются, но не подтверждают новый diff. Для нового diff
требуется полный прогон с тем же составом случаев и сопоставимым окружением;
сохраняются длительность серверной части полного прогона, сумма тел, число случаев и различия
окружения. Если исходный эталон/сопоставимое окружение недоступны, SC-005 остаётся
неподтверждённым, а не заменяется текущими фокусированными проверками.
