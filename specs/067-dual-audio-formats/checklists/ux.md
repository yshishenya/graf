# UX Checklist: Dual Audio Formats

**Purpose**: Validate requirement quality for review playback, download/export
expectations, and user-facing copy.

## User Expectations

- [x] Requirements say users do not choose or understand formats during normal
  record, upload, review, or approved download flows.
- [x] Requirements explain in plain language that WAV remains for transcription
  and M4A is for playback/distribution.
- [x] Requirements avoid implying automatic sharing, public links, transcript
  editing, echo cancellation, or noise suppression.

## Playback And Download States

- [x] Requirements distinguish in-page playback from downloadable/exportable
  audio.
- [x] Requirements define available, pending, degraded, failed, blocked,
  purged, and not-applicable states.
- [x] Requirements define truthful fallback when only size/seek improvement is
  possible.

## Accessibility And Review Surface

- [x] Requirements keep playback routed through existing review surfaces instead
  of adding a new unreviewed UI.
- [x] Requirements require timestamp seek behavior to remain meaningful for
  transcript review.
