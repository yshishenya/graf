## Наблюдаемый Krisp

Веб и приложение используют одинаковую панель Share/Export. Исходный код и ресурсы конкурента не копировались.

Ограничения доказательств: смена роли демо на AI Notes не дала надёжного отдельного доказательства ограничения у вошедшего аккаунта; не переносим это как корректную модель прав. Мобильная/светлая версия и завершение регистрации Krisp не подтверждены. Приватный путь исследован отдельно после обнаружения авторизованного сеанса IAB. Реальным людям писем не отправляли. Учебные итоги созданы с разрешения пользователя; общий доступ возвращён к исходному Invite only, подтверждено интерфейсом владельца.

Официальное описание для сопоставления: https://help.krisp.ai/hc/en-us/articles/30666838645660-Share-your-meetings . Оно подтверждает публичное чтение без входа и сохранение адресных приглашений при смене общего доступа. Документация не заменяет живое наблюдение.

## R001: сервер и приватность

Решение: расширить существующий MeetingShareGrant и сервис summary_sharing; без новой таблицы расшифровок. F286 остаётся сохранённой публикацией итогов. У модели уже есть scope/capabilities/version/ciphertext/snapshot. Одна активная ссылка на встречу — существующий уникальный индекс. Все современные изменения должны проходить один сервис с grant_id/expected_version под lock_shareable_meeting. Legacy API не может менять современную версионную ссылку без версии.

Полная публичная проекция получает только текущий effective_processing_result_query, сегменты с совпадающими workspace/meeting/result, имена говорящих/текст/время. Не передавать get_cabinet_meeting_review или owner session гостю. Итоги берутся существующей узкой проекцией; если их нет, страница остаётся рабочей.

Публичное audio требует явного доказательства grant под meeting fence. Не подставлять владельца в decide_meeting_access. Повторная проверка действительности токена, scope, политики, срока и удаления на каждый диапазон. Обычные пользовательские маршруты сохраняют _refresh_egress_access. Ограниченное потоковое чтение с буфером до 4 MiB закрывает сборку всего файла в память для анонимного запроса; используются существующие Range/хранилище и аудит с actor_user_id/device_id=None. Расшифровка не дублируется в БД и удаляется существующим процессом.

Отклонённые варианты: выдача внутренней страницы владельца (лишние поля), новая копия расшифровки (лишнее хранение/удаление), мнимый owner для аудио (обход прав), автоматическое расширение старых ссылок (утечка), вторая система рассылки (дубли и неизвестные исходы).

## R002: приложение и возврат

Решение: встроенный кабинет и отдельный строгий парсер навигационного намерения. Сейчас AppDelegate принимает только grafrec://attribution; Dev/production регистрируют одинаковую схему. Dev переходит на grafrec-dev, production сохраняет grafrec; атрибуция должна учитывать ту же конфигурацию.

Для публичного открытия схема несёт workspace UUID, токен общей ссылки, вкладку и позицию, а не сеанс входа. Origin берётся только из DesktopCabinetConfiguration. Маршрут публичной страницы разрешается точной политикой. Для адресного открытия используются meeting/workspace UUID и собственный аккаунт приложения; отсутствие доступа не повышает роль. Одно ожидающее намерение поглощается после готовности окна; не хранится 90 дней как атрибуция.

Найденная потеря nextRoute.path при expiredSession должна исправляться общим сохранением разрешённого относительного адреса с query/fragment, включая Dev. Для веб-входа зашифрованный cookie продолжения TTL 10 минут не размножает токен в query входа. Прямое локальное перенаправление проверяется существующим safe_first_party_path.

Неизвестные технические решения отсутствуют; точные сигнатуры уточняются при реализации в перечисленных модулях без изменения продуктового объёма.

## Обновление 2026-11-11 — компоновка владельца

Скриншот пользователя показывает съехавший замок под native select и перенос details рядом с copy. Предыдущие тесты проверяли достижимость панели, но не геометрию значка и платформенного select. Исходный CSS зависит от absolute inset и нативного appearance; footer использует две колонки, отнимающие место у длинной русской подписи. В T033 устраняется сама зависимость от размеров native popup и конкурирующая строка.

Официальный источник повторно прочитан: https://help.krisp.ai/hc/en-us/articles/30666838645660-Share-your-meetings (2026-11-11). Общая структура: invitation/owner/general access/copy; Can view включает доступные материалы, только notes — отдельная роль. Справка описывает автоматическое открытие Anyone with link при Copy ранее закрытой встречи; GRAF сохраняет явный выбор и подтверждение ради прозрачных прав. Новых ресурсов или кода Krisp не заимствуется. Актуальное живое наблюдение аккаунта/приложения отдельно от справки и исторического исследования.
