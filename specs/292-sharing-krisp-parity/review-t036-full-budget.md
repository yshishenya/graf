## Зависимый предел validator

Прочитан `scripts/validate-full-ci-workflow.py`173–177: текущая версия
требует `1 <= timeout <= 60` для каждого job. Независимая проверка без
записи workflow или временного файла подтвердила зависимость: функция
validate получила текст через read_text в памяти. Исходный текст прошёл;
единственная замена server-phases30→90 дала
`job timeout must stay within one hour: server-phases`.

Текущие требования T036 уже учитывают эту зависимость: analysis scope
называет workflow и validator, task T036 также называет оба файла. Только
server-phases получает допустимый диапазон1..90, остальные остаются1..60.
Self-tests должны принимать90 и отклонять91 для server-phases, отклонять61
для другого job. Отсутствующий/нулевой предел по-прежнему не разрешён.
Так область исправления согласована с обязательной проверкой, а конечное
ограничение остальных jobs не расширяется. Новых тестовых исключений,
параллелизации strict или ослабления performance threshold не вводится.
