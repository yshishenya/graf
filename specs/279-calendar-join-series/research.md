# F279 — исследование календаря и Krisp

Дата: 2026-09-28. Основа GRAF: `59aa72e22bf94725fac37f1248613114954498c5`.
Статус: исследование и проект решения; продуктовый код не изменён.

## 1. Почему «Подключиться» приводит к ошибке

Подтверждено чтением исходников GRAF; сквозное воспроизведение в GRAF Dev пока не выполнялось.

| Шаг | Источник | Вывод |
|---|---|---|
| Кнопка календарного обзора | `apps/server/src/twobrain_rec_server/cabinet/rendering.py`, `_render_home_upcoming` | Обычная ссылка ведёт на `/api/v1/calendar/events/{event_id}/open` |
| Политика встроенного кабинета | `apps/macos/RecApp/Sources/Cabinet/DesktopCabinetRoutePolicy.swift`, `decision` | Нет разрешённого пути для этого API; неизвестный внутренний маршрут блокируется |
| Ошибка навигации | `apps/macos/RecApp/Sources/Cabinet/EmbeddedCabinetWebView.swift`, `blockWithMessage` | Состояние меняется на `.blockedRoute`, заменяя страницу кабинета |
| Текст ошибки | `apps/macos/RecApp/Sources/Cabinet/DesktopCabinetState.swift` | Совпадает с сообщением на скриншоте пользователя |
| Серверный переход | `apps/server/src/twobrain_rec_server/api/calendar.py`, `open_calendar_meeting` | Проверяет владельца/пространство/источник/выбор календаря, расшифровывает ссылку и возвращает 303 |
| Следующий барьер | `DesktopCabinetRoutePolicy.externalDecision` | Обычные внешние конференционные адреса тоже блокируются |
| Потеря параметров | `DesktopCabinetRoutePolicy.sanitizedExternalURL` | Общий обработчик внешних ссылок удаляет query; его нельзя применять к паролю/коду в ссылке встречи |

**Decision**: отдельное действие подключения: UUID события → авторизованное разрешение актуальной цели → native-открытие. Веб-страница не должна проходить по цепочке перенаправлений.

**Rationale**: сохраняются страница и история, серверные проверки доступа и полная ссылка встречи, без ослабления общей политики навигации.

**Alternatives considered**:

- Просто разрешить `/api/v1/calendar/events/*/open`: недостаточно, следующий внешний переход всё равно блокируется.
- Разрешить любые внешние сайты из кабинета: слишком широкое изменение границы безопасности.
- Передать внутренний `/open` системному браузеру: у браузера может не быть сессии GRAF, поэтому это не надёжный путь.
- Использовать общий `sanitizedExternalURL`: теряет важные параметры подключения.
- Передать произвольный адрес из JavaScript в `NSWorkspace`: позволяет странице выбирать недопустимую цель. Передавать только идентификатор события.

Дополнительный независимый исследователь подтвердил маршрут, две последовательные блокировки и удаление query. Его рекомендации включены в `design-proposal.md`. Это проверка исходников, не проверка установленного приложения.

## 2. Где теряется признак повторения

| Уровень | Фактически существует | Чего не хватает |
|---|---|---|
| `db/models/calendar.py` | `CalendarEventSnapshot.recurring_series_id`, `recurrence_instance_id`, `original_start`, правила/исключения | Явной проекции серии для интерфейса |
| `calendar/google.py` | `recurringEventId` и исходное начало из Google | Надёжное правило частоты не всегда приходит с экземпляром |
| `calendar/normalize.py` | UID, RECURRENCE-ID, RRULE/RDATE/EXDATE; развёртывание повторов и исключений | Не нужно писать новый парсер повторений |
| `calendar/sync.py` | Сохранение повторов; отмена помечает событие удалённым | Регрессионные проверки новой группировки поверх существующего жизненного цикла |
| `api/schemas.py`, `CalendarEventSummary` | Время, заголовок, источник, наличие ссылки | Нет явных типизированных `is_recurring`/идентичности серии |
| `cabinet/view_models.py`, `UpcomingPreviewItemView` | Отдельная строка события | Нет серии/правила/ссылки на историю |
| `cabinet/rendering.py` | Каждое из первых четырёх событий рисуется отдельно | Нет группировки перед ограничением числа карточек |
| `calendar/matching.py` | Хеш серии для связи записей | Старый ключ учитывает пространство и источник, но не `external_calendar_id` |
| `cabinet/queries.py` | Независимо авторизованная ссылка на предыдущую запись серии | Это указатель на одну запись, а не каталог всех повторов |

**Decision**: сохранить существующие экземпляры событий и добавить проекцию серии. Не заменять экземпляры единственной записью серии.

**Rationale**: напоминания, выбор контекста, переносы и ссылки подключения принадлежат конкретной дате. История записей использует самостоятельные права доступа.

**Alternatives considered**:

- Группировка по заголовку или ссылке: ложное объединение разных регулярных встреч.
- Группировка после `preview[:4]`: одна частая серия может вытеснить остальные серии и разовые встречи; ограничивать нужно результат группировки.
- Новый слой самостоятельной генерации дат из RRULE в интерфейсе: риск несоответствия исключениям, часовому поясу и текущим данным провайдера.
- Удаление экземпляров после группировки: ломает контекст, переносы, напоминания и несколько записей одной даты.

## 3. Krisp: что действительно исследовано

Локально установлен `ai.krisp.krispMac`, версия `3.16.8` (Info.plist). Через обычный интерфейс проверены:

| Состояние | Наблюдение | Уверенность/предел |
|---|---|---|
| Главный экран My Notes | Сверху Upcoming, ниже список записей; есть пустое состояние сегодняшнего дня и будущее событие | Непосредственное наблюдение текущей версии |
| Нажатие на будущее событие | Открывается панель события с датой/временем и личными заметками; список остаётся позади | Непосредственное наблюдение; действие не было подключением |
| Нажатие на календарно связанную запись | Открывается отдельная страница записи с датой и вкладками AI Notes/My Notes/Transcript | Непосредственное наблюдение; частное содержимое не включено в артефакты |
| Дата на странице записи | Доступна как кнопка; попытка нажатия в выбранной записи не дала подтверждённого списка повторов | Нельзя заявлять наличие переключателя серии по этой попытке |
| История повторов | Не удалось показать несколько связанных повторов в текущей выборке аккаунта | Не подтверждено в живом интерфейсе |
| Подключение к звонку | В исследованной будущей карточке не было подтверждённой кнопки Join | Реальное подключение и приоритет приложения не проверены |

Официальное [объявление Krisp от 1 марта 2024](https://whatsnew.krisp.ai/announcements/february-updates-for-free-and-pro-users) описывает объединение экземпляров при открытии повторяющейся встречи. Это историческое описание функции, не доказательство полного поведения текущей версии.

[Страница справки Krisp о Meetings](https://help.krisp.ai/hc/en-us/articles/10291109632412-Meetings-page-in-account-dashboard) описывает записи/протоколы и отдельную работу с будущими событиями. Наблюдаемый актуальный интерфейс имеет другие названия разделов; не переносить историческую документацию буквально.

### Доступный код и границы обратного анализа

По прямому запросу пользователя выполнен ограниченный статический просмотр поставляемого JavaScript внутри `app.asar` без исполнения кода, изменения приложения или копирования его реализации в GRAF:

- В `BootstrapApp-BiqTUzCg.js` и `index-CAmVYtnC.js` найдены отдельные действия `joinMeeting`; основной процесс использует системное открытие внешних адресов через Electron.
- Имена `recurrence` в локальных файлах преимущественно относятся к повторным уведомлениям выхода из аккаунта, а не к календарным сериям. Совпадение слова не является доказательством алгоритма календаря.
- Кабинет реально загружается с `desktop.krisp.ai`, поэтому локальный пакет не содержит подтверждённой полной реализации списка серий.
- Публичная HTML-страница без cookies вернула имя `/assets/index-DZnH0xxo.js`, но запрос самого файла вернул HTTP 403. Доступ не обходился; закрытые API, cookies и данные аккаунта не извлекались.
- Серверный код, алгоритмы идентификации серий, отмен и миграций Krisp неизвестны. Их нельзя выдавать за восстановленные.

Результат обратного анализа — карта подтверждённых взаимодействий, механизм разделения web/native на уровне доступных признаков и перечень неизвестного. В репозиторий не перенесены код/ресурсы/шрифты/логотипы/снимки частных встреч Krisp. Собственная реализация проектируется по контрактам GRAF и публичным стандартам.

## 4. Идентичность серии и исключения

[Google Calendar: recurring events](https://developers.google.com/workspace/calendar/api/guides/recurringevents) отдельно определяет родительскую серию и исходное начало экземпляра. Перенесённый экземпляр сохраняет исходную идентичность; фактическое время может измениться. У развёрнутых экземпляров может отсутствовать правило повторения.

[iCalendar RFC 5545](https://www.rfc-editor.org/rfc/rfc5545) задаёт UID, RECURRENCE-ID и правила повторения/исключений. Для GRAF это означает: сохранить подтверждённую связь с серией и исходным повтором, отображать актуальное время, не восстанавливать недостающие правила по похожим датам.

Предложение идентичности:

- Серия: пространство + владелец источника + источник + внешний календарь + provider series ID (или подтверждённый UID повторяющегося iCalendar).
- Повтор: серия + устойчивый ID экземпляра провайдера/исходная календарная дата-время с семантикой all-day и timezone. Фактическое начало не является единственным ключом.
- Запись: существующий `Meeting.id`, независимо от календарной серии.
- Старый хеш `recurring_series_key_sha256` не менять молча: проверить совместимость старых контекстов; при необходимости ввести версию ключа. Нельзя склеивать неоднозначные старые записи автоматически.

## 5. Выводы для следующего этапа

1. Сначала отдельный безопасный механизм подключения и его проверки; код общего запрета навигации сохраняется.
2. Затем проекция серии поверх существующего календаря, группировка до ограничения количества карточек и история с отдельной пагинацией.
3. Напоминания и календарное сопоставление остаются на уровне события, поэтому группировка не теряет даты.
4. История протоколов расширяет действующий проверяемый указатель на предыдущую запись; доступ проверяется отдельно к каждому результату.
5. Матрица запуска приложений должна доказать прямой переход к установленному Телемост/Zoom/Teams там, где он поддерживается. Открытие HTTPS само по себе такого доказательства не даёт.
6. Карточка серии с историей выбрана как рабочее допущение для плана; вопрос о предпочтении необязательный и остаётся доступен пользователю. Продуктовый код, сборка, установка, commit и deployment не выполнялись.

## 6. Проверка системного обработчика на настоящем Mac

Live GRAF Dev выявил msteams-регистрацию Parallels без установленного Mac Teams. Наличие обработчика схемы не доказывает наличие поддерживаемого приложения. Решение: явные bundle ID `com.microsoft.teams2` / `com.microsoft.teams`, `us.zoom.xos` и `ru.yandex.desktop.telemost`; запуск через NSWorkspace с указанным приложением. Отсутствие поддержанного приложения оставляет HTTPS-путь. Это собственное наблюдение GRAF, не вывод о коде Krisp.
