# F279 — контракты

Контракты реализованы и проверяются серверными и нативными регрессиями.

## Разрешение цели подключения

`GET /api/v1/calendar/events/{event_id}/join-target` с действующей авторизацией GRAF.

Ответ: event_id (UUID), provider_family, https_url. Cache-Control: no-store. Сервер возвращает только URL из актуального разрешённого события, после существующей расшифровки и safe_open_meeting_url. Не принимает URL или произвольный домен во входе. Успех — JSON без внешнего redirect.

401 — истёкшая сессия; 404 — единая недоступность чужого/удалённого/отменённого/невыбранного/отключённого события или отсутствующей безопасной ссылки; 503 — зависимость недоступна. Ошибки без полных URL и приватного содержимого. Повторная проверка актуального owner/workspace обязательна.

Существующий `/api/v1/calendar/events/{event_id}/open` сохраняется для браузеров и вызывает тот же resolver, затем 303. Cookies/auth GRAF не добавляются к целевому адресу.

## Мост встроенного кабинета

Вход: `{ action: "joinCalendarEvent", eventId: UUID, requestId: bounded opaque id }`. UUID, requestId и action валидируются; произвольный URL, лишние поля и недоверенный frame отклоняются.

Требуются: действующий trusted main document кабинета, подходящий маршрут, готовая сессия, прикреплённый WebView и явное действие пользователя. Делегированный обработчик работает и после обновления календарного HTML. Сообщение моста не является самостоятельной авторизацией к календарному событию.

Выход: requestId + resolving/opening/handed_off/failed/cancelled + безопасный код локализуемой ошибки. URL в ответ странице не возвращается. После await перепроверяются текущая сессия/документ/операция. Браузерная страница без native-моста использует совместимый веб-путь.

## Серии

Текущий `/calendar/events/upcoming` сохраняет семантику экземпляров для старых клиентов и напоминаний; новые optional поля не обязательны при чтении старого ответа.

Новая проекция обзора (предлагаемый путь `GET /api/v1/calendar/overview`) возвращает карточки одиночных событий/серий, cursor, диапазон данных и partial. Серия содержит representative event и не заменяет его собственной «общей» ссылкой. Ограничение применяется к карточкам после фильтрации/группировки; первая версия может отдавать четыре карточки на главном экране.

`GET /api/v1/calendar/series/{series_key}/occurrences` принимает bounded date range и cursor; limit по умолчанию 20, максимум 50. Возвращает разрешённые даты и доступные записи, next_cursor, coverage_range, partial. История не обещает выходить за синхронизированные данные и сохранённые разрешённые контексты. Чужая/недоступная серия — 404 без раскрытия её существования.

Native route policy разрешает только новые точные same-origin UI-маршруты серии, если они вводятся для отдельной страницы; внешние URL не разрешаются глобально. Вариант панели внутри текущей страницы предпочтителен для первой реализации и сохраняет back/forward.

## Совместимость и приватность

- Серия не является новой областью доступа. Каждый результат и счётчик проходит прежние ограничения.
- Без надёжной identity legacy-запись остаётся отдельно.
- Hidden title/time одинаково соблюдаются в видимом тексте, aria-label, данных в HTML и истории.
- Native opener не удаляет query из HTTPS для подключения; никогда не использует общий sanitizer справочных ссылок.
- Unknown provider — только проверенный HTTPS/browser fallback; произвольные custom schemes запрещены.

## Ограничения истории и курсора

from/to — timezone-aware ISO8601; from < to, to-from <= 366 суток. По умолчанию от полуночи UTC 180 дней назад включительно до конца тридцатого будущего календарного дня (полночь UTC дня +31 исключительно). Такой стабильный диапазон включает все события обзора до now+30 суток; явный to остаётся исключительным. limit — целое 1..50, default 20. Некорректный диапазон, limit или cursor дают 422 с безопасным кодом без содержимого курсора. Cursor максимум 2048 ASCII-символов; подписан HMAC, включает версию, owner/workspace, series_key, from/to, последнюю пару (starts_at,event_id), срок действия 1 час. Подпись, срок и все привязки проверяются до выборки; подмена, другая серия/сессия/диапазон отклоняются. Сортировка starts_at ASC, event_id ASC. Cursor не включает названий, ссылок или записей.


## Восстановление подключения

Корректный явный HTTPS-порт 0..65535 сохраняется. Native-преобразование Zoom/Teams и обработчик Телемост применяются только без порта или на 443; остальные порты направляются браузеру. При отказе native-приложения автоматического второго запуска нет: отдельная кнопка «Открыть в браузере» заново разрешает UUID и проверяет сессию/документ до и после запроса. HTTPS открывается в конкретном системном браузере, не через повторный выбор universal-link приложения. Отмена диалога ничего не открывает.

Напоминание ожидает результат Join; только успешная передача закрывает его. Ошибка оставляет сообщение и «Повторить подключение»; двойное нажатие блокируется до результата. Поздний результат не применяется после смены сессии, закрытия или замены уведомления. Record/Stop и настройки автозаписи не меняются.

Временный отказ фонового обновления сохраняет failed Join той же сессии максимум 5 минут после явной попытки; auth/404, замена, закрытие, успешная новая проекция и истечение срока удаляют устаревшее действие. Фоновая ошибка не продлевает срок.


Обзор сохраняет в подписанном зашифрованном курсоре исходный timestamp anchor и его диапазон from/to. Последующие страницы восстанавливают тот же anchor для выбора представителя и SQL-окна, в том числе через полночь UTC; owner/workspace/session/series и TTL проверяются, текущие права/настройки применяются заново. Курсор истории по-прежнему требует точного совпадения всего переданного контекста.

Корректный запрос Join из текущего доверенного главного документа получает terminal cancelled при временной неготовности WebView; недоверенные и некорректные сообщения не получают ответа. Это снимает pending в изолированном скрипте и разрешает новый явный повтор. Нативное меню сообщает об ошибке и предлагает повтор с новым resolver, сохраняя защиту сессии и повторного нажатия во время диалога. Напоминание показывает «Открываем…» в тексте действия, сообщении и accessibility, в том числе при выборе из нескольких дат; Record не меняется.

История применяет ту же eligibility-политику, что обзор, к активным датам. Исключение для минимальных отменённых/удалённых у провайдера дат не расширяет доступ к календарю, приватным событиям или записям.

Браузерный кабинет разрешает UUID через join-target перед внешним переходом. Ошибка остаётся у исходного действия, пустая зарезервированная вкладка закрывается; успешный HTTPS-переход не имеет opener/Referer. Нативный обработчик перехватывает trusted click до браузерного. Проверка актуальности напоминания сохраняется через async resolver и явное восстановление в браузере.
