# F279 — модель данных

## Серия и её идентичность

Логическая `CalendarSeries` — проекция уже имеющихся событий. Внутренний состав ключа версии 2:

`(workspace_id, source_owner_user_id, calendar_source_id, external_calendar_id, provider_series_identity)`.

provider_series_identity = Google recurringEventId либо подтверждённый UID повторяющегося iCalendar. UID обычного разового события сам по себе не делает его серией. Публичный series_key непрозрачен, не содержит названий/почт/ссылок; каждый запрос независимо авторизуется. Хеш не является разрешением доступа.

Поля представления: series_key, is_recurring, доступный title/title_state, необязательная recurrence_label, selected_event_id, current_occurrence_count для доступных одновременных событий, loaded_range, partial, next_cursor. В счётчики входят только видимые данные.

Старый `recurring_series_key_sha256` содержит другую семантику. Для неизменяемых старых контекстов сохранить v1; добавить явную версию/новое поле v2 при реализации, если нужно долговременное индексированное чтение. Не перезаписывать доказательства старого сопоставления. Однозначное отображение v1→v2 возможно только через связанный snapshot/сохранённую identity; без неё новая история не склеивает записи автоматически.

## Повтор

Сохраняется существующий `CalendarEventSnapshot.id`. Фактические starts_at/ends_at изменяемы при синхронизации. Исходные provider instance identity, original_start, timezone/all-day нужны для устойчивой идентификации переноса. Для all-day нельзя превращать календарную дату в произвольную полночь UTC; для floating-time сохраняется его семантика.

Состояния: актуальный → изменённый/перенесённый → отменённый/удалённый. Отмена помечает только соответствующий экземпляр; завершённая серия не требует физического удаления сохранённых записей. Разделённая провайдером серия с новым ID имеет новую identity.

## Записи

Существующий `Meeting` и `RecordingCalendarContextLink`. Связь: серия 1→N повторов, повтор 0→N записей. Каждая запись открывается через прежний meeting URL и авторизацию; принадлежность серии не предоставляет прав. Нет автоматического слияния аудио, transcript, AI notes, sharing или владельцев.

## Попытка подключения

Короткоживущий native-state: request_id, event_id, session_generation, начальный trusted document, состояние idle/resolving/opening/handed_off/failed/cancelled. URL существует лишь на время разрешения/открытия, не сохраняется в state diagnostics, логах или HTML.

В один момент одна активная попытка для данного UI действия. Выход/смена аккаунта/уничтожение WebView отменяют ответ. `handed_off` означает только передачу системному обработчику; не является состоянием «пользователь участвует».

## Хранение и запросы

- Существующие snapshots, provider credentials, sync horizon и purge policy сохраняются.
- Owner/workspace/source/selection/privacy фильтры выполняются до группировки, LIMIT и подсчёта.
- Карточки и даты имеют раздельную пагинацию; стабильный tie-break — event ID / непрозрачный ключ после времени.
- Запрос истории не читает все записи пользователя, чтобы затем отфильтровать их в Python; ограничение серии и доступности входит в запрос.
- После отключения источника будущая проекция недоступна. История сохранённых записей подчиняется уже действующим правилам; новый постоянный кеш серии не создаётся.
- Индекс и миграция добавляются только после проверки SQL плана на синтетическом объёме и согласования версии старых связей.

Эфемерное поколение браузерной сессии: случайные32hex в host-only cookie `__Host-graf_session_epoch` (Secure,SameSite=Lax; Dev использует `graf_dev_session_epoch`). Marker доступен JavaScript только для отмены ожидающего Join, не содержит bearer/identity и не даёт полномочий. При выдаче auth-cookie TTL совпадает с ней, при её удалении новое поколение сохраняется60с; обычное продление не меняет marker. Изменений БД/миграций нет.
