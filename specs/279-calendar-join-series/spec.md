# Feature Specification: Календарь — подключение и повторяющиеся встречи

**Feature Branch**: `codex/279-calendar-join-series`

**Created**: 2026-09-28

**Status**: Реализация и локальная приёмка завершены; готовность PR подтверждается текущими exact-SHA checks, релизный кандидат проверяется отдельно

**Input**: Пользователь просит выделить новый номер фичи, исправить «Подключиться» (вместо ошибки должно открываться соответствующее приложение), изучить интерфейс и доступную реализацию Krisp и продумать отображение повторяющихся встреч.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Подключиться к нужной встрече (Priority: P1)

Пользователь нажимает «Подключиться» у события. GRAF открывает правильную встречу в соответствующем установленном приложении; для браузерных сервисов или отсутствующего приложения используется системный браузер. Страница GRAF сохраняется.

**Why this priority**: Сейчас основной путь из календаря заканчивается полноэкранной ошибкой.

**Independent Test**: В GRAF Dev открыть синтетическое событие, нажать кнопку, проверить адресата, отсутствие второй попытки открытия и сохранение списка/прокрутки/фокуса GRAF. Присоединение к чужому звонку для этого не требуется.

**Acceptance Scenarios**:

1. **Given** доступное актуальное событие с поддерживаемой ссылкой и установленным приложением, **When** пользователь нажимает «Подключиться», **Then** открывается нужная встреча в этом приложении, GRAF остаётся на прежнем экране.
2. **Given** приложение отсутствует или сервис работает в браузере, **When** пользователь нажимает кнопку, **Then** открывается исходная проверенная ссылка в системном браузере без передачи авторизации GRAF.
3. **Given** ссылку удалили, событие отменили или источник отключили после показа карточки, **When** пользователь нажимает кнопку, **Then** внешнее приложение не открывается; рядом с действием показано понятное объяснение и способ обновить данные.
4. **Given** запрос выполняется, **When** пользователь нажимает повторно, **Then** существует одна активная операция открытия; после ошибки можно явно повторить её.
5. **Given** открытие отклонено системой, **When** попытка завершилась, **Then** GRAF не утверждает, что пользователь подключён, и предлагает доступный запасной путь.

### User Story 2 — Видеть повторяющуюся встречу как серию (Priority: P1)

Пользователь различает разовую встречу и серию, видит ближайшую дату и может перейти ко всем доступным повторам этой серии. Основное предложение: одна карточка серии, а не несколько одинаковых строк подряд.

**Why this priority**: Сейчас признаки повторения сохраняются в данных, но не доходят до календарной карточки.

**Independent Test**: Синтетический календарь: серия из 12 повторов, две одноимённые независимые серии и разовая встреча. Проверить группировку, ближайшее событие, историю и отсутствие ложных объединений.

**Acceptance Scenarios**:

1. **Given** несколько повторов одной подтверждённой серии, **When** открыт обзор календаря, **Then** видна карточка с пометкой «Повторяющаяся» и ближайшим доступным повтором; его кнопка открывает именно его ссылку.
2. **Given** одинаковые названия или ссылка у разных серий, **When** открыт обзор, **Then** эти серии остаются раздельными.
3. **Given** открыт день с двумя повторами одной серии, **When** пользователь смотрит расписание или напоминания, **Then** обе даты/времени доступны независимо; группировка не скрывает вторую встречу.
4. **Given** правило повторения недоступно, **When** серия известна по календарным данным, **Then** показано «Повторяющаяся» без выдуманного «каждый понедельник».
5. **Given** ограниченный период синхронизации, **When** открыта история, **Then** интерфейс обозначает границы доступных данных и не представляет количество загруженных событий как полное число повторов.

### User Story 3 — Перейти к результатам конкретного повтора (Priority: P2)

Пользователь открывает серию, выбирает дату и видит только доступные ему записи и результаты этого события.

**Why this priority**: Связь с предыдущими встречами полезна для подготовки, но не должна смешивать записи и права доступа.

**Independent Test**: У трёх повторов есть соответственно две записи, одна запись и ни одной; одна другая запись недоступна пользователю. Проверить выбор даты, подписи и отсутствие утечки недоступного результата или его количества.

**Acceptance Scenarios**:

1. **Given** у повтора есть запись, **When** пользователь выбирает её, **Then** открывается существующая страница соответствующего разговора и его протокол.
2. **Given** доступной записи нет, **When** пользователь раскрывает повтор, **Then** показано «Нет доступной записи»; это не утверждение, что встреча не состоялась.
3. **Given** у одной даты несколько записей, **When** пользователь раскрывает повтор, **Then** каждая запись доступна отдельно; GRAF не выбирает произвольно одну и не сливает файлы.
4. **Given** права на запись отозваны, **When** пользователь возвращается к серии, **Then** запись, её заголовок и скрытый счётчик не выдаются без независимой проверки доступа.

### Edge Cases

- Один повтор перенесён на другой день; его исходная календарная идентичность сохраняется.
- Отменён один повтор, вся серия завершена либо организатор изменил «этот и последующие»; новая серия не склеивается по названию.
- Переименование одного повтора; изменение ссылки только у одной даты.
- Две серии с одинаковым UID в разных выбранных календарях; один источник содержит несколько календарей.
- Дубликат одного события в двух источниках; дедупликация события не доказывает идентичность всей серии.
- Переход на летнее время, смена часового пояса пользователя, событие на весь день и время без часового пояса.
- Нет полной схемы повторения, есть лишь один доступный экземпляр; повтор не превращается в разовую встречу.
- Устаревший снимок, частичная синхронизация, недоступный провайдер, отключённый источник, удаление записи, выход из аккаунта во время запроса.
- Ссылка на неизвестный сервис, отсутствующий обработчик macOS, вредоносная схема, локальный адрес, подмена домена, вложенный кадр, программный клик, перенаправление.
- Длинное название, клавиатура, VoiceOver, увеличенный масштаб, узкое окно, светлая и тёмная тема.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: «Подключиться» MUST быть отдельным пользовательским действием с проверкой актуального доступа к конкретному событию. Просмотр карточки, обновление и автоматический переход MUST NOT запускать приложение.
- **FR-002**: Для поддерживаемого установленного приложения MUST открываться корректная встреча; для браузерного сервиса/отсутствующего приложения — проверенная исходная ссылка в системном браузере. Отсутствие поддержки прямого открытия MUST быть явно указано в матрице совместимости.
- **FR-003**: Подключение MUST сохранять экран GRAF, выбранные фильтры, прокрутку и возвращаемый фокус. Ошибка MUST показываться около действия, не заменяя кабинет целиком.
- **FR-004**: Одна попытка MUST открывать не более одного внешнего адресата; повторный запуск возможен только после окончания операции и нового явного действия.
- **FR-005**: Авторизация GRAF, cookies, заголовки устройства и внутренние ссылки MUST NOT передаваться внешнему приложению/сайту. Полные ссылки встреч и коды входа MUST NOT попадать в журналы и материалы проверки.
- **FR-006**: Отменённое, удалённое, недоступное событие и отключённый/невыбранный источник MUST NOT давать действующее подключение; при изменении состояния после показа карточки нужна повторная проверка.
- **FR-007**: При ошибке сети или отсутствующем обработчике MUST быть различимые состояния «Открываем…», «Не удалось открыть», «Обновить»/«Повторить»; успех передачи адреса системе MUST NOT называться доказанным подключением к звонку.
- **FR-008**: Серия MUST определяться по устойчивой идентичности календаря с учётом владельца, рабочего пространства, источника и календаря; название, участники и ссылка не являются ключом объединения.
- **FR-009**: Для подтверждённой серии MUST отображаться признак повторения даже при одном доступном повторе. Частоту MUST показывать только при наличии достоверного правила.
- **FR-010**: Предлагаемый обзор MUST показывать одну карточку серии с текущим либо ближайшим неотменённым событием. Раскрытие MUST давать доступ ко всем разрешённым событиям в доступном диапазоне, с явной догрузкой.
- **FR-011**: Дневное расписание, выбор календарного контекста и напоминания MUST сохранять каждое событие. Несколько одновременных событий MUST оставаться видимым выбором пользователя.
- **FR-012**: Перенос MUST менять время отображения, сохраняя исходную идентичность повтора; отмена одного события MUST NOT отменять остальные.
- **FR-013**: Карточка MUST показывать границы доступного периода и частичную загрузку; число видимых дат MUST NOT называться числом всей серии.
- **FR-014**: Записи и протоколы MUST оставаться отдельными сущностями, связанными с конкретным повтором. Серия MUST NOT создавать новые права доступа или автоматически делиться результатами.
- **FR-015**: Старые записи без надёжной календарной связи MUST оставаться доступными отдельно. Автоматическое объединение по похожим названиям MUST NOT выполняться.
- **FR-016**: Скрытие названий/времени и календарные настройки приватности MUST действовать одинаково в карточке, истории, доступных названиях для VoiceOver и поисковой выдаче.
- **FR-017**: Отключение календаря MUST убирать будущие события и ссылки подключения; сохранённые записи подчиняются существующим правилам доступа, хранения и удаления GRAF.
- **FR-018**: Старые клиенты MUST продолжать получать понятные отдельные события. Существующие ссылки на записи и правила напоминаний MUST сохранять совместимость.
- **FR-019**: UI MUST поддерживать клавиатуру, VoiceOver, светлую/тёмную тему и узкое окно без потери кнопок и дат; значок повторения MUST иметь текстовый эквивалент.
- **FR-020**: «Подключиться» MUST NOT само запускать запись или обходить действующий выбор «Всегда / Спрашивать / Никогда». Ручные Start/Stop и видимый индикатор записи сохраняются.

### Key Entities *(include if feature involves data)*

- **Календарная серия**: устойчивое объединение событий одного владельца и календаря; подтверждённое правило повторения может отсутствовать.
- **Повтор (событие на дату)**: исходная идентичность, фактическое начало/окончание, часовой пояс, состояние, собственная ссылка и изменённые поля.
- **Запись разговора**: самостоятельное аудио/текст/протокол с отдельными правами; у повтора может быть 0..N доступных записей.
- **Попытка подключения**: явное действие пользователя, проверяемое событие, состояние получения ссылки и передачи её macOS; не доказательство участия в звонке.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Во всей утверждённой матрице приложений и браузерных сервисов 100% синтетических сценариев подключения открывают правильного адресата и не показывают полноэкранную ошибку GRAF.
- **SC-002**: Во всех сценариях двойного нажатия, ошибки, выхода из аккаунта и отмены события не происходит лишнего или неразрешённого открытия.
- **SC-003**: Серия из 12 синтетических повторов отображается одной карточкой в обзоре и всеми 12 событиями при раскрытии соответствующего периода; две независимые одноимённые серии не объединяются.
- **SC-004**: Сценарии переноса, отмены, изменения ссылки, летнего времени и смены часового пояса показывают ожидаемые даты/адресата без дублей и смешения протоколов.
- **SC-005**: Ни один сценарий отзыва доступа, приватного события и отключения источника не раскрывает запрещённое название, запись, количество записей или ссылку подключения.
- **SC-006**: Клавиатура и VoiceOver позволяют открыть серию, выбрать дату и вызвать подключение; после ошибки действие повторяется без перезагрузки всего кабинета.
- **SC-007**: На согласованной локальной тестовой среде индикация нажатия появляется не позднее 200 мс; выбор и открытие серии из уже загруженных данных укладывается в p95 500 мс. Внешняя сеть и запуск приложения измеряются отдельно.

## Assumptions

- Эта фича продолжает существующие календарные интеграции GRAF, не включает новые провайдеры и не меняет их разрешения.
- Референс Krisp используется для понимания взаимодействий. Поведение, недоступное в текущем аккаунте/версии, отмечается как неподтверждённое.
- Выполненный по прямому запросу пользователя статический просмотр поставляемого JavaScript не означает доступ к серверному коду Krisp. Код, ресурсы и частные протоколы не переносятся в GRAF.
- Вне объёма: редактирование календаря у провайдера, массовое удаление серии, слияние записей, автоматическая отправка протоколов, новые правила автозаписи, внедрение в production.
- Реализация требует завершения clarify → plan → checklist → tasks → analyze → taskstoissues → independent review → implement → converge. Этот документ и исследование не являются доказательством исправления установленного приложения.

### Детерминированный выбор даты серии

Текущая встреча: starts_at <= now < ends_at. Она приоритетнее будущей. Среди нескольких текущих выбирается последняя начавшаяся; при одинаковом начале — меньший UUID события. Если текущих нет, выбирается самая ранняя будущая, затем меньший UUID. Карточка явно показывает выбранную дату; «Подключиться» открывает только её, а «Все даты» позволяет выбрать любой другой доступный экземпляр. All-day без ссылки не получает кнопку подключения.

История запрашивается диапазоном не более 366 суток и страницами 20 записей (максимум 50); некорректные параметры отклоняются без раскрытия данных. Скрытие времени и названия распространяется на историю и служебные данные страницы.

## Legacy Impact

- Classification: `untouched`
- Сохранены отдельные календарные события, API для старых клиентов, неизменяемые ключи исторических контекстов и ссылки на записи. Новый ключ v2 используется только проекцией серии и не переписывает сохранённые связи.
- Удалённые системы захвата и маршрутизации звука не восстанавливаются; новые legacy aliases, зависимости и флаги совместимости не добавлены.
- HTTPS для браузерного сервиса или отсутствующего приложения — предусмотренный текущий путь подключения, а не восстановление legacy.
- `legacy_new=0`, `unowned_legacy=0`, `expired_exceptions=0`; исключение с owner/expiry не требуется.
