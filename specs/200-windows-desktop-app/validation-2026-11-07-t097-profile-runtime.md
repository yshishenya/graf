# T097 — сравнение опубликованного и исправленного меню «Вид»

На 2026-11-07 рабочий сервер по HTTPS отдал следующие публичные
ресурсы кабинета. Выполнены только GET без входа, сессии или cookies.
Ответы с параметром версии исправленных ресурсов и без него совпали.
Оба опубликованных файла побайтно совпадают с файлами в истории Git
на `d6243efb782d889e3b9b10da0b750c7a90f0707f`. Совпадение двух файлов
не устанавливает версию всего развёрнутого сервера.

| Ресурс | Опубликованный SHA-256 | Исправленный SHA-256 на рабочем дереве F200 |
| --- | --- | --- |
| `cabinet.js` | `0ae5cbcce998004589cfa30760bc1fe3ad8ca9484024e5c78038ee98c411e02f` | `9e458d3999da015e4be8268038fa54405a80d89b0f6fedae9dd815635361e6fb` |
| `cabinet.css` | `57b9d1328a7a7a392885c8bb8e272827c4650bf7053e3f2645e4e39433025916` | `67f696c45a029d3df3ff1bf0596ea93c743677706d9b2f6e42631f50b21f439d` |

В опубликованном CSS правило `max-height: 620px` назначает подменю
`position: static` независимо от места справа. Исправленные ресурсы
помещают боковое подменю поверх прокручиваемого меню; если свободного
места с обеих сторон нет, сохраняется раскрытие внутри меню.
Шаблон `cabinet/components/sections.html`, содержащий это меню,
побайтно одинаков в найденном историческом коммите и в рабочем дереве.

Оба набора по очереди подключены к одной синтетической странице встреч.
Chromium и WebKit: 24 измерения (две пары файлов × три размера × мышь и
клавиатура × два движка). В Windows x64/Parallels отдельно проверен
настоящий WebView2 156.0.4314.58: три размера на каждую пару файлов,
перехват браузерного ввода и Escape, локальная синтетическая страница,
другие сетевые адреса заблокированы. Результаты совпали:

| Видимая область страницы, CSS px | Опубликованные файлы | Исправленные файлы |
| --- | --- | --- |
| 1080×620 | Раскрытие вниз внутри меню | Справа, зазор 8 px, без перекрытия |
| 744×400 | Раскрытие вниз внутри меню | Справа, зазор 8 px, без перекрытия |
| 375×620 | Раскрытие вниз внутри меню | Раскрытие внутри меню: сбоку не помещается |

`aefc7d19cd2ed5eaf6241eeec64e208f6f272f00287e30fb4f422e14c4430176`.
Это предел наблюдения, а не доказательство отсутствия кнопки на экране.
Точный ответ, загруженный самим установленным приложением, здесь
не измерялся. Настройки и данные рабочего аккаунта не менялись,
снимки рабочего кабинета не делались. Временные профили стенда удалены,
пакет и процесс GRAF остались прежними.

Текущий удалённый `master`:
`2ca0465aa1721be293cd9b479d8f9d75b8854bfa`, предок F200

Следующая приёмка меню требует согласовать версию общего кабинета и

## Изолированная правка меню на точном master

На копии `2ca0465aa1721be293cd9b479d8f9d75b8854bfa` браузерный тест
сначала воспроизвёл раскрытие «Вид» вниз при 1080×620. Выделенный патч
затрагивает только позиционирование общего меню (JS и CSS) и два файла
проверок. В нём нет адаптации платформенных подписей, экспорта,
авторизации, локальных записей и нативной части. Независимое ревью
подтвердило границы и нашло два дополнительных дефекта исходного
варианта:

- При паузе мыши в зазоре между меню и панелью подменю закрывалось до
  выбора пункта. Теперь невидимая область подменю перекрывает только
  этот зазор и его края, без изменения видимых размеров панели.
- Без поддержки Popover проверка селектора выбрасывала исключение
  раньше, чем выполнялось раскрытие внутри меню. Закрытие, прокрутка
  и изменение размера теперь сначала проверяют наличие API подменю.

Оба отказа подтверждены отдельно. В браузерной регрессии есть проверка
точного элемента под курсором в середине зазора, паузы дольше таймера
закрытия, доступности варианта темы, раскрытия справа/слева и масштаба
200%. Дополнительный тест эмулирует отсутствие поддержки Popover
у подменю, проверяет появление варианта темы, прокрутку и возврат
клавиатуры по Escape. Родительский Popover в этом тесте остаётся
доступен; это не приёмка старого браузера целиком.

Итоговая проверка: Chromium и WebKit — по 44 сценария. Контрактные
проверки общего кабинета — 78, включая существующие браузерные
проверки удаления. На Windows x64/Parallels WebView2 156.0.4314.58
прошёл четыре раскладки: 1080×620 вправо, 744×400 вправо, 375×620
внутри меню и 1200×620 влево при меню у правого края. Для обоих
боковых направлений WebView2 подтвердил попадание мыши в зазор и
открытое подменю после паузы. После этого независимое ревью подтвердило
код; последняя правка добавила прямую проверку попадания мыши в
браузерный тест. Хеши JS/CSS и контрактного теста сохранились.

## Повтор на совмещённых изменениях F200

Синтетический кабинет запущен из рабочей копии F200 на
`3dfeaff5a6774ab12be781547e4a300f9ce2a46c` с незакоммиченными правками.
Сверены полные SHA-256 HTTP-ответов локального стенда и файлов:
`cabinet.js` — `dc967def35c6e67519d1433b767a01bc42d33c3b0b22d73629f3eb4b29a684fa`,
`cabinet.css` — `d2974567042dd2a0f949e4e619881c135d16d18a42b2917bda159dde6a99b3a3`.
Меню «Вид» прошло 44 сценария в Chromium и 44 в WebKit, включая
боковое раскрытие, клавиатуру, узкое окно и доступные имена.

В смежной проверке экспорта WebKit доставил событие обычного браузерного
скачивания уже после проверки успешного состояния формы. Позднее событие
`synthetic.txt` попало в счётчик следующего этапа, который должен начинаться
с пустым списком. Изменён только тест: он ждёт первое скачивание и сверяет
имя и содержимое, затем отдельно проверяет, что Windows начинает только
актуальный запрос после нативного подтверждения. После правки оба браузера
прошли отдельный экспорт, экспорт из общего доступа и ошибку создания
файла; Chromium дополнительно прошёл два прямых маршрута скачивания аудио.

В двух связанных файлах контрактов прошли 86 тестов, включая браузерную
проверку восстановления после удаления. Ещё два сценария поиска получателя
не стартовали: PostgreSQL 14 отклонил `NULLS NOT DISTINCT` при подготовке
базы; проектный запускатель использует PostgreSQL 17. Временный сервер
остановлен. Эти два сценария не засчитаны.
