## Вход и навигация в настоящем WebView2

На Windows 11 ARM64 в Parallels выполнены 7/7 сценариев
штатного тестового хоста Release x64. Перед и после прогона
совпали 238 входов снимка 0.1.0.37 и три библиотеки, извлечённые
из точного MSIX. Хост подключал настоящий WebView2, обращался
только к локальному серверу с искусственными сессиями и
создавал отдельный временный профиль на каждый сценарий.

1. Кабинет на HTML 200 и форма входа на HTTP 400: штатная
   загрузка и ожидаемое состояние ошибки.
2. После временной ошибки HTTP 503 повторный выбор маршрута
   возвращает пользователя в кабинет.
3. Недоверенный TLS: WebView2 отказал до первого HTTP-запроса.
   В остальных сценариях тестовый HTTPS допускался только в
   параметрах одноразовой среды WebView2; доверие Windows
   и параметры рабочего приложения не менялись.
4. Собственный кабинет → общая встреча → кабинет: нативные
   возможности доступны, отозваны, снова доступны; общий
   читатель не вызывает нативных действий.
5. Обновление истории, которое ведёт к форме входа: форма
   загружается без повторной отправки POST.
6. Смена тестового аккаунта A на B при задержанном
   перенаправлении: поздний переход отменён самим хостом,
   сервер не получил GET формы входа от старой навигации,
   а обновление сохранило сессию B.

Для всех семи случаев отдельно подтверждены коды 0 сервера
и тестового EXE, а также штатное завершение браузерного процесса.
Временные профили и ключ удалены. Рабочая 0.1.0.18 отвечала;
версия, EXE, PID и время запуска остались прежними.
