# F200/T097 — системный масштаб Windows: фактический режим главного окна

## Наблюдение на установленном GRAF

Windows 11 ARM64 в Parallels, приложение x64. Живое главное окно
установленного GRAF 0.1.0.18 отвечает. Независимый опрос Win32 дал:

| Что измерено | Результат |
| --- | --- |
| Режим окна по `GetWindowDpiAwarenessContext` | `DPI_AWARENESS_CONTEXT_UNAWARE` |
| `GetDpiForWindow` | 96 |
| Масштаб монитора в момент этого замера | 100% |
| Внешняя рамка с измерительного потока Per-Monitor V2 | 1080×620 физических пикселей |
| SHA-256 установленного EXE | `20a7544617b3008cc6706f94b769d0ad3e66b3e3ec146e30768b3a795bb1f17b` |

Установленный EXE и EXE из внутреннего [MSIX 0.1.0.25](validation-2026-11-07-package-025.md)
прочитаны утилитой Windows SDK `mt.exe` как ресурсы `RT_MANIFEST #1`.
Оба встроенных манифеста имеют SHA-256
`be8918559280a2e74748bf8f6238b568ed7cbf75183b2180a6a8a979a1ebf243`
и не объявляют ни `dpiAware`, ни `dpiAwareness`. Хеш EXE
кандидата совпал с квитанцией сборки. SHA-256 журнала Windows:
`ef6301d5e39a11c84cc7ef146528ce1ce23ae9514b5732a1e9dacdf752ba04b2`.

Windows возвращает 96 для окна без учёта DPI независимо от масштаба
монитора. Поэтому проверка размеров при 100% не подтверждает работу
при 200%, а замена масштаба страницы WebView2 не меняет режим нативного
окна. См. [GetDpiForWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdpiforwindow)
и [настройку DPI через манифест](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process).

Проверка только на чтение: настройки дисплея, установленный GRAF и
профиль не менялись. Исполняемый файл из MSIX извлечён для чтения
ресурса без запуска; временная копия удалена. Это подтверждение
причины, по которой старые замеры не доказывают системный масштаб,
и отдельный вход для проверки T097/SC-009.

## Проверка следующего MSIX

Внутренний [0.1.0.26](validation-2026-11-07-package-026.md) содержит
тот же встроенный Win32-манифест. Это проверено по ресурсу точного
EXE в подписанном MSIX; кандидат не запускался. SHA-256 журнала:
`2abc6653bd240ace3c1a1b098b8d9e9fb5c73d744eb477b8efe2804112321047`.

Независимый разбор выделил три места для проверки при смене режима:
расчёт размера и центрирование WinUI при первом открытии и возврате
из трея; размер, шрифт и попадание по элементам дочерней панели
экспорта при переносе на другой монитор; расположение уведомления
относительно кнопки «Стоп». Для сравнения нужны одна версия исходников
и два свежих процесса — с обычным манифестом и с `PerMonitorV2`.
После проверки отдельного Win32-манифеста нужны рабочие окна при
100% → 200% → 100%. Не менять формулы размеров по одной проверке
манифеста.

## A/B: манифест на нативном стенде экспорта

Оба x64 EXE собраны из одних и тех же входов с реальным
`ExportSavePanel.cpp` текущего дерева, MSVC `/W4 /WX`, и запущены
в отдельных процессах Windows. Различие — параметр компоновщика
`/MANIFESTINPUT` с `PerMonitorV2`. Первый запуск вернул
`PER_MONITOR_V2_OWNER=0 PANEL=0`, второй — `OWNER=1 PANEL=1`.
В обоих `GetDpiForWindow=96` на дисплее 100%. Прошли геометрия
320×240, управление папками с клавиатуры, возврат фокуса, повтор
после ошибки, уведомление UI Automation, отзыв и уничтожение окна.
Оба кода завершения — 0; гостевые временные каталоги удалены.

| --- | --- |
| Манифест входов | `5f698ee29f7faafa206b5df10128d91742d1c872233524a23034f4187af90478` |

## Манифест продукта в MSIX 0.1.0.27

Изменение подключено в MSBuild через `AdditionalManifestFiles` и
проверено по [точному EXE из 0.1.0.27](validation-2026-11-07-package-027.md).
Независимое ревью подтвердило, что новый Win32-манифест сохраняет
штатный путь объединения; отдельная проверка извлечённых ресурсов
подтвердила, что изменилось только объявление `PerMonitorV2`.
Формулы размеров и назначения шрифтов в этом пакете те же, что в
0.1.0.26. Режим живого окна 0.1.0.27 и системные 200% ещё не
наблюдались.

Повтор A/B с тем же частичным манифестом, что попал в пакет, измерял
масштаб монитора отдельно от `GetDpiForWindow`. Монитор в обоих
запусках показал 100%, окно — 96 DPI, высота шрифта заголовка — 13
пикселей. Проверки клавиатуры, фокуса, UI Automation и узкого окна
снова прошли в обоих режимах. Квитанции: манифест входов
`61b746695faca197ba0e2616b1dff7fccc4c0a9937ac31745c5981bd0d0eb846`,
контроль `c737350fce73339612af31fd71b9169685c5b1152a59424f4fc4b95a65be6517`,
PerMonitorV2 `7236340d064e4fa952447bb921147a638282d0fe6ad5cc451700f7b0e533b062`.

Разбор кода выявил отдельную границу: панель назначает
`DEFAULT_GUI_FONT` один раз, а при смене DPI перестраивает только
размеры элементов. Следующий прогон измеряет шрифт и размеры на
системных 200% и при возврате к 100%, чтобы проверить читаемость
до правки и после неё. Текущие замеры при 100% этот вопрос не закрывают.

## Шрифт панели экспорта при смене DPI

Панель получает системный шрифт сообщения для текущего DPI через
`SystemParametersInfoForDpi` и обновляет шрифт своих полей, подписей и
кнопок вместе с размерами. Предыдущий шрифт остаётся действительным
до окончания переназначения; новый остаётся действительным даже при
закрытии панели из синхронного обработчика `WM_SETFONT`. Вложенный
запрос раскладки откладывается до выхода из текущего прохода.

На Windows 11 ARM в Parallels, с тестовым EXE x64 и `PerMonitorV2`,
подача 192 DPI в расчёт старой панели оставила высоту `LOGFONT=-11`
при системной `-24` (ожидаемый отказ). Исправленная панель выдала
`-24` для заголовка, поля и кнопки, вернулась к шрифту 96 DPI,
сохранила фокус и освободила старые шрифты. Усиленная регрессия
до исправления владения шрифтом упала на `font-live-inside-nested-close`.
После исправления шрифт был доступен внутри закрывающего обработчика
и освобождён после его выхода, отложенная раскладка не публиковалась
внутри вызова, а закрытие вернуло один результат.

Отдельный прогон собрал неизменённый производственный исходник
(SHA-256 `b63e764931813ab53b7b159c280b818822613640c43412a69857129552e3319d`)
с MSVC `/W4 /WX`. Фактический масштаб монитора 100%, окно — 96 DPI,
`REAL_DPI_SYSTEM_FONT=PASS`. В обоих успешных прогонах прошли
клавиатура, повтор после конфликта и ошибки расположения, возврат
фокуса, уведомления UI Automation и закрытие узкой панели.
Гостевые временные каталоги удалены.
