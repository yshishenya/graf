# 2026-11-06 — T110: фокус нативной карточки Windows

На Windows 11 в Parallels собран и запущен оригинальный
`RecordingNoticePresenter.cpp` из
`d1340645da9cb9f401861cc42406b514e8e16fad` с вымышленной встречей.
Четыре файла реализации и заголовков сверены с Git, затем повторно
проверены по SHA-256 при копировании в Windows. На macOS исходный
`DesktopNotificationCardPresenter.swift` той же базы использует
неактивирующую панель; запуск или визуальное сравнение Mac в этот прогон
не входили.

| Проверка | Наблюдение в Windows |
| --- | --- |
| Появление фонового предложения записи | Настоящее видимое окно создано без активации. HWND активного окна другого процесса не изменился до показа и после обработки очереди сообщений. |
| Обновление, перестановка и закрытие | При обновлении остались прежние окно, поколение и фокус. Смена права на показ до активации оставила окно скрытым и уничтожила его. Повторный показ нового предложения также не менял фокус. |
| Доступные элементы | Порядок Tab: закрытие, запомнить выбор, пропустить, начать запись. При прокручиваемом тексте между закрытием и флажком доступно и поле чтения. Проверка активации мышью вернула `MA_NOACTIVATE`. |
| Явный перевод фокуса | В своём тестовом окне вызван тот же метод `focus()`, что используется оболочкой. Он активировал карточку и сфокусировал закрытие. Сообщения Tab, отправленные только собственным элементам теста, прошли по флажку и действиям. Escape закрыл карточку, не запустил запись и вернул фокус; исходное активное окно восстановлено. |
