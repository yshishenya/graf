# T101 — проверка скрытых библиотек AEC3

Рабочая база F200: `3dfeaff5a6774ab12be781547e4a300f9ce2a46c`
с локальными изменениями. Требование T101 прежнее: сборка приложения
и MSIX допускает только закреплённый и проверенный AEC3.

`ValidateGrafAEC3` разрешает явно указать
`libwebrtc-audio-processing-2.lib`. Проверка существования в MSBuild
видит скрытый файл, а прежняя опись PowerShell без `-Force` его
пропускает. В результате проверка подлинного `.a` могла пройти, хотя
свойство проекта выбирало другой, неучтённый файл. Исправление включает
скрытые файлы в ту же опись и сравнение хешей. У самой аудиообработки
изменений нет. Изменение сценария сборки требует пересобрать кэш:
предыдущая квитанция привязана к прежней версии этого сценария.

## Воспроизведение на Windows

В Windows 11 ARM64 / Parallels проверена настоящая цель MSBuild
`ValidateGrafAEC3` для x64 на временной копии 27 артефактов.
Хеши копий совпали с квитанцией подлинного кэша. Для проверки
нового перечисления только в стенде обновлён хеш сценария в
копии квитанции; это не подтверждение новой сборки.

| Случай | Результат |
| --- | --- |
| Обычная библиотека из описи | Принята до и после |
| Лишняя скрытая `.lib`, явно выбранная в MSBuild | Прежняя проверка пропустила; исправленная отклонила по описи |
| Скрытый `.a`, уже входящий в опись | Исправленная проверка приняла при совпадении байтов |
| Скрытый `.a` из описи с изменёнными байтами | Исправленная проверка отклонила по хешу |

Исходный кэш и его квитанция не менялись. Временные копии удалены.
В `validate-aec3-build.ps1` добавлен повторяемый отрицательный
контроль с реальным MSBuild и неучтённой скрытой библиотекой.

## Свежая сборка и полный набор проверок

В отдельном каталоге собран настоящий AEC3 Release x64 из закреплённого
коммита `846fe90a289f58b7c9303a635142aa2c7caa93e5`. Meson и MSVC
выполнили **440/440** шагов. Опись и хеши созданы исправленным
сценарием после сборки, без правки квитанции.

Следом `validate-aec3-build.ps1` прошёл **10/10** проверок и вернул 0:
подлинная библиотека допущена, скрытая неучтённая библиотека
отклонена с `AEC3 cache artifact inventory changed`. Гостевой
временный каталог удалён. Отдельная проверка подтвердила, что
у рабочего GRAF 0.1.0.18 не изменились PID и время запуска,
окно отвечает. Микрофон, рабочие записи и настройки не использовались.

## Полный путь сборки без AEC3

Проверены обычные цели `/restore /t:Rebuild` Release x64, а не прямой
вызов `ValidateGrafAEC3`. Из текущей рабочей копии F200 перенесён 231
исходный файл в отдельный временный каталог Windows. NuGet восстанавливал
зависимости из локального кэша в новый каталог; сетевой источник не
использовался. Обеим сборкам передан пустой каталог AEC3 и штатное имя
библиотеки, чтобы проверить именно отсутствие закреплённого модуля.

| Сборка | Код завершения | Причина | Новый EXE | Новый MSIX GRAF |
| --- | --- | --- | --- | --- |
| `GrafWindowsApp.vcxproj` | 1 | `GRAF requires the pinned AEC3 backend.` | 0 | 0 |
| `GrafWindows.Package.wapproj` | 1 | Та же ошибка в нативном проекте пакета | 0 | 0 |

Фильтр выходных файлов учитывал только `GrafWindowsApp.exe` и
`GrafWindows.Package*.msix`; MSIX зависимостей NuGet не являются
выходным пакетом GRAF. Временный каталог Windows удалён. Текущая
рабочая установка не обновлялась, аудиоустройства не использовались.

SHA-256 проверенных сборочных входов:
- приложение: `0508421ee1bf20f0ac66be7d41f60bba75ca7a36adf5a38f88bdcc362c88ba4b`;
- упаковка: `9ad98a78e026e546b7e21b2c9f9d083f7e6ee8f988181a4b091bf7eed813f486`;
- сценарий AEC3: `6cc8453f6083d90b90b54c065c3fa3f5182b00c11718105654616a52484da909`.

Дополнительно в актуальных исходниках нативных обёрток Mac и Windows
совпали 8 настроек AEC3, включая отключённые фильтр, подавление шума и
автоматическое усиление. Обе вызывают обработку опорного звука
(`ProcessReverseStream`) до микрофона (`ProcessStream`). Повторно
сверены сохранённые MSIX 0.1.0.32 и его EXE с
[квитанцией пакета](validation-2026-11-08-package-032.md): хеши
совпали. Установленная самопроверка этого EXE с кодом 73 относится к
предыдущему отдельному прогону. Совпадение конфигурации и самопроверка
не доказывают качество на устройствах; T101 и T071 остаются открытыми.
