# Боевой канал Windows: что нужно и в каком порядке — 2026-11-23

Документ описывает переход с тестового канала (самоподписанный `CN=GRAF`) на
публичную поставку по решению владельца от 2026-11-12: прямой подписанный MSIX
с сайта GRAF через системный App Installer. Пока не выполнены пункты раздела
«Блокеры», боевой пакет выпускать нельзя.

## Блокеры, которые нельзя обойти инженерно

1. **Сертификат подписи кода от удостоверяющего центра.** Нужен сертификат с
   EKU `1.3.6.1.5.5.7.3.3` (Code Signing). Самоподписанный сертификат для
   публичного канала не годится: Windows не доверяет ему без ручной установки.
2. **Утверждённый `Publisher`.** Должен совпадать с `Subject` выданного
   сертификата посимвольно. Из легального имени «ИП Шишеня Ян Александрович»
   его выводить нельзя: удостоверяющий центр может выдать другой Subject.
   Пока `Publisher` не зафиксирован, менять манифест и семейство пакета нельзя.
3. **Оплата сертификата.** Требуется международная оплата у удостоверяющего
   центра; это решение и платёж владельца, а не техническая задача.
4. **Адрес канала.** Нужен постоянный HTTPS-адрес без перенаправлений, который
   не будет меняться между версиями.

## Варианты сертификата

| Вариант | Что это | Плюсы | Ограничения |
| --- | --- | --- | --- |
| Certum Open Source Code Signing | сертификат для открытого проекта, облачная подпись Certum | самый дешёвый, подпись из CI через облако | нужна публичная лицензия проекта; проверяют, что подписывается именно открытый продукт |
| Certum / GlobalSign OV Code Signing | обычный коммерческий сертификат | подходит для закрытого продукта | дороже; выдача через токен или облако, срок проверки юридического лица |
| SSL.com OV + eSigner | облачная подпись с API | удобно для CI, без токена на руках | дороже, нужен аккаунт и оплата |
| Microsoft Store | публикация через магазин | подпись делает магазин, доверие по умолчанию | отдельный процесс, аккаунт, проверка; не подходит как «быстро» |
| Azure Trusted Signing | подпись Microsoft | удобна для CI | нужен Azure-аккаунт; из РФ оплата, как правило, недоступна |

Рекомендация: если проект остаётся открытым — Certum Open Source; если нужен
закрытый продукт — Certum или GlobalSign OV. Оба варианта дают обычную
доверенную цепочку и доверенную метку времени.

## Бесплатные и почти бесплатные пути

| Путь | Цена | Что даёт | Условия и ограничения |
| --- | --- | --- | --- |
| SignPath Foundation | 0 | сертификат уровня OV от Sectigo, ключ в их HSM, подпись в CI | проект должен быть открытым под лицензией OSI, публичным, активно поддерживаемым, без проприетарного кода; нужна заявка и ревью SignPath |
| Microsoft Store | 0 | подпись делает магазин, установка без предупреждений | индивидуальным разработчикам из РФ отказывают на проверке личности (сообщения Microsoft Q&A, 2026); считать недоступным, пока не подтверждено обратное |
| Certum Open Source в облаке | ~€25–58 в год | обычная доверенная цепочка, SimplySign в облаке | не бесплатно; лимит 5000 подписей в месяц; нужна международная оплата |
| Самоподписанный сертификат | 0 | ничего для публичного канала | требует ручной установки сертификата; это тестовый канал |

Для бесплатного пути SignPath нужна открытая лицензия у репозитория.
**Решение владельца 2026-11-24: AGPL-3.0**, файл `LICENSE` в корне. Лицензия
касается кода проекта; сторонние компоненты сохраняют свои лицензии и
перечислены в `ThirdPartyNotices` внутри пакета. Материалы для заявки —
`signpath-application-ru.md`.

Даже с сертификатом OV репутация SmartScreen у нового издателя набирается не
сразу; для MSIX установку в первую очередь определяет доверенная цепочка
подписи, но фактическое поведение проверяется на приёмке в чистой Windows.

## Что утверждает владелец до сборки

Фиксируется в задаче T138 и переносится в манифест и в `.appinstaller`:

- точный `Publisher` = `Subject` сертификата;
- постоянные `Name` пакета и ожидаемое семейство (`Name_PublisherId`);
- поддерживаемые ОС: Windows 10 22H2 (`10.0.19045.0`) и Windows 11, только x64;
- способ подписи: файл PFX или облачный сервис, и адрес службы метки времени;
- точные HTTPS-адреса: `.appinstaller`, пакета, каждой зависимости;
- версия CalVer и точный SHA исходников.

того, чего нет.

## Порядок выпуска

Публикация канала — часть обычного выпуска, а не отдельная операция. Издатель
попадает в манифест **до** заморозки кандидата: иначе замороженный SHA несёт
тестовый `CN=GRAF`, а сборка после заморозки уже не соответствует
утверждённым исходникам.

1. Утвердить пункты раздела «Что утверждает владелец» и получить сертификат
   (T138). Записать `Subject` и проверить его в `Cert:\CurrentUser\My` на
   Windows-хосте.
2. Внести утверждённый `Publisher` в
   `apps/windows/Installer/Package.appxmanifest`, закоммитить и смержить в
   `master`. Смена издателя меняет семейство пакета: для Windows это другая
   установка, старые данные не удаляются автоматически.
3. Заморозить релизный кандидат и получить разрешение: `prepare-release.sh`,
   `release-candidate.sh freeze`, один полный `release-full` на точном SHA,
   `release-candidate.sh decide` = `go`. Без `go` канал не публикуется.
4. Собрать MSIX из точного SHA замороженного кандидата тем же проектом
   упаковки, что и тестовый канал. Квитанция сборки привязывает SHA
   исходников, версию и хеши пакета к кандидату.
5. Подписать с меткой времени:
   `signtool sign /fd SHA256 /f <pfx> /p <пароль> /tr <служба> /td SHA256 <msix>`.
6. Проверить подпись: `Get-AuthenticodeSignature` = `Valid`,
   `signtool verify /pa /all /tw /v <msix>` = код 0 с цепочкой и меткой
   времени. Тестовая подпись `CN=GRAF` отклоняется.
7. Сформировать `.appinstaller` существующим инструментом
   `apps/windows/scripts/prepare-public-appinstaller.ps1` из `.psd1` с
   фактическими хешами; он не принимает `Publisher = CN=GRAF` и проверяет
   достижимость всех зависимостей.
8. Выложить пакет, зависимости и `.appinstaller` по утверждённым адресам,
   проверить `Content-Type` (`application/appinstaller`, `application/msix`)
   и отсутствие перенаправлений.
9. Приёмка на чистой Windows x64 обычной учётной записью: установка,
   первый запуск, вход, запись, перезапуск, обновление A → B, отказ при
   подмене источника, сохранность профиля, очереди и записей.
10. Только после этого включить кнопку в карточке Windows на `/download` и
    записать evidence в `validation-*.md`.

Если после приёмки меняется сам пакет, установочная и аппаратная приёмка
повторяются на новом пакете: сборка и проверка подписи их не заменяют.
Изменение манифеста после заморозки требует нового кандидата и нового
`release-full`.

## Чего делать нельзя

- Публиковать пакет с самоподписанным сертификатом как боевой.
- Выводить `Publisher` из легального имени, минуя выданный сертификат.
- Включать в публичный `.appinstaller` `OnLaunch`,
  `AutomaticBackgroundTask` и `ForceUpdateFromAnyVersion`.
- Менять семейство пакета без отдельной проверки переноса: для Windows это
  другая установка, старые данные не удаляются автоматически.
- Обещать на сайте Windows раньше, чем появится подписанный пакет по
  утверждённому адресу.
