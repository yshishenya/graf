# T097 — воспроизведение дефекта контраста нативной оболочки

База F200 `3dfeaff5a6774ab12be781547e4a300f9ce2a46c`. Точный
`AppMain.cpp` соответствует входу внутреннего MSIX 0.1.0.32.

В отдельном диагностическом x64 EXE на Windows 11 ARM64 / Parallels
с MSVC `/W4 /WX` запущены извлечённые без правок выбор системного
цвета, привязка акцентной кнопки и оба пути обновления из
`AppMain.cpp`. Входы — две разные искусственные контрастные палитры;
состояние переключателя и светлый/тёмный режим не меняются.

- **Один цвет текста и фона:** обе привязки акцентной кнопки читают
  `COLOR_HIGHLIGHT`. Совпадение получено в обеих палитрах. Общую
  кнопку используют «Начать запись», кнопки обновления и «Остановить
  запись» в индикаторе. [Документация Microsoft для Win32](https://learn.microsoft.com/windows/win32/w8cookbook/high-contrast-mode)
  указывает соответствующий цвет текста: `COLOR_HIGHLIGHTTEXT`.
- **Смена палитры:** ранняя ветка не выполняется при прежних двух
  признаках, но ниже `refreshNativeState` обновляет кисти обычным
  путём. Первичная проверка не учитывала этот вызов. Общий вывод об
  устаревшей палитре отозван; смена A → B остаётся регрессией приёмки.

В повторном прогоне тот же тест собран в двух вариантах. Текущий код
дал один цвет текста и фона, проверка с одной строкой
`GrafAccentForegroundBrush → COLOR_HIGHLIGHTTEXT` в копии дала
различимые цвета в обеих палитрах. Обычное обновление кистей и
контроль выключения контраста сработали в обоих вариантах.

Временный гостевой каталог удалён. Рабочие цвета, установленный GRAF
и код продукта не менялись. Проверка показывает назначение цветов и
сохранение обычного обновления, но не изображение окна: точный WinUI, Narrator
и системные 200% остаются отдельными условиями T097.

## Правка исходника

Независимая проверка требований: C0/H0/M0, чеклист 4/4.
Проверены связь FR-002/SC-009 → T097 → открытая задача #7240 и
отдельные границы проверки в WinUI и установленном MSIX.

В `AppMain.cpp` применена ровно одна строка, испытанная в сравнении
выше. После применения извлечённый блок выбора цвета совпадает с
блоком прошедшего Windows-теста. Новый SHA-256 исходника:
`591fe6320301397a765d05f8c2457dbb7843c4435f08834db90bda2547a9e9c3`.
Порядок обновления кистей и состояния записи, цвета без контраста,
общий кабинет и macOS не менялись. Локальный Spec Kit governance,
разбор F200.yaml и `git diff --check` прошли.

Пакет 0.1.0.32 был собран до правки. Для финальной проверки этого
исправления нужен новый MSIX и сценарий из Quickstart §5; успешный
тест выбора системной роли не закрывает T097.

Правка вошла во [внутренний MSIX 0.1.0.33](validation-2026-11-08-package-033.md).
Содержимое пакета проверено; визуальная приёмка установленной версии
остаётся открытой.
