# Публичная встреча: отмена устаревшей позиции до загрузки записи

Проект отдельного среза требований. Связь: F200 T121 / #7933,
F292 FR-018 и T022. Публичная страница находится вне адресного среза
CHK022; его отметки и условия остаются отдельными.

При открытии публичной встречи по ссылке с позицией проигрыватель
ждёт метаданные. Если до их получения человек переключается на «Итоги»
и затем возвращается на «Расшифровку» без позиции в адресе, ожидающая
команда больше не относится к текущей странице. Сегодня она всё ещё
передаётся через «Открыть в GRAF» и применяется при загрузке записи.
[Воспроизведение и пробная правка](validation-2026-11-06-t121-current-document.md#публичный-проигрыватель-устаревшая-позиция-после-переключения-вкладки).

## Границы и критерии приёмки

- Отменять только ещё не применённую команду из прежнего фрагмента.
  Переход к фрагменту без позиции не меняет уже достигнутое время
  проигрывателя и не запускает звук.
- Пока команда относится к текущему фрагменту, сохранять её до получения
  метаданных и передавать через «Открыть в GRAF» и продолжение входа
  по действующим правилам версии записи. Явная позиция 0 допустима.
  Новый явный таймкод вытесняет предыдущий.
- В момент применения или передачи позиции действует текущий допустимый
  фрагмент, даже если `hashchange` ещё не обработан. Переход A → `#outcomes`
  передаёт вкладку итогов без позиции; A → `#recording` передаёт фактическое
  время, включая `position_ms=0` при допустимой версии; A → B передаёт
  свежую явную позицию B, включая 0. Позднее событие не перематывает
  повторно к уже применённому B. «Назад» и «Вперёд» к записи истории с
  явным таймкодом создают новую команду.
- Эти ожидания одинаковы для «Открыть в GRAF», «Войти» и «Начать
  пользоваться GRAF». Назначение и действие входа/регистрации сохраняются.
  После переключения вкладки с уже загруженной записью ссылки передают
  её ненулевое фактическое время. При сменившейся версии позиция
  не передаётся. Проверить метаданные до и после обработки `hashchange`.
- Проверять в Chromium и WebKit на штатном HTML публичной встречи,
  искусственном WAV и управляемой задержке ответа. Зафиксировать адрес
  каждой ссылки и фактическое время после загрузки. Браузерная проверка
  не заменяет запуск точного установленного MSIX по ссылке.
  Для раннего порядка поставить перехватывающий обработчик настоящего
  `loadedmetadata`, поменять фрагмент до обработчика проигрывателя и
  проверить, что счётчик `hashchange` ещё равен 0, `isTrusted=true`,
  метаданные доступны. Для позднего порядка изменить фрагмент, дождаться
  `hashchange` и только тогда вернуть WAV. В обоих случаях после события
  проверять число присваиваний позиции, фактическое время и отсутствие
  автовоспроизведения. Ссылки проверять до `hashchange` и после него.
- Не менять протоколы, права публичного просмотра, серверную сессию,
  адресный проигрыватель и правила версий. Рабочий сервер не участвует.

Кандидат реализации — локальная отмена ожидания в общем публичном
проигрывателе. Одного сброса в обработчике смены фрагмента недостаточно
для доказательства порядка событий: при применении позиции и построении
ссылок нужно сверять ожидание с текущим адресом. Перед изменением общего
кода — отдельная проверка требований и Spec Kit analyze. Этот проект
не добавляет отметок о выполнении и не открывает выпуск.
