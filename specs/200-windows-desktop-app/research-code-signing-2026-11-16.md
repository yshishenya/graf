# Windows Code Signing для ИП Шишеня Ян Александрович, РФ

Проверено 16 ноября 2026 года по открытым официальным страницам; ключевые ценовые данные GlobalSign прочитаны прямым публичным GET в 09:58 UTC. Область: исследование, без покупок, аккаунтов, запросов поставщикам, ВМ, Git и продуктовых изменений. Издатель для сравнения — именно **ИП Шишеня Ян Александрович, зарегистрированный в РФ**. Регистрационные документы и фактическое право заявителя на выдачу не проверялись.

**Практический вывод:** из четырёх рассмотренных решений первым кандидатом для дальнейшего уточнения является **GlobalSign Standard/OV Code Signing на токене**: его официальная российская страница прямо допускает ИП. Выдача этому конкретному ИП не гарантирована. У DigiCert и Sectigo обнаружены прямые ограничения для РФ, у Microsoft Artifact Signing Public Trust — географическое исключение РФ. Поэтому это четыре реальные технологии доверенной подписи Windows, **не четыре доступных предложения для российского ИП**. Основания и пределы приведены ниже.

## Что именно проверено в ценах

В `gsp.load(...)` найдены поля `cs_one_yr` и `ev_cs_one_yr`, их значения для `RUB - Russian Ruble` — **25 620** и **30 988**; эти ключи связаны с видимыми годовыми карточками через `data-gs-pricing`. SHA-256 полученного HTML: `d8145181153e6983a9412c5fc018270256b71cb0954011c98bcd832a6dbd930f`. HTML целиком не сохранялся; метод и извлечённые суммы записаны здесь. [Проверенная страница](https://shop.globalsign.com/ru-ru/code-signing)

В том же общем словаре есть старые двух-/трёхлетние поля и отдельные HSM-поля; их наличие не доказывает актуальный продаваемый тариф. Они **не использованы** для оценки. Точная итоговая HSM-цена не установлена. Публичная GlobalSign EN-страница сообщает о текущих однолетних сертификатах366дней, а не о едином сертификате на несколько лет. ## Подпись документов, токен и публичное доверие Windows

Для EXE/MSI/DLL требуется сертификат назначения **Code Signing** и соответствующая цепочка доверия Windows. EKU Code Signing — `1.3.6.1.5.5.7.3.3`. Наличие «электронной подписи ИП» для налоговой/документов, сертификата AATL для PDF, SSL-сертификата или USB-токена само по себе не означает пригодность для Windows Authenticode. Сертификаты имеют разные разрешённые назначения; один носитель не превращает сертификат документов в code signing. [GlobalSign о KU/EKU](https://support.globalsign.com/code-signing/general-information/code-signing-faq), [Microsoft о Code Signing EKU](https://learn.microsoft.com/en-us/azure/artifact-signing/concept-certificate-management)

Для traditional code signing нужен одобренный поставщиком защищённый ключ на токене/HSM с требуемой аттестацией. Обычный экспортируемый PFX на диске не следует считать допустимой современной заменой. Точные модели и текущие требования нужно согласовать с УЦ; старые страницы2023года не доказывают соответствие произвольного устройства новым требованиям. [DigiCert о хранении ключей](https://knowledge.digicert.com/general-information/new-private-key-storage-requirement-for-standard-code-signing-certificates-november-2022), [текущая процедура выдачи](https://docs.digicert.com/en/certcentral/order-and-manage-certificates/request-certificates/request-a-code-signing-or-ev-code-signing-certificate/request-code-signing-certificate.html)

Публичное доверие здесь означает возможность стандартной Windows проверки подписи без установки собственного корня пользователю. Для Artifact Signing механизм — Windows Platform Trust List; это не тождественно присутствию CA в общем Trusted Root Program/CCADB. Самоподписанный сертификат, Private Trust или вручную добавленный корень не предлагаются как общедоступная доверенная подпись. [Microsoft certificate management](https://learn.microsoft.com/en-us/azure/artifact-signing/concept-certificate-management)

## SmartScreen: подпись не гарантирует отсутствие предупреждений

SmartScreen отдельно оценивает репутацию издателя и конкретного файла. Даже корректная OV/EV-подпись нового приложения может сопровождаться предупреждением. **EV больше не даёт автоматического обхода SmartScreen**; Microsoft прямо не рекомендует переплачивать за EV только ради этого. Не установлены гарантированные сроки/число установок для получения репутации. Самоподписанный сертификат в этой оценке не решает проблему публичного доверия. [Официальное объяснение Microsoft](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)

Практическая последовательность для будущего подписанного выпуска — сохранять проверенную идентичность издателя, подписывать финальные неизменяемые файлы и использовать доверенную метку времени. Метка времени не является гарантией против отзыва сертификата, вредоносного кода или решения SmartScreen. Microsoft отдельно различает Store MSIX с переподписью Store и MSI/EXE, которые должен подписать сам издатель; здесь канал распространения не меняется и Store не предлагается как обход российского ограничения. [Windows signing options](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options), [timestamp management](https://learn.microsoft.com/en-us/azure/artifact-signing/concept-certificate-management)

## Рекомендация и непроверенные условия

**Моя рекомендация:** рассматривать GlobalSign Standard/OV на поставляемом токене как основной предмет следующего уточнения для этого ИП; облачный/HSM вариант имеет смысл лишь при подтверждённой доступности и поддерживаемом оборудовании. EV рассматривать только при отдельном требовании к расширенной проверке/сценарию использования, не ради обещания SmartScreen. В рамках этого исследования никаких обращений поставщику не выполнялось.

Перед решением об оплате остаются конкретные вопросы, на которые публичная страница не даёт индивидуального ответа:

1. Принимается ли сейчас новый Code Signing заказ именно от **ИП Шишеня Ян Александрович, РФ**, какие регистрационные/адресные документы, проверка личности/полномочий и контактов потребуются; как точно будет записан publisher/Subject, включая согласованную транслитерацию при необходимости. «GRAF» — имя продукта, не основание подменить юридического издателя.
2. Какой именно токен/сертифицированный режим и процесс генерации ключа предоставляются, где возможна доставка, входит ли она в стоимость, каковы итоговые НДС/цена/продление и условия возврата при отказе в проверке. Совместимость уже имеющегося токена **не подтверждена**.
3. Каковы текущие сроки и санкционные/экспортные/логистические ограничения именно этой заявки. Упоминание российского офиса и допуска ИП — основание рассматривать вариант, **не гарантия выдачи/оплаты/доставки**.

Не предлагаются посредник для сокрытия владельца, чужой сертификат, вымышленное юрлицо, страна/адрес или обход географической проверки. Гражданство, место проживания и страна регистрации бизнеса — разные сведения; каждое должно отражаться правдиво. Выбор зарубежного cloud endpoint или другого региона Azure не заменяет проверку заявителя. Никаких новых продуктовых задач, изменений требований, канона или выпуска этот отчёт не создаёт.
