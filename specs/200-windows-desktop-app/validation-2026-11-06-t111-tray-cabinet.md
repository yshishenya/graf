# T111: меню Windows и возврат из настроек к встречам — 2026-11-06

Активный срез F200 на базе `d1340645da9cb9f401861cc42406b514e8e16fad`.
Mac открывает раздел `account` в главном окне. Windows уже передаёт в то же
пользовательское действие маршрут `/desktop/settings/account` от доверенного
адреса текущего кабинета. Обратная кнопка «Встречи» в оболочке Windows брала
отдельно прописанный адрес. При другом доверенном адресе тестового кабинета
политика WebView2 считала этот адрес внешним и не открывала список внутри окна.

Исправление: `CabinetWindow::openCabinet()` получает адрес из той же политики
и открывает фиксированный путь `/desktop/meetings`. Рабочий адрес по умолчанию
и правила доступа не менялись. Тестовый генератор задаёт только адрес в
конструкторе копии; `CabinetWindow.cpp` больше не переписывается. Генератор
также исключает файлы, которые Git уже видит удалёнными из рабочего дерева:
старый `AppInstaller.xml` вызывал `ENOENT` до сборки стенда. Проверка
обычных файлов сохранена.

- С исходным `openCabinet()` новый переносимый тест упал на переходе к
  встречам с локальным адресом. После исправления проверены точные пути
  по умолчанию и на loopback HTTPS, путь возврата и запрет внутреннего
  перехода на другой адрес. Три выбранных теста прошли на Mac и Windows.
- Стенды настроек и закрытия оболочки сгенерированы из тех же 224 файлов,
  что и Windows-тесты. Удалённый файл не попал в манифесты, маршрут
  `CabinetWindow.cpp` совпал с рабочим деревом, контрольные хеши 11 и 17
  соответственно неизменённых обработчиков записаны.
- В Windows 11 / Parallels (x64 под эмуляцией ARM64) прошли 14 циклов
  настоящего меню Windows. Новые проверки прочитали названия и доступность
  команд, выбрали «Начать запись» и «Настройки» клавиатурой в собственном
  меню теста и проверили по одному вызову при скрытом окне-владельце.
  «Начать запись» повторно проверяется при доставке: если готовность снята
  после выбора, вызовов 0. При завершении обе команды недоступны.
  Обработчики тестовые: звуковые устройства и профиль GRAF не использовались.
- SHA-256 манифеста входов:
  `e489add76fe65d7c3c8174f44c6083093cbe59aff95adbd0fad4f6362b9fbee4`;
  результата Windows:
  `58e6ba8ca14edf7399332a60fcc365afbe7279c1c67310f2fdf968fc93069f1f`.
  Настройка сборки, сборка, тесты: 0/0/0; временная папка VM удалена.

Эти прогоны проверяют маршрут и доставку команд отдельно. T111/T097 остаются
открытыми: на точном установленном MSIX из скрытого главного окна нужно
открыть настройки через значок, вернуться к встречам и проверить фактическую
запись и её единственность в условиях приёмки. Установленная 0.1.0.18 в
этом прогоне не обновлялась.

## Связанный прогон T108/T111 на одном окне WinUI

Рабочая ветка: `972af4762e7afc1a5a1c8d9025aec1eb6ce7127e` и
зафиксированный манифест 225 файлов рабочего дерева. На момент проверки
удалённый `master` `2ca0465aa1721be293cd9b479d8f9d75b8854bfa`
уже входил в историю ветки. Установленный на Mac GRAF Dev содержит
`GRAFSourceSHA=bd088c8fdea6007a12df3eee13da62b20e3c5828`: его
команда «Настройки» показывает главное окно и открывает раздел `account`.

В Windows 11 ARM64 собран отдельный Release x64 EXE. Регистрация
значка, обработчики закрытия, создания меню, настроек, кнопки «Встречи»
и выхода взяты из текущего кода. Стенд отделил запуск WebView2, записи и
хранилища от оболочки. Он воспроизвёл системное сообщение для собственного
значка, затем выбрал пункт клавишами в настоящем меню Windows; команду
для выбора пункта сам не создавал. Обработанный сценарий:

1. `WM_CLOSE` скрыл главное окно, приложение осталось запущено.
2. «Настройки» в меню значка показали тот же HWND и передали
   доверенный маршрут `/desktop/settings/account` контроллеру кабинета.
3. Настоящая кнопка WinUI «Встречи» через провайдер Invoke передала
   `/desktop/meetings`. Повторный крестик снова скрыл окно.
4. «Закрыть GRAF» в том же меню штатно завершило экземпляр и освободило
   объект значка. «Начать запись» в обоих меню была недоступна.

Два ранних запуска стенда не зачтены: первый закончился ошибкой WinUI до
команды, второй — ошибкой пользовательского оконного обратного вызова
после первого крестика. В успешном варианте исправлен обход кнопок
WinUI и запрещён повторный вход таймера стенда в цикл меню. Это изменения
только стенда. Успешный EXE прошёл пять фаз и вернул предусмотренный код
76; запускатель завершился с кодом 0, PID и EXE рабочего 0.1.0.18 совпали
до и после.

записи и продолжение записи после крестика требуют отдельных проверок.
T108, T111 и T097 остаются открыты.

## 2026-11-07 — настоящий значок установленного GRAF в Parallels

установленного EXE:
`20a7544617b3008cc6706f94b769d0ad3e66b3e3ec146e30768b3a795bb1f17b`.
Это наблюдение о 0.1.0.18; сборка из текущего рабочего дерева этим
прогоном не проверена.

Из области уведомлений Explorer через UI Automation открыто контекстное
меню единственного видимого значка GRAF. Проверены принадлежность
нативного окна меню тому же процессу и все восемь доступных для чтения

## 2026-11-07 — отрисованный кабинет установленной 0.1.0.18

Для того же PID, времени запуска и SHA-256 EXE проверены два разных
источника по текущему главному HWND процесса. В сыром дереве WinUI найдены по одной видимой и включённой
кнопке «Встречи» и «Настройки». Обход не усечён (34 элемента). Прямой
запрос `AccessibleObjectFromWindow(OBJID_CLIENT)` к видимому дочернему
окну Chromium вернул объект MSAA, но без потомков и роли документа.
Это не проверка экранного диктора. WinUI подключает дерево WebView2
к дереву XAML через отдельный межпроцессный интерфейс
([описание Microsoft](https://github.com/microsoft/microsoft-ui-xaml/blob/main/docs/design-notes/Uia.md#webview2)).

Отдельная проверка точного HWND получила отрисовку клиентской области
3192×1743. Пиксели переданы локальному распознаванию через память и
канал между процессами, без файлов изображений. В журнал выведены
только счётчик и флаги заранее заданных заголовков. Первый проход
на полном кадре был неубедительным; повтор с перекрывающимися
областями независимо подтвердил «Аккаунт», «Профиль»,
«Оформление и время», «Язык интерфейса» и «Часовой пояс».
Так подтверждена фактическая отрисовка страницы настроек в том
окне 0.1.0.18, где перед этим был выбран пункт значка «Настройки».
Область захвата экрана целиком не использовалась: попытка получить
снимок экрана остановилась на проверке активного окна до чтения пикселей.
