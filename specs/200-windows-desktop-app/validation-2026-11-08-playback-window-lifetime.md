# F200 — окно локального проигрывателя при закрытии во время активации

Действующий срез высокого риска, база F200
`3dfeaff5a6774ab12be781547e4a300f9ce2a46c`. Сценарий уже входит в
приёмку окна T097 (#7240) и защищённого воспроизведения T118 (#7446):
FR-002/005/006, SC-002/006/009. Нового пользовательского выбора нет.
554 пункта чеклистов требований отмечены, 0 открыто. Ни один критерий
приёмки пакета по этому счётчику не закрывается.

Нативный стенд MSVC x64 на Windows 11 ARM64 / Parallels использовал
настоящий WinUI, оконные дескрипторы, DPI и изменение размера.
Обе версии блока активации взяты из AppMain. Вызов оформления заменён
регистрацией окна-получателя. Закрытие и появление окна B синхронно
вызваны обработчиком Activated. Это управляемая проверка порядка событий,
без открытия аудио, доступа к записям или запуска установленного плеера.

| Сценарий | Прежний блок | Исправленный блок |
| --- | --- | --- |
| Обычное открытие, затем Close | Оформление и размер окна A, код 0 | То же, код 0 |
| Close внутри Activate | Closed, затем `0xC0000005` | Код 0, оформление и изменение размера не вызваны |
| Close и окно B внутри Activate | Старый вызов оформил и изменил размер B, отрицательный результат | Код 0, B не затронуто |

Единственный вызов `showLocalPlayback` следует за закрытием предыдущего
окна и допуском следующего запроса. Удалена ветка повторной активации
уже существующего окна. Попытка получает поколение до создания окна;
локальная ссылка удерживает A до возврата из Activate. После возврата
оформление и размер допустимы только для того же окна и поколения.

Независимый просмотр выявил ещё один разрыв: обработчик ошибки прежней
попытки мог отменить B, а продолжение могло разрешить воспроизведение
после отзыва исходного документа. Очистка при ошибке теперь относится
только к текущему поколению. После открытия управление возвращается
периодической проверке: она заново проверяет исходный документ перед
допуском воспроизведения. Проверка начала прежнего и нового
`pollLocalPlayback` с подставными событиями: 6/6 проверок. Прежний путь
допустил отозванный документ и отменил преемника; новый сохранил B,
не допустил отозванный документ и сохранил обычное открытие и очистку
при ошибке актуальной попытки. Тест не заменяет реальный MediaEngine.
Отдельный штатный путь reentry при прямом Close не подтверждён и не менялся.

Полный итоговый AppMain прошёл MSVC x64 `/Zs /WX` (232 входа, код 0).
Предупреждение D9025 сообщает о двух флагах уровня из команды проекта;
последний `/W4` применён. Копии сборки удалены. Рабочая версия 0.1.0.18
сохранила EXE, PID и время запуска в ходе нативного стенда. Защищённое
хранилище и MediaEngine не изменялись.
