# F200 / T116: диагностика загрузки зависимостей Windows CI

Дата: 17.11.2026. Срез существующей F200/T116, high-risk-product.
Результат относится только к безопасной диагностике подготовки FFmpeg;
T116/T118, установленное приложение и выпуск остаются открытыми.

## Причина изменения

Windows x64 diagnostic tests в PR #8130 дважды остановились при
Invoke-WebRequest до компиляции приложения. Первый журнал содержал ошибку
соединения, второй — HTML страницы Verification Required. Прежняя процедура
не указывала имя зависимости до запроса; конкретный URL определить нельзя.
Повторять неизменённый запуск без новой информации не следует.

Изменена только Download() в `apps/windows/scripts/build-graf-ffmpeg.ps1`:
перед единственным запросом выводятся имя зависимости и публичная часть
исходного адреса без userinfo/query/fragment. При отказе выводятся только
ограниченная цепочка типов исключений, HResult и числовые сетевые коды.
Исходные сообщения, ErrorDetails, тело HTTP и перенаправленный адрес
не печатаются и не перевыбрасываются. Ошибка по-прежнему завершает сборку.

Версии, источники, размер, SHA-256, один запрос, timeout 120 секунд и проверка
скачанных байтов сохранены. Сообщение verified появляется после проверки
размера и SHA-256. Изменение не обходит защиту источника и не исправляет
недоступность внешней сети само по себе.

## Проверки

В QA Windows PowerShell 5 проверен разбор точного исходника — 0 ошибок.
Из AST извлечена только Download(); код сборки не исполнялся.
`FFmpegDependencyDownloadTests.ps1` заменяет Invoke-WebRequest собственной
синтетической функцией и проверяет шесть случаев:

1. Успех: ровно один путь в потоке результата, verified после bytes/SHA.
2. HTTP-ошибка с искусственными HTML и скрытыми маркерами: фиксированный
   отказ и безопасный статус, без тела и скрытых полей в выводе.
3. Вложенная socket-ошибка: числовой код, без произвольного сообщения.
4. Цепочка исключений глубже четырёх: вывод ограничен четырьмя уровнями.
5. Неверный размер: прежний pin mismatch, нет verified или пути результата.
6. Неверный SHA-256: тот же безопасный отказ.

**6/6 PASS**, по одному вызову mock в каждом случае, 0 реальных сетевых
запросов. Собственный временный файл и каталог удалены. Тест выполнен также
из точного текста нового файла в `Tests/GrafWindowsPackageTests/`.
Это проверяет функцию в PowerShell 5; реальный HTTP-код ответа внешнего
источника ещё неизвестен.

Локальные доказательства:
`.dev/ci-ffmpeg-committed-selfcheck-r1.stdout`,
`.dev/ci-ffmpeg-committed-selfcheck-r1-result.json`,
`.dev/ci-ffmpeg-observability-20261117.md`.
Независимое ревью и новый exact-SHA GitHub CI фиксируются отдельно;
прежние неудачные запуски не переименовываются в успешные.

## Установленная причина и замена адреса

Новый Windows CI на `fcc5b5d6b035ecf851b58c792144e41598af2beb`, run
44095686587, подтвердил скачивание и bytes/SHA трёх первых зависимостей:
FFmpeg, MSYS2 base и make. Четвёртая, diffutils, получила ProtocolError /
HTTP 403 от `mirror.msys2.org`. Отказ произошёл до компиляции GRAF;
произвольное тело ответа новая диагностика не вывела.

Для diffutils выбран уже используемый этим же manifest адрес зеркала
`mirror.selfnet.de/msys2/`. Получение пакета с Mac вернуло HTTP 200,
394 515 байт и прежний SHA-256
`7902c8ce3d4dd69a0f5e98dc9d5c83c17b23314ba486169db57ef6e2835ce3b6`.
Изменено только поле URL: версия, размер, hash, остальные входы и процедура
проверки сохранены. Контрольный запрос к repo.msys2.org завершился Timeout;
его доступность не заявляется.

Материалы: `.dev/windows-pr-fcc5-first-failed.log` и
`.dev/diffutils-source-probes-20261117.json`. Получение точных байтов с Mac
не доказывает доступность из GitHub Windows: нужен новый CI окончательного
коммита. Изменение не решает CAPTCHA и не меняет клиент для обхода защиты
сервера; используется обычное скачивание с другого существующего зеркала.
