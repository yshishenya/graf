# T112: источник обновлений Windows — 2026-11-06

Активный срез F200. Удалён старый `apps/windows/Installer/AppInstaller.xml`:
файл не входил в проект пакета, и исходники, сборка и публикация на него не
ссылались. В нём были неподтверждённые адреса и проверка при запуске
(`OnLaunch`); он не годился как заготовка для выпуска с явным действием
пользователя. В собранном 0.1.0.19 этого файла уже не было. Механизм обновления,
проект MSIX и подпись не менялись.

## Проверка

- В Windows 11 в Parallels открыт и отвечает установленный GRAF **0.1.0.18**.
  SHA-256 установленного EXE:
  `20a7544617b3008cc6706f94b769d0ad3e66b3e3ec146e30768b3a795bb1f17b`.
  Системный `PackageManager.FindPackageForUser` вернул тот же полный identity,
  что `Get-AppxPackage`. `GetAppInstallerInfo()` вернул null: источника у этой
  установки нет. Запрос доступности обновления и установка не выполнялись.
- Из точных исходников контроллера и теста
  `d1340645da9cb9f401861cc42406b514e8e16fad` собран отдельный тест x64 Release
  в той же VM. Оба прогона успешны: контролируемые ответы/повтор/закрытие,
  запреты установки и нативный отказ `noPackage` при запуске теста без MSIX.
  Это проверка контроллера; тест без пакета и наблюдение регистрации пакета —
  два разных случая. Временный каталог сборки удалён.
- SHA-256 списка входов теста
  `39c3b514809007e4039c38cacc438f5bb063b1d5435db013fd8803fd23bd5fa0`,
  результат с кодами завершения и очисткой
  `d506a9e0a30f1364a0e0109fa828036b839f5a71042500d5f4d2482dceb2e8ae`.

## Граница приёмки

Ожидаемое сообщение в открытом из трея окне: для установки не настроен
источник обновлений. Факт отсутствия источника подтверждён системным API;
ручное открытие окна этим не подтверждено. T112 остаётся открытой: требуются
проверка окна установленного MSIX и сквозная проверка на одобренном подписанном
канале с зарегистрированной привязкой, доступной новой версией, явной
установкой после завершения записи и сохранением данных. Доступ к записям,
изменение сертификатов и публикация канала для этой проверки не потребовались.

## Повторная сверка пути установки

На базовом исходнике F200 `972af4762e7afc1a5a1c8d9025aec1eb6ce7127e`
и текущем срезе `AppMain.cpp` создаёт `WindowsAppUpdateController`
без `AppUpdateApprovedRelease`. Даже ответ Windows об обновлении
не открывает кнопку установки: `canInstall()` дополнительно требует
явного одобрения выпуска. Обнаружение обновления, системная привязка
и разрешение устанавливать являются разными проверками. Установленный
0.1.0.18 без привязки и проверка подписанного 0.1.0.24 без установки
не подтверждают этот сценарий.

Следующий воспроизводимый сценарий — одна отдельно одобренная
тестовая пара подписанных MSIX и неизменяемый HTTPS App Installer:
базовый полный identity, издатель и архитектура совпадают с нативным
`AppUpdateApprovedRelease`, точный URL совпадает с системной привязкой,
установка при запуске отключена. Из трея проверить появление кнопки,
ручную установку после остановки записи, версию после перезапуска и
сохранение локального состояния. Без одобрения, с чужим издателем,
архитектурой либо URL кнопка установки недоступна. Этот сценарий требует
отдельной установки и подтверждения канала; настройки и код Windows
в этом повторе не менялись.

## 2026-11-09 — нативная проверка в контексте установленной 0.1.0.38

Устранён пробел предыдущей проверки: теперь контроллер запустили в
системном контексте зарегистрированного точного
[MSIX 0.1.0.38](validation-2026-11-09-t108-window-close-policy.md#пакет-01038-и-проверка-его-установки).
Для этого MSVC x64 собрал отдельную пробу с настоящим
`WindowsAppUpdateController.cpp` из исходного манифеста пакета
(`b419b9b0d521fae9f1a993706c58e322fe3c4dfa2d5b049b4aa13e7516e1f901`).
Источник контроллера и его заголовок совпали с манифестом. Это не
тестовая ветка в основном EXE и не отрисованное окно.

| Сценарий | Наблюдение |
| --- | --- |
| Проба вне MSIX | Windows не видит идентификатор пакета; контроллер возвращает `unavailable/noPackage` и подсказывает запустить установленный GRAF. |
| Та же проба с идентификатором установленной 0.1.0.38 | `Package::Current` и `FindPackageForUser` подтвердили точный идентификатор. `GetAppInstallerInfo()` вернул null. Контроллер возвращает `unavailable/noAssociation`, говорит об отсутствии настроенного источника и не разрешает установку. |

В обоих случаях проверка не выдаёт состояния «обновление доступно»
или «версия актуальна» и не блокирует новую работу. Вторая проба
проверяет отсутствие источника до обращения к контроллеру: при
неожиданном источнике она остановилась бы до сетевой проверки.
Рабочий сервер, устройства и данные не участвовали.

В отдельном обычном профиле сверены хеши установки .38 и отката на
.18. Контрольный файл сохранился; временный профиль, регистрация
и папки убраны. После первой компиляции Windows ненадолго удерживала
собранный EXE; после завершения процесса оставшиеся файлы временной
сборки сверены и удалены отдельно. У рабочего 0.1.0.18 совпали
хеш EXE, PID и время запуска; доверие Windows не менялось.

| Материал | SHA-256 |
| --- | --- |
| MSIX 0.1.0.38 | `85c22b9557b5e6d338a689955d535882c02dadcdfaaa8342622f5b258bc24440` |
| WindowsAppUpdateController.cpp | `558f63f754f2c16510a56170dbfa984fabe64a4c8516cceab2971621c4069e2f` |
| Нативная проба x64 | `94482cb735cea9346fb1b72fee9eeafa382561d4fa3f7088d99d429620b1270e` |
| Квитанция прогона | `1cba96a9a286bc4e3a7b59339d41960f1121912281d9b32dd91d99bb7adc9bdc` |

T112 остаётся открытой. Нужны открытие окна из трея и кабинета,
клавиатура, системные темы и сквозной переход на новую версию
по одобренному подписанному тестовому каналу. Подмена системной
привязки и публикация канала не выполнялись.

## 2026-11-09 — отказ перед передачей установки Windows

В отдельном обычном профиле Parallels повторно установили точный 0.1.0.38.
Проба MSVC x64 (/W4 /WX) проверила идентификатор и отсутствие association.
Затем только результат проверки наличия обновления подменили на Available;
проверку допуска и подготовку установки выполнил штатный контроллер с
нативным адаптером, собранный из того же исходника пакета.

- Без утверждённого канала `beginInstall` вернул отказ
  `noApprovedRelease` без блокировки новой работы.
- С искусственным разрешением пробы нативная подготовка вернула
  `error/noAssociation`: до повторной проверки готовности, регистрации
  перезапуска и передачи установки Windows. После отказа контроллер
  снял временный запрет новой работы. Повторная проверка готовности
  независимо запретила бы установку, даже если бы код дошёл до неё.

Сеть, устройства и основное окно не использовались. Первый прогон
остановила несовпавшая контрольная сумма временного запускателя ещё до
пробы; после исправления контрольных сумм повторный прогон прошёл с кодом
73. Контрольный файл сохранился при установке и откате. Профиль, его
регистрация и временные входные файлы удалены; PID, время запуска и
хеш EXE рабочего 0.1.0.18 совпали до и после. Доверие Windows не менялось.

Проба SHA-256: `6eaa43e92c318ff2f710fa5680664b8e49e16b71890ea09537cabcb6e606331c`.
Квитанция SHA-256: `3977256e6f4ad43c49437cb2234f8288d1bc6e1ff4e70a87b6c95039bd42f6b8`.
T112 остаётся открытой до проверки установленного окна и утверждённого
подписанного тестового канала. Отказ не подтверждает успешное обновление.
