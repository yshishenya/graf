## Исправления и очистка

- Удалены `CaptureHealthProjection`, `CustodyStatusProjection`,
  `AccessibilityState`, `WebRuntimeStateProjection`, `CaptureFaultRecovery`,
  `WindowsPermissionRecovery`: не было рабочих потребителей.
- Проверка констант доступности заменена честно названным тестом состояния
  индикатора. Доступность настоящих окон остаётся отдельной проверкой.
- Удалены синхронная отправка, прежние двоичные настройки автозаписи и
  неиспользуемые команды моста. Нет совместимых псевдонимов без потребителя.
- Сохранены записи, очередь, совместимость v5/v2 и проверки безопасности.
  Исходники удалённых модулей восстанавливаются из Git.
- Восстановлены lifecycle WebView, nonce/источник документа, переходы внутри
  страницы, повтор после ошибки, диалоги и загрузки без вложенного цикла событий.
- Локальные строки используют существующий интерфейс кабинета и непрозрачные
  идентификаторы. Нативные действия повторно проверяют состояние и хранилище.
- Удалены неиспользуемый `DesktopLocalPurgeService::purge`, три фиктивных вида
  подтверждения серверной очистки и `registerLocalPurge` с его маркером. Рабочая
  Корзина, подтверждение пользователем, проверка пути и журнал удаления сохранены.
- Удалены два пустых тестовых проекта `SmokeMain` и ссылки на них из решения.
  Настоящие 20 CMake-тестов сохранены; прежний успешный выход пустого проекта не
  считается проверкой продукта.
- По независимой проверке исправлены показ индикатора до начала захвата,
  неблокирующие запуск/отмена устройств, отложенное закрытие приложения до
  завершения записи и сохранения очереди. Кодирование WAV/AAC и проверка
  файлов выполняются вне потока интерфейса; окончательное изменение очереди —
  в её единственном потоке-владельце. Проверка потоков использует настоящие
  потоки выполнения с синтетическим телом устройства, не реальный микрофон.
- Исправлена ошибка размера буфера в обоих преобразованиях идентификаторов
  аудиоустройств: завершающий нулевой символ больше не делает вызов Windows API
  неуспешным. Проверяются и некорректные последовательности UTF-8/UTF-16.
- Обновление кабинета повторно проверяет локальные файлы после временной ошибки.
  Результат локального действия больше не скрывается старой ошибкой записи.
- Безопасная сводка получает реальные счётчики обработанных/записанных блоков
  только после завершения потоков. Префикс `ep_` больше не позволяет обойти
  обезличивание; фиктивные нулевые счётчики и неиспользуемые поля удалены.
  Кнопка копирования использует локальный буфер обмена, без отправки на сервер.

## Нерешённые условия

1. Визуальная проверка каждого окна не завершена: после прежней блокировки
   Mac содержимое кабинета снова видно, но прямой автоматический ввод в госте
   не даёт подтверждённых переходов. Причина не установлена. Успешное создание
   окна не выдаётся за визуальную проверку.
2. Нужны сценарии входа/выхода, OAuth-цепочки, списка/детали/экспорта, локальных
   действий и отправки на окончательной сборке с разрешёнными тестовыми данными.
3. Принадлежность записи фиксируется в момент Record, хранится в очереди и
   повторно проверяется перед отправкой; старая неизвестная запись требует
   явного назначения, а запись другого владельца не переназначается. Проверки
   очереди/декодирования/смены владельца пройдены. Первоначальное пространство
   теперь получается из существующего `/desktop/settings/spaces`, затем
   подтверждается через `/auth/me`; прежний вывод о необходимости изменения
   сервера снят. Алгоритм проверен синтетически, но сквозная отправка в
   настоящем кабинете ещё не подтверждена. Сервер не изменён и не развёрнут.
4. Для серверной очистки нет подтверждённой авторизации конкретной установки.
   Общая браузерная сессия не является основанием подтверждать такую очистку.
5. В Windows-каталоге нет утверждённых целей. Установленный подписанный Teams
   является наблюдением, а не разрешением автоматической записи. Нужны
   положительные и отрицательные проверки владения WASAPI-сессиями.
6. Общие условия автоматической записи не подменяются константой `true`.
7. T070/T071: подпись/чистая установка/обновление, реальное аудиооборудование,
   смена устройства, sleep/wake, системный звук, пауза/возобновление/Stop,
   физический x64-компьютер, клавиатура/Narrator/High Contrast/200% DPI.

## Справочная причина исправления WinUI

Приложение написано без App.xaml и автоматически создаваемого провайдера
метаданных. По официальному примеру Microsoft оно должно реализовать
`IXamlMetadataProvider`, делегируя три метода
`XamlControlsXamlMetaDataProvider`, до создания `XamlControlsResources`.

- [Microsoft: поддержка Microsoft.UI.Xaml.Controls.dll](https://github.com/microsoft/microsoft-ui-xaml/blob/aa3207e6ae8fce6f84baae35f965241913fe55ef/docs/design-notes/desktop-app-walkthrough.md#supporting-microsoftuixamlcontrolsdll)
- [Windows App SDK: пример провайдера](https://github.com/microsoft/WindowsAppSDK-Samples/blob/0057c23a44157b4cc8a539d52282a3d1f3559de8/Samples/Islands/cs-winforms-unpackaged/XamlApp.cs)

- Главный кабинет/панель больше не определяют готовность автостарта.

  прерывают этот отсчёт; повтор не продлевает положительное подтверждение.
