# F200/T112 — внутренний MSIX 0.1.0.31 x64 и носитель для чистой Windows

Проверка упаковки в действующей F200. База
`3dfeaff5a6774ab12be781547e4a300f9ce2a46c` и точный снимок локальных
изменений Windows. С текущей рабочей копией совпали 231/231 входных
файлов. После 0.1.0.30 изменился один вход, `AppMain.cpp`, с исправлением
[порядка активации окна обновлений](validation-2026-11-08-t112-window-order.md).
В копии для сборки отдельно заменена версия манифеста с 0.1.0.17 на 0.1.0.31.

В Windows 11 ARM64 / Parallels заново собран AEC3 Release x64 из
закреплённого исходника, пройдено 10/10 проверок, включая отказ при
неучтённой скрытой библиотеке. Сборка и подпись MSIX завершились
с кодом 0. Проверки средства упаковки — 17/17; в проверках подписи
и регистрации из этого набора использованы имитации ответов ОС.
Для готового MSIX отдельная Windows-проверка подтвердила действительную
подпись сертификатом разработки `CN=GRAF`. Независимо сверены 26/26
файлов пакета, тип PE x64 и встроенный манифест с `PerMonitorV2`.
Манифест упаковки совпадает с 0.1.0.30 за вычетом версии.
Временные копии сборки и проверки удалены.

После открытия пользователем через «Пуск» рабочая 0.1.0.18 прошла
`-VerifyInstalled -RequireRunning`: совпали точный подписанный пакет,
регистрация, SHA-256 установленного EXE и настоящее отвечающее окно.
Проверка 0.1.0.31 на совпадение с этой регистрацией ожидаемо отказала.
Рабочий пакет, EXE и процесс не изменились в ходе проверки 0.1.0.31.
Это подтверждение окна, а не исправления ранее наблюдавшейся ошибки
защищённого хранилища, входа или записи.

Собран отдельный ISO для проверки запуска 0.1.0.31 на чистом стенде.
На нём исходный 0.1.0.18, новый 0.1.0.31 и те же зависимости, что
на носителе 0.1.0.29. Сценарий проверки окна использует тот же
`validate-package-smoke.ps1`, который отвергает системные диалоги
ошибки. Для `-RequireWindow` ему нужна `-LocalPackage`: путь к копии
MSIX на локальном NTFS. Содержимое ISO сверено на Mac и после
подключения копии в Windows (9/9 файлов); Windows разобрала новый
сценарий PowerShell и выполнила проверку хешей носителя. ISO отключён,
временная копия удалена. Новый ISO не подключали к чистым стендам;
прежний носитель для T117 сохранён.

## Установка, самопроверка звука и откат в отдельном профиле

На Windows 11 ARM64 / Parallels точный 0.1.0.31 установлен в новый
временный профиль обычного пользователя, поверх 0.1.0.18. Использованы
уже установленные зависимости и существующее доверие к сертификату
разработки. Проверены SHA-256 входных пакетов и EXE из регистрации.
Подтверждены четыре фазы: 0.1.0.18, обновление до 0.1.0.31,
самопроверка и откат до 0.1.0.18 без удаления перед откатом.

Установленный EXE 0.1.0.31 выполнил `--verify-audio-backend` в контексте
своего пакета и вернул ожидаемый код 73: AEC3 прошёл проверку на
искусственных потоках. Искусственный контрольный файл в `LocalState`
сохранился побайтно после обновления и отката. Окно нового пакета,
микрофон и системный захват не запускались.

Тестовая регистрация, профиль, учётная запись и временные копии
удалены. Независимая сверка подтвердила единственную установленную
0.1.0.18, прежние EXE, PID и время запуска рабочего GRAF. Его окно
отвечает. Рабочие данные и доверие к сертификатам не менялись.
