Доставка после обычного выхода из приложения — вывод рецензента из цели паритета
и ранее прочитанного Mac-кода с планированием UNNotificationRequest, а не отдельный
запрос пользователя. Предыдущая атрибуция исправлена.

T104: due = startsAt−offsetMinutes; ранняя карточка сохраняет отдельное окно.
После выхода системная заявка остаётся; смена аккаунта/контекста, выключение
напоминаний и известная отмена очищают принадлежащие контексту заявки/историю.
Ключ попытки стабилен для occurrence, startsAt не часть identity; до due
допустима замена, после due повтор не следует из отсутствия доказательства показа.
Первая поздняя заявка — now+1s строго до min(endsAt,startsAt+300s).
Актуальная pending-заявка не удаляется лишь из-за наступления due.
Журнал v1 хранит хешированные ключи/срок/состояние, не содержимое; отказ записи
или неизвестная схема не разрешают повтор. Окно сбоя трактуется как безопасное
молчание, не обещание exactly-once доставки. Во всех состояниях захвата
напоминания подавляются/отменяются; системный sound не обходит denied/DND.
Передано ОС, история, активация и фактический показ/звук различены.
Активация использует непрозрачный ID и повторную проверку контекста/события.
Изменения календаря при закрытом приложении не обещано узнавать без обновления.

T112: PackageManager.FindPackageForUser, зарегистрированный источник, раздельные
NoUpdates/Available/Required/Unknown/Error; новая версия не выдумывается.
HTTPS URI без userinfo/query/fragment недостаточен сам по себе: нужен
утверждённый канал, совпадение identity/publisher/version/architecture и отсутствие
неожиданных дополнительных пакетов/redirects. Без канала установка недоступна.
Явное нативное действие, повторная сверка, блокирование новых записей,
завершение фоновых изменений файлов и отмена при истечении ожидания предшествуют
передаче установщику. ForceTargetAppShutdown не заменяет подготовку;
Status=Valid, проверка минимальной ОС/XML и условность restart сохранены.
Эфемерная модель D §8 описывает UI, не исчерпывающий enum API: Required/Unknown
различаются по P/M; unavailable не приравнивается к current.

Два добавленных первичных источника прочитаны:
[Microsoft: планирование уведомлений](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/app-notifications-scheduled)
подтверждает независимость от running app и ограниченное окно доставки;
[Microsoft: CheckUpdateAvailabilityAsync](https://learn.microsoft.com/en-us/uwp/api/windows.applicationmodel.package.checkupdateavailabilityasync?view=winrt-26100)
подтверждает App Installer association и обход известного отказа Package.Current
через получение пакета PackageManager. Это проверка обоснования плана, не запуск API.

## Сохраняющиеся специальные проверки

- canOpenSystemSettings — необязательный boolean отображения, Windows false;
  старый Mac без поля сохраняет поведение после успешного native connection.
  Это не разрешение команды; версия/nonce/requestId/schema остаются обязательны.
- request_app_update: ровно шестая команда, пустой payload, только ready approved
  cabinet main document; auth/payment/frame/external и URL/path/installer исключены.
  Установка не начинается веб-сообщением, новый native-to-web event не вводится.
- T108/T109 — начальные работы; T110/T111 после T108, общие AppMain/host/
  NativeSettingsBridge изменения интегрируются последовательно. T112/T102/T103
  не меняют host параллельно; T104 отдельно лишь до общей интеграции.
  Новых циклов, дублирующих задач и непокрытых требований не обнаружено.
- Settings открывает /desktop/settings/account; hide не вызывает безусловный
  automaticPolicy.cancel и сохраняет сопровождение активной автозаписи.
- Будущий паритет остаётся в F200: общие контракты/проверки двух клиентов,
  без новой capture-архитектуры, серверной схемы или глобального процесса выпуска.
- Новых нарушений constitution 7.1.0 нет. Аппаратные SC, privacy/custody,
  подпись, release approval и независимые проверки не ослаблены.
