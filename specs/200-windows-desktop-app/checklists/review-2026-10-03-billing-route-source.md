## Корректность и доверительные границы

1. **Точное разрешение, а не prefix/wildcard.** Добавлены ровно
   `/billing/storage/preview`, `/billing/storage/cancel-selection`,
   `/billing/subscription/early-preview`, `/billing/purchases/confirm`.
   Они проходят существующее `path == allowed`; соседние действия и дочерние
   пути автоматически не разрешаются. Динамические status/invoice правила
   не меняются.
2. **Origin и схема.** `evaluate` по-прежнему сначала разбирает HTTPS и
   сравнивает origin; внутренний route список применяется только после этого.
   Чужой origin не становится доверенным из-за совпадения billing path.
   Host/port/userinfo parsing, auth continuation и внешняя payment navigation
   не изменены. Новая регрессия удерживает внешний URL как `openExternal`.
3. **Недопустимый path.** Прежняя проверка `//`, `..`, `%` остаётся перед
   классификацией внутренних маршрутов. Новый цикл тестирует `/`, `/extra`,
   `-extra`, `/../checkout`, `/%2fextra`, включая запрет моста и начала оплаты
   от этих адресов. `/desktop/billing/...` отдельно проверен как `deny`;
   нормализация и новые aliases не добавлены.
4. **Оплата.** Добавление разрешённого внутреннего billing-документа позволяет
   использовать существующий `canStartPayment`, а не новую платёжную логику.
   В тесте есть разрешённый `api.yookassa.ru` и отказ для
   `api.yookassa.ru.evil.test`. Точный provider список, HTTPS chain и
   PaymentNavigation deadline/reset остались вне разницы; прежние проверки
   первого provider, frame, 900 секунд и непродления сессии сохранены.
5. **Мост.** Для чужого origin, неверного action path и ложного provider
   доверие не расширяется. Новый тест непосредственно отвергает мост для
   внешних/недопустимых адресов; прежний тест отвергает мост bank/auth страниц.
   Разрешённый same-origin billing-документ следует прежним правилам своей
   категории: новое требование «отключить мост вообще для billing» не вводится.
   Typed commands, cookie extraction, native bootstrap и host не изменены.
6. **Возврат и отсутствие повторной отправки.** `safeRecoveryUrl` сохраняет
   самостоятельный список безопасных GET-документов. Ни один новый action path
   не попадает в этот список или разрешённый динамический prefix; POST
   отсекается до разбора пути. Для каждого действия тест требует пустой
   результат для GET и POST и возврат при expiredSession именно на
   `/login?next=%2Fbilling`, не на action. Транспорт method/body, response
   policy и auth HTML-ошибки не изменены.

Разница устраняет известный пропуск классификации, не меняя server/backend,
бизнес-логику оплаты, сроки, request replay или правила trusted-origin.

## Покрытие тестом и его пределы

`billingActionParityContract` действительно вызван первым из `main`, поэтому
новые assertions не являются неиспользуемой функцией. В начале существующего
файла `NDEBUG` снимается перед `<cassert>`: assertions не выключаются только
из-за Release-конфигурации.

Для каждого из четырёх действий проверяются `allow + billing`, сохранение
категории при query/fragment, допустимый первый provider, ложный provider host,
GET/POST recovery, fallback после истечения входа, недопустимые соседи/кодировки,
неподдерживаемый `/desktop` alias и внешний origin. Это соразмерная регрессия
данного изменения списка; неизменённые `paymentAndResponseContract` и остальные
проверки не удалены и продолжают вызываться.

Тест не имитирует полный browser POST, popup adapter, HTTP redirect или
установленный WebView2. Его assertions описывают policy contract, не доказывают
фактическую сохранность метода/тела или полный пользовательский сценарий.
Для проверки неизменённого общего URL parser не требуется размножать всю
прежнюю матрицу scheme/port/auth на каждую новую строку списка.
