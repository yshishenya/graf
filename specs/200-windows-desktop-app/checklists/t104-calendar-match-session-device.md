# T104/B2c.6 — независимая проверка требований к устройству сессии

T104/#7281, high-risk-product. Отметки относятся к требованиям, а не к реализации или приёмке установленного пакета.

- [x] CMD001 `auth/me` возвращает необязательный `active_session_device_id` без кэширования только из проверенного principal той же активной сессии, владельца и пространства. Заголовки, список устройств и необработанное поле строки сессии не дают доказательства; непривязанная или legacy-сессия поля не получает, действующие отказы сохраняются. [План](../plan.md#t104b2c6-подтверждённое-устройство-текущего-токена), [principal](../../../apps/server/src/twobrain_rec_server/auth/dependencies.py#L350).
- [x] CMD002 Windows читает только точное корневое поле с каноническим ненулевым UUID, если обычная идентичность уже валидна. Отсутствующее, `null` или непригодное поле не наделяет календарный запрос правом и не ломает вход либо обычную загрузку. Список устройств не заменяет поле. [План](../plan.md#t104b2c6-подтверждённое-устройство-текущего-токена), [Quickstart](../quickstart.md#t104b2c6-устройство-из-подтверждённой-сессии).
- [x] CMD003 Поле живёт только в подтверждённом снимке токена и поколения. B2c.5 требует совпадения UUID снимка, исходной попытки и явного устройства запроса. Обычная загрузка сохраняет прежние заголовки; журнал, панель, сохранение исходной попытки и строгий POST не получают новых прав в этом срезе. [План](../plan.md#t104b2c6-подтверждённое-устройство-текущего-токена), [задача](../tasks.md).
- [x] CMD004 Проверки отличают доверенную привязку при пустом `AuthSession.device_id` от сырого поля строки и доказывают, что ответ прежнего поколения не может передать UUID новому токену того же аккаунта и пространства.

**H1 / CMD004.** Положительная серверная проверка должна явно оставить `AuthSession.device_id=NULL`, создать одну доверенную привязку и ожидать её UUID даже с другим UUID в заголовке: [resolver поддерживает эту форму](../../../apps/server/src/twobrain_rec_server/auth/sessions.py#L236), но текущая формулировка Quickstart допускает fixture, где оба источника совпадают. На Windows удержать `auth/me` для токена A с устройством, заменить его на B того же владельца и пространства, затем доставить поздний ответ A. До подтверждения B нет календарного GET; если ответ B не содержит поля, обычная идентичность B принимается, но B2c.5 по-прежнему делает ноль запросов. Ссылка на прежние проверки отмены поколения не проверяет новое поле на границе [принятия ответа](../../../apps/windows/RecApp/Recording/NativeCapture.h#L3485) и копирования снимка.
