# T104/B2c.4 — независимая проверка требований к разбору квитанции Windows

Срез T104/#7281, high-risk-product. Отметки относятся к качеству требований; тесты реализации и приёмка установленного приложения сюда не входят.

- [x] CMCR001 Три исхода различены: точная квитанция, полный HTTP 404 с корневым `recording_not_found`, отсутствие доказательства. Ни один исход сам по себе не разрешает POST, доступ к очереди или удаление. Привязка к подтверждённой сессии, серверу, аккаунту, пространству и устройству остаётся в следующем срезе; обычная загрузка и UI не меняются. [План](../plan.md#t104b2c4-проверка-подтверждения-на-стороне-windows), [задача](../tasks.md).
- [x] CMCR002 HTTP 200 подтверждает только явный сохранённый исход: совпадают UUID записи, обе проекции локальной ревизии, UUID известной встречи при наличии, UUID попытки и пара решения/исхода; требуются явные `owner` и `none` для доступа и удаления, удалённая ревизия исключается. При отказе UUID встречи не возвращается. [План](../plan.md#t104b2c4-проверка-подтверждения-на-стороне-windows), [серверная схема](../../../apps/server/src/twobrain_rec_server/api/schemas.py#L1013), [Quickstart](../quickstart.md#t104b2c4-windows-сверяет-точную-квитанцию).
- [x] CMCR003 Разрешённые состояния конфликта и причины `dependency_unavailable` определены исчерпывающе. При точной квитанции сбой загрузки не отменяет доказательство; несовместимые, отсутствующие, неизвестные состояния и причины вне разрешённого списка оставляют результат «не доказано». Quickstart проверяет обе стороны.
- [x] CMCR004 Проверки разбора охватывают оба явных исхода, точный и посторонний 404, несовпадения идентификаторов и исхода, отзыв доступа, удаление, неполный и чрезмерный JSON, дубли после декодирования, отсутствие квитанции, отмену и сбой транспорта. Проверки привязки запроса, запрета запасного POST и отката установленного пакета выделены отдельно. [Quickstart](../quickstart.md#t104b2c4-windows-сверяет-точную-квитанцию).

**H1 / CMCR003.** Сервер может выдать точную квитанцию вместе с `dependency_unavailable`: [сбой чтения upload session](../../../apps/server/src/twobrain_rec_server/ingest/desktop_sync.py#L816) не входит в [условия выдачи квитанции](../../../apps/server/src/twobrain_rec_server/ingest/desktop_sync.py#L952). Но [в ветке истечения сессии](../../../apps/server/src/twobrain_rec_server/ingest/desktop_sync.py#L670) то же состояние означает как `upload_session_unavailable`, так и `meeting_unavailable`. В plan нужен закрытый список: `none`, `upload_session_expired`, `processing_failed`, `processing_blocked`, и `dependency_unavailable` только с `conflict.reason=sync_state_dependency_unavailable` или `upload_session_unavailable`. Для последней ветки Quickstart должен различать оба разрешённых случая с точной квитанцией и отказы для `meeting_unavailable`, отсутствующей/чужой причины и неизвестного состояния. Проверки самой квитанции действуют во всех разрешённых ветках.
