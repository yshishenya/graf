## Самые рискованные переходы

- Последовательный Write B+short должен подтвердить реальные DATA первого блока,
  оставив short pending, а не заранее увеличить committed EOF ZERO до всей
  длины входа. Sparse gap — только пространство **до** записываемых bytes;
  частичный старый tail требует exact merge, не замены его prefix нулями.
- Dirty shrink→grow не может восстановить RAM suffix или ссылку на старый DATA.
  Writer Read отражает pending truncation/extension; уже закреплённый Reader
  продолжает читать свой прежний snapshot, не mutable candidate Writer.
- Несколько actual ACK внутри Write/checkpoint допустимы. Последующая ошибка
  относится к текущему переходу от последнего подтверждённого root: notCommitted
  не означает отсутствие предыдущих ACK, ambiguous не означает rollback.
  State сохраняет latest acknowledged Tree и actual failed-result lease,
  base/target и первый fault; отсутствие byte ACK всего вызова не стирает disk truth.
- Healthy destruction не устанавливает shared cancellation и не превращает
  revokeWrites в physical Owner fault. Реальная cancellation/integrity/native
  failure остаётся sticky по соответствующему owner/reader lifecycle. Healthy
  reads после revoke и reads после observed fault — разные состояния.
- Все fixed allocations/dirty capacities/retained results входят в прежнее
  owned admission. Нельзя увеличивать dirty4/job4/pins32 для удобства вложенного
  Tree перехода; отказ должен сохранять lease и не давать false success.

Это следствия принятых требований для будущего source review, не новые нормы
и не выбор дополнительной архитектуры. Требования достаточно точны; C/H gap
для начала bounded RED/implementation не выявлен.
