# Чеклист требований: возврат Windows к общей встрече (T121 / CHK022)

Область: публичная ссылка, вход или регистрация и возврат к той же
встрече. Основания: [проект §11.4](../contracts/windows-native-web-bridge.md#114-проект-windows-возврата-после-входа-t121--chk022),
[план T121](../plan.md), [сценарии приёмки](../quickstart.md#t121-windows-возврат-после-входа),
[#7933](https://github.com/yshishenya/graf/issues/7933).
Отметки принадлежат независимому рецензенту.

- [X] CHK001 Определены отдельные Windows-маршруты, условия допуска и точный результат каждого шага. Сохранён прежний 303 и старый cookie Mac и браузера; при старом сервере Windows предлагает явный повтор.
- [X] CHK002 Описано, где создаётся и передаётся значение попытки, как ограничен cookie и что не попадает в адрес входа, фреймы, журналы и нативный мост. Проверки сессии и доступа остаются обязательными.
- [X] CHK003 Определены отказ при позднем A и текущем B для одного ресурса, правила отмены и безопасный повтор. Поздние ответы не очищают контекст новой попытки; совпадение URL не подтверждает принадлежность.
- [X] CHK004 Разделены проверки HTTP-сервера, настоящего WebView2, входа с провайдером и установленного пакета. Указаны отрицательные контроли и совместимость Mac/браузера, включая потерю сети и откат.

## Независимая проверка требований

**Итог: 4 подтверждено, 0 открыто.** После уточнения §11.4.1 повторно проверены только CHK001 и CHK002. Проверено качество требований, без зачёта исполнения.

| Пункт | Основание или пробел |
| --- | --- |
| CHK001 | §11.4 сохраняет прежние 303/cookie Mac и браузера и явный повтор Windows при откате. §11.4.1 задаёт точные OAuth GET для включённых Yandex/VK, один декодированный `next=/shared-meeting/continue/windows` и только для VK один необязательный `auth_provider`: `vkid`, `mail_ru` или `ok_ru`. Сверено с `browser_login_provider_start` и `_safe_vk_auth_provider` в `cabinet/web_routes/auth.py`, а пути — с `WebViewRoutePolicy::authContinuationForStart`. Строгий допуск относится только к новому заголовку; обычный вход сохраняет прежнюю нормализацию. |
| CHK002 | §11.4/§11.4.1 ограничивают передачу `X-GRAF-Share-Operation` настроенным HTTPS-origin, подготовкой, resolve и одним допущенным start из текущего верхнего документа. Дубликаты, неизвестные/неверные параметры, изменённый путь, callback, фреймы и последующие редиректы не получают заголовок. Маршрут callback сверён с `api/auth.py`. Границы cookie, проверки сессии и гранта и запрет выдачи значения в URI, журналы и мост сохраняются. Это проверка границы требования; фактическая передача заголовка проверяется отдельно по quickstart. |
| CHK003 | §11.4/§11.4.1 и quickstart Сервер, Привязка к входу, Между разрешением и показом: cookie A при операции B даёт 409 без цели; поздний resolve не меняет cookie; квитанция, попытка и конкретная сессия должны совпасть даже для одного пользователя. Отмена прекращает использование значения; повтор начинает новую подготовку, одного совпадения URL недостаточно. |
| CHK004 | Quickstart отдельно задаёт HTTP на тестовой БД, настоящий WebView2, проверки привязки email/OAuth и путь с действующим провайдером на установленных MSIX/Mac Dev. Есть контроли поздней сессии, подмены ответа, редиректа, утечки заголовка, 404 и потери сети. §11.4 явно требует безопасного повтора при откате без Windows fallback на старый 303; обычный Mac/браузер сохраняет прежние 303 и cookie. |
