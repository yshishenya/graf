# F200 — регистрация и запуск MSIX у второго пользователя Windows

Проверен запасной стенд для T116/T117/T118 и установленной приёмки
T097/T121. Кандидаты GRAF не устанавливались. Рабочий GRAF 0.1.0.18
оставался запущенным, отдельная `GRAF F200 QA ARM` по-прежнему не
предоставляла гостевой сеанс.

На Windows 11 ARM64 в Parallels собраны два минимальных пакета x64
одной **тестовой** семьи `com.graf.f200probe.*` с версиями
`1.0.0.0` и `1.0.1.0`. В них нет GRAF, его протокола `grafrec`,
записи звука, сетевых сценариев, автозапуска и данных пользователя.
Подписаны имеющимся сертификатом разработки; сертификаты, доверие
и настройки UAC не менялись.

1. Под текущим пользователем установлен и через штатную активацию
   запущен `1.0.0.0`. Процесс подтвердил полное имя своего пакета
   и оставался запущенным в момент следующей проверки.
2. Под отдельным временным локальным пользователем с загруженным
   профилем и без группы Administrators в токене установлен
   `1.0.1.0`. Пока обе регистрации существовали, родитель независимо
   прочитал версию каждого пользователя: `1.0.0.0` и `1.0.1.0`.
   Первый процесс продолжал работать. В этой конфигурации Windows
   разделила регистрации двух версий по пользователям.
3. Штатная активация второй версии через
   `IApplicationActivationManager::ActivateApplication` из процесса
   вторичного входа вернула `0x80070520` / `ERROR_NO_SUCH_LOGON_SESSION`.
   Запуск приложения под вторым пользователем не состоялся. Загрузка
   профиля и успешная регистрация MSIX не заменяют интерактивный вход
   в Windows для этой проверки. См. [описание активации](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iapplicationactivationmanager-activateapplication)
   и [коды ошибок Windows](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--1300-1699-).
4. Оба тестовых пакета сняты с регистрации. Независимая проверка после
   завершения вернула ноль установленных или подготовленных тестовых
   пакетов, временных учётных записей, профилей и каталогов теста.
   Версия, SHA-256 EXE, PID и время старта рабочего GRAF совпали до и
   после. Его файлы и профиль не открывались.

| Артефакт | SHA-256 |
| --- | --- |
| Манифест входов итоговой пробы | `b9476edc009c1deb08f813c6e7150322007d1234ec0358f3aa9b6a8a52ef918c` |
| Тестовый MSIX A | `d13376b749ea7d6125e8ffdcce9515113714d369276edb8f59888a5bd36cc728` |
| Тестовый MSIX B | `d8b60de55d7a37e19fe5dd7eecf76f21ecb82881c671bd55f0487cc688d4bbf2` |
| Квитанция итоговой пробы | `d094c65855ffe871002a1d6573601b992d290e332790d99fc24202b9031d038f` |

Для запуска точного кандидата нужен интерактивный сеанс отдельной
QA Windows под обычным пользователем. Результат регистрации тестовой
семьи не доказывает безопасность обновления/отката рабочего GRAF или
работу его нативных действий. Все установочные и аппаратные условия
выпуска остаются отдельными.

## Точные MSIX GRAF 0.1.0.18 → 0.1.0.28 → 0.1.0.18

В рабочей Windows 11 ARM64 создан один временный обычный пользователь
с отдельным пустым профилем. Запускатель подтвердил SID, собственный
`LocalApplicationData` и отсутствие группы Administrators в токене.
Под этим пользователем зарегистрированы точные подписанные пакеты
из автономного носителя, затем применены обновление и откат:

| Шаг | Версия по данным Windows | SHA-256 установленного EXE |
| --- | --- | --- |
| Первая регистрация | 0.1.0.18 | `20a7544617b3008cc6706f94b769d0ad3e66b3e3ec146e30768b3a795bb1f17b` |
| Обновление | 0.1.0.28 | `942ac0202c3707039aadc880a5aa488747a6cfb22d24e893353413a29c15ea5e` |
| Откат | 0.1.0.18 | `20a7544617b3008cc6706f94b769d0ad3e66b3e3ec146e30768b3a795bb1f17b` |

Для отката применён
[`Add-AppxPackage -ForceUpdateFromAnyVersion`](https://learn.microsoft.com/en-us/powershell/module/appx/add-appxpackage?view=windowsserver2025-ps#-forceupdatefromanyversion)
без удаления перед откатом и без принудительного закрытия процессов.
Использованы уже установленные x64 версии VCLibs 14.0.33728.0 и
Windows App Runtime 2.6.5.0, а также ранее доверенная подпись разработки.
Доверие не менялось. Не проверялась установка этих зависимостей на
чистой Windows.

После каждого шага независимый процесс сверил регистрацию тестового
пользователя и работающий GRAF 0.1.0.18 основного пользователя:
версия, SHA-256, PID и время запуска основного процесса совпали.
Один искусственный файл в `LocalState` временного профиля сохранился
побайтно после обеих смен версии. Содержимое рабочего профиля не читалось.

После проверки снята только регистрация GRAF временного пользователя;
удалены его профиль, учётная запись и временный входной каталог.
Повторный опрос всех регистраций показал только исходную 0.1.0.18,
окно рабочего процесса отвечает. Оба запускателя вернули 0.

| MSIX 0.1.0.28 | `f8aeeea3ea31e0920d4683a8590d6486de6267fbf58aa22219fbb13dab566449` |

Это проверка регистрации и сохранности контрольного файла. Приложение
под вторым пользователем не запускалось; миграция записей, WebView2,
управление из окна и отказ старого приложения при чтении перенесённого
профиля здесь не проверялись. Чистый образ Windows, установленная
приёмка и требования внешнего выпуска остаются открытыми.

## Эхоподавление в точном установленном 0.1.0.28

На том же стенде проверена встроенная команда
`--verify-audio-backend`, в отдельном обычном профиле. EXE после
регистрации сверялся с хешем из MSIX. Прямой запуск из процесса
вторичного входа вернул `InvalidOperationException` из `Start-Process`
и не исполнил самопроверку. Причина по этой квитанции не установлена.
Установленную для теста регистрацию сняли; Windows ещё показывала
кандидата как подготовленный к установке (`Staged`), без установленных
регистраций пользователя.

Отдельная проверка через
[`Invoke-CommandInDesktopPackage -PreventBreakaway`](https://learn.microsoft.com/en-us/powershell/module/appx/invoke-commandindesktoppackage?view=windowsserver2025-ps)
прошла: оболочка в контексте пакета сверила SID обычного пользователя,
зарегистрированную 0.1.0.28 и хеш EXE, запустила точный файл и получила
код **73**. В продукте этот код требует наличия идентичности пакета,
успешного создания AEC3 и встроенной проверки двух синтетических
аудиопотоков. Устройства, интерфейс и сеть не открывались.

Кандидат в тестовом профиле откачен до 0.1.0.18 перед снятием его
регистрации. Независимая проверка после завершения нашла на машине
только рабочую 0.1.0.18; временные учётные записи, профили и входные
каталоги отсутствовали. PID и время запуска рабочего GRAF не менялись.

| Квитанция | SHA-256 |
| --- | --- |
| Прямой запуск, отказ до самопроверки | `6f64a45b5e6d9b803599c36f407871fd228833a6d862eb7f7d2812bc5ea751c1` |
| Запуск в контексте пакета, код 73 | `277bd314a77144a0bcc67881b3a22754f50ab023bf12036a185f2670d65003ca` |
| Журнал успешного прогона | `12e5909dd63255f1c8aec36081cbc83ea7e6a4b3b525f658de37067eaf8ac938` |

Это проверка нативной зависимости точной сборки. Отладочный запуск
отличается от обычной активации. Захват реального звука, качество AEC,
устойчивость часов, обычный запуск и визуальная приёмка остаются открытыми.

## Обычное окно 0.1.0.28: ограничение вторичного входа

Тем же способом попробовали запустить точный установленный EXE
0.1.0.28 **без аргументов**. Только во временном обычном профиле
выставлены правила «Никогда» для обеих известных целей автозаписи;
вход в кабинет и запись не запускались. До старта и после завершения
Windows независимо сверила регистрацию и хеш EXE. Рабочее приложение
0.1.0.18 осталось открытым в своём профиле.

У процесса кандидата появилось отвечающее окно 420×159 px, но в нём
не обнаружились элементы основной оболочки или документ WebView2.
После закрытия окна процесс вернул `0x80070520`
([ERROR_NO_SUCH_LOGON_SESSION](https://learn.microsoft.com/ru-ru/windows/win32/debug/system-error-codes--1300-1699-)).
Это отказ при запуске оболочки данным отладочным способом в контексте
вторичного входа. Код не определяет конкретный неудавшийся вызов
Windows и сам по себе не доказывает ошибку при обычном запуске
из меню «Пуск» в полноценном сеансе. Успех установщика и квитанции
об очистке не означает успех интерфейса.

Кандидат откачен до 0.1.0.18 в тестовом профиле; временная
регистрация, профиль, учётная запись и входной каталог удалены.
На стенде осталась только рабочая 0.1.0.18, с тем же EXE, PID
и временем запуска. В рабочем сеансе её окно видимо и отвечает,
запущен один непосредственный дочерний процесс WebView2. Через UI
Automation содержимое документа и состояние баннера хранилища в этом
окне независимо не подтверждены. Рабочий профиль не менялся.

| Артефакт | SHA-256 |
| --- | --- |
| Квитанция запуска окна 0.1.0.28 | `63ac0955d4c85b75db6f587765e75b1ba0bf27d8d3edf6657fab0704b1e8af76` |
| Журнал запускателя | `e9f72f77e6a11b4a40d10b588faa5e1b8b3ae71c273cce9f3e6d50f7b52f2b55` |
| Проверка окна рабочего 0.1.0.18 | `13f63d1309e4270b21d27b30c4498ae5b2ad094e8fd30808674152df072f2e85` |

Следующий приёмочный шаг — штатный запуск того же кандидата из
меню «Пуск» в отдельном интерактивном сеансе Windows. Состав окна,
кабинет, меню «Вид» и управление клавиатурой остаются открытыми;
эта проверка не закрывает T097 и не меняет статус выпуска.

## 2026-11-08: установка, обновление, самопроверка AEC3 и откат точного 0.1.0.29

В Windows 11 ARM64 / Parallels создан новый временный обычный
пользователь без существующей регистрации GRAF. Использованы ранее
установленные зависимости и уже доверенный сертификат разработки;
системное доверие не менялось. Входы сверены по SHA-256 обоих MSIX
и EXE внутри них. Для кандидата 229 из 231 входа сборки совпали
с текущей рабочей копией; два расхождения — документация сценариев
и проверка окна, которые не входят в продуктовый пакет.

1. Установлена 0.1.0.18. Во временном `LocalState` создан один
   искусственный контрольный файл. Независимый процесс сверил
   регистрацию и хеш установленного EXE.
2. Установлена 0.1.0.29 поверх 0.1.0.18. Контрольный файл сохранился
   побайтно. Независимый процесс сверил новую регистрацию и EXE.
3. В контексте пакета точный установленный EXE 0.1.0.29 выполнил
   `--verify-audio-backend` и вернул код **73**: идентичность пакета
   подтверждена, самопроверка AEC3 на двух искусственных потоках
   прошла. Окно, аудиоустройства и кабинет не открывались.
4. Через `Add-AppxPackage -ForceUpdateFromAnyVersion` выполнен
   откат до 0.1.0.18 без предварительного удаления. Хеш файла
   снова совпал, старая регистрация и EXE подтверждены.

Временная регистрация, учётная запись, профиль и входной каталог
удалены. Независимый запрос Windows подтвердил нулевое число
остатков стенда и единственную рабочую 0.1.0.18. Её EXE, PID 12304
и время запуска не менялись; окно отвечает. Программа проверки
под обычным пользователем вернула 0, итоговая квитанция содержит
все четыре подтверждённые фазы и завершение очистки. Внешняя
обёртка zsh после выполнения команды ошиблась при записи кода
выхода в зарезервированную переменную; вывод Windows и отдельная
проверка очистки сохранены. Прогон не повторялся.
