# T097 — закрытие нативных настроек во время активации

База F200 `3dfeaff5a6774ab12be781547e4a300f9ce2a46c`, работа
в действующем срезе высокого риска. T097 / #7240 остаётся открытой.
Правка времени жизни окна соответствует FR-002/005/006 и SC-002/009:
полномочия, маршрут, размеры и действия пользователя не изменены.
Независимый просмотр подтвердил, что `Closed` обнуляет поле, которое
первое открытие читает после `Activate`; найденные прямые `Close`
выделены в отдельные сценарии проверки. Чеклисты требований:
554 отмечено, 0 открыто; это не приёмка продукта.

На Windows 11 ARM64 / Parallels нативный стенд Release x64
использовал настоящие WinUI Window, Activated и Closed. Обработчик
стенда закрывал окно синхронно из события Activated. Это управляемое
воспроизведение порядка событий, не наблюдение падения в установленном
GRAF при обычной работе.

| Случай | Наблюдение |
| --- | --- |
| Прямой Close после обычного открытия | Один Closed, Close вернулся, код 0 |
| Close с локальной ссылкой после обычного открытия | Один Closed, Close вернулся, код 0 |
| Закрытие из Activated, прежнее открытие | Closed внутри Activate, затем процесс завершился с `0xC0000005` |
| Закрытие из Activated, локальная ссылка и проверка окна | Closed внутри Activate, Activate вернулся, изменение размера не вызвано, код 0 |

В `openNativeSettings` первое и повторное открытие теперь удерживают
ссылку до возврата из активации. Размер первого окна меняется только
если оно всё ещё текущее. Обычные Close в настройках не менялись.
Стек внутри WinUI не исследовался. Отдельной проверки требуют
случаи выхода из приложения с открытыми настройками/обновлениями
и активация окна проигрывателя.

Полный файл с правкой прошёл MSVC x64 `/Zs /WX`: 231 исходный
вход Windows и сценарий компиляции сверены, временная гостевая
копия удалена. В репозиторий внесён побайтно тот же AppMain.
