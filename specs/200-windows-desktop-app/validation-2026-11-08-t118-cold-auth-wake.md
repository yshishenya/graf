# T118 / SC-005 — 100 повторных открытий после подтверждённой отправки

На Windows 11 ARM64 / Parallels собран MSVC x64 Debug стенд на входах
GRAF 0.1.0.29, ветка `codex/200-windows-followup`,
`3dfeaff5a6774ab12be781547e4a300f9ce2a46c` с текущими изменениями.
Сверены 231 входной файл. Изменён только тестовый
`NativeCaptureStorageIntegrationTests.cpp`: вместо одного холодного
открытия существующий сценарий делает 100. Продуктовый код не менялся.

Стенд создал защищённую запись из 3000 искусственных аудиоблоков
(30 секунд), штатно завершил её, независимо проверил хеши, целостность
и AAC, отправил её через имитацию сервера и дождался принятия результата
в локальную очередь. Имитация проверяла точные тела и диапазоны.
На этом этапе: одно создание встречи, одна сессия загрузки, одно
завершение загрузки, девять запросов загрузки всего.

В каждом из 100 циклов новый экземпляр `NativeCapture` в том же
тестовом процессе холодно открывал прежнее хранилище. Он сначала
обрабатывал событие пробуждения без учётных данных, затем получал
искусственную сессию и после следующего пробуждения заново подтверждал
аккаунт. После завершения фоновой работы оставалась одна и та же
отправленная запись с теми же владельцем, встречей, сессией и
принятыми диапазонами. Каждый цикл сверял имена и хеши файлов.

**Результат:** 100/100, ни одного нового запроса загрузки после первой
отправки. Общее число запросов проверки аккаунта — 404, включая
исходную запись и отправку. Прогон завершился кодом 0; память,
учитываемая защищённым хранилищем, вернулась к исходному уровню.
Первый прогон также дошёл до 100 циклов, но завершился на оставшейся
проверке счётчика для одного холодного открытия. Для успешного повтора
изменена только эта итоговая проверка стенда.

Рабочий GRAF 0.1.0.18 сохранил прежние хеш EXE, PID и время старта.
Микрофон, рабочие данные и сеть не использовались; временные каталоги
удалены, журналы и накладка сохранены.
