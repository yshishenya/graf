# Проверка Windows в запросах на слияние

План опытного запуска в рамках F200. Он дополняет FR-002, FR-006,
SC-002 и SC-009: один общий кабинет, сравнимые сценарии на macOS и
Windows и отдельная проверка нативных действий. Настройки защиты
ветки и условия выпуска пока не меняются.

1. Для запроса в `master` брать точный SHA исходной ветки из события
   GitHub, сверять его с фактически извлечённым `HEAD` и отдельно хранить
   базовый SHA. Переиспользовать `scripts/ci-pr-scope.py` с отдельной
   копией инструментов, как в действующем `macos-pr`: он читает полный
   список изменений от общей базы, включая старые пути при
   переименовании. Изменения Windows, macOS, общего кабинета, моста и
   самого задания требуют проверки; неизвестные пути тоже считаются
   потенциально общими. До определения области не применять фильтр
   путей в событии GitHub. Если область вычислить нельзя, показывать
   ошибку; пропуск допустим лишь при известной области вне настольных
   приложений. При новом head, переносе PR на другую базовую ветку или
   изменении проверяемого base прежний результат не подтверждает
   новую пару head/base.
2. На машине GitHub `windows-2022` собрать CMake/Ninja Release x64
   существующим MSVC 2022. Перед сборкой проверить архитектуру машины,
   компилятора и цели; в отчёте оставить версии инструментов.
   Для первого прогона: `RecordingAudioTimelineTests`,
   `WebViewRoutePolicyTests`, `WebViewBridgeEnvelopeTests`,
   `NativeHashFailureTests` и `NativeCustodyProtectionFailureTests`.
   Это искусственные проверки времени, маршрутов, моста и отказов
   защищённого хранения. PASS требует успешного кода завершения CTest
   и ровно одного подтверждённого прохождения каждого из пяти тестов
   в JUnit. Отсутствующий, повторный, отключённый, пропущенный,
   завершившийся с ошибкой или по тайм-ауту тест исключает PASS.
3. Выполнять код PR только на одноразовых машинах GitHub через
   `pull_request`. Разрешить токену только чтение исходников,
   не сохранять учётные данные извлечения, не подключать секреты,
   среды развёртывания, OIDC и кэш с другими заданиями. Закрепить
   действия по полному SHA. PR из форков обрабатываются только
   когда их запуск разрешён действующими правилами GitHub; правила
   форков опытный запуск не меняет. `pull_request_target` не
   исполняет код PR. Не открывать устройства, не устанавливать MSIX
   и не менять доверие к сертификатам.
4. Публиковать репозиторий, номер PR, head/base и workflow SHA,
   идентификатор запуска и номер попытки, решение об области и
   контрольную сумму списка путей, тип машины и список тестов. Если
   CTest запущен, сохранить JUnit при его наличии. Пропуск или ошибка
   должны отличаться от успешного прогона, в том числе до CTest.
   Журнал и JUnit содержат данные исполняемого PR; они диагностические
   и не могут служить доверенным разрешением на слияние, выпуск или
   изменение рабочего сервера. PR может менять собственные тесты и
   файл задания.
5. До использования результата как условия слияния отдельно
   подтвердить запуск на GitHub: подходящий запрос даёт отчёт на точном
   SHA; неподходящий даёт объяснимый пропуск; переименование из
   области Windows в документацию вызывает проверку; новый head или
   retarget не принимают старый результат. Отдельно подтвердить
   видимый отказ от намеренно сломанного и от удалённого теста.
   Существующие задания и требования остаются в силе. Отдельный
   контроль доверия к заданию нужен до изменения защиты ветки.
   Ни статус задания, ни отчёт не заменяют T063/T071:
   проверку настоящего ПК, устройств, AEC3, установленного MSIX,
   пользовательских сценариев и доступности.

Справка: [машины GitHub Actions](https://docs.github.com/en/actions/reference/runners/github-hosted-runners),
[инструменты образа Windows Server 2022](https://github.com/actions/runner-images/blob/main/images/windows/Windows2022-Readme.md),
[исполнение кода PR и границы доверия](https://docs.github.com/en/actions/reference/security/secure-use#mitigating-the-risks-of-untrusted-code-checkout).

## Предварительный локальный прогон

В Parallels (Windows 11 ARM64) MSVC 14.44.35207 собрал пять выбранных
целей Release x64 из отдельного архива коммита
`972af4762e7afc1a5a1c8d9025aec1eb6ce7127e`. CMake 4.4.2,
Ninja 1.13.2. CTest: **5/5**, ноль пропусков и ошибок, 2,40 с
на тесты после сборки. Сборка и тестовые данные находились в отдельном
каталоге Windows; каталог и копия исходников удалены. GitHub Actions
и нативный хост x64 пока не проверены.

Проверка действующего определителя области: 13 тестов управления
прошли. В отдельном искусственном репозитории набор из 307 документов
пропускает нативное задание, путь Windows включает его, а изменение
неизвестного модуля на 308-й позиции также включает проверку. Несовпавший
`HEAD` и отсутствующая база отвергнуты.

Проверка правила PASS: разбор отчёта принял исходный JUnit Windows
с пятью результатами и положительный искусственный прогон CTest на
Mac. Реальные отчёты CTest для удалённого, отключённого, пропущенного
и повторного теста вернули код 0, но правило PASS их отклонило.
Отдельно отклонены упавший тест и тайм-аут (код CTest 8), отсутствующий
и повреждённый отчёт. Это проверка правила на изолированных данных,
а не доказательство работы задания GitHub.
