# Фактическая автоматическая серверная обработка — T014/#3361

Дата: 2026-11-17. Lane: `high-risk-product`. Этот контракт уточняет способ
доказательства действующих FR-026–030/040/042 и SC-013/015/020/022.
Он не добавляет API, схему, продуктовый режим или новое право на рабочие данные.
Исторические контракты сохраняются в своей области; новые first-party источники
подчиняются F275, без создания старых microphone/system пакетов.

## Область и этапы

| Этап | Обязательный результат | Граница доказательства |
|---|---|---|
| A: связность | Настоящий HTTP accepted-source → commit → автоматический dispatcher → Temporal workflow/Worker → MinIO/FFmpeg → canonical; успешный WAV и принятый повреждённый источник | Только эти два сценария, без закрытия T014 |

| C: отказы и жизненный цикл | Quickstart §§6–9: ограничения, missing/mismatch, lost dispatch, retry/restart, backfill, конкуренция, deletion/retention, Range и состояния | Подменённый транспорт и прямой вызов job не считаются настоящей автоматической цепочкой |

На начало этапа A/B/C **не были исполнены**; A исполнен 2026-11-18 UTC, B/C открыты. Исторические подтверждения и
guard #8128 сохраняют собственные границы. Непроверенный случай остаётся
открытым; никакой новый этап не отменяет исходные критерии issue.

## Изоляция до импорта и collection

Отдельный запускатель вызывает существующий PostgreSQL runner в дочернем
процессе с новым явно составленным окружением. Это происходит до pytest
collection и Alembic. Не наследуются прикладные переменные, proxy/cloud
credentials, `PYTHONPATH`, `PYTHONHOME`, `PYTEST_ADDOPTS`, `PYTEST_PLUGINS`
и пользовательские `UV_*`. Из системных значений допустимы проверенный PATH,
существующий HOME без изменения его значения и locale. `TMPDIR` — собственный
каталог `0700`. Явно включены `UV_NO_ENV_FILE=1`, `UV_NO_CONFIG=1`,
`UV_OFFLINE=1`, frozen dependencies; отсутствие готовых зависимостей — ошибка.

До collection проверяется отсутствие root `.env` и `apps/server/.env`, в том
числе dangling symlinks, без чтения их содержимого. Наличие останавливает опыт;
переименовывать чужие файлы нельзя. Все Settings передаются явно с
`_env_file=None`; очищенное окружение защищает также `Settings()` миграций.
Только отключения dotenv недостаточно. Processing, AI, почта, платежи,
аналитика и любые рабочие интеграции выключены. Применяется собственная
синтетическая авторизация через существующую fixture, без настоящих аккаунтов.

Docker допускается только через заранее проверенный локальный Unix socket,
явный `DOCKER_HOST` и собственный пустой `DOCKER_CONFIG`. Удалённый daemon,
общие Compose-проекты, тома, фиксированные порты и перезапуск служб запрещены.
До запуска проверяются свободное место по AGENTS и наличие нужных локальных
образов. Скачивание недостающих образов не является скрытым запасным путём.

## Настоящие зависимости

- PostgreSQL: существующий `scripts/run_local_postgres_tests.sh --focused`,
  его одноразовый PG17 и настоящие миграции. Для этого запуска используется
  описанная ниже передача владения; общий runner получает узкое дополнение,
  а не подменяется копией или перехватчиком Docker. До первого SQL, миграций
  и сценарных данных фактический image ID собственного контейнера должен
  совпасть с заранее принятым локальным ID. Отсутствие, изменение или
  неизвестное владение — ошибка; один изменяемый tag недостаточен.
- API: отдельный `create_app(settings)` с настоящим storage, собственным
  PostgreSQL и Temporal client; `httpx.AsyncClient(ASGITransport)` в той же
  асинхронной петле. Общий синхронный TestClient не переносит client между
  петлями. Lifespan/engine teardown обязателен.
- MinIO: один собственный одноразовый контейнер из уже имеющегося образа
  `minio/minio:RELEASE.2025-05-24T17-08-30Z`; image ID проверен и передаётся
  `docker run --pull=never`. Только случайный `127.0.0.1` порт, синтетические
  credentials и bucket, память/CPU ограничены, данные временные, именованных
  томов нет. Имя/label/ID владельца проверяются перед удалением.
- Temporal: существующий SDK `temporalio==1.30.0` и `start_local` с явным
  `dev_server_existing_path`, `ip=127.0.0.1`, случайным портом, `ui=False`,
  SQLite в памяти и настоящими часами. Нельзя использовать незафиксированный
  `default` download или time skipping для этого доказательства.
- Для локального Mac принят уже установленный CLI **1.8.2**, сообщающий Server
  **1.31.2**, SHA-256 обычного исполняемого файла
  `268711d469c0b8a981251d49c4f2150c7ae41665018800749b95ca44aa83593a`.
  Несовпадение — ошибка до запуска; совместимость SDK/server подтверждена прогоном A 2026-11-18 UTC.
  Другая платформа требует отдельно проверенного бинарника и checksum.
- Worker: `create_normalization_temporal_workers` с отдельной уникальной
  очередью. Зарегистрированная activity только передаёт настоящий payload и
  реальные зависимости в `run_playback_normalization_activity`. Никакого
  fake storage/pipeline/client, подмены результата или прямого вызова job.
  FFmpeg/ffprobe — настоящие локальные бинарники; версия и SHA фиксируются до
  опыта. Этот host-процесс не доказывает контейнерные ресурсы production worker.

API использует owner-backed fixture; это **не** проверка production API grants.
Activity использует отдельный `twobrain_rec_media` sessionmaker из штатной
fixture. Перед обработкой определены проверки `NOSUPERUSER`, `NOBYPASSRLS`,
`row_security=on`, нужной tenant scope и отказа чужому tenant. Пропуск или
подмена media-role owner-соединением делает опыт недействительным.

## Передача владения PostgreSQL и аварийная очистка — H1

Обнаружен пробел интерфейса: прежний общий runner выбирает неизвестное
родителю имя и удаляет контейнер только своим EXIT trap. Поэтому узкое
изменение `apps/server/scripts/run_local_postgres_tests.sh` и его проверок
теперь явно входит в этот этап. Это не найденный сбой production и не повод
менять продуктовый runtime. Обычные вызовы runner без нового контекста
сохраняют существующие выбор тестов, режимы, RLS и результаты.

Единственный новый служебный вход — `GRAF_TEST_POSTGRES_RESOURCE_DIR`.
Запускатель создаёт свой абсолютный каталог `0700` и до запуска child пишет
в нём обычный `postgres-resource.json` с правами `0600`. Ровно четыре поля:
`schema_version=1`, `run_token` (32 lowercase hex), `container_name`
(`graf-postgres-test-f099-` + тот же token) и `image_id` (`sha256:` + 64 hex).
До любого создания ресурса те же безопасные значения и состояние
`cleanup_required` сохраняются отдельной внешней квитанцией. Паролей,
database URLs, media или окружения в ней нет. Имя и label известны родителю
до Docker, поэтому потеря ответа create или отсутствие cidfile не теряют
владельца ресурса.

Runner до collection проверяет схему, отсутствие лишних полей, владельца,
права и отсутствие symlink у каталога/manifest; недействительный или неполный
контекст останавливает запуск. Контекст разрешён только для `--focused`;
`--collect-only` проверяет его без Docker и без создания ресурсов. Пути
`postgres.cid` и `postgres-state.json` выводятся из собственного каталога,
не принимаются отдельно; существующий cidfile/symlink запрещает create.

Перед bootstrap runner атомарно пишет `postgres-state.json` с фазой
`starting` и монотонным временем; внешний процесс ограничивает этот этап
60 секундами. Он сверяет наличие принятого local image ID, запускает именно
его с `--pull=never`, `--cidfile` и label
`pro.2brain.graf.f099.run=<run_token>`. До первого SQL проверяет фактические
ID, точное имя, label и image ID контейнера. После готовности и выдачи
одноразовых DB targets атомарно пишет фазу `ready`; повторный start не
обнуляет общий 60-секундный предел. Для повторного create прежний контейнер
должен быть подтверждённо удалён и отсутствовать; лишь тогда свой cidfile
можно убрать. Любой неизвестный результат останавливает повтор.

Runner и внешний процесс перед удалением проверяют точное имя, label и image;
после проверки удаляют по фактическому container ID, а не широкому prefix.
Отсутствие подтверждается успешным точным lookup; ошибка Docker не означает
отсутствие. Чужой label/image/name, неоднозначный lookup и неизвестная identity
дают FAIL без удаления. Поиск всех `graf-postgres-test-*` и разница docker ps
не являются основанием владения. Общий `docker prune` запрещён.

После TERM/KILL child, превышения срока или обычной ошибки внешний запускатель
завершает только свою группу процессов и очищает проверенные собственные
ресурсы, независимо от child trap/cidfile. TERM grace и ожидание после KILL
ограничены 5 секундами каждое; каждая операция очистки — 30 секундами.
SIGKILL самого единственного supervisor не имеет гарантированного обработчика:
его заранее сохранённая квитанция остаётся `cleanup_required`, опыт не PASS.
Дальнейший владелец — основной агент/оператор следующего продолжения; до нового
опыта он сверяет эту квитанцию с фактическими identity/labels/image и остатками,
очищает только доказанно свои ресурсы и пишет отдельный итог. При сомнении
ресурс не удаляется, состояние остаётся FAIL; новый daemon/watchdog не вводится.

До настоящего A нужны ограниченные проверки со служебными doubles, без
утверждения о real-transport acceptance: malformed/symlink/foreign manifest
до create; image/label/name mismatch до SQL; create failure до и после
появления контейнера, включая смерть child до записи cidfile; TERM/KILL child;
bootstrap/whole-run timeout; cleanup failure/unknown absence; повтор только
после подтверждённого удаления; сохранность параллельного чужого контейнера.
Проверяются также отсутствие секретов в failure/evidence и сохранение обычного
runner contract. Эти проверки разрешены для управления опытом, но не заменяют
настоящие зависимости и A/B/C.

## Обнаружение и обычный CI — H2

Приёмочный файл расположен вне `testpaths=[tests]` и имеет имя
`acceptance/playback_normalization_real_transport.py`, которое также не
совпадает с `test_*.py`/`*_test.py`. Он выбирается только явной командой
очищенного запускателя. Не менять общий pytest config,
CI inventory/partition map, workflow или `--ignore` ради его исключения.
Обычные collection и execution без CLI/MinIO/приёмочного контекста не
импортируют этот файл, не создают его ресурсы и сохраняют весь прежний набор
тестов; новых skip/xfail как способа исключения нет.

До любых application imports приёмочный модуль стандартной библиотекой
проверяет явный контекст запускателя и его безопасный manifest. Затем
подключает существующие fixtures через `pytest_plugins=("tests.conftest",)`,
без копирования seed/role fixture. Родительского conftest в `apps/server`
нет; `tests/conftest.py` не загружается автоматически для этого пути.
В новом собственном режиме PG runner явно загружает
`tests.fixtures.test_resources` также для предварительного collection, чтобы
его inventory options существовали до разбора pytest CLI. Это дополнение
ограничено новым контекстом; обычный discovery/CI не меняется.

Обычный автоматически обнаруживаемый
`tests/contract/test_playback_normalization_real_transport_runner.py`
проверяет эту границу на синтетическом проекте с настоящим pytest discovery
и явным выбором файла, без реального API/Docker/Temporal. Импорт stdlib-only
запускателя также не читает настройки и не запускает ресурсов. Проверки
общего runner дополняются в существующем
`tests/contract/test_local_postgres_test_runner.py`. Отдельно фиксируются
обычные collection/execution и явный acceptance запуск: явно выбранный файл
без корректного контекста завершается FAIL до импорта приложения/миграций
и без создания ресурсов. Missing dependency/skip/setup/timeout по-прежнему
не дают A PASS. Подготовка недостающих frozen dependencies — отдельное
явное действие до опыта; скрытая установка во время collection запрещена.

## Сценарии этапа A

Оба источника создаются только в собственном временном каталоге:

1. Короткий синтетический WAV PCM mono/16 kHz, пригодный для полного decode.
2. Непустой повреждённый файл из одного нулевого байта с синтетическим именем
   `invalid.wav`, `audio/wav`, `duration_seconds=1`, уникальным
   `local_recording_id`, `archive_audio=true`. Пустой файл не подходит:
   он отклоняется до accepted-source boundary и не доказывает отказ worker.

Проверка отправляет только настоящий `POST /api/v1/media-uploads`.
Она не вызывает dispatcher, `start_workflow`, reconciliation или
`run_normalization_job`; workflow handle разрешён только для наблюдения.
Оба HTTP ответа должны быть 202; непредвиденный отказ API не считается
отрицательной приёмкой normalization.

Перед делегированием настоящей activity допускается ограниченный барьер
наблюдения: отдельная DB-сессия подтверждает accepted revision, один durable
job и отсутствие доступного canonical. Барьер не заменяет activity и не
создаёт задания. Обёртка наблюдения verified-download делегирует настоящий
метод без изменения аргументов, данных, исключений и результата; отдельно
подтверждается его вызов для исходника, а не только для скачивания результата.

Успешный WAV: один record/revision/job, `ready`, ровно один validated/stored
playback, опубликованная attempt, правильная исходная lineage, неизменные
source bytes/digest. Настоящим helper скачивается именно сохранённый canonical;
независимо проверяются размер/digest, BMFF/profile и полный strict decode.
Авторизованный Range возвращает правильные 206/Content-Range и байты этого
объекта. Успех playback не объявляет успех transcript/summary.

Повреждённый источник: **точно `terminal/corrupt_source`**, без
`next_attempt_at`, canonical ID, validated/stored playback, published attempt
или доступного playback-объекта. Accepted source остаётся в исходном размере
и с исходным digest. `unsupported_*`, `dependency_unavailable`, timeout,
отказ collection/setup и skip не заменяют ожидаемый исход. Объекты и файлы
своей незавершённой попытки должны быть удалены.

## Ограничения времени и очистка

Пределы этапа A: старт каждого ресурса ≤60 секунд, ожидание каждого сценария
≤120 секунд, отдельный download/probe/decode ≤60 секунд, teardown каждого
ресурса ≤30 секунд, весь дочерний запуск ≤600 секунд. Это пределы проверки,
не новые продуктовые лимиты. Большая исходная матрица использует существующие
пределы контрактов и отдельные измерения, без их искусственного уменьшения.

Остановить Worker до Temporal/DB; затем закрыть HTTP/lifespan, storage и engines.
Удалить только свои MinIO/PostgreSQL контейнеры и work directory. При ошибке
или таймауте внешний запускатель завершает свою группу процессов и выполняет
проверяемую очистку по сохранённым ID/labels. Обычный `async with`/EXIT trap
не объявляется гарантией ограниченного завершения, особенно после SIGKILL.
Неудачная очистка — FAIL с безопасным описанием остатка; `docker prune`
запрещён. Сырые бинарники/зависимости/аудио/резервные копии в evidence не остаются.

## Доказательства и оставшиеся ворота

Receipt содержит SHA исходников и изменённых файлов, версии/checksums/image ID,
полный список реально исполненных строк матрицы и их результат, counts,
автоматичность dispatch, source/output integrity, RLS-role, ограниченные сроки
и cleanup. Только безопасные метаданные, без адресов с паролями, credentials,
ключей объектов, stderr, имён рабочих файлов и содержимого media.

Stage A PASS не подтверждает B/C, `run_worker()` startup/reconcile, non-root
production container, near-limit benchmark, UI/единственный GRAF Dev,
release/deploy или полный #3361. Их отдельные применимые ворота и исходные
условия остаются открытыми. До реализации нужны независимые применимые
checklists, analyze и sync существующего #3361. До слияния — штатные точные
SHA/current-base PR checks и review; до COMPLETED — исходная приёмка,
русский комментарий, `validate-issue-closeout.py --verify-live` и live state.
