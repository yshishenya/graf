# Media storage read contract

Внешний API и ответ интерфейса не меняются. Внутренний контракт: `effective_paid_storage` работает под настоящей `twobrain_rec_media` с worker-контекстом и ровно SELECT столбцами из data-model.md.

Настройка ролей: в одной транзакции убрать прежние права столбцов этих четырёх таблиц, назначить точный набор, проверить таблицы/столбцы/атрибуты; второй запуск даёт тот же результат. Избыточные табличные и столбцовые права отвергаются проверкой. Нет контекста → нет строк; другая область → нет чужих строк; лишние поля/финансовая запись → отказ PostgreSQL.

Бонус с NULL-снимком сохраняет прежнюю квоту подписки; будущие/истёкшие права не выдаются сейчас. Ошибки квоты, удаления, целостности и зависимостей сохраняют существующие конечные/повторные состояния.

## Граница доверия контекста

Существующие финансовые политики PostgreSQL проверяют вид контекста и workspace_id из доверенной серверной сессии; принадлежность пользователя/устройства устанавливает сервер до этой точки. F287 не меняет этот механизм. Проверяем отсутствие контекста, удалённый workspace_id, подмену вида контекста на maintenance под медиаролью и взаимную изоляцию двух валидных рабочих контекстов. Произвольная подмена доверенной службой всего workspace_id не является новым обещанием проверки идентичности на уровне этих таблиц.
