# Feature Specification: Надёжная подготовка аудио при платном хранении

**Feature Branch**: `287-audio-storage-permissions`
**Created**: 2026-10-10
**Status**: Draft
**Input**: Пользователь просит устранить причину повторного зависания аудио после завершённой расшифровки.

## Clarifications

### Session 2026-10-10

Проведён обязательный `$speckit-clarify`: критических продуктовых неоднозначностей нет. Все категории покрытия ясны. Существующий расчёт объёма, права владельца, автоматическое восстановление, квоты и правила удаления сохраняются. Изменяется лишь возможность штатной службы прочитать минимальные факты для этого расчёта. Выпуск требует отдельного разрешения по правилам проекта.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Аудио становится доступным при оплаченной подписке (Priority: P1)

Владелец завершает встречу; полученное сервером аудио проходит подготовку и становится доступно даже когда объём хранения определяется подпиской, бонусом или дополнением.

**Why this priority**: Сейчас доступная расшифровка может сопровождаться многодневным ожиданием аудио из-за отсутствующих прав службы.
**Independent Test**: Синтетическая встреча в изолированной базе проходит подготовку от штатной ограниченной службы и получает доступный проверенный аудиофайл.

**Acceptance Scenarios**:

1. **Given** действующая платная подписка без дополнительных прав, **When** завершена загрузка и есть свободная квота, **Then** подготовка завершается с доступным аудио без ошибки доступа к расчёту хранения.
2. **Given** действующий бонус или дополнение хранения, **When** служба рассчитывает объём, **Then** результат совпадает с существующим расчётом и не включает будущие/истёкшие права.
3. **Given** уже запланированный повтор после ошибки доступа, **When** права службы исправлены и наступает повтор, **Then** существующая задача завершается без дубликата встречи или повторной расшифровки.

### User Story 2 - Служба видит только необходимые данные (Priority: P1)

Оператор исправляет подготовку аудио, сохраняя границы доступа службы.

**Why this priority**: Подготовка аудио не требует доступа к адресам, платёжным данным или возможности изменять финансовые записи.
**Independent Test**: В той же базе разрешено чтение только необходимых полей текущей рабочей области; посторонняя область, лишние поля и финансовые изменения недоступны.

**Acceptance Scenarios**:

1. **Given** две рабочие области, **When** служба читает факты хранения, **Then** видны только строки области из установленного контекста доступа.
2. **Given** ограниченная служба, **When** запрашиваются прочие поля или изменение финансовых записей, **Then** база отклоняет запрос.
3. **Given** повторная настройка служебных прав, **When** она завершена, **Then** необходимое чтение сохраняется, а избыточные разрешения не появляются.

### Edge Cases

- Бесплатная и пробная подписки сохраняют прежний расчёт.
- Действующий бонус с пустым снимком объёма сохраняет прежний запасной расчёт.
- Есть будущие/истёкшие дополнения, старый счёт или исторический кэш расширенного объёма: значения совпадают с текущими правилами.
- Недостаточная квота, недоступное хранилище, повреждённый источник и удаляемая встреча сохраняют прежние отказы и восстановление.
- Разрыв контекста рабочей области не разрешает чтение других клиентов.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Подготовка принятого аудио MUST завершаться под штатной ограниченной службой при достаточном объёме хранения для всех действующих вариантов подписки.
- **FR-002**: Расчёт оплаченного объёма MUST сохранять прежние значения для бесплатной/пробной/платной подписки, бонусов, дополнений, будущих/истёкших прав и исторических снимков.
- **FR-003**: Службе MUST быть разрешено читать только поля финансовых записей, необходимые для расчёта хранения; другие поля и запись финансовых данных MUST оставаться запрещены.
- **FR-004**: Все новые разрешения MUST сохранять изоляцию рабочих областей, отсутствие повышенных прав и требование установленного контекста доступа.
- **FR-005**: Повторная штатная настройка прав MUST сохранять точный минимальный набор разрешений и отклонять лишние права при проверке.
- **FR-006**: Исправление MUST сохранять контроль целостности, декодирование, квоты, защиту от удаления и дубликатов, существующую последовательность повторов и отсутствие повторной генерации текста.
- **FR-007**: Проверки MUST воспроизводить исходный отказ под реальной ограниченной ролью в одноразовой базе и подтвердить успешную подготовку после исправления, недоступность чужих строк/лишних полей/записи, повторную настройку прав.
- **FR-008**: Журналы и артефакты MUST содержать только синтетические данные и технические метаданные; выпуск MUST пройти существующие проверки и отдельное разрешение владельца.

### Key Entities

- **Право хранения**: действующий оплаченный/бонусный интервал и объём; владельцем остаётся существующая подсистема оплаты.
- **Служба подготовки аудио**: ограниченная серверная учётная запись с контекстом рабочей области.
- **Задача подготовки**: существующая устойчивая задача, аудиоисточник, проверенный результат и статус.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Все заявленные варианты объёма дают прежний результат; разрешённая подготовка переходит в готовность без отказа доступа к финансовым фактам.
- **SC-002**: В каждой проверке чужая рабочая область, лишнее поле и финансовая запись остаются недоступны службе.
- **SC-003**: После двух настроек прав итоговый набор разрешений совпадает с утверждённым минимумом; проверка лишнего разрешения завершается отказом.
- **SC-004**: Причинная проверка до изменения воспроизводит отказ доступа, после изменения проходит; обязательные проверки выполняются без пропусков.

## Assumptions

- Ошибка подтверждена серверным сообщением `permission denied for table time_credit_ledger_entries`; сырой звук и текст встречи не нужны для её воспроизведения.
- Вне объёма: изменение интерфейса, аудиозахвата, цен/платежей, схемы финансовых данных, политики хранения, публикация и изменение рабочего сервера до отдельного разрешения.
- Используются существующие службы подготовки, расчёта хранения, настройка ролей и изолированные проверки PostgreSQL.
