# Первое включение полноценных протоколов: передача общему выпуску

**Только инструкция, не выполненный выпуск.** Feature 239 заканчивается
проверенным PR. Merge, release, deploy и Langfuse `production` — отдельная
задача владельца. PR #6661 снял техническое ограничение модели, но не включил
протоколы. Отдельного выпуска прежнего плоского формата больше не планируется.

## До передачи

Нужны exact SHA, convergence/review/CI, новый полный пригодный корпус после
последней общей правки, самостоятельные оценки Codex, семь реальных controls
и privacy review. Все модельные параметры принадлежат exact Langfuse config.
На текущем срезе это **не завершено**; release-qualified root не выбран.
Экспериментальная метка `dev` и локальный hash не разрешают production.

## Единственная операторская команда

`python -m twobrain_rec_server.cli.prompt_optimization promote-root`
использует действующие operator Settings и maintenance database identity.
Включать автоматическую оптимизацию для команды не требуется. Аргументы:

- `--operation-id`: UUID операции; повтор сохраняет тот же UUID;
- `--run-id`: UUID полностью проверенного оценочного прогона;
- `--actor-id`: оператор, одобривший именно этот комплект;
- `--expected-source-version`: фактическая числовая версия текущего root label;
- `--workdir`, `--source-host`, `--source-container`: приватный каталог оценки
  и прежний read-only источник полного корпуса;
- `--confirm`: явное подтверждение операции.

Новая операция требует в оценочном каталоге два дополнительных JSON файла
0600; каталог — 0700, вне checkout:

- `evaluation-settings.json`: настройки существующей отдельной оценочной БД,
  очереди, проекта Langfuse и pinned root. Это не модельные параметры.
  Production DB/очередь использовать нельзя.
- `operator-checks.json`: ровно `approved_at`, `protected_label` и
  `sole_mutation_credential`. Две последние записи имеют закрытую форму
  OperatorCheck из contracts/meeting-protocol.md и подтверждают реальные
  возможности проекта/права; неподтверждённая декларация не является проверкой.

Пароли и действующие пути ключей не попадают в Git, PR или обычные журналы.
CLI возвращает только состояние, operation id, root version и root export hash.
Writer сам вызывает `finalize_run`; произвольный Qualification/PASS JSON
не импортируется. Worker не получает ключ изменения label.

Completed replay проверяет полный Event под lock без новой мутации,
Langfuse или уже очищенных оценочных входов; workdir/source аргументы для него
можно опустить. Историческая квитанция не утверждает, что текущий label
по-прежнему указывает на этот root.

`reconciliation_required` требует отдельной операторской сверки:
нельзя повторять перемещение новым operation id или приписывать авторство
изменения по одному read-back. `root_bundle_source_conflict` требует заново
проверить намерение и ожидаемую исходную версию, а не молча подменить аргумент.

## Порядок отдельного общего выпуска

1. Зафиксировать общий release candidate/SHA; пройти release-full и CD dry-run.
2. Остановить новый AI/optimizer/evaluator dispatch. Завершить либо явно
   классифицировать текущие попытки; ambiguous inference не повторять.
   Запись и расшифровка остаются независимыми от AI-допуска.
3. Установить проверенный GRAF и миграции, включая операторский журнал.
   До первого допуска новый AI не исполняется; рабочего v1/fallback нет.
4. Перепроверить текущий root, protected label, единственный ключ мутации
   и полный отчёт; выполнить операторскую команду. Она сохраняет prepared,
   делает одно перемещение, проверяет exact read-back и атомарно пишет Event/current.
5. В отдельно разрешённом инфраструктурном scope убрать остаточную
   регистрацию/mount/переменные старого GRAF callback в LiteLLM, если остались.
   Сам специальный pre-call запрет снят ранее. Обычные guardrails, ключи,
   upstream routes, бюджеты и лимиты не менять.
6. Проверить production loader, все три стадии на synthetic smoke,
   request settings/provenance, HTTP-кандидат, принятие, таймкоды,
   share/export и observations. Возобновить AI только после PASS.

Первое включение не требует выдуманного прошлого PromotionEvent.
Безопасный выход при сбое — остановить новые AI-вызовы. Возврат deployment
image не является legacy-веткой в новом коде и здесь не выполняется.
