# Контракт генерации и отображения

## Запрос и ответ

Редакционное ядро: [original-prompt.md](../original-prompt.md), исходный
пользовательский `draft-meeting-minutes` без YAML-метаданных. Оно сохраняется
дословно; отдельный небольшой адаптер меняет только форму ответа на JSON
и задаёт Ref по sequence. Все встроенные и пользовательские форматы получают
полный документ; профиль меняет акценты/подробность, но не включает плоскую
генерацию или альтернативный fallback.

Существующие HTTP-вход и Temporal workflow остаются. Prompt snapshot содержит
исходный editorial prompt, небольшой адаптер JSON/refs и настройки Langfuse.
Ввод: полная каноническая расшифровка с номерами и достоверная метаинформация.
Системная дата не подставляется как дата встречи.

Модель возвращает только MeetingProtocol из [data-model.md](../data-model.md).
Проверка структуры не оценивает смысл; второй LLM нет. Prompt требует для
решений источник согласия, для задач подтверждения задания/исполнителя/срока,
в том числе нескольких разнесённых фрагментов. Общие примечания не требуют
выдуманных источников. Отсутствующие разделы используют empty states исходного
промпта. Частичность источника видима, новые сведения не додумываются.

## Представление

UI, Markdown, TXT, JSON и XLSX читают опубликованный outcome, не journal.
Порядок разделов соответствует первоначальному образцу. В HTML текст
экранируется, задачи — доступная таблица; ссылки используют существующий
переход к тексту/плееру, доступны клавиатуре, имя «Источник, <время>».
Без аудио доступен текст. Markdown не экранирует всю обычную пунктуацию:
только необходимые структурные символы, таблицы и ссылки. Ответ не исполняет
HTML/JS, не загружает внешние картинки и не запускает формулы таблиц.
XLSX делит значения длиннее 32767 единиц UTF-16 на последовательные строки
в тех же колонках, без потери текста; продолжения также остаются текстом,
даже если начинаются с `=`.

Настройка «включить основания» сохраняется: при отключении не выдаются
ссылки/цитаты, смысловой текст не меняется. JSON добавляет полный protocol;
нынешние поля API сохраняются точной проекцией для существующих клиентов.
Combined export не смешивает ревизии. Shared view подчиняется прежним правам.

Пустые решения: `Принятые решения в транскрипте не зафиксированы.`
Пустые задачи: `| Задачи не зафиксированы | Не назначен | Не указан |`.
Пустые вопросы: `Открытые вопросы не зафиксированы.` Неизвестная дата:
`Не указано`, пустые участники: `Не определено`. Nullable owner/due выводятся
как `Не назначен`/`Не указан`. Prompt требует в notes точный текст:
`Имена спикеров указаны только в случаях их однозначной идентификации в транскрипте.`
Сервер не дописывает это утверждение как будто его сгенерировала модель.

| Старое API-поле | Детерминированная проекция без извлечения смысла |
| --- | --- |
| summary | executive_summary, затем objectives |
| key_points | название каждой темы, затем context/discussion/proposals/outcome |
| decisions | decisions |
| action_items | task с неизменными owner_text/due_date_text |
| followups | next_steps |
| questions | open_questions |
| evidence | notes |
| risks | [] / unavailable: отдельная проекция не создаётся, риски остаются в темах полного protocol |

Заголовок темы получает объединение её refs без дубликатов; пустая тема
может не иметь refs. Нумерация items каждой категории начинается с 0.
Непустая категория available, пустая not_found, кроме указанного risks.
Для risks полного protocol причина: «Риски отражены в обсуждениях полного
протокола; отдельный список не создаётся». Это ограничение представления,
не утверждение об отсутствии рисков или невозможности их определить.
UI полного протокола не превращает это состояние проекции в ошибку генерации.
Проверка обязательно включает явный риск в теме при пустой проекции risks.
Шапка остаётся только в
полном protocol. Ограниченность плоской проекции не меняет полный документ.
Исторический NULL protocol читается старым отображением без backfill.

`include_evidence=false` удаляет все вложенные source_refs/quote из копии
экспорта, в том числе из полного protocol в JSON; хранимые поля и слова
не меняются. HTML/Markdown/XLSX выводят задачи таблицей, TXT — строками с
разделением колонок. Combined export использует одну закреплённую ревизию.

## Ошибки и переход

Ошибка провайдера следует прежней retry policy. Неверный JSON/ref — честная
техническая ошибка, не успешный пустой документ. Доставка наблюдений не
блокирует готовность. Повтор завершённой попытки использует сохранённый ответ.

До первой новой генерации нужен совместимый prompt/config. Подготовить его
под dev и записать точный name/version/hash и модель в релизные инструкции.
Production-метку не двигать. Нет переключателя старого генератора. История
результатов/миграций и retained histories не удаляется.


## Совместный выпуск F239/F249/F255 от 2026-09-08

Формат выгрузок — `graf.transcript-export.v3`. XLSX сохраняет первые четыре
листа `Transcript`, `Summary`, `Action Items`, `Metadata`; при наличии полного
протокола добавляет пятый лист `Протокол`. Старые сохранённые файлы неизменны.

Ссылки TXT/Markdown/XLSX закрепляют `source_result_id` и точный идентификатор
фрагмента. Страница проверяет право полного просмотра, принадлежность результата
встрече/пространству и неизменность аудиоревизии. При повторной обработке того же
аудио показывает сохранённую расшифровку с явным пояснением. Неизвестный, чужой
или заменённый вместе с аудио источник недоступен; текущий фрагмент по времени
не подставляется. Исправление спикеров и повторная обработка из такого просмотра
отключены. Переход к историческому заменённому аудио не добавляется.

Достоверные названия используют общий AUTHORITATIVE_TITLE_SOURCES, время
закрепляет также recording_display_timezone_offset_minutes. Повтор завершённого
вызова сохраняет validation_error. Журнал оптимизатора читает допустимый большой
запрос в пределах существующего ограничения MAX_CHECKPOINT_BYTES.
