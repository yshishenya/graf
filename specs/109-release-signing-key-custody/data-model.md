# Data Model: custody подписи обновлений

This feature persists no meeting or user data.  The following documents and
ephemeral values define the release trust state.  Private key bytes are
explicitly absent from every entity below.

## Update Signing Key Manifest

**Location**: `apps/macos/Installer/UpdateSigningKey.json`

| Field | Type | Rules |
| --- | --- | --- |
| `schemaVersion` | integer | Starts at `1`; unknown future major schema fails closed. |
| `status` | enum | `unprovisioned`, `active`, or `retired`; production staging accepts only `active`. |
| `keyId` | string | `sha256:` plus lowercase SHA-256 of decoded 32-byte public key. It is safe to disclose. |
| `publicKey` | base64 string | Exactly 32 decoded bytes; public material only; must equal final app `SUPublicEDKey`. |
| `trustGeneration` | integer | Monotonically increases only for an explicit manual bootstrap. |
| `channels.primary` | object | GitHub environment/secret *names* only; no values, URLs with credentials, or local paths. |
| `channels.recovery` | object | Keychain account/service *names* only; no key content or local keychain path. |

Relationships: one active manifest defines the expected public verifier for one
trust generation.  Both signing channels must derive that public key.  Every
regular release bundle embeds it.

## Signing Channel Attestation

**Location**: transient local output or GitHub Actions artifact; never copied to
the public appcast/download host.

| Field | Type | Rules |
| --- | --- | --- |
| `schemaVersion` | integer | Must match supported safe-attestation schema. |
| `channel` | enum | `github-environment` or `macos-keychain`. |
| `keyId` | string | Must match manifest and candidate app. |
| `state` | enum | `ready`, `degraded`, or `unavailable`; only `ready` proves routine redundancy. |
| `releaseRef` | string | A tag/ref when a workflow checked one; no credentials. |
| `runId` | string/integer | GitHub run identifier for audit lookup; optional for local check. |
| `createdAt` | ISO-8601 string | Check time; stale attestations cannot authorize a release. |

Validation rules: a malformed, missing, stale, or mismatched attestation is
`unavailable`; it never becomes success based on the secret name alone.

## Release Request

**Location**: workflow-dispatch inputs plus draft release assets.

| Field | Type | Rules |
| --- | --- | --- |
| `version` | CalVer | Strictly greater than each appcast version. |
| `tag` | git tag | Must resolve to the approved `master` release commit. |
| `previousVersion` | CalVer | Existing trusted app used for continuity validation. |
| `archive` | draft ZIP asset | Must contain exactly `GRAF.app`, matching version and manifest key. |
| `releaseNotes` | draft Markdown asset | Must contain Russian user-facing content. |

State transitions:

```text
draft assets
  -> protected workflow validation
  -> signed draft artifacts
  -> owner verification
  -> archive/package copied and verified
  -> appcast replaced last
  -> live rollout
```

Any failed validation leaves the live appcast unchanged.  Rollback restores a
known-good feed or releases a strictly higher forward-fix; it never serves a
lower unsigned downgrade.

## Manual Bootstrap Package

| Field | Rule |
| --- | --- |
| `fromTrustGeneration` | The historic app's known configured generation. |
| `toTrustGeneration` | The active manifest generation; greater than the old value. |
| `delivery` | One manually invoked `.pkg`, outside normal Sparkle feed. |
| `identity` | Must preserve GRAF name, bundle identifier, signed app lineage and permission descriptions. |
| `postcondition` | The installed bootstrap embeds the manifest public key and can validate the next normal appcast. |

The bootstrap must never be generated by a path that publishes an appcast with
the old key or marks a regular update as a key rotation.
