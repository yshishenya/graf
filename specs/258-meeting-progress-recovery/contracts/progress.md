# Пользовательское состояние

| Подтверждённый факт | Основная подпись | Доступно / действие |
|---|---|---|
| старт не завершён | Подготавливаем запись… | Отказ старта не становится записью |
| capture работает | Идёт запись | Пауза микрофона, Stop |
| Stop ещё работает | Сохраняем запись… | Индикатор до освобождения capture |
| локальная копия сохранена | Отправляем запись | Локальная сохранность только по факту |
| нет сети, копия подтверждена | Запись сохранена. Отправим, когда появится связь | Не повторять встречу |
| сервер принял запись | Готовим расшифровку | Готовый архивный звук |
| transcript ready, summary queued/running | Расшифровка готова. Готовим итоги | Звук, расшифровка |
| summary dependency wait | Подготовка итогов задерживается. Продолжим автоматически | Уже готовые части |
| summary available/partial | Итоги готовы | Ограничения разделов по факту |
| summary terminal failure | Итоги не удалось подготовить | Расшифровка доступна, безопасное действие summary API |
| no speech | Речь не распознана | Прослушать пригодный звук |
| input непригоден | Не удалось обработать этот файл | Загрузить другой файл |
| архивирование выключено | Аудио не сохранялось | Расшифровка/итоги по готовности |
| access revoked/deleted | Встреча недоступна | Прежнее содержание скрыто |

## Автоматическое обновление

Активные экран/список: GET <=15с при pending. Transient failure — нейтральная подпись и ограниченный повтор; online/pageshow/visibility возобновляют. Длительность не превращается в failed. Запросы прекращаются при уничтожении экрана/доступа, но не после только transcript. Selected summary проверяется по своему template/revision, не default другого формата. Сохранить старый результат при manual refresh и player/focus/title draft.

## Native

- Ask: тот же controller восьми секунд, короткая читаемая композиция, доступные действия и remembrance; не второй countdown.
- Start: подтверждённый короткий native отклик и постоянный Stop, независимо от OS notifications.
- Stop: result widget с фактической передачей, не ложной готовностью.
- Recap: «Итоги встречи готовы» после текущего перехода своей записи; «Расшифровка готова. Итоги не удалось подготовить» при terminal summary failure. Без текста встречи, email, путей или signed URL. Одна попытка на session/milestone/context, звук выключен при capture, разрешение/Focus соблюдаются. Категория включается явно в настройках, отсутствующее старое значение false.
- Reminders/incidents: foreground сам по себе не suppress, только соответствующее видимое состояние/связанная встреча. Постоянное управление не зависит от OS permission.
- Auth только из успешного native scoped ответа, новая epoch отменяет старые callbacks, нет зависимости от наличия календарных встреч.

Readiness на этом Mac заменяет F249 FR-020 только в этой части. Веб-inbox остаётся отдельной историей; старые F249 задачи автоматически не закрываются.

## Дополнение desktop sync

`review.summary_status` — необязательное подтверждённое состояние. `review.summary_event_id`
и `review.summary_updated_at` — необязательные UUID и время принятия результата
(`accepted_at`, для старого автоматического результата — `generated_at`) либо завершения
неудачной попытки (`ended_at`). Ожидание не создаёт событие; отсутствие времени не заменяется
временем ответа. Содержимое встречи не передаётся. Уже существующее `transcript_available`
переносится отдельно от `review.available`, которое означает только доступность страницы.

`GET /api/v1/desktop/notification-context` использует действующие Principal/Device/Tenant
проверки, возвращает только `user_id`/`workspace_id`, `Cache-Control: no-store`.
Календарь не является обязательным условием определения владельца уведомлений.
