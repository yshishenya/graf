# Источники первой версии

Код изучен на 6ff8db3ee18dc7faf52fd8a31c8bade97c5ca548. Этот перечень конкретизирует N11–N19, не добавляет новые доменные события.

| Событие | Источник и получатель | Актуальность, текст, действие |
|---|---|---|
| Расшифровка/итоги/ошибка обработки | processing/store.py:persist_processing_result, set_workflow_status; outcomes/ai_service.py:_cas_summary_slot. Владелец встречи в текущей области | Одна карточка встречи. Вставка в той же транзакции принятого текущего результата. Готовность тихая. Только terminal failure/no-speech требует действия. Retry не меняет revision; новый принятый успех снимает проблему. Тексты N11–N15, переход в существующую встречу. Удаление/отзыв исключает карточку и индикатор при каждом чтении |
| Адресный доступ | cabinet/access.py:create_scoped_share_grant и accept_share_invitation, только конкретный user_id действующего grant | Одна тихая карточка на grant. Текст N18; права перепроверяются через существующий recipient proof, membership чужого пространства не создаётся. Отзыв/удаление исключают карточку. Непринятое приглашение по email не является доступом |
| Финансовое состояние | Существующие billing/events.py, billing/notifications.py, billing/entitlements.py и fair_use.py | В первой версии N19 сохраняет существующие контекстные предупреждения на странице биллинга/аккаунта и обязательный outbox. Отдельная карточка появится только для категории с доказанными источником, текущим получателем и разрешением; такой полностью проверенной категории сейчас нет. PAYMENT_FAILED есть в enum, но вызов реального producer не найден: фиктивную карточку не создавать. Успехи/чеки/неизвестный статус платежа не зажигают точку |
| Нужен вход/переподключение календаря | Существующие auth и calendar settings | N16/N17 остаются контекстным статусом и входом/настройками. Не создают новую карточку истории. Нет нового события безопасности и open_account_security без проверенного producer |

Для первой версии web action enum: open_meeting/open_transcript/open_outcome. N16/N17/N19 продолжают использовать существующую навигацию своего контекста. Новые переключатели подписок под неподдержанные категории отсутствуют.

Проверки T003/T011/T012 включают: отсутствие billing success/progress/локальных событий в ленте; повтор callback, rollback, проигранный CAS; действующего адресата sharing; revoke/delete и старый cursor; изменение read_revision во время нового результата. Серверная история сохраняет метаданные, без текста встречи; физическая очистка завершённых карточек через 30 дней не меняет аудит или документы.

## Объединение аккаунтов

История уведомлений прежнего recipient остаётся исторической, как delivery
outbox: она не переносится как новый доступ другому user ID и не создаёт
новых сигналов внимания при merge. Перенесённые встречи и активные состояния
доступны через существующий доменный интерфейс; следующий фактический переход
создаёт карточку текущему владельцу. FK inventory фиксирует historical_only.
