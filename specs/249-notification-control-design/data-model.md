# Модель данных и владение

Предложение, не существующая схема. Актуальное разделение — [surface-separation.md](surface-separation.md).

## ServerNotification — только веб-события

Одна строка — карточка: `id`, `recipient_id`, `scope_kind`, `scope_id`, `family`, `source_id`, `source_revision`, `revision`, `created_at`, `updated_at`, `read_revision`, `requires_action`, `resolved_at`, `expires_at`, `action_kind`, `object_id`.

Стабильная уникальность: recipient + scope + family + source_id. Для результатов family=result/source_id=meeting_id; расшифровка, итог и частичный результат обновляют одну карточку. `source_revision` берётся из домена, не сравнивается арифметически, если это UUID/непрозрачная строка. Producer сверяет актуальный доменный результат под существующим механизмом конкурентного доступа; старый callback не заменяет новую версию и не переоткрывает решённую проблему. Вставка метаданных атомарна с доменным commit либо гарантируется существующей надёжной outbox. Отправка наружу — после commit.

`revision > read_revision` означает непросмотренную версию. Но точка требует дополнительно актуальность, доступ, `requires_action` и `resolved_at IS NULL`. Обычная готовность никогда не создаёт точку. Progress/retry/повтор доставки не повышают revision и не создают карточку.

Фильтр important включает все актуальные доступные проблемы, включая просмотренные. History включает разрешённые серверные события. Подтверждённое восстановление снимает requires_action/точку, не создавая success-notification. Новое подтверждённое возникновение может повысить revision; просмотр не разрешает инцидент.

## Чтение и список

GET возвращает items, next_cursor и has_unseen_action_required из согласованного серверного снимка. Индикатор вычисляется по всей доступной области, не только текущей странице. Порядок стабилен: created_at/id desc; обновление одной карточки не превращает каждую попытку в новое событие. При возвращении/обновлении клиент получает актуальную первую страницу. Cursor непрозрачен, защищён от подмены, привязан к пользователю/auth epoch/области и фильтру. Нельзя сравнивать несвязанные порядки разных областей как одну глобальную sequence.

Одиночный read принимает только показанную revision: `read_revision=max(read_revision, requested_revision)`. Будущая revision отклоняется; новая версия после открытия не поглощается старым подтверждением. Ошибка перехода не запускает read. Ошибка сохранения сохраняет индикатор и возможность повторить. Новые/прочитанные значения принимаются клиентом лишь для совпадающих auth epoch/области.

Массового read-all нет ни в веб-дизайне, ни в нативном состоянии; ранее предложенные watermarks и сериализация счётчика ради массового чтения убраны до реализации. Не нужна отдельная глобальная блокировка или новая очередь ради просмотра.

## Область, приватность и сроки

Рабочие события принадлежат текущему пространству. Личные mandatory account events и адресные sharing events принадлежат получателю и показываются с обозначенной личной областью; факт sharing не делает его членом чужого workspace. Используется существующий recipient access proof, без RLS-исключения для чужого пространства.

Список, индикатор и действие каждый раз проверяют актуальные права. Отзыв/удаление убирают название и действие; старый ID ведёт к нейтральному «Встреча недоступна». При logout/401/смене области cache очищается; при 503 старый содержательный cache скрыт до проверки доступа, состояние неизвестно, не ложный ноль. Payload — шаблон и безопасная проекция, без transcript, signed URL, HTML и путей Mac.

Полезные/решённые события видны 30 дней после результата/разрешения. Активная проблема не истекает сама, пока актуальна. Это не срок хранения встречи, финансового документа или аудита.

## UserNotificationPreferences

Существующие optional_email_enabled и optional_in_app_enabled сохраняют значение и смысл. Серверная версия формы обеспечивает conflict detection; отсутствие поля старой формы не считается false. Не добавляем result_ready_enabled/system-delivery в веб-настройки. Новые неподдержанные comments/mentions/sharing producers не создаются из одного желания отрисовать переключатель.

Обязательные финансовые каналы и billing outbox сохраняются. Наличие account event не разрешает прислать письмо другому адресату или выдать доступ. Workspace policy ограничивает содержимое/действия.

## Mac-owned состояние

Capture, source health, local recording ownership и upload queue — существующие нативные источники истины. Активный local incident содержит opaque ID, owner, device, local recording ID, kind, generation, health и доступное нативное действие. Нет сервера как владельца локальной сохранности, нет local read_revision и общей inbox-таблицы.

«На этом Mac» — проекция текущих проблем, не второй журнал. После подтверждённого восстановления проблема исчезает. Локальная запись/очередь остаётся в существующем хранилище. Ключ попытки OS-уведомления owner/device/incident/generation предотвращает повтор; хранится ограниченно вместе с текущим механизмом состояния. OS delivery не считается доказательством, что пользователь увидел сообщение.

Локальные preferences: reminders_enabled, reminder_offset_minutes (0/1/5), show_titles_in_system_notifications, sound_enabled. OS permission читается отдельно. Автозапись 214, widget и theme используют существующие настройки.

Server event не преобразуется в OS notification. Local incident не экспортируется в веб-ленту. Embedded cabinet сохраняет серверную модель, независимо от нативной оболочки.

## Presentation snapshot

Capture и delivery независимы: отправка не означает продолжающийся захват. Native health не вычисляется из server job. Серверная обработка не удерживает решённый локальный upload incident. UI не обещает сохранность/готовность до подтверждения владельца соответствующего состояния. Метрики только kind/surface/outcome/latency, без приватного содержимого.
