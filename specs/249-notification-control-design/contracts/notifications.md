# Предлагаемые интерфейсы после разделения поверхностей

Не реализованы. [Модель данных](../data-model.md), [владельцы событий и полный путь](../surface-separation.md).

## HTTP — серверная лента веба

- `GET /notifications?filter=important|history&cursor=...`: HTML fallback; embedded `/desktop/notifications` использует ту же семантику и текущую route policy.
- `GET /api/v1/notifications?filter=...&cursor=...&limit=30`: items, next_cursor, has_unseen_action_required, generated_at. Limit 1–100. Только текущий получатель/пространство и допустимые личные события; элементы/индикатор из согласованного снимка.
- `POST /api/v1/notifications/{id}/read`: показанная revision, идемпотентно. Не читает новую версию; будущая → 422. HTML формы имеют POST+CSRF.
- Существующие `/settings/notifications`, `/desktop/settings/notifications`: только серверные optional preferences + version. Нет result-ready-to-macOS или локальных permission controls. Конфликт → 409, пользовательский черновик сохраняется.

Read-all не вводится. Нативному состоянию не нужна серверная прочитанность; веб не предлагает массовую очистку обычных результатов. Auth/CSRF/RLS/current route policy переиспользуются. Нет anonymous feed и произвольного recipient_id от клиента.

401 → cache clear и вход. 403/404 → нейтрально недоступно. 409 → сравнить актуальные настройки. 422 → ошибка ввода. 503 → неизвестное состояние и повтор, содержательные старые карточки скрываются до проверки прав.

## Действия

Веб: `open_meeting`, `open_transcript`, `open_outcome` — enum + object ID + revision, safe relative path строит сервер. Актуальность/права проверяются на действии. Нет произвольного URL или локального пути из payload. No-speech карточка сама не запускает provider job; восстановление в существующем экране встречи.

Mac: `open_local_recording`, `retry_upload`, `open_os_permissions`, `pause`, `resume`, `stop` — существующие native actions с owner/device/state checks. Stop не требует сети. Retry использует существующий upload pipeline. Calendar join — проверенный HTTPS из безопасной calendar projection.

## Native presenter

Получает только нативные локальные/календарные события. ServerNotification не является его входом. OS permission/Focus и истечение события проверяются перед попыткой доставки. Статус уже виден → обычный дополнительный баннер подавлен. Постоянное состояние записи/Stop и NSPanel 214 не зависят от ordinary presenter.

Одна попытка прерывания на owner/device/incident/generation; claim перед OS submission. При сбое между claim и подтверждением нет слепого повторного баннера: текущая проблема остаётся доступной. Это at-most-once попытка, не гарантия фактической доставки. Смена foreground не разрешает повтор. Во время записи звук не воспроизводится. No critical-alert bypass.

В OS payload — непрозрачный локальный ID/версия, без transcript/путей/готового произвольного действия. По нажатию заново проверяются владелец, текущее состояние и событие. Устаревшее → актуальное локальное состояние, без ложного действия. Названия внешних превью выключены по умолчанию; logout/revoke очищает известные pending/delivered IDs, но ранее увиденный текст отозвать нельзя.

## Embedded — без общей ленты и нового моста событий

Веб-кабинет внутри GRAF — та же серверная лента. Локальные проблемы не подмешиваются, server events не вызывают OS presenter и не командуют capture. Нативный слой может открыть существующий кабинет/экран встречи по явному действию, через текущую безопасную route policy. Никаких новых bridge-команд записи ради уведомлений.

При смене auth epoch/пространства обе поверхности очищают чужую проекцию; локальная очередь сохраняется в текущих owner-boundaries. Неизвестные origin/schema/actions отклоняются существующей проверкой. Отсутствие веба не ломает локальную запись.

## Источники и совместимость

Только committed domain facts; повтор доставки сохраняет source_revision. Результат/итог одной встречи обновляет существующую карточку. Подключение sharing только при реальном надёжном producer. Нет backfill старых всплывающих успехов; нет web push/toast/sound. Billing outbox и обязательная доставка сохраняются.

Две независимые формы живут в разных областях: веб-аккаунт на сервере и локальные настройки Mac. Нет «сохранить всё», обещающего атомарность двух систем. Прежние optional false сохраняются. До миграции сверить фактическую схему: удаляются лишь невнедрённые предложения, не существующие пользовательские данные.

Область реально поддержанных источников и контекстных событий: [producer-contract.md](../producer-contract.md). При каждом запросе права проверяются заново; pageshow/возврат во вкладку скрывает данные до проверки, открытая панель обновляется каждые 30 секунд. Известная invalidation очищает сразу; мгновенный отзыв без сигнала не обещается. Локальные предпочтения owner+device и отмена requests — experience §12.
