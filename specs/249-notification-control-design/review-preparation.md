## Уточнение пользователя: macOS — основная поверхность

После прямого уточнения пользователя добавлен FR-019 и отдельный нативный макет `native-preview/Preview.swift`: без WebView, настоящие NSStatusItem/NSPopover, NSPanel, SwiftUI-история/настройки и UNUserNotificationCenter. Результаты фактических native-проверок и непроверенные части находятся в [native-preview/README.md](native-preview/README.md). Это подготовка к review; рабочий GRAF не изменён. Рецензент должен проверить FR-019 в UX CHK001/010/012 и security CHK001/004; наличие HTML не является достаточной приёмкой Mac.

## Материал для рецензента

- UX CHK001–004: experience §1–3, §11; сценарии записи, паузы, скрытия управления и остановки в макете.
- UX CHK005–007: experience §4–7, data-model; показанная revision race/error, раздельные формы Mac/аккаунта.
- UX CHK008–009: experience §8/11 и quickstart. Требования клавиатуры/диктора отделены от реального прохождения macOS VoiceOver. Восемь секунд защищены конституцией, но достаточность описания доступности должен оценить рецензент.
- UX CHK010–012: research (включая ограничения Krisp), макет, результаты браузерной проверки.
- Security CHK001–003: data-model и contracts/notifications: auth epoch, области, CAS, CSRF и запрет web→capture.
- Security CHK004–007: experience §9/11; Stop без сети, safe actions, порядок commit, срок UI-истории и обязательная доставка.
- Security CHK008: research «Точная граница legacy-кандидата», T018/T019, rollback в plan.

## Открытые ворота

Нужна независимая оценка требований по 12 UX + 8 privacy пунктам, затем чистый analyze и ownership задач в GitHub перед реализацией. Запрос выбора рецензента отправлен пользователю. Команда «продолжай» уже разрешает дальнейшую работу, повторного разрешения на подготовку не требуется.

Не путать review требований с приёмкой реализации: нативная доставка, реальный видимый Stop во всех Spaces, VoiceOver, upgrade/rollback и 5 участников проверки пока не проверены. Макет не даёт основания отмечать T020/T021 выполненными.

## Обновление для рецензента после веб-аудита

[Повторный аудит](web-attention-audit.md) заменяет прежнюю визуальную модель общего unread badge: «Важное / История», точка только нового action-required, без web-баннеров и массовой кнопки чтения. Новые аккаунты не получают системные баннеры готовности до включения категории. Нативный preview требует отдельной синхронизации. Reviewer-owned checklist markers не изменены.
