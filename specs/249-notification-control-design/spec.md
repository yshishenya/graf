# Feature Specification: Верхняя панель и уведомления GRAF

**Feature Branch**: `codex/249-notification-control-design`
**Created**: 2026-09-06
**Status**: Реализация разрешена; независимая проверка требований выполняется
**Input**: Полный UX/UI/IA/CX кнопки верхней панели, уведомлений и настроек на основе установленного Krisp; осторожная очистка обнаруженного legacy.
**Reservation**: https://github.com/yshishenya/graf/issues/6635
**Risk lane**: High-risk UX / reference fidelity / capture-adjacent.

## Context

Уточнение пользователя: уведомления должны работать внутри **macOS**, а не только в вебе. Основная поверхность — нативное приложение с системными баннерами macOS, панелью строки меню и плавающим виджетом. HTML — вспомогательный макет; наличие веб-колокольчика не выполняет это требование.

Пользователь должен сразу понимать, записывается ли встреча, одним действием остановить запись, узнать о готовом результате и восстановиться после сбоя. Сейчас значок строки меню GRAF открывает календарь, управление записью живёт в окне, а настройки уведомлений содержат только две дополнительные категории. Предлагается связать эти поверхности без замены рабочего механизма записи.

Полный контракт дизайна: [contracts/experience.md](contracts/experience.md). Наблюдения и ограничения: [research.md](research.md). Все примеры искусственные.

## Clarifications

### Session 2026-09-06

- Последующее указание пользователя: все установленные macOS-проверки проводятся только в существующем GRAF Dev через общий dev-harness. Отдельные Local/Preview-сборки запрещены; устаревшие пути запуска отключаются.

- Проведён обязательный разбор неоднозначностей: управление записью, момент старта, источник состояния, приоритеты сообщений, сохранение настроек, прочитанность, приватность, совместимость.
- Текущий контракт 214 проверен в конституции и product-gates: «Спрашивать» запускает запись через 8 секунд; «Всегда» не показывает запрос; «Никогда» не показывает запрос и не запускает запись. Не меняется.
- После первого результата пользователь дал команду «продолжай»: работа продолжается до внедрения в рамках проектных gates. Устаревшее допущение об остановке только на дизайне снято. Независимая проверка требований завершена: UX 13/13, security 9/9; см. review-evidence.md. Область: обе поверхности — строка меню macOS и верхняя панель кабинета; прототип служит проверке перед внедрением.
- Новые числовые параметры уведомлений и значения по умолчанию ниже являются предложением дизайна, не результатами наблюдения Krisp.
- Защищённые продуктовые решения не переопределяются; показ уведомлений не даёт новых разрешений на запись, доступ или отправку данных.

## User Scenarios & Testing

### User Story 1 — Понимать и контролировать запись (Priority: P1)

Участник встречи видит состояние в строке меню и управляет текущей записью, не открывая большой кабинет.

**Independent Test**: пройти готовность → ручной/автоматический старт → пауза → продолжение → остановка; состояние совпадает во всех открытых поверхностях.

**Acceptance Scenarios**:
1. При подтверждённом старте значок, таймер и видимая кнопка остановки появляются; запрос старта сам по себе не показывает «Идёт запись».
2. При потере интернета запись остаётся активной, рядом пояснение о локальном сохранении только при подтверждённой записи на диск.
3. При скрытом окне и панели строки меню компактный виджет предоставляет остановку одним нажатием. Один закрытый значок не считается выполнением этого критерия.
4. При паузе микрофон исключается из записи GRAF; пауза не отключает системную запись, которая продолжается при доступном исправном источнике (контракт Feature 022). Статус «Микрофон на паузе», независимое состояние системного источника и непрерывный общий таймер отражают это; Stop завершает всю запись.

### User Story 2 — Получать нужное сообщение в нужный момент (Priority: P1)

До встречи пользователь получает приглашение подключиться; во время — только управление записью и существенные проблемы; после — сообщение о фактически готовом результате.

**Independent Test**: синтетическая встреча с напоминанием, разрешённой автозаписью, временной потерей сети и отдельными этапами готовности расшифровки и итогов.

**Acceptance Scenarios**:
1. Напоминание не запускает запись и истекает после своего временного окна.
2. Запрос автозаписи не скрывается настройкой обычных уведомлений. Истечение отсчёта не сохраняет «Запомнить выбор».
3. Один сбой не создаёт новое сообщение на каждой повторной попытке; устранение обновляет прежний инцидент.
4. При активной встрече готовность предыдущей попадает в историю без всплывающего сообщения.

### User Story 3 — Увидеть важное и найти результат без лишних отвлечений (Priority: P2)

Колокольчик в верхней панели открывает историю текущего пространства. Нажатие на результат ведёт к нужному экрану, а не к общему списку.

**Independent Test**: открыть «Важное», перейти к проблеме, восстановить обработку; проверить, что 12 готовых результатов не создают точку/баннер, а повтор той же ошибки не возвращает точку.

**Acceptance Scenarios**:
1. Открытие панели не помечает всё прочитанным; действие с конкретным сообщением отмечает только его.
2. В вебе нет общего счётчика и «Прочитать всё»: точка только у нового актуального события, требующего действия. Обычные результаты остаются в тихой истории.
3. «Прочитано» не равно «проблема решена»; активный сбой остаётся в разделе «Важное».
4. После выхода или смены пространства прежние данные сразу исчезают; отложенный ответ не возвращает их.

### User Story 4 — Настроить удобство без потери контроля (Priority: P2)

Пользователь понимает, какие категории включены, на каком устройстве действуют настройки и что продолжит показываться всегда.

**Independent Test**: проверить отсутствие системных категорий в вебе и серверных категорий на Mac; запретить уведомления macOS, сохранить веб-настройки при сетевой ошибке и проверить область действия.

**Acceptance Scenarios**:
1. Запрет macOS не блокирует запись и не скрывает локальные элементы управления.
2. Настройки Mac и аккаунта сохраняются отдельными формами. При ошибке одной формы её черновик остаётся, её действующие значения не меняются; сохранённая другая форма не откатывается.
3. Настройки «Новости и советы» мигрируют без повторного включения отказов пользователя.
4. Запись, системные разрешения, показ названий и письма имеют отдельные ясно подписанные границы.

### User Story 5 — Обновиться без утраты восстановления (Priority: P1)

При переходе на новую панель остаются доступны записи на устройстве, повторная отправка, старые настройки и безопасный календарь.

**Independent Test**: обновление со старой конфигурацией и локальной очередью, затем откат на совместимую версию.

**Acceptance Scenarios**:
1. Новая панель использует существующие действия записи и календарные данные.
2. Нельзя удалять миграционный decoder или старый обработчик, пока поддерживаемый клиент обращается к нему.
3. Старую панель удаляют только после проверки равнозначных состояний, включая автономный режим.

### Edge Cases

Одновременные встречи; отменённое/перенесённое событие; нет ссылки; календарь отключён; несколько дисплеев; скрытая строка меню; полноэкранное окно; сон/пробуждение; запрет Focus; истёкшая сессия; потеря разрешений; заполненный диск; старое уведомление после удаления; отсутствующие права; повреждённый файл; ответ сервера после выхода; повторное событие; новый результат во время другой записи; устаревшее время компьютера. Правила каждого класса определены в контракте.

## Requirements

### Functional Requirements

- **FR-001**: Одна панель строки меню объединяет текущее состояние записи, источники, ручные действия, календарь и переходы в GRAF.
- **FR-002**: Состояния записи и отправки показываются независимо; сбой отправки не скрывает факт продолжающейся записи.
- **FR-003**: Для активной/приостановленной сессии всегда видим локальный индикатор и доступна остановка одним взаимодействием; закрытый popover не единственный путь.
- **FR-004**: Сохраняется полный контракт 214: три режима, 8 секунд, явный отказ, запоминание только явного действия, ограничения источников и разрешений.
- **FR-005**: Для каждого сообщения определены причина, канал, приоритет, текст, действие, срок актуальности, повтор и условие разрешения.
- **FR-006**: При активной записи обычные готовности/советы не прерывают встречу; ошибки текущего захвата видны немедленно.
- **FR-007**: История содержит реальную готовность и требующие действия события; технические повторы и прогресс не создают карточку или точку. Веб показывает только тихую историю и точку нового важного, без числового счётчика и всплывающих баннеров.
- **FR-008**: Прочитанность, скрытие баннера и устранение проблемы — разные состояния. Подтверждение просмотра не поглощает новую revision; решение автоматически убирает проблему из «Важного» без нового сигнала. Локальный статус Mac не имеет прочитанности: он существует до фактического устранения. Массовый read-all не входит в первую версию.
- **FR-009**: Переходы проверяют актуальные права и существование объекта; уведомление не передаёт разрешение на действие.
- **FR-010**: Настройки разделены по категории и области действия; существующие отказы от дополнительных сообщений сохраняются.
- **FR-011**: Внешние/системные превью не содержат названий и содержания встреч по умолчанию. Названия внутри авторизованного кабинета допустимы по правам.
- **FR-012**: Системный запрет уведомлений, отсутствие связи и ошибка сохранения имеют понятное объяснение и следующий шаг.
- **FR-013**: Все поверхности имеют светлую/тёмную тему, клавиатурное управление, понятные имена для диктора, видимый фокус и работоспособны при увеличении текста.
- **FR-014**: Календарные переходы и настройки сохраняют безопасную проекцию и HTTPS-проверки Feature 168; событие календаря само по себе не запускает запись.
- **FR-015**: Очистка устаревшего кода проводится по реальным обращениям, с миграционными условиями и проверками восстановления; общий автономный режим сохраняется.
- **FR-016**: Ошибки не обещают сохранность, завершение, удаление или готовность без подтверждения соответствующего состояния.
- **FR-017**: Меню, виджет, кабинет и уведомления используют одинаковые названия действий и приводят к одним и тем же результатам.
- **FR-018**: Прототип использует только синтетические данные; активные проверки записи, платёжных и приватных действий не выполняются им.

- **FR-019**: Напоминания и допустимые сообщения о локальных проблемах доставляет нативный Mac-клиент через macOS; они не зависят от открытого окна или загруженного WKWebView. Системное разрешение/Focus соблюдаются; нажатие открывает соответствующее место в GRAF после проверки текущего владельца и доступа. Критический контроль записи остаётся нативным и не зависит от системных баннеров.

### Key Entities

- Сессия записи: локальная истина состояния, источники, длительность, допустимые действия.
- Событие календаря: контекст, время, безопасная ссылка, актуальность.
- Уведомление: получатель, пространство, причина, объект, прочитанность, состояние проблемы и допустимое действие.
- Настройки: категории пользователя и отдельные предпочтения этого Mac.

## Success Criteria

### Measurable Outcomes

- **SC-001**: В сценариях проверки 100% активных записей видимы и останавливаются одним нажатием на постоянно видимой поверхности.
- **SC-002**: В 100% тестов повторов один переход не порождает второе уведомление в том же канале.
- **SC-003**: В матрице privacy/permissions отсутствуют названия или содержимое встреч на запрещённых поверхностях и переходы к чужим объектам.
- **SC-004**: Не менее 4 из 5 участников проверки находят настройки нужной категории за 15 секунд и понимают, идёт ли запись, за 3 секунды. Это целевая пользовательская проверка, ещё не проведена.
- **SC-005**: Все состояния контракта доступны в сценариях приёмки; критические действия доступны с клавиатуры и диктором.
- **SC-006**: На ширине 360 px и при масштабе 200% основные действия и текст не обрезаются; время визуального ответа локальной команды целевое p95 ≤ 200 мс без ложного подтверждения записи.

## Assumptions

- Команда «продолжай» разрешает дальнейшую работу; статус дизайна не выдаётся за внедрённую или выпущенную функцию.
- Исследуемая версия Krisp 3.15.6; действующие настройки наблюдаемого аккаунта не являются доказательством заводских значений.
- Запись звука и её разрешения остаются у нативного приложения; сервер хранит только серверную историю и пользовательские предпочтения.
- Веб не получает права управлять чужим Mac. Колокольчик не является новой кнопкой начала записи.
- Не добавляются AI-генерация текста уведомлений, новая очередь задач, платёжная логика или новая система автозаписи.

## Уточнение после повторного веб-аудита · 2026-09-06

[Правила внимания и полный путь](web-attention-audit.md) уточняют FR-007/008: обычный день без баннеров и точки; подтверждённая проблема остаётся доступной до разрешения. Этот вариант заменён последующим разделением поверхностей: системной доставки серверных результатов в новом контракте нет. См. surface-separation.md.

## Разделение поверхностей после проверки Krisp

- **FR-020**: Mac отвечает за запись, устройство, локальную отправку и напоминания. Веб отвечает за результаты, серверную обработку, доступ и аккаунт. Embedded cabinet сохраняет веб-семантику; local incidents не передаются в web inbox, server events не передаются нативному presenter. Настройки соответствуют своей области. Проверка: локальная ошибка даёт ноль карточек веба; серверный результат даёт ноль нативных сообщений. Полный путь — [surface-separation.md](surface-separation.md).

## Уточнение метода приёмки, 2026-09-06

Пользователь сообщил об отсутствии исследования с людьми и поручил исследование
пяти субагентам. Для этой итерации выполнены пять независимых экспертных разборов
(см. agent-study.md и review-evidence.md). Это согласованный метод качественной
проверки пути. Числовые цели SC-004 для живых пользователей не измерены;
их нельзя выдавать за пройденный эксперимент. Измерение p95 и аппаратные
проверки SC-005/006 остаются отдельными обязательствами.

## Уточнение пользователя, 2026-09-07 — размещение и плотность

На предоставленном снимке нативная панель выходит за границы экрана и
перегружена техническими пояснениями. Полная рамка панели должна помещаться
на выбранном дисплее после изменения содержимого; состояние и Stop остаются
в неподвижной верхней части, вторичные сведения прокручиваются. В покое
не показывать две отдельные строки разрешений и длинный календарный подвал.
Проблема показывается кратко с относящимся к ней действием; подробности —
в существующем экране GRAF.

Пользователь отверг колокольчик в верхней строке и попросил проверить меню
Krisp. В живом Krisp Activity находится в левой навигации. В GRAF вход
«Уведомления» переносится в нижнюю часть постоянного левого меню над профилем;
в свёрнутом меню остаётся значок с доступным именем. Сохраняются «Важное /
История», тихое поведение и точка только для нового требования действия.
Поиск, фильтры и ширина окна не меняют место входа. Настройки остаются отдельно.


### Уточнение workflow единственного Dev — T038

Владелец потребовал сохранить один GRAF Dev и исправлять причины отказов
штатного пути, сохраняя защитные проверки. После совмещения с выпущенной
схемой обнаружен недостающий сохраняющий данные переход схемы.

- **FR-021**: Единственный Dev допускает лишь доказанный переход от текущей
  ревизии к единственной целевой вершине при неизменных образах хранилищ.
  До изменения данных остановлены пишущие компоненты и проверен согласованный
  снимок PostgreSQL/MinIO. Ошибка до допуска новых записей компенсируется
  проверенным снимком; после допуска запросов/worker возврат старого снимка
  автоматически запрещён. При неуспехе состояние явно заблокировано, без
  ложного active/PASS. Не допускаются сброс данных, stamp, подмена observed
  revision, новое приложение, production-контур или новый рабочий namespace.
  Полный контракт и проверки — `dev-schema-transition.md`; до их принятия
  существующий отказ сохраняется.
