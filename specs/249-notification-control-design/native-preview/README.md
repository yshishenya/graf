# Нативный макет macOS

Отдельное локальное приложение **GRAF · Макет**. SwiftUI + AppKit + UserNotifications; без WebView, зависимостей, сети GRAF, записи звука и чтения пользовательских встреч. Это проверка дизайна, не внедрение в рабочий GRAF.

## Запуск

Сборка отдельного приложения прекращена. Используйте основной Dev-стенд.

Ранее отдельный макет собирался и запускался для исследования дизайна. Этот путь закрыт; дальнейшая проверка проводится в основном GRAF Dev.

## Реальные поверхности

- `NSStatusItem` «GRAF·Макет» и `NSPopover` управления. В главном окне кнопка «Открыть панель строки меню», в меню приложения команда «Панель управления» / ⌘P.
- Плавающий `NSPanel`: состояние, пауза/продолжение и Stop; остаётся после закрытия главного окна. Перетаскивается за фон, поддерживает all Spaces/full-screen auxiliary на уровне конфигурации. Реальное поведение во всех Spaces/на втором мониторе ещё не принято.
- Отдельный `NSPanel` восьмисекундного запроса: явный отказ/запись, remember, исход по истечении. Сценарий запускается вручную кнопкой, реального детектора нет.
- Нативные локальные проблемы и настройки; ⌘, открывает настройки, кнопка «Этот Mac» — активные проблемы данного устройства. Колокольчика результатов, числового unread и read-all нет.
- Кнопка системного уведомления использует **UNUserNotificationCenter**. Текст синтетический. Разрешение запрашивается только по явному нажатию, не при запуске. Во время имитации записи обычный баннер подавляется. Отказ ОС не скрывает историю/Stop. У приложения собственный bundle id `pro.graf.notification-design-preview`.

## Историческая проверка до разделения поверхностей

- Swift 6.3.3 / macOS SDK; локальная сборка и 6 self-check прошли.
- Главное окно и нативные настройки реально открыты и осмотрены.
- После выбора «Запись» и закрытия главного окна CUA увидел отдельный плавающий NSPanel с «Идёт запись · 12:34», «Пауза», «Стоп»; screenshot подтверждает именно отдельное окно.
- Пауза переключила панель в «Запись на паузе» / «Продолжить запись». Stop скрыл активный виджет; ⌘, открыл настройки без перезапуска.
- Восьмисекундный запрос осмотрен как отдельный NSPanel. Remember + «Не записывать» показал правило «Никогда» и отсутствие активной записи.
- История открылась с двумя непрочитанными; массовое чтение дало 0, а фильтр «Требуют действия» сохранил локальную проблему.
- В настройках наблюдено «Разрешение ещё не запрашивалось». Системный баннер **не показан и не принят**: запрошено разрешение пользователя на разрешение OS и одно тестовое уведомление.
- Попытка открыть именно tray popover при закрытом окне завершилась timeout UI-инструмента. Наличие реализации NSStatusItem/NSPopover не считается визуальным доказательством его открытия. Окно восстановлено через ⌘,.

## Ограничения

Состояния записи и таймер 12:34 искусственные; нет захвата, сохранения на диск, очереди отправки, аккаунта и системного детектора встреч. Настройки живут только в памяти. Реальные формы сохранения/сбои проверяются отдельным HTML-прототипом и будущими тестами интеграции. Не проверены VoiceOver, все Spaces, второй монитор, нативная светлая тема, доставка/нажатие OS уведомления, гонки настоящего capture. Контракт 214 и рабочее приложение не изменялись.
