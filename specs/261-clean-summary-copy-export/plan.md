# План F261

## Решение

`initContentExport` в `cabinet.js` собирает один запрос для копирования и
скачивания. Передавать `include_evidence: false` во всех запросах интерфейса;
удалить флажок и обработчики его состояния из `rendering.py` и `cabinet.js`.
Существующие формирователи TXT/Markdown/JSON/XLSX уже поддерживают этот режим.

Не очищать готовый текст регулярными выражениями: это может удалить обычные
ссылки или время, которые являются частью содержания. Не менять значения
по умолчанию серверного API и не пересоздавать сохранённые итоги.

## Проверка и риск

- Lane: tiny-low-risk; локальный компонент формы, без изменения общих серверных
  функций, контрактов, авторизации, генерации и хранения.
- Конституция: новых артефактов хранения и получателей данных нет; используется
  существующий экспорт с теми же проверками доступа и ревизии.
- Регрессионная проверка выполняет реальный сборщик запроса в Node и проверяет
  параметр источников, идентичность ревизий и настройки расшифровки.
- Существующие тесты экспорта расширены на комбинированный документ; шаблон
  проверяется и в обычном, и во встроенном кабинете.
- Перед PR: quickstart, проверка метаданных, проверка изменений агентом.
- Перед слиянием: GitHub `governance-fast` на точном SHA PR.
- Перед выпуском: отдельный замороженный кандидат, `release-full` и штатные
  проверки развёртывания. Локальные тесты не заменяют доказательство выпуска.

## Откат

Обычный откат серверного релиза возвращает прежнюю форму и параметр запроса;
восстанавливать данные не требуется.
