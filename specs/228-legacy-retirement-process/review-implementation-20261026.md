## Что проверено без дополнительных замечаний

- Общий `validate_exception` в `validate-legacy-impact.py:21–59` вызывается
  обоими потребителями. Все восемь полей проверяются ровно по одному разу;
  пустота/кавычки/обозначенные шаблонные значения отклоняются. Expiry требует
  точный формат и настоящую календарную дату, сравнивается строго с UTC-днём.
- Retirement task проверяет наличие ровно одной F###, T### и положительной
  #issue. Существование или принятие связанной задачи не обещается: это
  отдельные реестровые/содержательные ворота.
- PR запускает соседний helper через абсолютный путь от собственного
  `__file__`, без выбора пути из текста PR или cwd. Реальный workflow
  `pr-metadata.yml` выполняет checkout доверенного `github.workflow_sha`,
  получает PR только как Git objects и вызывает Python с `-I`.
- `test_trusted_exception_uses_sibling_policy_not_pr_helper_or_cwd` создаёт
  исполняемый вредоносный helper в PR, возвращается checkout к policy, затем
  проверяет решение для полного/неполного исключения, отсутствие исполнения
  attacker helper, приватного traceback и сохранение policy HEAD. Fixture
  копирует оба доверенных sibling-файла в policy commit; изменённый runner
  действительно вызывает policy script fixture под `-I`.
- Прежние значения `remove`/`untouched` не попадают в новый helper; PR-регулярное
  выражение с допустимой завершающей пунктуацией не изменено. Существующая
  проверка `untouched` с точкой сохранена. Новые проверки Classification
  отклоняют и вторую пустую/неверную метку внутри того же раздела.
- Fixtures покрывают каждый из восьми missing/empty/duplicate/placeholder
  случаев для spec/PR, дату сегодня/вчера/завтра/неверную, F/T/#, UTC clock,
  настоящий CLI из чужого cwd под `-I` и доверенный PR-путь.
- Шаблон PR и development-process перечисляют все восемь полей, UTC и предел
