# Наблюдение Krisp и причины дефектов GRAF

Дата: 2026-09-09. Источники: два пользовательских снимка GRAF; установленный Krisp через обычный интерфейс (CUA, AX и экран); исходный код GRAF на `bc41c10bf`. Скриншоты с персональными данными не сохраняются в git. Настройки Krisp не менялись.

| ID | Наблюдаемое поведение | Решение для GRAF |
|---|---|---|
| R01 | Settings в основной боковой панели заменяет её меню настроек; Back сверху | Тот же принцип, отдельный «Обзор» не нужен |
| R02 | Account → Workspace → Meeting Assistant → Audio → App Behavior & System; текущая строка с нейтральной подложкой | Только существующие разделы GRAF, без пустой группы Audio |
| R03 | Над содержимым одна небольшая строка с иконкой и именем текущего раздела | Один заголовок; убрать повторяющие название огромные вводные блоки |
| R04 | Account: профиль, безопасность, support; текст слева, действие справа, блоки разделены тонкой линией | Сохранить функции GRAF и применить компоновку, не добавлять 2FA/support access |
| R05 | AI Note Taker: строки автозапуска, автооткрытия, итогов, заголовка с коротким пояснением и switch справа | GRAF «Запись»: существующие три правила вместо нового глобального switch |

| R09 | App: light/dark/system; блок System с startup/open app/updates | Оставить поддерживаемую тему; не показывать отсутствующие автозапуск/виртуальные устройства |
| R10 | При выборе другого раздела остаются левое меню и одна область содержимого, отдельные вкладки/окна не появляются | Все готовые embedded пути — в основной экран |
| R11 | Используются тёмно-серые плоскости, нейтральное выделение раздела, фиолетовые активные переключатели, небольшие границы и умеренная плотность | Аналогичная визуальная система на собственных CSS/SwiftUI иконках |

## Подтверждено исходным кодом GRAF

- `MeetingDetectionSettingsView.swift`: вложенный sidebar шириной 176 + padding, длинное введение, HStack имени и трёх кнопок шириной 112 каждая. Контролы не уступают место, а имя с `maxWidth: infinity` сжимается. Это объясняет вытеснение названий и широкие пустые строки на пользовательских снимках; конкретный размер установленного окна отдельно не измерялся.
- `TwoBrainRecApp.swift::presentSettingsWindow`: поверх этого view добавлен `NSTabViewController.segmentedControlOnTop`; окно нересайзабельное. В результате две конкурирующие навигации.
- `settings_recording_content.html`: действующий редактор через `grafRecordingSettings` и постоянная ссылка «Открыть локальные настройки» редактируют одно хранилище.
- `settings_notifications_content.html`: локальные настройки доступны только через «Настроить на этом Mac», аккаунтные ниже в вебе. Native view использует Form и отдельные Save/Cancel/Test.
- `settings_content.html` и `sections.html`: обзор карточками повторяет список бокового меню.

## Ограничения наблюдения

Не проверялись сохранение изменений в Krisp, системные разрешения, фактическая доставка, светлая тема и его крайние responsive-состояния: не требуются изменения пользовательских предпочтений ради исследования. Эти состояния для GRAF определяются действующими правилами и собственными проверками. Пропорции на снимке — ориентир, точные логические CSS-размеры Krisp не извлекались. До сравнения реализованного GRAF Dev нельзя заявлять полное визуальное совпадение «1 в 1».
