# Feature Specification: Единые настройки GRAF

**Feature Branch**: `codex/260-unified-settings`
**Created**: 2026-09-09
**Status**: Design review
**Input**: Исправить нечитаемые настройки и названия приложений, убрать два места редактирования, продумать весь путь записи и уведомлений, воспроизвести наблюдаемую структуру Krisp с учётом GRAF.
**Lane**: High-risk product / reference-fidelity UX. Изменение представления и маршрутов; семантика записи сохраняется.

## Clarifications

### Session 2026-09-09

Обязательный clarify выполнен: критических вопросов без разумного ответа из запроса и действующего контракта нет. Пользователь уже выбрал референс и единую структуру. Ниже перечислены принятые ограничения, а не новые ответы пользователя.

- Единый обычный путь — настройки в основном окне. Веб-кабинет редактирует настройки аккаунта; локальные настройки доступны только на текущем Mac. Отдельная локальная поверхность нужна только при недоступности кабинета.
- «1 в 1» относится к наблюдаемой композиции, иерархии и поведению релевантных элементов. Не добавляются отсутствующие в GRAF возможности Krisp.
- Три правила, полный реестр допустимых приложений, отсчёт 8 секунд, запоминание выбора, ручная запись и видимый Stop сохраняются. Удалять или скрывать неподключённые приложения из реестра нельзя.
- Простые переключатели сохраняются сразу с подтверждением результата. Сложные формы профиля, безопасности, оплаты и подключения календаря сохраняют явное подтверждение.

## User Scenarios & Testing

### User Story 1 — Одно место настроек (Priority: P1)

Из меню GRAF, профиля или сочетания клавиш пользователь попадает в одни настройки; из напоминания или управления записью — сразу в нужный раздел. Назад возвращает к встречам, изменение не открывает второе обычное окно.

**Independent Test**: открыть все точки входа, перейти между разделами и назад, повторить при недоступности кабинета.

**Acceptance Scenarios**:
1. При готовом кабинете команда настроек открывает «Аккаунт» без промежуточного обзора; боковое меню остаётся единственным списком разделов.
2. «Настройки автозаписи» открывают «Запись», «Настройки уведомлений» открывают «Уведомления» в основном окне.
3. При недоступном кабинете доступно одно локальное окно с двумя разделами, одной боковой навигацией и понятным возвратом. При восстановлении доступен переход в основные настройки без потери сохранённых правил.

### User Story 2 — Понятные правила приложений (Priority: P1)

Пользователь видит имя каждого поддерживаемого приложения и выбранное правило справа. Названия не пропадают при изменении размера, длинные названия переносятся. Три огромные кнопки заменены одним раскрывающимся списком.

**Independent Test**: поменять правило одного приложения, всех приложений, открыть заново, проверить ошибку записи на диск и весь реестр.

**Acceptance Scenarios**:
1. При разных правилах общий список показывает «Разные правила» без ложного выбора «Всегда».
2. Выбор «Никогда» для одного приложения не меняет соседние правила, не останавливает текущую запись и сохраняет ручной старт.
3. «Спрашивать» явно поясняет автоматический старт через 8 секунд без отказа. Новый target по-прежнему получает «Спрашивать».
4. При ошибке сохраняется прежнее подтверждённое значение и рядом появляется сообщение с повтором; интерфейс не сообщает ложное сохранение.

### User Story 3 — Уведомления без переходов в другое окно (Priority: P1)

В одном разделе пользователь выбирает напоминания, время, названия и звук на Mac, а ниже — необязательные письма и подсказки для аккаунта.

**Independent Test**: на одном экране изменить каждое правило; проверить разрешённые/запрещённые/ещё не запрошенные уведомления, активную запись, смену аккаунта и отсутствие связи.

**Acceptance Scenarios**:
1. Разрешение macOS показано фактическим состоянием отдельно от желаемых правил. Запрос разрешения — только по явному нажатию.
2. Без разрешения можно выбрать будущие правила, но нельзя обещать доставку. Предложена понятная системная настройка.
3. При выключенных напоминаниях недоступен только выбор времени; при записи звук подавлен, индикатор записи и Stop остаются.
4. Аккаунт сменился во время чтения или сохранения: старые данные/результаты не показываются новому аккаунту и не меняют его настройки.
5. В обычном браузере нет ложных переключателей текущего Mac; вместо них короткое объяснение, где доступны локальные правила.

### Edge Cases

Полный реестр недоступен или пуст; длинное название; нет приложения на Mac; неизвестное приложение; узкое окно; 200% масштаб; работа без мыши; отсутствие JavaScript; прерванный/неподтверждённый ответ; быстрое повторное изменение; устаревшая страница/смена пользователя; закрытие окна во время сохранения; неизвестное разрешение macOS; сервер недоступен при доступном локальном хранилище.

## Requirements

### Functional Requirements

- **FR-001**: Один обычный экран с одной боковой навигацией и разделами «Аккаунт», «Пространства», «Тариф и оплата», «Запись», «Итоги», «Календари», «Уведомления». Группы и порядок соответствуют исследованию Krisp; отсутствующие функции не показываются.
- **FR-002**: Все существующие точки входа ведут к этому экрану или конкретному разделу. Убрать обычный обзор с карточками, повторные ссылки на локальное окно и дублирующие панели навигации.
- **FR-003**: Сохранить доступность локальных настроек без сервера через резервное окно с одной боковой навигацией. Его минимальный размер и компоновка не обрезают содержание; повторное открытие переиспользует окно.
- **FR-004**: Каждое допустимое приложение представлено одной компактной строкой «полное имя → текущее правило». Поиск по имени фильтрует только видимые строки; массовое действие применяется ко всему реестру с явной подписью области. Идентичность берётся из действующего реестра; браузеры/произвольное аудио не объявляются поддержанными.
- **FR-005**: Сохраняются ровно три записываемых правила и массовое применение только к известным допустимым приложениям. Смешанное состояние не записывается как четвёртое правило.
- **FR-006**: Сохранить отсчёт, запоминание выбора, разрешения, локальное владение записью, ручной старт/Stop, видимый индикатор и ограничения пространства.
- **FR-007**: Простые правила и переключатели сохраняются автоматически; подтверждённое состояние авторитетно. Ошибка, недоступность и неопределённый результат отличаются от успеха; повторное чтение восстанавливает истину. Сложные формы остаются с явным сохранением и существующими защитами.
- **FR-008**: Локальные уведомления редактируются внутри общего раздела и в резервном окне через одно существующее хранилище для текущего аккаунта на этом Mac.
- **FR-009**: Напоминания, 0/1/5 минут, названия и звук сохраняют текущую семантику. Во время записи звука нет. Ошибки записи/отправки, индикатор, Stop и обязательные письма нельзя скрыть этими настройками.
- **FR-010**: Состояние разрешения macOS — отдельно: проверка / не запрашивалось / разрешено / запрещено / неизвестно. Запрос, переход в macOS и тестовое уведомление требуют явного действия. Тест использует сохранённые настройки и сообщает передачу системе, не гарантированную доставку.
- **FR-011**: Письма и подсказки сохраняют серверное владение, CSRF, версионность и поведение без JavaScript. Нет переноса локальных правил на сервер или притворного управления другим Mac из браузера.
- **FR-012**: Локальный обмен доступен только доверенной основной странице своего раздела и текущему аккаунту; неправильные origin/frame/route/nonce/shape, прежний документ и устаревший ответ отклоняются. Только строго разрешённые поля и действия; нет команд записи и произвольных системных URL.
- **FR-013**: Смена раздела, восстановление связи, обновление реестра и изменение из резервного окна не оставляют устаревшую видимую настройку. Сохранять фокус на прежнем контроле при обновлении значения.
- **FR-014**: Один заголовок страницы, умеренная плотность, нейтральные разделители, названия слева и управление справа; фирменный акцент только для выбранного/активного. Светлая и тёмная темы, контраст WCAG 2.2 AA, видимый фокус и нативная клавиатурная работа обязательны.
- **FR-015**: В узком виде строки переходят в вертикальную компоновку; названия и контролы не обрезаются и не требуют горизонтальной прокрутки. Навигация остаётся доступной при 200% и без мыши.
- **FR-016**: Для каждого отличия от Krisp записать причину. Использовать собственную реализацию, существующие иконки GRAF и системные шрифты; не копировать бинарники, исходники, активы и личные данные Krisp.
- **FR-017**: При миграции сохраняются все существующие правила, настройки уведомлений и аккаунта. Откат восстанавливает прежнее представление без миграции данных.

### Key Entities

Раздел настроек; поддерживаемое приложение с идентификатором, именем и локальным правилом; локальные настройки уведомлений с владельцем; статус разрешения macOS; настройки писем и подсказок аккаунта; подтверждённое/ожидающее/ошибочное состояние сохранения.

## Success Criteria

- **SC-001**: Все существующие обычные точки входа ведут в один экран; от меню настроек до любого раздела не больше одного дополнительного выбора, от контекстного действия — сразу нужный раздел.
- **SC-002**: Для 100% допустимого реестра имя и правило видны целиком при окне от 820×600; при 320/390/768/1024/1440 CSS px и 200% нет горизонтального переполнения.
- **SC-003**: Матрица трёх правил, смешанного/пустого реестра, ошибок сохранения, обновления состояния и работы клавиатуры проходит без потери правил.
- **SC-004**: Матрица разрешения/звука/смены владельца/устаревших документов проходит; ни один отвергнутый запрос не меняет настройки.
- **SC-005**: До заявления о готовности пройдены независимая проверка требований, analyze без critical/high, синхронизация задач, профильные проверки, convergence и требуемые проверки точного SHA. Полное визуальное совпадение требует отдельной проверки GRAF Dev.

## Assumptions & Scope

Не добавляются шумоподавление, виртуальные устройства, новые интеграции, автозапуск приложения, управление чужим Mac, новые каналы уведомлений или функции записи. Профиль, безопасность, оплата, пространства, календари и итоги сохраняют действующие операции; изменение их оформления не разрешает изменение политик, доступа, удаления, отправки писем или платежей. Продакшен и выпуск отдельно. Исследование установленного Krisp — только наблюдаемый интерфейс, без изменения его пользовательских настроек.
