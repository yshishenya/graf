# F260 — Проверка кода и соответствия

2026-09-09. Проверка автором реализации, не замена независимого reviewer требований и установленного Dev.

## Корректность

- Обычный маршрут настроек ведёт в аккаунт; контекст записи/уведомлений — прямо в соответствующий раздел. `.loading` не открывает резерв, явный повтор восстанавливает кабинет. Резерв переиспользует одно окно с одной боковой навигацией.
- Правила записи обновляют прежний store patch-операцией. Поиск фильтрует представление, bulk обходит полный допустимый реестр. Неизвестные targets и mixed не записываются. При нечитаемом native store не показываются выдуманные правила по умолчанию.
- Уведомления используют presenter, не прямую запись UserDefaults. Поля проверяются по имени/типу, offset ограничен 0/1/5. Защита origin/main-frame/exact encoded path/query/fragment/current WebView/nonce дополнена authEpoch.
- Cookie reconciliation и обновление контекста предшествуют активации моста. Auth change инвалидирует мост синхронно; A→B→A не возрождает nonce. После await повторно проверяются поколение и документ; поздняя отправка теста удаляется по уникальному ID.
- При ошибке локальный UI возвращает подтверждённое значение. Таймаут не обещает отмену записи. Старые ответы и disconnect не оживляют контролы. Обычный POST/CSRF/version/no-JS аккаунтных предпочтений сохранены.
- Код старта/остановки записи, 8 секунд, индикатор, локальное владение, серверные политики, платежи и удаление не изменены.

## Ponytail review

Сохранены существующие system Picker/select, store, presenter, маршрутизатор, стили switch и fixture. Новых зависимостей и общей системы настроек нет. Новый специализированный мост нужен для доверенной границы WebKit → локальные уведомления. Дополнительных полезных сокращений без потери требуемого поведения не найдено.
