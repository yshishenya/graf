## 3. Проверка предыдущих блокеров

### 3.1 FR-011 vs automatic eviction — закрыт

`spec.md:133` теперь разрешает automatic eviction только по FR-025…FR-032 и только для WAV; ручная очистка требует подтверждения. Это согласовано с clarify Q2 (`spec.md:16`), FR-025 (`:147`), FR-031/032 (`:153-154`), assumption (`:189-190`) и Phase C (`plan.md:181-193`). `analyze-2026-11-16.md:17` больше не противоречит spec.

### 3.2 Custody revision vs playback revision — закрыт на уровне контракта

`spec.md:125` (FR-003) требует custody **той же ревизии, которую проверяет playback**, и явного `upload_session.media_revision_id`. Это повторено в `plan.md:70,78-80,87`, `research.md:31`, `data-model.md:67-76` и `contracts/desktop-sync-proof.md:38-41`. Mismatch custody/playback объявлен keep-local. T002 требует pinned-older-revision test.

Остаётся implementation-уточнение: `plan.md:88` должен явно передать уже разрешённую `revision` в `review_playback_state`, а `plan.md:89` — использовать finalized-custody helper, а не legacy default `archive_audio_for_revision`. Это не меняет дизайн, но должно быть закреплено в T002/T003.

### 3.3 `object_verified` bounded read probe — закрыт

`plan.md:90` требует `stat_object` и bounded read probe первых 12–64 КиБ с timeout; `research.md:23`, `data-model.md:19,24` и `contracts/desktop-sync-proof.md:39` требуют того же. `object_verified=true` теперь означает stat/size + успешное чтение, а не только наличие записи. Тест на bounded-read failure добавлен в T003.

### 3.4 Storage role matrix и 503 vs projection failure — закрыт

`spec.md:127` (FR-005) задаёт: personal owner — `manage` + суммы/действие; corporate owner/admin — `read_only` + видимые суммы + `contact_owner`; member — `read_only` + null amounts + `threshold=unknown` + `action=none`; unknown — безопасный member-профиль. `contracts/desktop-storage-status.md:28-37` содержит точную матрицу; `plan.md:120-121` и `research.md:47` согласованы. `contracts/desktop-storage-status.md:43-47` разделяет missing DB session (`503`) и projection failure (`200` + `unknown`).

Замечание: `data-model.md:48` всё ещё говорит «Visible only with management rights», хотя строки `:62-65` разрешают corporate admin видеть суммы. Это wording-долг; матрица из contract и validation однозначна. Исправить при реализации, не блокер дизайна.

### 3.5 Dry-run server expiry reconciliation exception — закрыт

`spec.md:132` (FR-010) явно разрешает существующую идемпотентную expiry-реконсиляцию sync-state, запрещает удаление встреч/объектов/локальных файлов и требует тест. `contracts/desktop-sync-proof.md:64-66` фиксирует read-side exception; `research.md:117-123` повторяет. Security CHK010 теперь сформулирован как «no destructive server mutation… exception explicitly allowed and tested». Тест ещё не реализован, поэтому item остаётся implementation-open.

### 3.6 Kill switch — закрыт

`spec.md:154` (FR-032) задаёт effective = persisted setting && no operator env disable; изменение действует со следующего запуска планировщика без restart. `spec.md:190` задаёт первый релиз с operator switch on, пользовательская настройка default true. `plan.md:189`, `research.md:87` и T020 согласованы. Тест immediate effect/operator override ещё не реализован.

### 3.7 Two-phase receipt и crash/retry — закрыт

`spec.md:141-142` (FR-019/FR-020) задаёт `pending` intent до unlink и `completed` после; при падении повторный запуск находит `pending`, сверяет отпечаток и пишет `completed`/`noop`, без второго удаления/квитанции. `spec.md:184` (SC-015) добавляет критерий. `plan.md:172-173`, `data-model.md:127-148`, `quickstart.md:70` и `contracts/cleanup-receipt.schema.json:7-20,43-50,67-73` требуют non-null `verifiedAt`/`playbackRevisionFingerprint` и state `pending/completed/noop`. Crash/retry tests ещё не реализованы (T015/T019).

### 3.8 Existing SHA-256 fields vs new proof hash rule — закрыт

`contracts/desktop-sync-proof.md:70` явно разрешает существующие `manifest_sha256`/`track_sha256_by_role` для совместимости и запрещает hashes только в новых proof-полях. Security CHK001 приведён к этой формулировке. Существующий no-secret тест не расширен на новые поля; это implementation evidence T008.

### 3.9 Canonical UX copy и VoiceOver — закрыт

`contracts/ux-copy.md` содержит точные строки для action, confirmation, space, success/no-op/unexpected, reason-to-copy таблицу, automatic eviction section/toggle/disabled/operator override/warning и VoiceOver labels. UX CHK001–CHK012 подтверждены на уровне copy-контракта. UI-реализация и copy/AX tests остаются T016/T020, но это implementation evidence, не дизайн-блокер.

### 3.10 OpenAPI/compat/no-mutation tests — implementation evidence open

OpenAPI, decode-тесты, no-mutation report и fail-closed matrix не реализованы. Они перечислены в разделе 4 и не блокируют design start.

## 5. Некритичные уточнения для реализации

Эти пункты не меняют архитектуру и не блокируют старт, но их нужно устранить в коде/тестах или поправить формулировки:

1. **`data-model.md:48`** — «Visible only with management rights» стоит привести к матрице: суммы видны personal owner и corporate admin, null — member/unknown.
2. **`plan.md:88`** — явно передать `revision=<playback revision>` в `review_playback_state`; без этого helper может повторно разрешить другую ревизию.
3. **`plan.md:89`** — для playback proof использовать `finalized_upload_custody_for_revision`, а не legacy `archive_audio_for_revision` с default `True`; иначе ответ может противоречить строке «No finalized session → null/null».
4. **`contracts/desktop-sync-proof.md:53` vs `plan.md:91`** — согласовать `automatic_recovery` для storage stat error (contract: `true`, plan: «по состоянию job»). На safety не влияет, но контракт должен быть однозначным.
5. **`upload_session`** — уточнить, что `session_id/status` остаются active upload state, а `media_revision_id/archive_audio/finalized_at` относятся к finalized custody; либо вынести custody в отдельный вложенный объект. Сейчас contract example показывает `status=finalized`, хотя текущий `upload_session` — active session.
6. **Retention projection** — `retention_projection` должен учитывать не только `retention_meeting_delete_after_days`, но и общую safety-политику (`retention_backup_expiry_days`, `retention_local_buffer_expiry_days`), иначе возможен `active` при фактически `unsafe` policy. Покрыть T004.
7. **Plan tree** — `contracts/ux-copy.md` не указан в `plan.md:213-232`; добавить в documentation tree.
8. **Tasks order** — T024–T026 стоят после T001–T023, хотя dependency block (`tasks.md:66`) требует их before implementation. Переставить или исправить dependency.
9. **Analyze metrics** — `analyze-2026-11-16.md:7,37` всё ещё говорит о 14 SC, хотя в `spec.md` теперь 15 (SC-015). Обновить metrics/coverage и повторно прогнать analyze перед T025.
10. **FR-014/FR-029** — закрепить в T013/T019 конкретные timeout и приоритет lifecycle/deletion, чтобы «bounded» и «не голодать» были проверяемыми, а не только описательными.
