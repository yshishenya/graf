## Addendum 2026-11-16 (after independent checklist review)

The independent reviewer read an earlier `spec.md` snapshot and reported FR-011 as still forbidding automatic eviction. FR-011 was already corrected to allow FR-025…FR-032. The following review findings were then fixed in the artifacts:

- A9 (HIGH, fixed): custody and playback revisions are now explicitly the same revision; `upload_session.media_revision_id` is exposed and a pinned-older-revision test is required.
- A10 (HIGH, fixed): `object_verified` now requires a bounded read probe, not only stat/size.
- A11 (HIGH, fixed): storage role matrix is exact (personal owner manage, corporate admin read-only with visible amounts, member/unknown null), and 503 vs projection-failure behavior is separated.
- A12 (MEDIUM, fixed): the idempotent sync-state expiry reconciliation is an explicit, tested exception to “no server mutation”; destructive mutation remains forbidden.
- A13 (HIGH, fixed): kill-switch semantics are now one policy — persisted setting default true AND no operator env disable, effective without restart; the first release starts with the operator switch on until the production dry run is clean.
- A14 (HIGH, fixed): receipts are two-phase (`pending` before unlink, `completed` after) with crash/retry reconciliation; `verifiedAt` and `playbackRevisionFingerprint` are required.
- A15 (MEDIUM, fixed): the hash rule now explicitly allows existing revision SHA-256 fields and forbids hashes only in new proof fields.
- A16 (HIGH, fixed): canonical UX copy and VoiceOver labels are in `contracts/ux-copy.md`.

Remaining review-unchecked items are implementation evidence (decode, OpenAPI, no-mutation report, tests). They stay open until T009–T030 produce evidence; a second reviewer pass is required after implementation.
