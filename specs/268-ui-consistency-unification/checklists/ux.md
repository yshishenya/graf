# UX Checklist: единый интерфейс GRAF (фича 268)

Назначение: проверить качество требований до реализации. Пункты заполняет
ревьюер; агент реализации не отмечает их сам.

## Визуальный язык и токены

- [x] Требования однозначно определяют, что источником палитры является кабинет, а приложение повторяет его значения.
- [x] Для светлой и тёмной темы требования проверяемы (перечислены поверхности и измеримые пороги контраста).
- [x] Шкала радиусов и типографики описана как закрытый набор без «свободных» значений.
- [x] Удаление мёртвых токенов и дублей сформулировано так, что не допускает регресса контракта кабинета и тестов.

## Состояния и обратная связь

- [x] Для каждого состояния (обработка, приостановка, внимание, отказ, загрузка, успех, ошибка, конфликт) указаны тон и требование передавать смысл не только цветом.
- [x] Требования к скелетону включают отсутствие смещения контента и видимость в обеих темах.
- [x] Требование к автосохранению явно различает успех, ошибку и конфликт.
- [x] Требование к окну «Поделиться» гарантирует соответствие текста фактическому состоянию доступа.
- [x] Требования к диалогам и кнопкам закрытия описывают единый компонент и единый тон опасных действий.

## Доступность

- [x] Вкладки карточки встречи описаны как доступные скринридеру без потери визуального порядка.
- [x] Палитра спикеров проверяема: минимальный контраст текста 4,5:1 и плашек 3:1 в обеих темах.
- [ ] Единая обводка фокуса сформулирована с исключениями только там, где элемент обрезается.
- [x] Цели нажатия приложения описаны измеримо (≥ 40pt) с явным списком допустимых исключений.

## Тексты и словарь

- [x] Требования фиксируют единственный термин для каждого действия и объекта.
- [x] Конвенция «без ё» описана с явными исключениями (имена, «Mute микрофона»).
- [x] Требование обновлять тесты, проверяющие пользовательский текст, не допускает отключения проверок.
- [x] Требования к обновлениям содержат один источник подписей для меню, трея, индикатора и полосы.

## Поведение и границы

- [x] Требования явно запрещают изменение поведения записи, авторизации, доступа, удаления, оплаты и обработки.
- [x] Описано поведение на узких ширинах (320–1440) и во встроенном режиме.
- [x] Описано поведение без JavaScript.
- [x] Для страниц вне системы (уведомления, удаления) требования включают тему и стандартные компоненты.
- [x] Определены зависимости и допущения (палитра кабинета как источник, сохранение «Mute микрофона»).

### Сомнения и дефекты

1. **[MUST, FR-004 / US4 AS-1] Видимая подпись «Стоп».**
   `apps/macos/RecApp/Sources/Cabinet/DesktopMeetingShellView.swift:1343` —
   `Label("Стоп", systemImage: "stop.fill")` в HUD записи, тогда как везде
   «Остановить запись» (`SystemAudioStatusLabels.stopButtonTitle`,
   `DesktopMeetingShellChrome.compactRailStopLabel`). Accessibility label
   правильный, видимый текст — нет; task T014 заявляет единый текст неточно.
2. **[MUST, FR-002] Границы состояний в приложении не совпадают с вебом.**
   `DesktopDesignTokens.swift:51-58` заменяет `color-mix(... %, var(--line))`
   прозрачностью. Пример: тёмная тема, CSS `--accent-border`
   (`cabinet.css:26`) ≈ rgb(145,143,195), Swift `accentBorder` поверх фона ≈
   rgb(85,78,123). Используется в видимых элементах:
   `CaptureControlViewCore.swift:622`, `DesktopMeetingShellView.swift:409-413`,
   `AppUpdateNotice.swift:30`.
3. **[MUST, FR-001 / SC-002 / US1] Локальная тёмная палитра настроек осталась.**
   `cabinet.css:6144-6156`: `html[data-theme="dark"]
   .app-shell[data-active-nav="settings"]` задаёт `--bg: #202123`,
   `--accent-solid: #9581ff` и др. Тест темы считает область одобренной
   (`test_cabinet_theme_contract.py:90-93`), но SC-002 и US1 «локальных палитр
   нет» этого не допускают; замеров тёмных настроек в evidence нет.
4. **[SC-002] Литералы тёмных цветов спикеров** — `cabinet.css:1200-1205`,
   значения живут вне блоков палитры и закреплены тестом
   `test_cabinet_web_shell.py:2408`. Светлая палитра измерена
   (`evidence/measurements.md:45-58`), тёмная — нет (FR-012, вторая тема).
5. **[Контракт §7] Вариант `.icon-button--ghost` не реализован** — в коде
   `--bordered` (`cabinet.css:466`), «призрачным» стал базовый вид; слова
   `ghost` в репозитории нет.
6. **[FR-004, «один источник» частично] `CalendarTray.swift:248`** и
   `DesktopMeetingShellView.swift:47` дублируют строку остановки вместо ссылки
   на `SystemAudioStatusLabels.stopButtonTitle`.
7. **[FR-018, мелко] Ошибка онбординга** закрашена `DesktopDesignTokens.red`
   (`DesktopPermissionOnboardingView.swift:196`) вместо `dangerText` из
   контракта §4.
8. **[FR-019, мелко] `.detecting` показывает summary «Встреча обнаружена»**
   (`MeetingDetectionModels.swift:73-74`) при label «Проверяется автозапись…».
9. **Evidence-пробелы:** нет замеров контраста тёмной темы, ширин 320/390/768 и
   тёмных настроек; нативная визуальная проверка индикатора обновления, трея и
   онбординга осталась за оператором (T026/T027 открыты, признано в
   `validation.md:72-79`).
