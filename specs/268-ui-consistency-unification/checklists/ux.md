# UX Checklist: единый интерфейс GRAF (фича 268)

Назначение: проверить качество требований до реализации. Пункты заполняет
ревьюер; агент реализации не отмечает их сам.

## Визуальный язык и токены

- [ ] Требования однозначно определяют, что источником палитры является кабинет, а приложение повторяет его значения.
- [ ] Для светлой и тёмной темы требования проверяемы (перечислены поверхности и измеримые пороги контраста).
- [ ] Шкала радиусов и типографики описана как закрытый набор без «свободных» значений.
- [ ] Удаление мёртвых токенов и дублей сформулировано так, что не допускает регресса контракта кабинета и тестов.

## Состояния и обратная связь

- [ ] Для каждого состояния (обработка, приостановка, внимание, отказ, загрузка, успех, ошибка, конфликт) указаны тон и требование передавать смысл не только цветом.
- [ ] Требования к скелетону включают отсутствие смещения контента и видимость в обеих темах.
- [ ] Требование к автосохранению явно различает успех, ошибку и конфликт.
- [ ] Требование к окну «Поделиться» гарантирует соответствие текста фактическому состоянию доступа.
- [ ] Требования к диалогам и кнопкам закрытия описывают единый компонент и единый тон опасных действий.

## Доступность

- [ ] Вкладки карточки встречи описаны как доступные скринридеру без потери визуального порядка.
- [ ] Палитра спикеров проверяема: минимальный контраст текста 4,5:1 и плашек 3:1 в обеих темах.
- [ ] Единая обводка фокуса сформулирована с исключениями только там, где элемент обрезается.
- [ ] Цели нажатия приложения описаны измеримо (≥ 40pt) с явным списком допустимых исключений.

## Тексты и словарь

- [ ] Требования фиксируют единственный термин для каждого действия и объекта.
- [ ] Конвенция «без ё» описана с явными исключениями (имена, «Mute микрофона»).
- [ ] Требование обновлять тесты, проверяющие пользовательский текст, не допускает отключения проверок.
- [ ] Требования к обновлениям содержат один источник подписей для меню, трея, индикатора и полосы.

## Поведение и границы

- [ ] Требования явно запрещают изменение поведения записи, авторизации, доступа, удаления, оплаты и обработки.
- [ ] Описано поведение на узких ширинах (320–1440) и во встроенном режиме.
- [ ] Описано поведение без JavaScript.
- [ ] Для страниц вне системы (уведомления, удаления) требования включают тему и стандартные компоненты.
- [ ] Определены зависимости и допущения (палитра кабинета как источник, сохранение «Mute микрофона»).
