Назначение: проверить качество требований до реализации. Пункты заполняет
ревьюер; агент реализации не отмечает их сам.

## Визуальный язык и токены

- [x] Требования однозначно определяют, что источником палитры является кабинет, а приложение повторяет его значения.
- [x] Для светлой и тёмной темы требования проверяемы (перечислены поверхности и измеримые пороги контраста).
- [x] Шкала радиусов и типографики описана как закрытый набор без «свободных» значений.
- [x] Удаление мёртвых токенов и дублей сформулировано так, что не допускает регресса контракта кабинета и тестов.

## Состояния и обратная связь

- [x] Для каждого состояния (обработка, приостановка, внимание, отказ, загрузка, успех, ошибка, конфликт) указаны тон и требование передавать смысл не только цветом.
- [x] Требования к скелетону включают отсутствие смещения контента и видимость в обеих темах.
- [x] Требование к автосохранению явно различает успех, ошибку и конфликт.
- [x] Требование к окну «Поделиться» гарантирует соответствие текста фактическому состоянию доступа.
- [x] Требования к диалогам и кнопкам закрытия описывают единый компонент и единый тон опасных действий.

## Доступность

- [x] Вкладки карточки встречи описаны как доступные скринридеру без потери визуального порядка.
- [x] Палитра спикеров проверяема: минимальный контраст текста 4,5:1 и плашек 3:1 в обеих темах.
- [x] Единая обводка фокуса сформулирована с исключениями только там, где элемент обрезается.
- [x] Цели нажатия приложения описаны измеримо (≥ 40pt) с явным списком допустимых исключений.

## Тексты и словарь

- [x] Требования фиксируют единственный термин для каждого действия и объекта.
- [x] Конвенция «без ё» описана с явными исключениями (имена, «Mute микрофона»).
- [x] Требование обновлять тесты, проверяющие пользовательский текст, не допускает отключения проверок.
- [x] Требования к обновлениям содержат один источник подписей для меню, трея, индикатора и полосы.

## Поведение и границы

- [x] Требования явно запрещают изменение поведения записи, авторизации, доступа, удаления, оплаты и обработки.
- [x] Описано поведение на узких ширинах (320–1440) и во встроенном режиме.
- [x] Описано поведение без JavaScript.
- [x] Для страниц вне системы (уведомления, удаления) требования включают тему и стандартные компоненты.
- [x] Определены зависимости и допущения (палитра кабинета как источник, сохранение «Mute микрофона»).
