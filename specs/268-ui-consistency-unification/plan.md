# Implementation Plan: Единый интерфейс GRAF: токены, состояния и копирайт

**Feature**: `268-ui-consistency-unification`
**Branch**: `268-ui-consistency-unification`
**Risk lane**: `high-risk-product` (UX, доступность, локализация, состояния
недоступности, нативные поверхности трея/онбординга)
**Validation lane**: focused server + macOS tests, браузерный стенд с
измерениями, обязательные GitHub `governance-fast`, `macos-pr`, `pr-metadata`
на точном SHA PR; `release-full` на замороженном кандидате релиза. Установка и
проверка в `/Applications/GRAF Dev.app` через `dev-harness`.

## Summary

Привести кабинет, публичный сайт и macOS-приложение к одному визуальному языку
и одному словарю: единственный источник цветов/радиусов/типографики, единые
компоненты состояний и окон, честные статусы, один индикатор обновления, единая
конвенция текста без «ё». Поведение записи, авторизации, доступа, удаления,
оплаты и обработки не меняется.

## Technical Context

- **Кабинет**: Jinja-шаблоны + `cabinet.css` (6297 строк), `cabinet.js`,
  `settings-autosave.js`; серверный рендеринг в `rendering.py`,
  `deletion_rendering.py`, `view_models.py`.
- **Публичный сайт**: `public/templates/public/**`, свои стили.
- **macOS**: SwiftUI `RecApp/Sources/**`, общие модели `Shared/Sources/**`,
  тесты `Shared/Tests/**`; `swift test --package-path apps/macos`
  (обёртка `apps/macos/Scripts/run-swift-tests.sh`).
- **Проверка**: синтетические браузерные стенды
  `apps/server/tests/fixtures/*_visual_ui_harness.py`; focused pytest; замеры
  вычисленных стилей; dev-harness для единственного Dev-приложения.
- **Ограничения**: без изменения HTTP-контрактов, схемы, прав, обработки,
  записи и удаления; без новых зависимостей.

## Phase 0: Research

Результаты — `research.md`: решение по индикатору обновления (по практикам
Chrome/VS Code/Firefox, Microsoft 365, Sparkle), источник палитры, шкала
радиусов, типографика, палитра спикеров, идентификаторы автозаписи, замеры
обрезки, судьба страниц вне системы, стратегия тестов.

## Phase 1: Contracts

`contracts/ui-tokens-and-copy.md` фиксирует:

- канонический список токенов и правило «нет цвета вне токенов»;
- шкалу радиусов и типографики;
- словарь состояний (обработка/внимание/отказ/загрузка/успех/ошибка);
- словарь текстов (остановка записи, автозапись, расшифровка, обновление) и
  конвенцию без «ё»;
- контракт индикатора обновления (один постоянный, полоса только для действия);
- контракт страниц вне системы (тема, shell, компоненты).

## Phase 2: Implementation

### US1. Единый визуальный язык (P1)

1. `cabinet.css`: палитра остаётся единственным источником; удаляются
   `.detail-page-main`/`.detail-playback` переопределения; жёсткие цвета
   переводятся на токены и `color-mix`; удаляются мёртвые токены и дубли правил;
   вводится шкала радиусов; выравнивается типографика (`--font-size-body` 14px,
   один заголовок страницы, диалоговые заголовки из токена).
2. macOS: новый модуль токенов `DesktopDesignTokens` с динамическими цветами,
   совпадающими с кабинетом; все фирменные элементы используют его; мёртвые
   hex-эталоны заменяются на реальные значения; системный акцент в фирменных
   элементах устраняется.

### US2. Состояния кабинета (P1)

3. Компонент `.notice` с тонами (info/success/warning/error) и применением на
   страницах биллинга и рефералов.
4. Статусы списка встреч: оформление `.meeting-status`,
   `.meeting-content-readiness`, `[data-processing-retry-class]` в едином
   спокойном наборе; текст состояния без опоры только на цвет.
5. Скелетон: цвета из токенов, высота строки равна токену высоты строки.
6. Кнопки-иконки: один компонент `.icon-button` с вариантом `--ghost`;
   исправляется каскадный дефект `.icon-control.danger-button`.
7. Диалоги: единые тень, радиус, ширина, заголовок, отступы.
8. Автосохранение настроек: цвет статуса по `form[data-state]`.
9. Окно «Поделиться»: текст возможностей по фактическому состоянию доступа.
10. Палитра спикеров: уникальные цвета, светлые варианты, контрастный текст.
11. `.meeting-toolbar` не занимает место, когда панель выбора скрыта.

### US3. Нативные состояния (P1)

12. `MeetingDetectionStatus` как единый тип; честные подписи статуса автозаписи.
13. Подсказки навигации без служебного текста (корректные сочетания клавиш).
14. Настройки уведомлений доступны без входа для системных действий.
15. Онбординг: единая типографика, ошибка в тоне ошибки, единые стили кнопок,
    цели нажатия ≥ 40pt.
16. Настройки автозаписи: одна ошибка вместо двух, без разделителя под
    последней строкой, fallback использует фирменный акцент.
17. Трей: читаемая обрезка с полным текстом, честный заголовок ближайших
    событий, информационные строки не выглядят отключёнными.

### US4. Словарь и текст (P2)

18. Единый источник подписей остановки записи во всех поверхностях.
19. Терминология: «Автозапись», «Расшифровка», «Итоги», «Запись встреч».
20. Конвенция без «ё» в пользовательских строках кабинета, сайта и приложения;
    тесты обновляются синхронно.
21. Опечатки: «ЮKassa», «недоступны».

### US5. Обновления (P2)

22. Один постоянный индикатор; полоса только для фаз действия; единые подписи
    меню/трея/индикатора/полосы из одного источника.

### US6. Навигация (P2)

23. Паддинг пункта и ширина панели настроек; блок профиля с ограничением строк.

### US7. Страницы вне системы (P3)

24. История уведомлений на shell кабинета с темой и навигацией.
25. Страницы удаления: стандартные карточки, ссылки, заголовки, единый текст.

### US8. Доступность (P3)

26. Вкладки карточки встречи без `display: contents` с сохранением визуального
    порядка; единая обводка фокуса; контраст палитры спикеров.

## Phase 3: Validation

- focused pytest: контракты кабинета, темы, статических ассетов, настроек,
  биллинга, доступности, удаления, уведомлений; `node --check cabinet.js`;
  `python3 scripts/check_spec_kit_governance.py`.
- Браузерный стенд: скриншоты и замеры (контраст, обрезка, радиусы, скелетон,
  окна, статусы) в тёмной и светлой теме, standalone и embedded, 320–1440.
- macOS: `bash apps/macos/Scripts/run-swift-tests.sh`.
- Dev-приложение: `dev-harness build → promote → status → smoke`, проверка
  индикатора обновления, статусов автозаписи, трея, онбординга.
- Changelog-фрагмент в `changes/unreleased/`, запись evidence в `validation.md`.

## Complexity Tracking

| Решение | Почему оправдано |
|---|---|
| Динамические токены в Swift через `NSColor(name:)` | Сохраняет поддержку светлой/тёмной системы и совпадение с вебом без двух кодовых ветвей. |
| Перечисление `MeetingDetectionStatus` вместо строк | Устраняет класс ошибок «неизвестная строка → неверный статус» и делает подписи единым источником. |
| Переход истории уведомлений на shell | Убирает отдельную типографику и отсутствие темы; использует существующие компоненты. |
| Правка контрактных тестов | Тесты кодируют старые значения; обновление сохраняет смысл проверок и не ослабляет гейты. |
