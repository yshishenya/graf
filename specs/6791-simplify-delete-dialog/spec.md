# Feature Specification: Простое подтверждение удаления встречи

**Feature Branch**: `codex/6791-simplify-delete-dialog`
**Created**: 2026-09-09
**Status**: Implemented; PR and installed acceptance in progress
**Input**: Пользователь просит простое и понятное окно удаления из самой встречи, с минимумом текста и без усложнения.

## User Scenarios & Testing

### User Story 1 — Понятное подтверждение (Priority: P1)

Владелец встречи выбирает удаление и понимает последствия без знания внутренних сервисов.
**Why this priority**: Нынешнее окно повторяет предупреждение и перегружено техническими подробностями.
**Independent Test**: Открыть подтверждение в браузерной и встроенной странице встречи; прочитать короткий текст и отменить действие.

**Acceptance Scenarios**:
1. **Given** удаление разрешено, **When** открывается окно, **Then** видны заголовок «Удалить встречу?», текст «Встреча будет удалена из GRAF. Восстановить её не получится.» и две кнопки «Отмена» / «Удалить».
2. **Given** окно открыто, **When** выбраны «Отмена» или Escape, **Then** встреча сохраняется, окно закрывается, фокус возвращается к меню.
3. **Given** пользователь подтверждает, **When** отправляется запрос, **Then** используется существующее удаление с прежними проверками прав и защиты формы.
4. **Given** окно открыто, **When** пользователь читает последствия, **Then** нет технических названий и ссылки на ещё не существующий отчёт; полный отчёт остаётся частью существующего процесса удаления.

### Edge Cases

- Недоступное удаление: действие и окно не появляются.
- Потеря прав, ошибка сервера, повторный запрос: прежнее серверное поведение.
- Узкий экран, обе темы, клавиатура: существующие адаптивные стили, видимый фокус, Tab внутри окна и возврат фокуса сохраняются.
- Скачанные и отправленные в другие сервисы копии: текст не обещает их стирания.

## Requirements

### Functional Requirements

- **FR-001**: Окно содержит только заголовок, основной текст из двух предложений и две кнопки из US1/AC1.
- **FR-002**: Убрать повторное предупреждение и названия Generation Call, Langfuse, Temporal History, буферов и политик оператора из подтверждения. Сохранить существующие подробности в отчёте удаления.
- **FR-003**: Обещание ограничено удалением встречи из GRAF. По прямому указанию пользователя оговорка о скачанных и отправленных копиях в этом окне отсутствует; сведения об ограничениях остаются в существующем отчёте.
- **FR-004**: Сохранить права доступа, защиту формы, серверную границу подтверждения, URL запросов, обработку ошибок и состояния удаления без изменений.
- **FR-005**: Сохранить именованное окно, начальный фокус, Tab/Escape, отмену и возврат фокуса. Одинаковый текст для браузерного и встроенного кабинета; существующие светлая/тёмная тема и адаптивная ширина.
- **FR-006**: Удалить ссылку на отчёт из подтверждения: до первого запроса отчёта ещё нет. Не создавать новый экран, раскрывающийся блок или дополнительные шаги.

## Success Criteria

- **SC-001**: Один абзац основного текста не длиннее 12 слов; ровно две кнопки и ни одной ссылки в подтверждении.
- **SC-002**: Ни одного внутреннего технического названия в тексте подтверждения; ограничения удаления остаются правдивыми.
- **SC-003**: Целевые проверки текста, доступности, формы и отчёта проходят для обоих путей кабинета.

## Assumptions

Изменяется только подтверждение на странице встречи. Массовое удаление, механизм удаления и содержимое отчёта не входят. Новые зависимости, стили, серверные маршруты и изменения схемы данных не требуются. Установка приложения, коммит и выпуск отдельно от локальной реализации.
